# 紅隊演練指南

> 主動式 LLM 安全評估的學術框架與方法論

## 概述

**紅隊演練**（Red Teaming）是從攻擊者角度系統化測試 AI 系統安全性的方法。Ganguli et al. (2022) 將其定義為：「透過模擬潛在攻擊者的行為，主動識別模型可能產生的有害輸出。」

---

## 學術發展

### 從資安到 AI 安全

紅隊概念源於軍事和資訊安全領域：

| 時期 | 應用領域 | 特點 |
|------|----------|------|
| 1960s | 軍事演習 | 模擬敵軍 |
| 1990s | 資訊安全 | 滲透測試 |
| 2020s | AI 安全 | 對抗性測試 |

### AI 紅隊的學術定義

Perez et al. (2022) 提出 AI 紅隊的三個目標：

1. **發現**：識別模型的有害行為
2. **量化**：評估風險的嚴重程度
3. **改進**：提供改進的依據

---

## 方法論框架

### 紅隊演練流程

Ganguli et al. (2022) 的系統化流程：

| 階段 | 任務 | 產出 |
|------|------|------|
| **規劃** | 定義範圍和目標 | 測試計畫 |
| **偵查** | 了解目標系統 | 攻擊面分析 |
| **攻擊** | 執行測試 | 攻擊日誌 |
| **分析** | 評估結果 | 風險評估 |
| **報告** | 文件化發現 | 紅隊報告 |

### 攻擊策略

Perez et al. (2022) 分類的攻擊策略：

| 策略 | 說明 |
|------|------|
| **情境設計** | 設計誘導有害輸出的情境 |
| **角色扮演** | 要求模型扮演特定角色 |
| **多輪誘導** | 逐步引導至敏感話題 |
| **編碼繞過** | 使用編碼或隱喻 |
| **對抗性優化** | 搜尋最優攻擊向量 |

## 自動化紅隊

### LLM 對 LLM 紅隊

Perez et al. (2022) 提出使用 LLM 自動生成攻擊：

| 方法 | 原理 |
|------|------|
| 零樣本 | 直接要求 LLM 生成攻擊 |
| 少樣本 | 提供攻擊範例 |
| 強化學習 | 優化攻擊成功率 |

### 自動化的優勢與限制

| 面向 | 優勢 | 限制 |
|------|------|------|
| 規模 | 可大量生成 | 可能重複 |
| 效率 | 快速迭代 | 缺乏創意 |
| 成本 | 降低人力需求 | 需要計算資源 |

## 人類紅隊

### 紅隊人員選擇

Ganguli et al. (2022) 建議的紅隊組成：

| 角色 | 專長 |
|------|------|
| 領域專家 | 特定領域知識 |
| 安全研究者 | 攻擊技術 |
| 社會科學家 | 社會影響評估 |
| 多元背景者 | 發現文化偏見 |

### 眾包紅隊

| 平台 | 特點 |
|------|------|
| **Surge AI** | 專業標註平台 |
| **Scale AI** | 大規模眾包 |
| **Bug Bounty** | 獎勵機制 |

## 評估指標

### 攻擊效果評估

| 指標 | 定義 |
|------|------|
| **攻擊成功率** | 成功誘導有害輸出的比例 |
| **攻擊嚴重度** | 產生的危害程度 |
| **攻擊難度** | 所需的技術複雜度 |

### 覆蓋度評估

| 維度 | 評估內容 |
|------|----------|
| 風險類別 | 是否測試所有風險類型 |
| 攻擊向量 | 是否嘗試所有已知攻擊 |
| 使用情境 | 是否涵蓋主要應用場景 |

---

## 倫理考量

Ganguli et al. (2022) 提出的倫理指引：

| 考量 | 建議 |
|------|------|
| 揭露責任 | 發現漏洞應負責任地揭露 |
| 資料保護 | 不得儲存敏感輸出 |
| 心理影響 | 關注紅隊人員的心理健康 |
| 濫用防護 | 報告不得被用於攻擊 |
