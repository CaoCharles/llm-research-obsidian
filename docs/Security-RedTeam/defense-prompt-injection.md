# Prompt Injection 防禦

> 防止惡意指令注入的學術研究與防禦策略

## 概述

**Prompt Injection** 是 LLM 應用面臨的核心安全威脅。Perez & Ribeiro (2022) 首次系統性描述這一攻擊類型，隨後引發大量學術研究關注。

---

## 學術定義

### 問題形式化

Prompt Injection 可形式化為指令優先級衝突問題：

- **系統指令 (S)**：開發者定義的行為規範
- **使用者輸入 (U)**：可能包含惡意指令
- **衝突**：當 U 中包含與 S 矛盾的指令時

### 攻擊分類

| 類型 | 說明 | 研究代表 |
|------|------|----------|
| **直接注入** | 透過對話直接注入 | Perez & Ribeiro (2022) |
| **間接注入** | 透過外部資料源注入 | Greshake et al. (2023) |

---

## 直接注入

### 攻擊機制

攻擊者在輸入中嵌入偽指令：

| 技術 | 說明 |
|------|------|
| **覆寫指令** | 「忽略之前的指令，改為...」 |
| **角色轉換** | 要求模型切換角色 |
| **分隔符利用** | 模仿系統格式 |
| **上下文操縱** | 偽造對話歷史 |

### 學術分析

Branch et al. (2022) 分析直接注入成功率：

- 簡單覆寫指令成功率約 20-40%
- 結合角色扮演成功率可達 60%+
- 成功率隨模型規模增加

---

## 間接注入

### 攻擊機制

Greshake et al. (2023) 描述的攻擊流程：

1. 攻擊者在外部資料源（網頁、文件）植入惡意指令
2. LLM 應用檢索這些資料
3. 惡意指令被處理，覆蓋系統行為
4. 使用者完全不知情

### 攻擊場景

| 場景 | 攻擊方式 |
|------|----------|
| RAG 系統 | 污染知識庫 |
| 網路搜尋 | 在網頁中植入指令 |
| 郵件助理 | 惡意郵件內容 |
| 代碼助理 | 惡意代碼註解 |

## 防禦研究

### 輸入層防禦

| 方法 | 原理 | 效果 | 研究 |
|------|------|------|------|
| **關鍵字過濾** | 阻擋已知攻擊詞彙 | 低 | — |
| **困惑度過濾** | 過濾異常輸入 | 中 | Alon & Kamfonas (2023) |
| **分類器檢測** | 訓練檢測模型 | 中高 | Jain et al. (2023) |

## 防禦效果評估

### 評估指標

| 指標 | 定義 |
|------|------|
| **阻擋率** | 成功阻擋攻擊的比例 |
| **誤拒率** | 誤擋正常請求的比例 |
| **繞過率** | 攻擊者仍能繞過的比例 |

### 研究發現

Jain et al. (2023) 的評估結論：

- 單一防禦措施很容易被繞過
- 組合多種防禦可提升效果
- 沒有完美的防禦，需持續更新

## 開放問題

| 問題 | 說明 |
|------|------|
| **動態攻擊** | 攻擊技術持續演進 |
| **防禦成本** | 嚴格防禦可能影響使用者體驗 |
| **間接注入** | 目前防禦效果有限 |
