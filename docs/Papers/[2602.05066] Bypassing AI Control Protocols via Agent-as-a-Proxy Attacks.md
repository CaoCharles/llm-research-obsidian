# Bypassing AI Control Protocols via Agent-as-a-Proxy Attacks

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2602.05066)
- 📥 [PDF](https://arxiv.org/pdf/2602.05066v1)

## 摘要（中文翻譯）

隨著 AI Agent 自動化處理關鍵工作負載，它們仍然容易受到間接提示注入（Indirect Prompt Injection, IPI）攻擊。目前的防禦依賴監控協議，聯合評估 Agent 的思維鏈（Chain-of-Thought, CoT）和工具使用行為，以確保與使用者意圖一致。本文展示這些基於監控的防禦可被一種新型 Agent-as-a-Proxy 攻擊繞過：提示注入攻擊將 Agent 當作傳遞機制，同時繞過 Agent 和監控器。作者提出 Parallel-GCG 演算法，一種針對 Agent 情境設計的梯度優化方法，確保對抗性字串在跨越 Agent 推理和工具使用時仍保持效力。在 AgentDojo 基準上，對 AlignmentCheck 和 Extract-and-Evaluate 監控器達到超過 90% 的攻擊成功率。結果顯示，即使是前沿規模的監控模型（如 Qwen2.5-72B）也能被具有相似能力的較小 Agent（如 GPT-4o mini、Llama-3.1-70B）成功繞過。

## 問題背景

AI Agent 在處理開放網路資料（如電子郵件、網站、RAG 上下文）時，極易受到間接提示注入攻擊。目前最先進的防禦採用混合監控（Hybrid Monitoring）方式，由次要可信模型同時審查 Agent 的推理過程（CoT）、工具呼叫及工具輸出，以偵測偏離使用者意圖的行為。然而，這種聯合監控 CoT 和行為的做法，反而暴露了更大的攻擊面：攻擊者可透過 Agent 的工具呼叫和推理過程，將最佳化後的對抗性字串直接傳遞給監控器，操縱其判斷結果。

## 解決方案

本文提出 Agent-as-a-Proxy 攻擊框架，核心思路是：不僅利用提示注入誤導 Agent，更將 Agent 當作「代理人」來傳遞對抗性字串給監控系統。攻擊者設計的對抗性字串會被 Agent 在其推理和工具呼叫中重複，從而直接影響監控器的判斷。為實現此目標，作者開發 Parallel-GCG 演算法，同時在多個插入點最佳化對抗性字串，確保其在 Agent 軌跡中的不同上下文（推理軌跡、函數參數、執行日誌）中都能有效欺騙監控器。

## 核心貢獻
1. 提出 Agent-as-a-Proxy 攻擊框架，利用受害 Agent 作為傳遞媒介，將對抗性字串送達監控系統
2. 開發 Parallel-GCG 最佳化演算法，同時在多個插入點最佳化對抗性字串，保持跨上下文的攻擊效力
3. 揭示混合監控的弔詭：雖然對靜態攻擊更具魯棒性，但對自適應攻擊反而更脆弱，因為暴露了更大的攻擊面
4. 挑戰「可擴展監督」假說：具有相似能力的較小模型即可成功繞過前沿規模的監控模型，無需能力差距

## 技術方法

**Parallel-GCG 演算法**：基於 Greedy Coordinate Gradient（GCG）方法的擴展。標準 GCG 針對單一靜態上下文最佳化對抗性字串，但在 Agent 工作流中，監控器會在多個階段觀察到該字串。Parallel-GCG 的做法：

1. **軌跡擷取**：先用佔位字串執行 Agent，獲得參考軌跡，識別佔位字串出現的 K 個位置
2. **上下文切片**：提取每次出現位置周圍的文字，形成固定上下文切片集合 {c_0, ..., c_K}
3. **聯合最佳化**：建構聯合損失函數，同時最小化所有 K 個插入點上的損失。坐標梯度為各插入點梯度的加總
4. **多目標擴展**：針對 LlamaFirewall（包含 PromptGuard 2 + AlignmentCheck）使用多目標 GCG，同時最佳化兩個分類器的輸出

**攻擊目標**：
- AlignmentCheck：目標輸出 `"conclusion": false`（標記為安全）
- Extract-and-Evaluate：目標輸出 `<score>0</score>`（無可疑行為）
- PromptGuard 2 + AlignmentCheck：多目標同時繞過輸入過濾器和混合監控

## 關鍵結果

| 監控協議 | 模型 | 基準 ASR | ASR@1 | ASR@5 |
|----------|------|---------|-------|-------|
| AlignmentCheck | Llama-3.1-8B | 0.0 | 42.3 | 42.3 |
| AlignmentCheck | Mistral-7B | 14.4 | 90.2 | 93.3 |
| AlignmentCheck | Qwen2.5-7B | 2.1 | 62.5 | 90.7 |
| PromptGuard 2 + AlignmentCheck | Llama-3.1-8B | 1.0 | 44.3 | 76.3 |
| PromptGuard 2 + AlignmentCheck | Mistral-7B | 12.4 | 86.4 | 99.0 |
| PromptGuard 2 + AlignmentCheck | Qwen2.5-7B | 2.1 | 61.2 | 86.6 |
| Extract-and-Evaluate | Llama-3.1-8B | 0.0 | 11.2 | 54.7 |
| Extract-and-Evaluate | Mistral-7B | 10.3 | 68.2 | 95.5 |
| Extract-and-Evaluate | Qwen2.5-7B | 2.3 | 10.5 | 37.2 |

**混合監控的弔詭（Table 4）**：混合監控在靜態攻擊下優於純 CoT 監控，但在自適應攻擊下反而更脆弱。例如 Mistral-7B v0.3，靜態攻擊下 CoT ASR 為 83.1%、Hybrid 為 12.5%；但自適應攻擊下 CoT 為 88.8%、Hybrid 高達 98.9%。

**跨模型攻擊（Agent-as-a-Proxy）**：GPT-4o mini 和 Llama-3.1-70B 作為代理 Agent，可分別以 46.0% 和 60.2% 的 ASR@5 繞過 Qwen2.5-72B 監控器。

**可遷移性**：攻擊字串可跨模型遷移，最高可達 405B 參數的模型。

## 對我們的啟發
- [ ] 混合監控的根本弱點在於架構設計：聯合監控 Agent 行為反而給予攻擊者直接操縱監控器的管道
- [ ] 「可擴展監督」在 Agent 安全領域可能不成立：單純增加監控模型規模無法保證安全
- [ ] 防禦設計應朝向結構性安全保證，而非僅依賴運行時監控或模型規模
- [ ] Parallel-GCG 的多上下文最佳化思路值得關注：對抗性字串需在多個位置同時有效才能攻擊 Agent 監控系統

## 限制與未來工作

1. 對抗性字串具有高困惑度（high perplexity），可能被分類器或人類輕易辨識；未來低困惑度的攻擊字串可能更隱蔽
2. 目前僅針對白盒監控器（可取得模型權重），未來可擴展至黑盒監控器攻擊
3. Agent 可能無法完美複製高困惑度的對抗性字串，端到端執行時 ASR 會下降 5-8 個百分點
4. 需要開發結構性安全架構（而非僅靠監控）來根本解決此類攻擊
