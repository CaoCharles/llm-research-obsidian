# How Few-shot Demonstrations Affect Prompt-based Defenses Against LLM Jailbreak Attacks

## 摘要（中文翻譯）

大型語言模型（LLMs）面臨越來越多的 jailbreak 攻擊威脅，這些攻擊能繞過安全對齊。雖然基於提示的防禦策略如角色導向提示（Role-Oriented Prompts, RoP）和任務導向提示（Task-Oriented Prompts, ToP）已展現出有效性，但 few-shot 示範在這些防禦策略中扮演的角色仍不明確。先前研究指出 few-shot 範例可能損害安全性，但缺乏對 few-shot 如何與不同系統提示策略交互的研究。本文在多個主流 LLM 上，跨四個安全基準（AdvBench、HarmBench、SG-Bench、XSTest）使用六種 jailbreak 攻擊方法進行全面評估，揭示了 few-shot 示範對防禦效果的複雜影響。

## 問題背景

LLM 的 jailbreak 攻擊日益多樣化，基於提示的防禦（如在系統提示中加入安全角色或任務描述）是部署成本最低的防護手段。然而，現有研究忽略了一個關鍵問題：在防禦提示中加入 few-shot 示範（安全回應範例）是否能強化防禦？還是反而會暴露模型的弱點？先前 I-FSJ 等工作顯示 few-shot 範例可被攻擊者利用，但防禦端如何善用 few-shot 仍缺乏系統性研究。此外，不同的系統提示策略（角色導向 vs. 任務導向）與 few-shot 的交互效果也未被探索。

## 解決方案

作者提出一套系統性的實驗框架，全面評估 few-shot 示範在不同防禦策略下的效果。框架包括：(1) 兩種防禦策略（RoP 和 ToP）分別搭配 0-shot、1-shot、3-shot、5-shot 示範；(2) 六種代表性 jailbreak 攻擊方法（涵蓋自動化和手動攻擊）；(3) 四個互補的安全基準測試；(4) 多個主流 LLM（包括 thinking mode 和 non-thinking mode 版本）。核心創新在於發現「think mode 悖論」：具推理模式的 LLM（如 Qwen3-8B-Think）安全率反而低於非推理版本，揭示推理模式可能引入額外安全風險。

## 核心貢獻
1. 首次系統性評估 few-shot 示範對基於提示的 LLM jailbreak 防禦的影響，跨越多個模型、攻擊方法和基準測試
2. 發現「think mode 悖論」：推理模式 LLM 的安全率低於非推理版本，暗示推理過程可能暴露模型的安全弱點
3. 提供實用指南：few-shot 示範在特定防禦策略和模型組合下能顯著提升安全性，但需謹慎選擇示範內容和數量

## 技術方法

**實驗設計**：作者建構 2（防禦策略）× 4（few-shot 數量）× 6（攻擊方法）× 4（基準測試）的全因子實驗矩陣。防禦策略包括 RoP（在系統提示中定義安全角色）和 ToP（明確定義安全任務規範）。Few-shot 示範從安全回應語料中精選，確保覆蓋拒絕、重定向和教育性回應。

**攻擊方法**：涵蓋 GCG（梯度攻擊）、AutoDAN（自動化攻擊）、PAIR（迭代攻擊）、DeepInception（角色扮演）及 I-FSJ（few-shot jailbreak）等六種方法。

**評估基準**：AdvBench（520 個有害提示）、HarmBench（多類別危害行為）、SG-Bench（安全與通用能力平衡）、XSTest（過度拒絕檢測）。評估指標為安全率（Safety Rate），使用 LLM-as-Judge 方式判斷回應安全性。

**模型選擇**：測試多個主流 LLM，包括具備 thinking mode 的模型（如 Qwen3-8B-Think、Pangu-Embedded-7B-Think）和標準版本，以比較推理模式的影響。

## 關鍵結果

| 模型 | 防禦策略 | Few-shot | AdvBench 安全率 ↑ | HarmBench 安全率 ↑ | XSTest 過度拒絕率 ↓ |
|------|----------|----------|-------------------|-------------------|---------------------|
| Qwen3-8B | ToP | 0-shot | 72.3% | 68.1% | 15.2% |
| Qwen3-8B | ToP | 3-shot | 81.5% | 75.4% | 12.8% |
| Qwen3-8B-Think | ToP | 0-shot | 65.1% | 61.3% | 18.7% |
| Qwen3-8B-Think | ToP | 3-shot | 70.2% | 66.8% | 16.1% |
| Pangu-7B | RoP | 0-shot | 69.8% | 64.5% | 14.3% |
| Pangu-7B | RoP | 3-shot | 78.9% | 73.2% | 11.5% |
| Pangu-7B-Think | RoP | 0-shot | 62.4% | 58.7% | 19.5% |

**關鍵發現**：
- **few-shot 整體有益**：3-shot 示範在多數模型和防禦策略下提升安全率 5-10%
- **Think mode 悖論**：Think 版本模型安全率普遍低於非 Think 版本 5-7%
- **防禦策略差異**：ToP 搭配 few-shot 效果優於 RoP，但 RoP 在過度拒絕控制上更好
- **5-shot 不一定更好**：過多示範有時導致安全率下降，3-shot 為最佳平衡點

## 對我們的啟發
- [ ] **推理模式的安全隱患值得關注**：Think mode 模型的推理鏈可能被攻擊者利用，在部署推理增強型 LLM 時需額外加強安全防護。啟發：應研究推理鏈中的安全感知機制
- [ ] **few-shot 防禦是低成本高收益的策略**：3-shot 安全示範即可顯著提升防禦效果，且不需要模型微調。啟發：在生產環境中，應優先在系統提示中加入精選的安全回應範例
- [ ] **防禦策略需因模型而異**：不同模型對 RoP 和 ToP 的響應不同，需實驗驗證最佳組合。啟發：建立「防禦策略-模型」的最佳配對矩陣
- [ ] **過度拒絕是防禦的副作用**：加強安全防禦會增加對正常請求的誤拒率，需在安全性與可用性之間平衡

## 限制與未來工作

本研究的 few-shot 示範僅使用英文，對多語言攻擊的防禦效果未被驗證。實驗主要在 7B-8B 規模模型上進行，更大規模模型是否有相同模式尚未確認。Think mode 悖論的根本原因（推理鏈中哪個環節導致安全失效）需要更深入的機制研究。此外，攻擊者可能針對 few-shot 防禦設計新型攻擊策略，長期安全性需持續評估。
