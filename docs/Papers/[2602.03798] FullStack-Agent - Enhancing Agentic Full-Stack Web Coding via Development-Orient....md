# FullStack-Agent: Enhancing Agentic Full-Stack Web Coding via Development-Oriented Testing and Repository Back-Translation

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2602.03798)
- 📥 [PDF](https://arxiv.org/pdf/2602.03798v1)
- 📎 本地 PDF: [PDF](../PDFs/2602.03798.pdf)

## 摘要（中文翻譯）

本文提出 FullStack-Agent，旨在用 LLM 驅動的 code agent 協助非專家構建真正的 full-stack 網站，彌補現有方法只生成前端頁面、而未處理資料流、後端與資料庫的不足。系統由三部分構成：FullStack-Dev（一個多 agent 框架，具備規劃、程式編輯、程式庫導航與除錯定位能力）、FullStack-Learn（一種透過對爬取與合成的網站 repository 進行 back-translation 的資料擴增與自我提升方法，用於強化 backbone LLM）、FullStack-Bench（一個同時測試 frontend、backend 與 database 功能的綜合 benchmark）。實驗顯示 FullStack-Dev 在前端、後端與資料庫測試上分別較 SOTA 提升 8.7%、38.2% 與 15.9%；而 FullStack-Learn 對 30B 模型亦帶來顯著自我提升效果。

## 問題背景

問題在於現有 LLM code agents 多半聚焦於視覺化前端生成，未能處理真實的 full-stack 資料流、依賴更新與錯誤定位，導致生成的應用缺乏後端與資料持久化能力，難以達到生產級應用需求。

## 解決方案

作者提出一個統一的 full-stack agent 系統 FullStack-Agent，結合 FullStack-Dev（多 agent 協作以規劃與除錯）、FullStack-Learn（透過 repository back-translation 進行資料擴增與自我訓練）與 FullStack-Bench（針對 frontend/backend/database 的功能性基準測試）。核心創新在於以開發導向的測試驅動 agent 行為，以及用回譯資料自我強化 LLM，使 agent 在真實資料流與依賴環境下提高穩定性與除錯能力。

## 核心貢獻
1. 提出 FullStack-Dev：一個多 agent 的 full-stack 開發框架，整合規劃、程式編輯、codebase 導航與錯誤定位，以支援端到端開發流程。
2. 提出 FullStack-Learn：創新的 repository back-translation 與自我改進流程，透過生成多樣化訓練資料強化 backbone LLM，在真實倉庫分布上提升性能。
3. 建立 FullStack-Bench：一套同時測試前端、後端與資料庫功能性的 benchmark，提供更貼近生產環境的評估指標與基準。

## 技術方法

FullStack-Dev 採用多 agent 架構，包含任務規劃器、編輯 agent、導航/索引 agent 與除錯 agent。流程為：規劃器將用戶需求拆解成子任務，編輯 agent 負責生成或修改程式碼片段，導航 agent 在 codebase 中定位相關檔案與依賴，除錯 agent 根據測試回饋定位並修正錯誤。FullStack-Learn 的資料流程為：爬取公開與合成的網站 repository，對其進行 back-translation（將程式與設計語義轉回自然語言指令，再由 LLM 生成多樣化變體），以構建包含錯誤、修復與多版本的訓練資料來微調 backbone LLM。FullStack-Bench 定義了一組功能性測試用例，覆蓋前端互動、API 邏輯、資料庫 CRUD 與資料一致性檢查，評估指標包含任務成功率、錯誤定位精確度、修復成功率與端到端功能通過率。實驗在比較基準上對比既有 SOTA agent 與不同模型尺寸（含 30B）微調前後表現，並進行消融實驗分析各模組貢獻。

## 關鍵結果

| 模組 / 指標 | FullStack-Dev vs SOTA 提升 |
|---|---:|
| Frontend 任務成功率 | +8.7% |
| Backend 任務成功率 | +38.2% |
| Database 測試通過率 | +15.9% |
| FullStack-Learn 對 30B 模型提升（Frontend / Backend / Database） | +9.7% / +9.5% / +2.8% |

## 對我們的啟發
- [ ] 將測試驅動與多 agent 協作結合，可顯著提升 agent 在複雜 full-stack 任務中的除錯與修復能力，適合用於開發工具鏈整合。
- [ ] 對真實倉庫進行回譯（back-translation）能生成更具挑戰性的訓練樣本，促進模型在處理依賴與版本差異時的魯棒性。
- [ ] 功能性 benchmark 同時涵蓋 frontend/backend/database，能更準確反映端到端系統的可用性，應成為未來 agent 評估的重要方向。

## 限制與未來工作

論文可能在多語言框架支援、真實運行效能（如安全、資源開銷）與長期維護性方面討論不足；另外 back-translation 的質量控制與可能引入的偏差需更多實驗驗證。
