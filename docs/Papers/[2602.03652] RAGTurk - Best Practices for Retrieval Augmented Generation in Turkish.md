## 摘要（中文翻譯）

RAG 增強了 LLM 的事實性，但設計指南仍以英語為中心，對於土耳其語等形態豐富的語言缺乏指導。本文構建了源自土耳其語維基百科和 CulturaX 的綜合土耳其語 RAG 資料集，包含問答對和相關段落區塊。我們對 RAG 流程的七個階段進行基準測試，從查詢轉換、重排序到答案精煉，無需任務特定微調。結果顯示 HyDE 等複雜方法達到最高準確度 85%（基準線 78.70%）。使用交叉編碼器重排序和上下文增強的 Pareto 最優配置達到 84.60% 的相近效能，但成本更低。過度堆疊生成模組會因扭曲形態線索而降低效能，而簡單的查詢澄清配合穩健的重排序是有效方案。

## 問題背景

現有 RAG 研究和最佳實踐主要針對英語設計，缺乏對形態豐富語言（如土耳其語）的系統性研究。土耳其語的豐富詞形變化和黏著特性對 RAG 各階段帶來獨特挑戰。

## 解決方案

構建土耳其語 RAG 資料集，系統性地對 RAG 流程七個階段進行基準測試，包括查詢轉換、重排序、答案精煉等，找出適合形態豐富語言的最佳配置。發現 Pareto 最優配置可在保持高準確度的同時降低成本。

## 核心貢獻
1. 構建首個綜合土耳其語 RAG 基準資料集
2. 系統性評估 RAG 流程七個階段在形態豐富語言上的表現
3. 發現過度堆疊生成模組會扭曲形態線索，提出簡單有效的替代方案

## 技術方法

資料集源自土耳其語維基百科和 CulturaX，構建問答對和相關段落。在不進行任務特定微調的條件下，測試 RAG 流程各階段的多種方法：查詢轉換（HyDE、查詢擴展等）、檢索器（BM25、密集檢索）、重排序（Cross-encoder）、上下文增強等。使用準確度和成本作為評估指標，尋找 Pareto 最優配置。

## 關鍵結果

| 配置 | 準確度 | 成本 |
|------|--------|------|
| 基準線 | 78.70% | 低 |
| HyDE | 85.00% | 高 |
| Cross-encoder + Context Aug | 84.60% | 中等 |

## 對我們的啟發
- [ ] 對形態豐富語言，過度使用生成模組反而會損害效能
- [ ] Cross-encoder 重排序在非英語環境下仍然有效
- [ ] 簡單的查詢澄清比複雜的查詢轉換更適合形態豐富語言

## 限制與未來工作

僅在土耳其語上驗證，對其他形態豐富語言（如芬蘭語、匈牙利語）的通用性待驗證。資料集規模可能限制結論的廣泛性。
