# Use Graph When It Needs: Efficiently and Adaptively Integrating Retrieval-Augmented Generation with Graphs

## 摘要（中文翻譯）

大型語言模型在知識密集型任務中常因幻覺和過時的參數知識而表現不佳。RAG 透過整合外部語料庫來解決此問題，但其效果受限於非結構化文檔中的碎片化資訊。GraphRAG 透過結構化知識圖譜增強上下文推理，但在實際場景中反而表現不如傳統 RAG，出現顯著的準確度下降和延遲問題。我們發現根本原因是 GraphRAG 對所有查詢的僵化應用。為此，我們提出 EA-GraphRAG，一個高效自適應框架，透過語法感知的複雜度分析動態整合 RAG 和 GraphRAG。該方法包含：語法特徵建構器、輕量級複雜度評分器，以及分數驅動的路由策略。

## 問題背景

GraphRAG 雖然在複雜查詢上有優勢，但對所有查詢一律使用圖結構檢索，導致在簡單查詢上反而比傳統 RAG 表現更差，同時產生高延遲。這種僵化的應用方式未能考慮查詢複雜度的差異，造成資源浪費和效能下降。

## 解決方案

提出 EA-GraphRAG 框架，核心創新是根據查詢複雜度動態選擇檢索策略。框架包含三個組件：(1) 語法特徵建構器解析查詢並提取結構特徵；(2) 輕量級複雜度評分器將特徵映射為連續複雜度分數；(3) 分數驅動路由策略：低分用傳統 RAG、高分用 GraphRAG、邊界情況用複雜度感知的倒數排名融合。

## 核心貢獻
1. 識別 GraphRAG 僵化應用於所有查詢是效能下降的根本原因
2. 設計語法感知的查詢複雜度分析機制，實現動態路由
3. 提出複雜度感知的倒數排名融合方法處理邊界情況

## 技術方法

EA-GraphRAG 首先透過語法解析器提取查詢的結構特徵（如實體數量、關係類型、跳數等），然後使用輕量級評分器計算複雜度分數。根據分數閾值，系統自動選擇：簡單查詢走密集向量檢索（RAG）、複雜查詢走圖結構檢索（GraphRAG）、中間情況則融合兩者結果。實驗在包含單跳和多跳問答的綜合基準上進行，評估準確度、延遲和混合場景處理能力。

## 關鍵結果

| 方法 | 單跳 QA | 多跳 QA | 延遲 |
|------|---------|---------|------|
| Vanilla RAG | 高 | 低 | 低 |
| GraphRAG | 低 | 高 | 高 |
| EA-GraphRAG | 高 | 高 | 中等 |

## 對我們的啟發
- [ ] 並非所有查詢都需要圖結構檢索，根據複雜度動態路由可大幅提升效率
- [ ] 語法特徵是預測查詢複雜度的有效信號，無需實際執行檢索即可判斷
- [ ] 混合策略比單一策略在實際場景中更具優勢

## 限制與未來工作

複雜度評分器的閾值設定可能需要針對不同領域調整。語法特徵提取對於非標準或口語化查詢可能效果有限。
