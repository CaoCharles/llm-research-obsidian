# CoinRAG: Contextualized Information Nugget KV Cache Reuse for Long-Context RAG

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.07458)
- 📥 [PDF](https://arxiv.org/pdf/2608.07458v1)

## 摘要（中文翻譯）

近期 RAG 優化研究多利用 chunk-level KV cache reuse，避免在推論時重複處理冗長的 retrieved context，以提升效率；然而，粗粒度 chunks 仍包含大量資訊冗餘與噪聲。本論文提出 CoinRAG（Contextualized Information Nugget KV Cache Reuse for Long-Context RAG），在低 prefill latency 約束下，同時最大化回答準確度並優化 accuracy–latency Pareto frontier。CoinRAG 先於離線階段從 chunks 擷取細粒度、可對應至原文 token span 的 information nuggets，並預先計算完整 chunk 的 KV cache；線上則透過 two-stage retrieval 選出與 query 相關的 nuggets，再切片並組合其具上下文的 KV representations，形成更精簡且語義相關的 context。於 LongBench 三個 multi-hop QA 資料集的實驗顯示，在標準 100 ms P99 TTFT 預算下，CoinRAG 平均 F1 為 41.7，相較最佳競爭方法 39.6 提升 5.3%。

## 問題背景

長 context RAG 在每次 query 時重新編碼 retrieved chunks，造成高 prefill latency、GPU 記憶體與計算成本。既有 chunk-level KV cache reuse 雖能降低重複編碼，卻仍把 chunk 內無關、冗餘與噪聲內容送入模型，可能稀釋關鍵證據；若在低延遲 SLA 下減少 chunks，又會損失 multi-hop QA 所需的召回與推理資訊。

## 解決方案

CoinRAG 將 cache reuse 的粒度由 chunk 細化為 contextualized information nugget。系統先離線從每個 chunk 抽取可對齊原文 token span 的 nuggets，並計算完整 chunk 的 KV cache；線上先檢索相關 chunks，再於候選 chunks 內選取 query-relevant nuggets，直接切片其原 chunk KV，保留文件上下文而不重新編碼。選出的 slices 依原序連續組合，並以 RoPE position alignment 修正位置。最後透過 nugget-aware fine-tuning，使模型適應非連續 cache 組合，從而以較短 context 在低 TTFT 下取得較高 QA F1。

## 核心貢獻
1. 提出以 text-span information nuggets 為單位的 KV cache reuse 框架，將離線計算的 contextualized nugget caches 組合成精簡線上 context。
2. 設計 offline nugget extraction、two-stage chunk-to-nugget retrieval、position alignment 與 nugget-aware fine-tuning，以降低非連續 cache stitching 造成的 training–inference gap。
3. 在 HotpotQA、2WikiMQA 與 MuSiQue 上建立 accuracy–TTFT 與 accuracy–context-length Pareto frontier，並系統性比較 Standard RAG、CacheBlend、TurboRAG 與 KVLink。

## 技術方法

CoinRAG 使用 Qwen2-7B-Instruct 作為 answer generator，BGE-M3 負責 retrieval，並利用模型支援的 RoPE position rotation。離線階段將語料切成 512-token chunks，先以 GPT-4o-mini 從每個 chunk 擷取候選 information nuggets；候選文字若可在原文 exact match，便直接定位，否則以相近長度的 whole-word spans 做 fuzzy matching，低於 similarity threshold 的候選丟棄。接著對每個完整 chunk 做一次 forward pass，保存其 contextualized KV cache 與 nugget 的 start/end token indices。線上階段先以 dense retriever 取 top-kc chunks，再只在這些 chunks 內對預先抽取的 nuggets 做 embedding ranking，選出 top-k nuggets。系統從來源 chunk KV cache 切出對應 spans，與 system prompt cache 組合；由於 spans 來自不同 chunks，依文件順序重新排列並連續打包，透過 RoPE rotation offset 修正位置。之後在線上僅編碼 query，將其 KV representations 接到組合後的 context cache，再生成答案。為縮小連續訓練與非連續 cache stitching 的落差，作者以含 ground-truth 與 distractor 文件的 QA 資料進行 nugget-aware fine-tuning，直接對答案 token 的 cross-entropy 訓練。實驗使用 LongBench 的 HotpotQA、2WikiMQA、MuSiQue，掃描 chunk 或 nugget 數量形成 Pareto curves，主要指標為 token-level F1、平均與 P99 TTFT，以及 prefill active token length。

## 關鍵結果

主要結果如下（表中數字為論文 Table 3 報告值；TTFT 為平均值，P99 為 P99 TTFT，Len 為 active prefix context length）：

| 設定 | 方法 | HotpotQA F1 / TTFT / P99 / Len | 2WikiMQA F1 / TTFT / P99 / Len | MuSiQue F1 / TTFT / P99 / Len | 平均 F1 |
|---|---|---:|---:|---:|---:|
| P99 ≤ 100 ms | Standard RAG | 40.1 / 74 / 81 / 741 | 28.5 / 71 / 83 / 684 | 21.0 / 76 / 82 / 743 | 29.9 |
| P99 ≤ 100 ms | TurboRAG | 49.1 / 71 / 83 / 752 | 42.2 / 80 / 95 / 1059 | 27.4 / 73 / 94 / 754 | 39.6 |
| P99 ≤ 100 ms | KVLink | 49.0 / 57 / 65 / 749 | 38.7 / 70 / 80 / 1433 | 26.8 / 67 / 71 / 1170 | 38.2 |
| P99 ≤ 100 ms | CoinRAG | 51.4 / 87 / 618 | 46.0 / 78 / 389 | 33.1 / 77 / 387 | 41.7 |
| 無 latency 限制 | TurboRAG | 49.7 / 439 / 816 / 9262 | 44.8 / 116 / 150 / 1849 | 27.4 / 73 / 94 / 754 | 40.6 |
| 無 latency 限制 | CoinRAG | 51.4 / 72 / 87 / 618 | 44.5 / 96 / 115 / 695 | 32.2 / 106 / 427 | 42.7 |

在 P99 100 ms 預算下，CoinRAG 的平均 F1 為 41.7，較 TurboRAG 的 39.6 相對提升 5.3%，平均 contextual token length 為 465，較 TurboRAG 的 855 短 1.84 倍。無 latency 限制時，CoinRAG 平均 F1 為 42.7，較 TurboRAG 的 40.6 提升 5.2%，且平均 context length 為 580，較 TurboRAG 的 3955 短 6.8 倍。消融實驗顯示，isolated nugget encoding 使三個資料集 peak F1 分別下降 6.3、4.9、3.9 分；two-stage retrieval 相較 one-stage retrieval 的相對增益為 9.6%–17.5%；nugget-aware fine-tuning 使三個資料集 peak F1 分別提升 11.3、6.3、6.4 分。

## 對我們的啟發
- [ ] 若服務受嚴格 TTFT SLA 約束，可將固定且較少變動的文件於離線階段預編碼，並只載入 query 相關的 nugget KV slices，以在有限延遲與 GPU memory 下保留更多證據。
- [ ] information retrieval 不宜只在 chunk 層級停止；先以 chunk 篩選候選範圍，再於候選內進行 nugget ranking，可同時改善證據選擇與 active context 長度。
- [ ] 快取切片不能簡單視為獨立文字重新編碼；論文消融顯示保留來源 chunk 的 contextualized KV representations 明顯較佳，但仍須注意跨 chunk 互動不足及 nugget 選取造成的誤導。

## 限制與未來工作

離線 KV cache、nugget extraction 與 fine-tuning 具有 corpus-scale 的儲存、I/O 與一次性計算成本，且快取綁定特定模型，模型更新即需重建。品質仍受 chunk/nugget retrieval recall 限制；不同 chunks 的 nuggets 不會互相 attend。研究也未評估跨 query KV reuse，並假設文件不常變動。
