# Configuration, Not Conscience: A Large-Scale Empirical Study of LLM System Prompts

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2609.31575)
- 📥 [PDF](https://arxiv.org/pdf/2609.31575v1)

## 摘要（中文翻譯）

洩漏的 system prompt 常被視為商業語言模型隱藏價值觀的窗口，但其組成鮮少被大規模研究。本文合併四個社群資料集，分析來自 62 家供應商的 407 份洩漏、重建或官方發布的 system prompt，並辨識出涵蓋 66 個檔案的 29 個近重複群集。結果顯示，操作性內容遠多於倫理陳述：簡單的區塊分類器將約 58% 的分類詞分為工具／協定，約 5% 分為安全政策；最嚴格的規則行主要防護工具使用與檔案安全，其數量以約 11:1 超過有害內容規則。字面文字轉移集中於少數跨供應商配對，prompt 亦呈現可量測的維護負債，版本鏈每次發布會變更數千字。證據支持將洩漏 prompt 視為操作規格，較接近 configuration file 而非價值宣言，並將重用與 prompt rot 視為工程及供應鏈問題。由於多數文件具有對抗性來源，且偵測器刻意保持簡單，所有數值僅具方向性；作者也稽核了主要分類器的錯誤模式。

## 問題背景

現有研究多把 system prompt 當作 prompt extraction、indirect prompt injection 或 jailbreak 的攻擊目標，關注能否恢復、覆寫或突破它，較少直接研究洩漏文件實際包含哪些內容、不同供應商如何重用，以及 prompt 如何演化。本文要回答四個問題：語料的功能組成、文字與語義重用程度、操作／安全／法律／格式及注入防禦的分布，以及版本成長、自治程度與維護風險。其不足在於洩漏文本可能不完整、被修改且缺乏可信日期。

## 解決方案

作者提出一套以大規模語料分析為核心的 system-prompt 研究框架，而非建立可生成或執行的模型。框架先合併四個公開社群集合、排除非 prompt 內容並標記近重複檔案；接著以人工 taxonomy 與可稽核的 lexical／regex detectors，分析功能區塊、能力、規則強度、注入防禦、法律風險、拒答語境及 prompt rot。重用分析區分 literal reuse、semantic similarity 與 structural convergence，分別使用 5-gram Jaccard／containment、TF–IDF cosine、MiniLM embedding 及格式骨架相似度。另以五組官方與洩漏 Anthropic 配對校驗觀察，並以版本差異與 PromptLint、textstat 交叉檢查。核心創新是把 prompt 視為可測量的 operational specification，分離文字抄襲、語義趨同與架構趨同，並將維護負債納入安全與工程分析。

## 核心貢獻
1. 建立合併四個公開集合的 407 份 system-prompt 語料，並以近重複群集避免將跨來源重複文本靜默地當成獨立樣本。
2. 以 literal、semantic 與 structural 三個層次區分跨供應商重用與架構趨同，顯示字面複製集中於少數 coding-agent／browser-assistant 配對，而語義趨同可在近乎零字面重疊下出現。
3. 以功能區塊、強調規則、版本 diff、rot-risk 與官方／洩漏 Anthropic 配對，提出將 system prompt 視為 configuration-like operational specification 及軟體維護負債的實證觀點。

## 技術方法

資料來自 CL4R1T4S、System-Prompts、system-prompts-and-models-of-ai-tools 及 system prompts leaks 四個集合；排除僅含 tool-call schema、README、license、索引、建置腳本及工具文件的項目後，保留 407 個檔案、62 家供應商，其中 31 個為官方發布、376 個為洩漏或重建文本。以同供應商內 word 5-gram Jaccard≥0.85 建立近重複連通群集，並用不同模型層級／版本檔名防止誤合併，得到 29 群、66 檔，另報告 370 份有效獨特文件。人工將檔案分為六種 archetype 與三種 value posture。功能分析把段落依最強 lexical match 分到 tool/protocol、safety policy、legal/IP、formatting/style、identity/persona、memory/context、injection boundary 或 other；48 個分層抽樣區塊的整體 precision 為 35/48（73%）。重用分析在 95 份 vendor×archetype 代表文件上計算 TF–IDF 1–2-gram cosine、5-gram Jaccard／asymmetric containment、all-MiniLM-L6-v2（256-token chunks）語義 cosine，以及移除自然語言後的結構骨架相似度。其他分析以 regex 偵測能力家族、強調規則、危害／法律詞、注入防禦、拒答與 rot-risk；版本研究對五條鏈做 word-level sequence diff，並以 PromptLint 和 textstat 交叉檢查。研究沒有測量 prompt 差異是否實際改變模型行為。

## 對我們的啟發
- [ ] 對 agent red-teaming 而言，不能只測試 conversational refusal；論文結果支持優先檢查 tool-call、檔案編輯、程式執行、資料處理與 approval boundary。
- [ ] 產品團隊可將 prompt 納入版本控制、回歸測試與 linting，特別檢查過期 URL、日期、模型／套件版本、矛盾指令，以及 concise 與 thorough 等張力。
- [ ] 評估洩漏 prompt 時應分離官方政策與觀測到的操作文本，並同時報告去重結果、來源可信度及分類器誤差；本文數據不應直接解讀為部署模型實際能力或安全效果。

## 限制與未來工作

主要限制是 376 份文件來源對抗性、可能不完整或被修改，且缺乏可靠日期；只有五組 Anthropic 官方／洩漏配對可作校驗。分類器以英文 regex 和單一主導區塊判定，48 區塊驗證樣本小，人工標註亦為 single-coder。能力與自治指標只代表文本描述，不代表實際部署。未來需加入更多官方配對、多人標註、區分允許與禁止的安全提及，並測試 prompt 差異能否預測模型行為。
