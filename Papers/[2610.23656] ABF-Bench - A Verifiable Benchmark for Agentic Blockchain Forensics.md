# ABF-Bench: A Verifiable Benchmark for Agentic Blockchain Forensics

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2610.23656)
- 📥 [PDF](https://arxiv.org/pdf/2610.23656v1)

## 摘要（中文翻譯）

Blockchain forensics 具有對抗性且開放式：洗錢者會拆分、交換、跨鏈轉移資金，並在 mixer 或 custodial service 截斷軌跡、持續改變策略；調查者必須隨之調整追蹤方式。公共 ledger 的不可竄改性則保留所有已記錄的資金移動，使許多調查結論可獨立驗證。本文提出 ABF-Bench，一個互動式 benchmark，將有證據支持的資金追蹤轉化為可驗證的 agent 任務，要求每項聲稱的移動都引用 agent 實際取得的 ledger records。任務由真實洗錢活動建立，涵蓋多跳轉帳、DeFi exchange、跨鏈往返、custodial 與 mixer 存款及 address poisoning。作者另提出以 working memory 為核心的 ABF agent harness。其 edge recall 為 75%，高於相同模型的 Codex（47%）與 Claude Code（10%）；但 agents 常過早停止，在大型任務上的最終 recall 低於最佳 fixed-order tracer。

## 問題背景

現有 blockchain forensics 資源多聚焦於固定資料集的標註交易、特定 protocol linking 或事故流量重建，無法充分評估 agent 如何在查詢預算下自主搜尋記錄、辨識跨 protocol 操作、組織證據並提交可核驗結論。固定順序的 tracing procedures 又難以應對分流、跨鏈、mixer、custody 與 address poisoning 等變化。論文因此要解決：如何建立答案可由 ledger records 驗證、證據取得成本受控、且能公平比較 LLM agents 與規則式 tracer 的 benchmark。

## 解決方案

作者提出 ABF-Bench，將任務定義為 ledger records、seed fund states、scope/accounting declaration 與 operation rules 的組合。Agent 透過 metered evidence environment 查詢 activity、transaction、receipt、trace、UTXO 與跨鏈記錄，提交每個 movement 及其 citations；deterministic verifier 先獨立檢查證據是否支持操作，再由 grader 對隱藏 reference graph 計算 recall、fidelity 與 precision。case-to-task pipeline 以保守規則從真實 incident 建立可重現任務，並確保每條 reference edge 有可取得 witness。作者同時提出 ABF agent harness，以 working memory、工具和五項 forensic heuristics 支援搜尋、線索管理、證據引用及持續追蹤。

## 核心貢獻
1. 提出 ABF-Bench，將 evidence-backed blockchain fund tracing 形式化為具 metered retrieval、citation verification 與隱藏 reference graph 的 interactive verifiable agent task。
2. 建立可重複的 case-to-task pipeline，從真實 Bybit theft incident 產生跨 Ethereum 與 Bitcoin 的任務，並以保守規則與 witness 審查確保 reference edges 可驗證。
3. 提出 ABF agent harness，以 working memory、memory tools、submission preview、context compaction 與 forensic heuristics 支援 agent；實驗顯示相同 GPT-5.5 下 harness 的 recall 明顯高於 Codex。

## 技術方法

任務形式為 t=(L,Λ,S,O)：L 是指定 ledger 與區塊範圍內的固定記錄，Λ 是 seed fund states，S 定義 scope、會計分攤、方向、hop cap、資產與停止條件，O 則規定 transfer、exchange、cross-chain crossing 等操作所需證據。Agent 在隔離環境中依 query cost 取得 activity listings、balances、transactions、receipts、execution traces、Bitcoin output spends、contract-call results 與 events；每個有效查詢成本為 1，listing 每頁也計一次，submission 結束執行。生成流程先在單一 ledger 反覆 walk 與 sweep，依 traced-value membership 擴張 holdings，再跨 Ethereum 與 Bitcoin 反覆 link deposits/payouts，直到跨鏈結果收斂；經人工審查後保留有 verified witness 的 seed-rooted tasks。reference graph 對未解決 continuation 採保守停止。評估以 edge recall 為主：只有 agent 已取得其引用全部 records、且 operation 通過 verifier 的 reference edges 才算 recovered；另計 fidelity（通過驗證的 operations 比例）、edge precision、query budget、token 與 API cost。實驗比較 ABF harness、同模型 Codex、Claude Code，以及 BFS、DFS、largest-incoming-first greedy tracers；資料為 Bybit 2025 theft，追蹤 90 天、跨 Ethereum 與 Bitcoin，首輪評估 31 tasks。

其他結果：ABF harness 在預算 25% 時 evidence recall 為 39%，最佳 hindsight tracer 為 35%；預算 50% 時分別為 70% 與 41%。harness 平均使用 47% 預算即停止，且所有 agents 的 recall 都隨任務規模下降；harness 從最小到最大 reference-edge 三分位任務由 0.82 降至 0.69。harness 對已取得 operations 的 claim rate 為 83%，BFS 為 85%；對 undisclosed custody 的停止辨識為 89%（16/18），而 BFS、DFS、greedy 均為 0%。Claude Code 在 31 次執行中有 29 次引用未實際取得的 records；若忽略 retrieval condition，其 recall 會是 0.54，但論文未將此列為正式 edge recall。

## 對我們的啟發
- [ ] 評估 agentic investigation 時，應同時檢查答案正確性與證據是否真的被取得；ABF-Bench 的 retrieval condition 能揭露僅憑 listing 或模型既有知識引用記錄的 overconfidence。
- [ ] working memory 應明確區分 confirmed findings、未結 leads 與 notes，並將未結線索與停止條件納入控制流程，以降低 agents 在分支較多時過早提交。
- [ ] 效率與最終覆蓋率可能衝突：agent 在早期 evidence acquisition 領先，但 breadth-first tracer 因持續消耗預算而取得較高 final recall；實務系統應加入剩餘預算、fan-out 與未探索分支的停止決策。

## 限制與未來工作

論文僅評估一個公開的 Bybit theft incident，結果能否泛化至其他案件仍未確定；incident 也可能已出現在模型訓練資料中。保守停止規則只衡量 incident flow 的可驗證子集。比較同時改變 harness、模型與 query policy，未測量 agents 使用剩餘預算後可增加多少 recall；此外，未來仍需擴充更多 incidents、ledgers 與 operation types。
