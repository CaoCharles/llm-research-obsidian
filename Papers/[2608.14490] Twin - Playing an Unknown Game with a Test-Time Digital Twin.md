# Twin: Playing an Unknown Game with a Test-Time Digital Twin

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.14490)
- 📥 [PDF](https://arxiv.org/pdf/2608.14490v1)

## 摘要（中文翻譯）

本文提出 Test-time World-model Inference（Twin）系統：由 frontier coding agent 在測試時撰寫可執行的 world model，以完成 ARC-AGI-3 等 continual learning 任務。每個遊戲的規則與目標皆隱藏，Twin 僅依靠模擬與互動建構模型。系統以 grid-game 的歸納偏置恢復轉移規則，並在 twin world model 中進行 replay validation；只有當程式重現所有歷史轉移後，harness 才允許執行真實動作。任何預測與實際結果的不一致都會形成 counterexample，用於修補模型。Twin 清除 183 個 level 中的 179 個（97.8%），其中 158 個比首次遊玩的真人更有效率；在已清除的 level 中，156 個（87.2%）於獲得 reward 前即推斷出目標。結果顯示，建立可用 world model 比推斷正確目標容易。

## 問題背景

未知互動遊戲同時隱藏 dynamics 與勝利條件；agent 必須透過有限真實互動學會如何行動及何時完成。直接使用 frontier model 或一般 coding harness 容易反覆試錯、累積 transition 錯誤，且通常等到第一次 reward 才處理目標。既有 world-model 方法多依賴手工設計、跨回合訓練或未強制驗證，因此難以在測試時可靠規劃長序列。論文聚焦於如何從互動即時建構可驗證模型，並處理 reward 尚未出現時的 goal inference。

## 解決方案

Twin 讓 coding agent 在測試時撰寫未知遊戲的 executable digital twin，將環境變成可檢查、可反駁、可修補的程式假設。其核心是非對稱學習流程：對 dynamics 採硬性 consistency，任何真實 action 前都要重播並匹配完整 log；對 goal 則採 optimistic search，從 twin 中尋找具進展特徵的可達狀態，形成候選 predicate，再以最有效率的真實路徑驗證。整體循環由 harness 控制 validate、explore、plan 與 checked execution；mismatch 會立即停止行動並提供 counterexample，促使 agent 修復模型，避免錯誤計畫在長遊戲中擴散。

## 核心貢獻
1. 提出 Twin 的 test-time world-model inference：讓 coding agent 將未知環境寫成可執行、可檢查與可修補的 Python 模型，而非僅以反應式方式決策。
2. 設計由 harness 強制執行的 validate–explore–plan–execute_checked 循環；真實動作前必須重播並匹配完整互動歷史，錯誤則轉化為 counterexample 進行修復。
3. 將 dynamics learning 與 goal discovery 分離，透過可達狀態、候選 goal predicate 及真實 level boundary 測試，在 reward 稀疏或尚未出現時探索隱藏目標。

## 技術方法

Twin 使用 OpenAI Codex 驅動的 frontier coding agent；論文實驗的 base model 為 GPT-5.6 Sol，agent 透過檔案與 sandbox 連接遊戲，沒有 game-specific tools。每個 game 初始化 identity twin 與空的 append-only transition log D，模型需實作 step(grid, action) 與 goal_reached(grid)。每次觀察到 64×64、16 色 grid 的真實轉移後，系統先執行 Validate，逐筆 replay D，要求預測完全等於觀察結果；失敗時 Explore 將 mismatch 依失敗頻率、結果多樣性與證據不足等訊號排序，交由 agent 修補，且修補後必須重新通過完整歷史驗證。若 dynamics 已驗證但沒有目標路徑，Explore 從可達狀態產生候選進展，agent 將其寫成暫時 goal predicate；候選不得匹配任何已記錄 frame，若抵達卻沒有 level boundary，便永久排除。Plan 在 validated twin 中以 BFS 搜尋深度 8、最多 20,000 nodes 的路徑；goal discovery 使用深度 14、最多 30,000 nodes。ExecuteChecked 逐步提交路徑，首個預測 mismatch 即停止並追加 counterexample。評估採 ARC-AGI-3 的 completion 與 action-efficiency 分數（0–100），並報告遊戲及 levels 清除數、相對首次遊玩真人的 action 效率、模型轉移預測準確率與 goal hypothesis 成功率。

## 關鍵結果

| 系統 | 分數 | 完整清除遊戲 | 清除 levels |
|---|---:|---:|---:|
| Human reference | 100.0 | 25/25 | 183/183 |
| Codex（無 Twin harness） | 61.1 | 13/25 | 148/183 |
| EWM | 63.8 | 14/25 | 146/183 |
| Prime Agent（GPT-5.6 Sol） | 78.3 | 論文未報告 | 164/183 |
| OPINE-World | 78.4 | 20/25 | 160/183 |
| Twin（GPT-5.6 Sol） | 93.3 | 23/25 | 179/183 |

Twin 在 179 個已清除 levels 中，有 158 個（88.3%）比首次遊玩真人更有效率；其中 156 個（87.2%）在任何 reward 前即提出正確的第一個 goal hypothesis。92.9% 的 scored actions 執行了已在 twin 中測試的路徑；首次出現的 state–action pair 有 8,210/10,392（79.0%）被準確預測。Twin 與無 harness Codex 的比較顯示，移除整個 Twin 循環後分數由 93.3 降至 61.1，完整清除遊戲由 23 降至 13。實驗共使用 2.60 billion processed tokens、91.4 小時推論時間。

## 對我們的啟發
- [ ] 對互動式 agent 而言，將環境知識外化為可執行 artifact，並以完整歷史 replay 作為行動門檻，能降低錯誤在長序列中的累積。
- [ ] 應分別評估 dynamics 的 faithfulness 與 goal inference；前者每次互動都可獲得轉移監督，後者通常只有完成任務才得到正例。
- [ ] 在成本敏感的環境中，可先於真實執行在模型內搜尋最短路徑，並將少量真實 action 保留給模型修正或候選目標驗證；但需要處理錯誤 goal 假設造成的探索成本。

## 限制與未來工作

Replay validation 假設環境具 deterministic、可由程式表示的 dynamics，且主要適用於離散、可逐格比較的狀態。固定的 planning 與 goal-discovery 搜尋預算可能找不到較深目標；長時間歷史或完全 latent state 也超出範圍。連續觀測與 probabilistic twin 尚未處理，作者列為未來工作。
