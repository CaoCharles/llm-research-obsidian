# SafeEvolve: Harness-Policy Co-Evolution from Agent Experience for Safety Alignment

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2609.02786)
- 📥 [PDF](https://arxiv.org/pdf/2609.02786v1)

## 摘要（中文翻譯）

LLM agent 的效能由 base model 與其執行環境中的 harness 共同決定，因此安全風險不僅存在於有害的最終回覆，也存在於多步執行軌跡。現有安全 alignment 方法通常只依賴外部 harness 更新或 policy optimization，單獨採用任一方式都難以結合 runtime control 與 intrinsic safety。本文提出 SafeEvolve，一個由 agent experience 驅動的 self-evolving safety alignment framework。它利用已完成的 on-policy trajectories，持續推動 harness-policy co-evolution：將軌跡層級安全證據轉換為安全 prompt 與階層式 skills 的受限、可稽核、可回復更新；並透過兩階段 SFT-RL，先訓練 policy 使用演化後的 harness，再藉由 verifier-decomposed rewards 在多步探索中形成自主安全行為。實驗顯示，SafeEvolve 在 agentic safety benchmarks 上取得較佳 safety-utility trade-off。以 Qwen3.5-4B 為例，AgentDojo 的 ASR 由 2.37% 降至 0.79%，benign utility 則由 59.79% 升至 61.86%。

## 問題背景

LLM agent 在工具呼叫、規劃、記憶與環境互動的多步軌跡中，可能遭遇 harmful query、environment prompt injection、unsafe tool use 等風險。僅更新 harness 時，弱 policy 可能無法可靠遵循外部規則；僅更新 policy 時，固定 harness 難以因應新失敗模式，且安全能力較難跨模型轉移。因此，問題是如何將執行經驗同時轉化為可控的 runtime 防護與可內化的 policy 安全行為。

## 解決方案

SafeEvolve 建立以完成的 on-policy trajectory 為共同證據的持續 co-evolution loop。第一階段是 observability-driven harness evolution：分析風險、定位失敗原因，針對單一 safety prompt 或 hierarchical skill 進行 bounded mutation，並以 paired evaluation、safety/utility/execution-quality gate 驗證，保留版本、證據與 rollback metadata。第二階段是 harness-augmented policy optimization：先以通過 verifier 的軌跡進行 harness-use SFT，使 policy 學會使用檢索到的 skills；再在相同 evolved harness 下進行 RL，透過依任務類型分解的 safety-utility reward 內化拒絕、忽略注入及安全恢復等行為。

## 核心貢獻
1. 提出 SafeEvolve，將 completed on-policy trajectories 作為 harness refinement 與 policy optimization 的共同安全經驗，形成持續的 harness-policy co-evolution loop。
2. 提出受限且可稽核的 harness evolution：把軌跡安全證據歸因至單一 prompt 或 skill component，透過 paired accept-reject gate、版本化證據與 rollback metadata 控制更新。
3. 提出 harness-use SFT 加 harness-augmented RL 的兩階段 policy alignment，並以依任務類型分解的 verifier reward 同時訓練安全與工具任務效用。

## 技術方法

研究將多步 tool-use episode 表示為 user instruction、環境觀察與 agent action/tool call 組成的 trajectory，威脅模型包含 malicious-query 與 environment-injection。Harness 形式化為 instructions、tools、skills、permission/action policies、instruction-priority/information-flow constraints 及 rendering/execution controller；實作中主要演化 safety prompt 與 hierarchical SkillBank，後者包含 general、task-specific、common-mistake skills。每輪先以目前 policy-harness pair rollout，依 scenario、attack type、tool family 與失敗 bucket 彙整證據；proposer 僅修改一個 component，候選版本須在相同內部 panel 上相較 parent 提升至少 δ，且不得使 safety、clean utility 或 execution quality 退化，通過後才版本化保存。Policy optimization 使用 evolved prompt 與 episode-level retrieved skills。SFT 僅對 assistant response 和 tool-call turns 訓練；RL 每個 task 取 8 條 rollout、以 group-relative advantage 和 clipped policy objective 更新，並加入 reference-policy KL。clean task reward 為 utility，malicious query reward 為 safety，environment injection reward 結合 utility、safety 與乘積項。實驗使用 Qwen3.5-4B、Qwen3-4B-Instruct-2507，200 rollout steps、每批 32 tasks、每 task 8 rollouts。AgentDojo/AgentDyn 評估 utility、attack utility、ASR；AgentHarm 評估 harmful score、refusal、benign score。

## 關鍵結果

主要結果如下（數值為論文表格所報告的百分比；AgentDojo 與 AgentDyn 的 ASR 越低越好，utility 越高越好）。

| Backbone/方法 | AgentDojo Utility | AgentDojo U-Attack | AgentDojo ASR | AgentDyn Utility | AgentDyn U-Attack | AgentDyn ASR | AgentHarm Harmful | Refusal | Benign |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| Qwen3.5-4B Base | 59.79 | 60.04 | 2.37 | 15.00 | 15.45 | 6.88 | 56.45 | 28.98 | 83.09 |
| Qwen3.5-4B SafeEvolve | 61.86 | 56.77 | 0.79 | 15.00 | 15.09 | 4.51 | 12.27 | 83.83 | 71.31 |
| Qwen3-4B Base | 44.33 | 35.91 | 13.38 | 20.00 | 21.38 | 19.60 | 34.96 | 7.39 | 43.57 |
| Qwen3-4B SafeEvolve | 60.82 | 52.05 | 2.42 | 25.00 | 15.14 | 4.87 | 15.47 | 71.93 | 63.43 |

作者另報告：Qwen3.5-4B 在 AgentDojo 的 ASR 由 2.37% 降至 0.79%，benign utility 由 59.79% 升至 61.86%；AgentHarm harmful score 由 56.45 降至 12.27，refusal 由 28.98% 升至 83.83%。Held-out Agent Security Bench 中，SafeEvolve 在 DPI、IPI、PoT Backdoor 的 ASR 分別為 71.92%、0.50%、2.50%；對應 refusal rate 為 14.17%、21.25%、27.50%。

## 對我們的啟發
- [ ] 實務部署可將安全規則拆成可檢索、可版本控制的 task-specific 與 common-mistake skills，而非只依賴一段全域 safety prompt；論文的 frozen-policy ablation 顯示 evolved skills 通常比單一 prompt 更能改善多步執行安全。
- [ ] 安全更新應採同任務 paired evaluation、不可退化 gate 與完整 rollback provenance；論文的 online update 結果顯示，局部線上演化雖可能改善個別指標，卻會使其他 benchmark 的 ASR、utility 或 refusal 惡化。
- [ ] 評估 agent safety 時不應只檢查最終答案，應記錄中間 tool call、是否遵循注入、是否停止或恢復，以及 benign task completion；這正是 verifier-decomposed reward 與 AgentDojo/AgentDyn 類 trajectory-level 指標的價值。

## 限制與未來工作

論文指出目前演化仍受固定搜尋與更新排程限制，尚非真正的 meta-level recursive self-improvement；線上 harness 更新也出現跨指標退化。安全能力的跨模型轉移依賴目標 policy，弱模型可能無法執行 evolved guidance。作者建議未來進行長期多世代評估、開放式 red-teaming，並使用不可演化安全錨點、獨立 verifier、最壞情況安全下限、回復機制與人工監督。
