# Agent Against Agent: An Agentic System for Automatic Prompt Injection Red Teaming

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.05108)
- 📥 [PDF](https://arxiv.org/pdf/2608.05108v1)

## 摘要（中文翻譯）

Prompt injection 對 LLM agents 構成重大的安全風險，因此高效且有效的 red-teaming 對於評估風險及蒐集防禦訓練資料都十分關鍵。現有最先進的 prompt injection red-teaming 方法主要依賴 reinforcement learning（RL），但訓練出的 attacker models 往往難以泛化至新的 target LLM。本文提出 PIMiner，一個用於 prompt injection red-teaming 的 agentic system。訓練期間，PIMiner 依序處理多組（dataset、target model）配對，從零建立 strategy library；測試時，學得的策略庫可直接轉移至未見過的 target LLM，無須額外訓練。每個測試樣本僅需對 target agent 發出少量查詢，例如 10 次。實驗顯示，PIMiner 在 IPIArena 對 Gemini-2.5-Pro、GPT-5.1 和 Claude-Sonnet-4.5 的 ASR 分別為 76.2%、61.9% 和 42.9%；在 AgentDojo 則分別為 86.7%、53.3% 和 40.0%。

## 問題背景

論文聚焦於如何以低查詢成本、自動化方式對 LLM agents 進行 prompt injection red-teaming。RL-based 方法通常需約數萬次 target-agent 訓練互動，且 attacker policy 對新 target LLM 的 transferability 有限；search-based 方法雖不需訓練，卻常對每個樣本重新搜尋，無法累積與重用成功攻擊知識，因而效能通常低於 RL 方法。

## 解決方案

作者提出 PIMiner，將 agentic iterative search 與可持續更新的 hierarchical memory 結合。系統以 strategy library 保存跨 dataset、task 與 target model 的可解釋攻擊策略，由 strategy router 為每個樣本挑選相關策略，再透過 iterative attack module 根據當前回饋反覆修正 prompt。系統同時維護跨資料集、資料集內及樣本內三層記憶；完成一組 dataset–model pair 後，experience digester 將成功與失敗軌跡轉化為新策略、範圍更新及失敗條件。核心創新是無須重新訓練 attacker，即可把累積策略直接轉移至未見 target LLM，並以 router 控制上下文與推理成本。

## 核心貢獻
1. 提出 PIMiner，將 search-based attack 與可累積、可重用的攻擊知識結合，縮小其與 RL-based red-teaming 的效能差距。
2. 設計包含 strategy library、strategy router、iterative attack module 與 experience digester 的 hierarchical memory mechanism，能跨 dataset、task 與 target model 累積可解釋策略。
3. 在 IPIArena、AgentDojo 與 InjecAgent 上進行評估，顯示策略庫可轉移至未見過的 target LLM，且也能改善不同 attacker LLM 驅動的 PAIR。

## 技術方法

PIMiner 將 prompt injection red-teaming 定義為：樣本由 target instruction、untrusted context 與 injected task 組成；訓練時依序處理多個（dataset、target LLM）配對，利用 target agent 回饋更新長期記憶，測試時將累積策略轉移至新 target。其架構包含四部分。第一，strategy library 初始只有模板檔；每個策略以 Markdown 記錄適用 target LLM、user/injected task 範圍、injection template、案例、失敗條件及 metadata。第二，strategy router 讀取策略的 routing summary，針對每個樣本選取 Top-K 策略；預設 K=3，無適用策略時使用 cold-start template。第三，iterative attack module 在最多 Nmax=10 次迭代內產生並修正 injection prompt。attacker 同時使用三層記憶：跨資料集的 routed strategy library、同一 dataset–model pair 中先前樣本的 curated intra-dataset memory，以及目前樣本的 intra-sample history；後者包含歷次 prompt、可觀察 target output、成功或失敗判斷與分析。成功即停止，否則持續迭代。第四，experience digester 在整個 dataset–model pair 結束後分析軌跡：成功案例可補充既有策略、擴大適用範圍或建立新策略；失敗案例則加入 miss patterns 與限制條件。實驗使用 IPIArena（20 train、21 test）、AgentDojo（20 train、30 test），另以 InjecAgent 30 個測試樣本比較；訓練包含兩個資料集與四個 target models 的八組配對。主要指標為 ASR@1、ASR@5、ASR@10。測試亦檢驗未見 target LLM、記憶元件消融、router 的上下文縮減，以及將策略庫整合至不同 attacker LLM 的 PAIR。

## 關鍵結果

主要指標為 ASR@N：在最多 N 次攻擊迭代中，至少一次成功即視為成功。

| Benchmark / Target LLM | ASR@1 | ASR@5 | ASR@10 |
|---|---:|---:|---:|
| IPIArena / Gemini-2.5-Pro | 57.1% (12/21) | 76.2% (16/21) | 76.2% (16/21) |
| IPIArena / GPT-5.1 | 9.5% (2/21) | 47.6% (10/21) | 61.9% (13/21) |
| IPIArena / Claude-Sonnet-4.5 | 28.6% (6/21) | 38.1% (8/21) | 42.9% (9/21) |
| AgentDojo / Gemini-2.5-Pro | 60.0% (18/30) | 83.3% (25/30) | 86.7% (26/30) |
| AgentDojo / GPT-5.1 | 26.7% (8/30) | 46.7% (14/30) | 53.3% (16/30) |
| AgentDojo / Claude-Sonnet-4.5 | 13.3% (4/30) | 30.0% (9/30) | 40.0% (12/30) |

在 InjecAgent 上，PIMiner 對 GPT-4o-mini、GPT-4.1-nano、GPT-5-nano 的 ASR 均為 1.00；在 AgentDojo 上分別為 0.73、0.63、0.53。相較 PISmith 的 0.78、0.81、0.38，PIMiner 僅在 GPT-5-nano 更高。IPIArena 消融實驗中，完整 PIMiner 相較 vanilla iterative attacker 的平均 ASR 提升，Claude-Haiku-4.5 為 19.8%，Claude-Sonnet-4.6 為 17.8%。訓練階段成本估計方面，論文報告在使用 Claude Code subscription 的前提下，target-model API 的額外支出約為 20 美元。

## 對我們的啟發
- [ ] 實務上可將策略庫作為可檢視、可修訂的 red-team 知識庫，保存成功案例、失敗條件與適用範圍，支援安全稽核及防禦資料建置。
- [ ] 對高查詢成本的 frontier agents，先以少量測試查詢配合跨任務記憶，可能比針對每一個 target model 重新進行 RL attacker training 更具成本效率；但應以論文所示設定實際驗證。
- [ ] router 的選擇性載入可降低 attacker context 長度；論文報告在兩種 attacker backbone 上分別降低 43% 與 61% 的平均輸入長度，顯示記憶檢索與上下文成本控制應一併設計。

## 限制與未來工作

論文主要使用 Claude Code models 作為 PIMiner backbone，以降低推理成本，因此不同 orchestration backbone 的完整比較仍有限。部分 RL baseline 直接採用 PISmith 已發表結果，可能限制完全一致的重現性。訓練與測試依賴公開 benchmark、受控環境及特定存取假設；論文未報告真實部署中的效果。系統亦具有雙重用途風險，需搭配嚴格的授權與隔離措施。
