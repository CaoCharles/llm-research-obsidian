# RoboArchitect: Automating the Design of Robotic Agents with Persistent Memory

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2610.42141)
- 📥 [PDF](https://arxiv.org/pdf/2610.42141v1)

## 摘要（中文翻譯）

近期研究顯示，將 frozen robot policy 放入 agent harness 後，性能顯著優於單獨使用 policy；harness 中的控制程式可決定何時查詢 policy、使用 vision tools，或直接控制機械臂。然而，現有 harness 多由人工設計，且需針對不同機器人與 benchmark 重新開發。本文提出 RoboArchitect，利用 coding model 觀察機器人 rollout、診斷失敗原因，並迭代修改 frozen policy 周圍的 harness。harness 在訓練 episodes 上演化，並於未見 scenes 與 tasks 上評估。在不更新任何模型權重下，unseen scenes 的平均成功率由 9.7% 提升至 43.3%，unseen tasks 則由 12.7% 提升至 40.2%。系統也能自動形成控制策略與 persistent memory，將有效抓取深度等經驗帶入後續決策。

## 問題背景

機器人 policy 面對新任務、硬體或分佈外環境時，通常需要蒐集 demonstrations 並 finetune 權重；人工設計 agent harness 也需針對每個 robot、benchmark 反覆除錯，成本高且難以完整檢查長期 rollout。現有研究雖證實 orchestration、工具使用與 memory 能改善 frozen policy，但其控制分工、失敗處理與記憶結構多預先由人指定，缺乏可自動化、可泛化的 harness 設計流程。

## 解決方案

RoboArchitect 以 coding model 作為 harness 的自動設計者，圍繞 frozen robot policy 迭代建立可執行的 agent。系統從 pass-through policy 開始，執行 training episodes 並記錄完整 rollout；coding model 讀取觀測、動作、模型與工具輸出，診斷失敗模式後修改控制程式。新版本可選擇沿用 policy、呼叫 language/vision tools、使用幾何工具，或直接發出機械臂指令，並可加入跨 episode 的 persistent memory。候選版本只有在 training set 表現更佳時才保留，最後在未見 scenes、未見 tasks 及跨 embodiment 設定評估。核心創新是自動共同設計 policy orchestration、程式控制與 memory，而非更新模型權重。

## 核心貢獻
1. 提出 RoboArchitect，將 coding model 驅動的 rollout 診斷與程式迭代，應用於 frozen robot policy 周圍的 harness 自動設計，且不更新 policy 權重。
2. 在多個 benchmark、policy、未見 scenes 與未見 tasks 上驗證 harness evolution 的效果，平均成功率分別由 9.7% 提升至 43.3%，以及由 12.7% 提升至 40.2%。
3. 展示 harness 能自動學得 policy 與直接程式控制的分工、具體失敗修復策略，以及可跨 episodes、任務與 robot embodiments 使用的 persistent memory。

## 技術方法

Harness 接收 camera images、depth maps、gripper pose/status、robot readings 與自然語言指令，輸出低階 action vectors。初始版本直接轉發 frozen VLA policy 的 action。每輪執行 training episodes，記錄逐步觀測、動作、policy/tool 輸出與完整軌跡；coding model 使用這些 traces 找出卡住、碰撞、錯誤抓取、接觸力不足或場景記憶等失敗，產生新版 harness。可用工具包括 language model、vision-language model、object detection、segmentation、pointing、grasp pose generation，以及像素深度轉 3D 座標和相對軌跡 primitive。最多進行 5 次迭代，候選程式若未超過目前 training performance 即不接受。harness 可動態決定由 VLA 或 code-as-policy 控制，並在執行期間建立 persistent memory，儲存抓取深度、grip style、任務線索、scene reset 週期及不同 robot 的手指閉合方向。實驗涵蓋 LIBERO-Pro-10、RoboCerebra、VLABench、SimplerEnv WidowX、RoboCasa-365，以及 SimplerEnv Google 的 unified harness；policy 包括 MolmoAct-2、OpenVLA-7B、π0.5、RLinf-π0.5、SmolVLA、X-VLA 與 RLDX-1。評估採 unseen scenes、unseen tasks 與跨 benchmark unified harness；除 VLABench 使用官方 progress score 外，其餘主要使用 task success rate。

## 關鍵結果

主要結果如下；數值均來自論文報告，且 held-out episodes 未用於 harness optimization。

| 評估設定 | Bare policy 平均 | Iterative evolved harness 平均 | 提升 |
|---|---:|---:|---:|
| Unseen scenes，所有 setups | 9.7% | 43.3% | 4.5×；論文標示為 +345% |
| Unseen tasks，所有 setups | 12.7% | 40.2% | 3.2×；論文標示為 +216% |
| Unseen scenes，cross-benchmark 與 out-of-domain | 7.3% | 58.4% | 論文標示為 +696% |
| Unseen tasks，cross-benchmark 與 out-of-domain | 6.3% | 48.7% | 論文標示為 +671% |
| Unified harness：general X-VLA，held-out benchmark 平均 | 1.9% | 28.8% | 論文標示為 +1417% |
| Unified harness：finetuned X-VLA specialists，held-out benchmark 平均 | 45.9% | 47.0% | 論文標示為 +2% |

個別結果包括：VLABench 的 general X-VLA 在 unseen scenes 由 7.3% 提升至 52.6%，unseen tasks 由 1.2% 提升至 72.5%；SimplerEnv WidowX 則在 unseen scenes 由 0.0% 提升至 87.5%，unseen tasks 由 0.0% 提升至 66.7%。在 VLABench 及 SimplerEnv WidowX 的 unseen scenes，以及 VLABench 的 unseen tasks，evolved harness 超過同一 policy 的 benchmark-finetuned 版本；但在 SimplerEnv WidowX unseen tasks 上未超過 finetuned 版本。Persistent memory 的 held-out 讀取平均每 episode 約 3.4 至 13.0 次，actionable reads 為 92% 至 99%。完整成本方面，論文報告 5 次 evolution 少於 6 小時 coding-model time，平均低於 150 美元。

## 對我們的啟發
- [ ] 實務上可先保留既有 frozen policy，透過 rollout traces 自動優化其外部控制層；當 policy 在目標環境失效時，harness 可選擇以幾何與感知工具補足，而不必立即進行 finetuning。
- [ ] 將失敗模式轉化為可檢查的控制 routine，例如偵測卡住後退回並抬升、遇到障礙改採側向接近、或依物體尺寸調整抓取深度，有助於提升可解釋性與後續除錯效率。
- [ ] Persistent memory 不必固定單一 schema；論文結果顯示，依物理量、物體、任務脈絡或 embodiment calibration 索引的經驗，能在後續 episode 提供可操作資訊。但這是根據本文實驗的實務啟發，並不代表已證明適用於所有真實機器人環境。

## 限制與未來工作

論文只測試最多 5 次 evolution，尚未確定更多迭代的收益是否飽和；評估全部在 simulation，尚未驗證 sim-to-real。研究也尚未涵蓋 dexterous in-hand manipulation、tool use 等更複雜接觸任務。另有一個 RoboCasa-365 unseen scenes 設定中，harness 未改善 bare policy。
