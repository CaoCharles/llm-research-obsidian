# Know It, Act on It: Investigating Memory Utilization in LLM Personalization

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2607.29433)
- 📥 [PDF](https://arxiv.org/pdf/2607.29433v1)

## 摘要（中文翻譯）

隨著大型語言模型（LLM）agent 成為個人化夥伴，memory 已是核心能力。然而，即使相關使用者偏好完整存在於 context，LLM 仍可能無法據此行動，形成 knowledge utilization problem。當 agent 未能個人化回應時，難以判斷是未記住資訊，還是記住卻未使用。本文提出解耦式評估框架，針對同一使用者偏好配對執行 Know 與 Act 測試。作者在 16 個系統、5 類 memory architecture 上進行大規模實驗，評估 1,000 個偏好，並控制三種表達強度。結果顯示 Know 與 Act 存在顯著落差：agent 常能回憶偏好，卻未能在配對情境中反映該偏好。memory architecture 可縮小差距，但 health 與 therapy 相關偏好的 utilization 特別弱，而這些領域的失誤具有最高的實際風險。

## 問題背景

現有 LLM personalization 與 memory 研究多半分別測量資訊 recall 或個人化行為，未針對同一偏好同時驗證兩者，因此行為失敗時無法判斷是 memory retrieval 失敗，還是模型記得資訊卻未能使用。既有研究也多採 static long-context，而非真實 agent 的 incremental memory pipeline；只測 Know 不能證明資訊影響行為，只測 Act 也可能只是模型猜中或依賴一般先驗。

## 解決方案

作者提出 paired Know–Act evaluation paradigm。對每個相同的 user preference，先以 Know Test 直接詢問 agent 能否回憶，再以不明示該偏好的自然情境執行 Act Test，檢查記憶是否真正改變回應。框架加入 Explicit、Incidental、Inferential 三級表達梯度，並以 incremental injection 讓不同 memory architecture 透過原生流程處理歷史。除 Know Accuracy 與 Act Accuracy 外，作者定義條件式 Utilization Rate，量化已成功記住的偏好有多少被轉化為行為；再以 oracle chunk 與 oracle preference 逐步繞過 retrieval、comprehension 階段，定位失敗來源。

## 核心貢獻
1. 提出針對同一使用者偏好的 paired Know–Act evaluation，將「記得資訊」與「依資訊行動」分離測量，能直接診斷 personalization pipeline 中的 utilization bottleneck。
2. 建立包含 50 個 personas、1,000 個 preferences、三種 expression strength，以及 16 個系統與 5 類 memory architecture 的 benchmark；偏好涵蓋 stereotypical、anti-stereotypical、neutral、health/medical 與 therapy/emotional 類型。
3. 透過 Mem0 的 oracle chunk 與 oracle preference 實驗，將 KnowPass × ActFail 案例分解為 retrieval、comprehension 與 application failure，發現整體錯誤以 comprehension failure 為主。

## 技術方法

資料取自 PersonaMem-v2。作者分層抽樣 50 個來自 11 個文化區域的 personas，每個 persona 選 20 個 target preferences，共 1,000 個；其餘約 50–70 個偏好作為 non-target context，形成約 11,955 個 chunks、4.55 million tokens，target-to-non-target ratio 約為 1:3。每個偏好被改寫為三種 expression strength：Explicit 直接陳述；Incidental 將偏好置於 task-oriented 對話的旁支資訊；Inferential 則須由多個行為線索推論。三種版本共享 non-target chunks、Know 問題與 Act 情境。

評估採 incremental memory construction：逐一輸入 conversation chunks，讓各系統使用其 native pipeline。比較五類架構：long-context、simple RAG、embedding RAG、structure-augmented RAG 與 agentic memory。long-context 包含 GPT-4o-mini、GPT-4o、Gemini 3.1 Flash、Claude 4.6 Sonnet；RAG 使用 BM25 或 embedding retrieval；結構化系統包含 Mem0、Zep/Graphiti、Cognee、HippoRAG-v2；agentic memory 包含 Letta/MemGPT、Self-RAG、MemoryOS、A-MEM。除 long-context baseline 外，系統共用 GPT-4o-mini generation backbone；embedding 系統預設使用 text-embedding-3-small，MemoryOS 使用其實作內建的 all-MiniLM-L6-v2。

記憶建立後，在獨立 session 執行配對測試。Know Test 以第一人稱直接詢問偏好，由 GPT-5 judge 與 ground truth 比較並給予 Pass/Fail；Act Test 提供未提及偏好的自然情境，並將 memory response 與同一 backbone、無 memory 的 response 配對比較，由 GPT-5 judge 判定是否更反映該偏好。指標包括 Know Accuracy、Act Accuracy，以及 Utilization Rate = N(KnowPass, ActPass) / [N(KnowPass, ActPass)+N(KnowPass, ActFail)]。另以 zero-memory Know baseline 驗證問題不可由猜測回答，四個 generation models 的通過率均低於 3%。作者亦以 Mem0 的 oracle chunk（直接注入目標對話片段）與 oracle preference（直接注入偏好文字）進行 failure attribution。

## 關鍵結果

主要結果如下（數值為論文 Table 1 的 macro-average；Utilization Rate 定義為在 Know Pass 中同時 Act Pass 的比例）：

| 系統 | Know Accuracy (%) | Act Accuracy (%) | Utilization Rate (%) |
|---|---:|---:|---:|
| GPT-4o-mini | 34.7 | 17.3 | 16.3 |
| GPT-4o | 65.6 | 29.3 | 32.1 |
| Gemini 3.1 Flash | 78.8 | 53.4 | 57.0 |
| Claude 4.6 Sonnet | 76.2 | 61.5 | 65.1 |
| RAG BM25 | 39.1 | 16.5 | 17.2 |
| RAG text-embedding-3-small | 51.5 | 27.8 | 31.7 |
| RAG Qwen3-Embedding-4B | 56.5 | 30.7 | 33.5 |
| Mem0 | 60.3 | 46.0 | 54.6 |
| Zep/Graphiti | 19.2 | 11.2 | 16.7 |
| Cognee | 43.2 | 23.8 | 27.0 |
| HippoRAG-v2 | 46.9 | 24.7 | 28.0 |
| Letta/MemGPT | 42.0 | 23.1 | 26.0 |
| Self-RAG | 57.7 | 32.6 | 35.3 |
| MemoryOS | 45.8 | 27.8 | 33.2 |
| A-MEM | 41.6 | 21.1 | 23.4 |

論文指出，Claude 4.6 Sonnet 的整體 Utilization Rate 最高，亦即約僅能將三分之二的已記住偏好轉化為適當行為。Mem0 將 GPT-4o-mini 的 utilization 從 16.3% 提升至 54.6%。Expression 分析顯示，各類架構的 Know Accuracy 都從 Explicit 到 Incidental 大幅下降，Inferential 則部分恢復；Explicit 主要暴露 utilization failure，非 Explicit 條件則較多呈現 storage/comprehension failure。Mem0 的 722 個 KnowPass × ActFail 案例中，retrieval failure 為 30.7%、comprehension failure 為 53.0%、application failure 為 16.2%。依偏好類型的整體平均 utilization 數值，論文圖表呈現 Health & Medical 為 15.58%、Therapy & Emotional 為 21.92%；其餘類型分別為 Anti-Stereotypical 27.48%、Neutral 27.34%、Stereotypical 26.94%。

## 對我們的啟發
- [ ] 實務部署不應只追蹤 memory recall；應對同一記憶同步量測是否改變下游回應，並以 Utilization Rate 作為 personalization 的重要監控指標。
- [ ] 對健康、醫療與情緒偏好，系統應加入明確的 preference-to-constraint 檢查或安全閘門；論文結果顯示這些偏好即使被記住，也較難被正確轉化為行為。
- [ ] 記憶抽取與呈現格式會影響可用性：論文中 memory architecture 對 utilization 的改善通常大於對 Know Accuracy 的改善，因此設計重點不只是召回更多內容，也要將偏好轉成可操作的約束。

## 限制與未來工作

評估主要依賴 LLM judge，可能有偏好冗長回答或忽略細微行為線索的偏差；資料來自 PersonaMem-v2 的 synthetic personas，缺少真實長期互動中的 topic drift、矛盾與破碎資訊。實驗以單一 target passage、有限干擾項隔離 utilization，檢索難度低於真實部署，因此結果可能是 Know–Act gap 的保守估計。
