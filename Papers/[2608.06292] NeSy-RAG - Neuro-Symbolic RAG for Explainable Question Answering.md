# NeSy-RAG: Neuro-Symbolic RAG for Explainable Question Answering

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.06292)
- 📥 [PDF](https://arxiv.org/pdf/2608.06292v1)

## 摘要（中文翻譯）

Retrieval-augmented generation（RAG）透過以外部知識（如文字語料庫）為大型語言模型（LLM）提供依據，能改善問答。然而，其推理過程通常不透明：中間推理步驟難以驗證，也無法可靠地歸因至特定證據；此外，系統很少能系統性偵測缺少的使用者情境，因而可能產生不完整或錯誤的輸出。本文提出 NeSy-RAG，一個模組化的 neuro-symbolic RAG framework，能從檢索到的文字片段合成具可歸因性的 Prolog modules。系統為每個片段產生表達 Boolean claims 的語意謂詞，這些謂詞可以依賴使用者事實；接著利用自然語言與程式碼的聯合 embeddings 檢索並組合 Prolog queries。為處理不完整的使用者情境，本文提出 symbolic knowledge-gap detection，辨識會影響查詢結果的缺失使用者事實，並自動觸發後續互動。執行 Prolog queries 可產生確定性答案與透明 execution traces，將每個推理步驟連結至其來源。於 ShARC benchmark 上，在不使用 domain-specific training 的情況下，NeSy-RAG 達到 61.1% accuracy，優於相同模型的 RAG baseline（42.8%）。

## 問題背景

現有 RAG 雖能以外部文件 grounding LLM，卻難以提供可信的中間推理、規則層級的來源歸因與可驗證 execution trace。Chain-of-thought 不保證反映真實推理，生成答案也不必然能正確連結證據。此外，使用者特定資訊可能在初始互動中缺失，傳統 RAG 或 LLM 常直接給出確定答案，無法可靠判斷何時應追問，造成不完整、錯誤或過度自信的回答。

## 解決方案

作者提出 NeSy-RAG，將 dense retrieval 與 Prolog-based symbolic reasoning 結合。系統從各個 retrieved text chunk 個別合成可歸因的 Prolog module，並以 0-arity predicates 將複雜規則封裝為可理解的 Boolean claims，再透過 joint NL-code embeddings 進行 predicate retrieval 與受限 query composition。Prolog 的 deterministic execution 產生可追溯的 reasoning trace；每一步均可連回來源 chunk。對未知 user facts，系統在執行期間以 symbolic knowledge-gap detection 判斷其真值是否會改變查詢結果，只有必要時才觸發 targeted follow-up questions，若無法取得必要資訊則輸出 more。

## 核心貢獻
1. 提出模組化 neuro-symbolic RAG framework，從每個檢索文字片段合成並執行可歸因的 Prolog modules，使規則、事實與推理步驟可追溯至來源片段。
2. 提出 0-arity predicate abstraction，將複雜 Prolog logic 暴露為具語意的 Boolean claims，並透過自然語言到程式碼的 predicate retrieval 限制 query construction 的搜尋空間。
3. 提出 symbolic knowledge-gap detection，於 Prolog inference 過程中辨識會影響查詢結果的未知動態事實，並自動產生 follow-up interactions。

## 技術方法

NeSy-RAG 接收問題、檢索到的 snippets 與使用者情境，並將每個 snippet 個別輸入 LLM 以合成 Prolog module。每個 module 包含由文字抽取的 rules 與 facts，且每項規則和事實都保留來源 chunk 與文件的 attribution。系統區分 universal facts 與 dynamic facts；後者包含推理時才可取得的使用者資訊，通常以帶單一 Boolean argument 的 dynamic predicates 表示。合成後，LLM 另外產生 0-arity rules，將非零元謂詞抽象成可檢索的 Boolean claims。推理時先對候選 snippets 進行 relevant/irrelevant 分類，再使用 joint natural-language/code embedding 對 0-arity predicates 做 cosine-similarity ranking，取 top-k predicates，並要求 LLM 僅使用這些 predicates 組合 Prolog query。查詢在 SWI-Prolog 中執行；若遇到未知 dynamic predicate，系統透過 PySwip 呼叫模擬使用者取得 true、false 或 None。若必要事實未知，系統比較其在兩種 Boolean 指派下的查詢結果；結果不同則回傳 more，否則回傳穩定的 yes 或 no。實驗使用 ShARC test split 的 8,276 筆資料，每筆提供目標 snippet 與隨機 distractors，並以 accuracy 與平均單筆執行時間評估。比較對象包括可取得完整 context 的 LLM Upper Baseline，以及需追問的純 LLM RAG Baseline。

## 關鍵結果

| 方法 | 模型 | Accuracy (%) | 平均時間 (s) |
|---|---|---:|---:|
| LLM RAG Baseline | gpt-oss:20b | 42.8 | 11.4 |
| LLM RAG Baseline | gpt-5-mini | 53.7 | 25.1 |
| NeSy-RAG（k=3 / 10 / 20） | gpt-oss:20b | 60.0 / 61.1 / 60.4 | 7.0 / 7.4 / 7.3 |
| LLM Upper Baseline | gpt-oss:20b | 64.1 | 2.7 |
| LLM Upper Baseline | gpt-5-mini | 69.9 | 5.2 |
| BiAE（trained） | 未提供 | 77.9 | 論文未報告 |

NeSy-RAG 在 k=10 時達到最佳 accuracy 61.1%，高於 gpt-oss:20b RAG baseline 的 42.8%，平均處理時間也較低（7.4 秒對 11.4 秒）。在 more 類別上，NeSy-RAG 正確率為 61%，而 LLM RAG 與 LLM Upper 分別為 19% 與 23%，支持其 knowledge-gap detection 的效果。NeSy-RAG 有 178 次執行（2.2%）因 Prolog modules 或 queries 語法無效而失敗。其主要錯誤是將 yes 判為 more（31%）；此外，more 被判為 yes 與 no 的比例分別為 17% 與 15%。

## 對我們的啟發
- [ ] 在需要可驗證性的 RAG 應用中，可將生成式回答與可執行的 symbolic reasoning 分離，讓來源歸因與推理結果不完全依賴 LLM 的自然語言解釋。
- [ ] 知識缺口不應只透過 LLM 自我判斷；可利用對未知 Boolean facts 進行不同真值指派並比較查詢結果，系統性判斷是否必須追問使用者。
- [ ] 模組重用、分層 retrieval 與受限 query generation 能同時降低上下文負擔與執行時間，但實務部署仍須特別控制 Prolog synthesis 產生多餘動態 predicates 的問題。

## 限制與未來工作

評估僅使用 ShARC，且每個實例依賴單一相關 snippet；multi-hop 與 multi-chunk reasoning 尚未驗證。系統仍會合成過多 dynamic predicates，導致可回答問題被保守判為 more；另有 2.2% 執行因 Prolog 語法錯誤失敗。未來工作包括收緊 dynamic predicate 生成限制、擴展跨模組推理，並支援 Boolean 以外的資料型別。
