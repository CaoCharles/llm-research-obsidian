# NeSy-RAG: Neuro-Symbolic RAG for Explainable Question Answering

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.06292)
- 📥 [PDF](https://arxiv.org/pdf/2608.06292v1)

## 摘要（中文翻譯）

Retrieval-Augmented Generation（RAG）可透過外部知識為大型語言模型（LLM）提供依據，提升 Question Answering（QA）能力；然而，其推理過程通常不透明，中間步驟難以驗證，也無法可靠地將答案歸因於特定證據。此外，現有方法很少系統性偵測缺少的使用者情境，因而可能產生不完整或錯誤的輸出。本文提出 NeSy-RAG，一個模組化的 Neuro-Symbolic RAG 框架，能從檢索到的文字區塊合成具來源歸因能力的 Prolog 模組。系統為每個區塊產生表達 Boolean claims 的語意謂詞，並可依賴使用者事實；再利用自然語言—程式碼聯合嵌入檢索與組合謂詞，形成 Prolog 查詢。符號式 knowledge-gap detection 會找出影響查詢結果的缺失使用者事實，並自動觸發追問。執行 Prolog 後，系統提供確定性答案與可追溯至來源文字的執行軌跡。在 ShARC 上，NeSy-RAG 達到 61.1% accuracy，優於同模型 RAG baseline 的 42.8%。

## 問題背景

現有 RAG 雖能以外部文件支援 LLM 問答，但答案生成與中間推理通常缺乏可驗證的 source attribution，Chain-of-Thought 也不保證忠實反映實際推理。此外，當回答需要使用者的個人情境而資訊尚未提供時，LLM 往往直接做出確定判斷，無法系統性辨識 knowledge gaps 或提出必要追問。既有 Prolog/Neuro-Symbolic 方法則可能依賴單一大型知識庫、人工規則，或缺少來源歸因與可擴展的 query construction。

## 解決方案

作者提出 NeSy-RAG，將 dense retrieval 與模組化 Prolog reasoning 結合。每個檢索 chunk 個別轉換為可執行且可歸因的 Prolog module，使 facts、rules、execution trace 均能連回來源文字。系統以 0-arity predicates 將模組功能抽象成語意 Boolean claims，再透過自然語言—程式碼 embedding 做 predicate retrieval，限制 LLM 僅能組合問題相關的既有規則，以降低 query hallucination 與擴展成本。推理時區分 universal 與 dynamic facts；若 dynamic fact 缺失，系統自動追問。當資訊仍不可得時，透過比較不同 Boolean assignment 對查詢結果的影響，判定應回傳 more 或可安全輸出 yes/no。

## 核心貢獻
1. 提出模組化 Neuro-Symbolic RAG 框架，將每個檢索文字區塊轉換為可執行的 Prolog 模組，並讓規則與事實可唯一歸因至來源區塊。
2. 提出 0-arity predicate abstraction，將複雜 Prolog 知識以 Boolean claims 暴露，配合自然語言—程式碼嵌入進行階層式 predicate retrieval，限制查詢生成範圍。
3. 提出 symbolic knowledge-gap detection，在 Prolog 推理期間辨識會影響答案的缺失使用者事實，並透過互動式 follow-up questions 補足情境資訊。

## 技術方法

NeSy-RAG 作為既有 RAG 的 plug-in extension，輸入問題、檢索文字 chunks 與可能不完整的使用者情境。第一步由 LLM 逐一將每個 chunk 合成 Prolog module，分為 rules 與 facts；每個事實或規則保留其來源 chunk 與文件的 attribution。系統區分 universal facts 與 dynamic facts：前者可由領域文字直接確定，後者包含需在推理時取得的使用者資訊，本文主要處理單一 Boolean argument。第二步額外生成 0-arity rules，將非零元謂詞抽象為可直接匹配問題的 Boolean claims。推理時先以 snippet relevance filtering 選取相關 chunks，再使用 joint natural language–code embedding，依問題與 0-arity predicates 的 cosine similarity 排序，取 top-k predicates；LLM 只能從此受限集合組合 Prolog query。第三步在 SWI-Prolog 中執行查詢；遇到 dynamic predicate 時，透過 PySwip 呼叫外部互動方法向模擬使用者追問，並快取已取得的答案。若必要資訊無法取得，系統在 true/false 兩種設定下分別評估查詢；若結果不同則輸出 more，否則輸出穩定的 yes 或 no。若無相關 snippet 或無法建立查詢，則輸出 irrelevant。實驗使用 ShARC test split 的 8,276 筆資料，每筆提供目標 snippet 與隨機 distractor snippets，並比較兩種 LLM baseline；主要評估指標為四類標籤的 accuracy 與平均處理時間。

## 關鍵結果

| 方法 | 模型 | Accuracy (%) | 平均時間 (秒) |
|---|---|---:|---:|
| LLM RAG baseline | gpt-oss:20b | 42.8 | 11.4 |
| LLM RAG baseline | gpt-5-mini | 53.7 | 25.1 |
| NeSy-RAG（k=3） | gpt-oss:20b | 60.0 | 7.0 |
| NeSy-RAG（k=10） | gpt-oss:20b | 61.1 | 7.4 |
| NeSy-RAG（k=20） | gpt-oss:20b | 60.4 | 7.3 |
| LLM Upper baseline | gpt-oss:20b | 64.1 | 2.7 |
| LLM Upper baseline | gpt-5-mini | 69.9 | 5.2 |
| BiAE（trained） | — | 77.9 | 論文未報告 |

NeSy-RAG 在 ShARC test split 的 8,276 筆資料上，以 k=10 達到最佳 61.1% accuracy，較同模型 LLM RAG baseline 的 42.8% 高 18.3 個百分點。其 more 類別的正確率為 61%，高於 LLM RAG baseline 的 19% 與 LLM Upper baseline 的 23%，支持 knowledge-gap detection 的有效性。NeSy-RAG 有 178 次執行（2.2%）因 Prolog module 或 query 語法無效而失敗。主要錯誤是將 yes 誤判為 more（31%），顯示 dynamic predicates 可能過度生成。

## 對我們的啟發
- [ ] 對需要可驗證性的 RAG 應用，可將生成式推理與 deterministic symbolic execution 分離，讓答案、推理步驟及來源證據同步呈現。
- [ ] 將來源文件先轉為模組化 symbolic artifacts，可重用已合成的 Prolog modules，降低不同問題重複讀取與解析文件的成本。
- [ ] Knowledge-gap detection 不應只依賴 LLM 自行決定是否追問；可透過評估未定義 Boolean fact 在不同取值下是否改變查詢結果，形成較明確的追問觸發條件。

## 限制與未來工作

評估僅涵蓋 ShARC，且每個實例依賴單一相關 snippet；multi-hop retrieval、多區塊推理與跨模組歸因尚未驗證。系統仍有 2.2% Prolog 語法錯誤，並會過度生成 dynamic predicates。作者指出未來需改善 dynamic predicate 約束、擴展至 multi-hop 與 multi-chunk 推理，並支援 Boolean 以外的資料型別。
