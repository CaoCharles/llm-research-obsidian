# ExtractBench: A Benchmark for Schema-Guided Enterprise Document Extraction

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2607.29677)
- 📥 [PDF](https://arxiv.org/pdf/2607.29677v1)

## 摘要（中文翻譯）

企業工作流程日益依賴 agents 執行 schema-guided extraction：系統根據文件與使用者定義的 schema，忠實產生正確輸出，並附上作為 grounding metadata 的來源證據。本文提出 ExtractBench，據作者所知，是首個同時大規模評估 value accuracy、record completeness、grounding 與實測成本的 benchmark。資料涵蓋 370 份企業文件、4,869 頁、8 個商業領域及 67 種文件類型，並以挑戰標籤區分不同情境。其 schema 與 ground truth 建構流程結合真實文件的獨立系統一致性、合成清單的已知值，以及表單的人工作業驗證。評估採用不計順序的 value F1，以及 word-level 與 page-level grounding F1。商業 VLM 在短文件表現良好，但長文件常截斷記錄清單；coding agents 維持較高準確率卻成本更高。LlamaExtract Agentic Plus 在三項指標均排名第一，準確率接近 coding agents，但成本僅為其一部分。資料集與評估程式碼已公開。

## 問題背景

企業文件抽取從固定欄位轉向 user-defined schema，但現有 benchmark 多半只覆蓋固定 ontology、少量 schema 或單一挑戰，未同時衡量長清單完整性、真實掃描與手寫、來源 grounding 及成本。單一 aggregate score 也無法區分截斷、錯配、過度填值與感知噪聲，因而不足以支援生產部署與人機稽核。

## 解決方案

作者提出 ExtractBench，將 schema-guided extraction 定義為從文件與 JSON Schema 產生結構化 JSON 及逐值來源證據，並以五軸 taxonomy 標註 task challenge、perception challenge、table structure、document length 與 business domain。核心創新是把 value accuracy、重複記錄 completeness、page/word grounding 與 measured cost 統一評估。其 ground truth pipeline 依文件來源採用跨系統協議、人工作業驗證或程式化生成，兼顧真實版面多樣性、長清單可擴展性與表單標註可信度。

## 核心貢獻
1. 提出涵蓋 370 份文件、4,869 頁、8 個領域、67 種文件類型與 13 個挑戰標籤的 schema-guided enterprise document extraction benchmark。
2. 設計可擴展的 schema 與 ground-truth 建構流程，分別利用真實文件的跨系統協議與裁決、合成長清單的程式化已知值，以及掃描表單的人工作業驗證。
3. 將 value accuracy、重複記錄完整性、word/page-level grounding 與每頁成本納入同一評估框架，並比較 14 個 extraction systems 的品質—成本取捨。

## 技術方法

任務輸入是一份 born-digital 或 scanned 文件與使用者提供的 JSON Schema；schema 可包含 scalar、nullable field、nested object、record array 與 value constraints。系統輸出必須是 schema-valid JSON，並為每個值提供來源頁面與 bounding box。資料包含真實企業文件、依真實版面程式化生成的 synthetic long lists，以及真實掃描／手寫表單；每種文件類型共用一個 schema。真實文件先由不同模型與 pipeline 產生 schema 與抽取提案，對一致值採信，爭議欄位由人員依頁面裁決，若問題源於歧義則修訂 schema。合成清單先決定 records，再以 rendering code 產生 PDF，從渲染結果取得精確值與 word box，並透過機械檢查及模型池稽核。掃描表單由最多五個系統投票，爭議交由 agent 檢視，人員驗證每個欄位並修正框。評估 14 個系統，涵蓋 commercial/open-source VLM、coding agents 與 specialized APIs；所有系統使用相同 document-schema pairs，未作 benchmark-specific tuning。Value F1 將輸出攤平成 cells，陣列以 Hungarian algorithm 作不計順序的 record matching，經規定 normalization 後計算 precision、recall、F1；遺漏 scalar key 按 null 評分。Grounding 只在已驗證框的文件上計算，需同時值正確且 IoU≥0.5；page-level 僅要求來源頁正確。成本依實際 token 或 credit consumption 與公開價格計算，並按文件層級取平均，再依長度、任務、感知、表格結構及商業領域切片。

## 關鍵結果

| 系統 | Overall value F1 | Short / Medium / Long value F1 | Overall word-level grounding F1 | Overall page-level grounding F1 | 平均成本（¢/page） |
|---|---:|---:|---:|---:|---:|
| LlamaExtract Agentic Plus | 95.6% | 96.6% / 93.3% / 94.4% | 46.4% | 84.9% | 8.1 |
| LlamaExtract Agentic | 89.5% | 92.0% / 85.4% / 78.6% | 44.1% | 66.1% | 3.1 |
| LlamaExtract Cost-Effective | 86.8% | 90.8% / 80.1% / 69.2% | 40.4% | 64.2% | 1.0 |
| Reducto Deep Extract | 90.4% | 94.2% / 80.5% / 92.0% | 43.3% | 71.7% | 34.4 |
| Codex GPT-5.5 | 93.6% | 95.7% / 91.2% / 78.9% | 0.0% | 0.0% | 27.8 |
| Claude Code Opus 4.8 | 87.1% | 90.1% / 79.2% / 88.1% | 0.0% | 0.0% | 16.2 |
| Gemini 3.5 Flash | 79.8% | 87.9% / 69.8% / 27.9% | 0.0% | 0.0% | 1.0 |
| GPT-5.4 Nano | 74.9% | 87.2% / 62.6% / 8.9% | 0.0% | 0.0% | 0.21 |

論文報告：LlamaExtract Agentic Plus 在整體、長度切片及三項主要指標中表現最強；商業 VLM 在超過 50 頁的文件上大幅退化；超過 1,000 列的巨大表格中，多數 VLM 的 F1 低於 10%，而 LlamaExtract Agentic Plus、Reducto Deep Extract 與 Claude Code Opus 4.8 分別為 95.9%、95.3% 與 87.8%。

## 對我們的啟發
- [ ] 部署文件抽取系統時，不能只看整體 value F1；應額外切分長文件、長清單、跨頁表格、掃描與手寫等挑戰，以辨識具體失敗原因。
- [ ] 長文件的主要風險是 recall 下滑與整批記錄遺漏，而非單一欄位讀錯，因此生產流程應加入記錄數量檢查、跨頁續接驗證與完整性監控。
- [ ] 若工作流程需要可稽核輸出，應把來源頁面與精確 bounding box 視為一等指標；論文結果顯示 page-level grounding 明顯高於 word-level grounding，兩者不能互相替代。

## 限制與未來工作

資料集部分 ground truth 依賴跨模型一致性與裁決，而非所有真實文件欄位均由人工逐一標註；word-level grounding 僅在具驗證框的文件上評估。成本比較排除四個自託管 OSS pipeline，且結果反映 2026 年 7 月的供應商價格。文件與挑戰分布可能影響整體平均，論文未報告更廣泛產業或時間外推的結果；大 schema 導致失敗的因果關係也未經控制實驗確認。
