# MARC v1: An Open-Source Multi-Agent Framework for Clinical AI Reasoning and Coordination

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.13476)
- 📥 [PDF](https://arxiv.org/pdf/2608.13476v1)

## 摘要（中文翻譯）

本文提出 Multi-Agent Reasoning and Coordination（MARC），一個開源的 clinical AI framework，以 deterministic multi-agent orchestration 取代單一、整合式的 LLM prompting。MARC 協調分工明確的 agents，分別執行資訊擷取、推理、答案生成與評估，並透過明確的 context passing 傳遞資訊及記錄可追蹤的中間輸出，因此能進行分階段的 failure attribution。作者另提出 Decomposer module，能從 plain-language task description 自動產生 task-specific agent prompts，降低手動 prompt engineering 的需求。框架支援 API-based 與 local CPU-compatible deployment，所有設定皆可透過 YAML 修改而不需變更程式碼。MARC 具備 model-agnostic、可解釋及易於使用等特性，讓 clinical domain experts 即使沒有 programming expertise 也能建立與調整臨床 AI workflow。完整框架已開放於 GitHub。

## 問題背景

現有 clinical LLM 系統常以 single prompt 要求單一模型同時完成資訊擷取、推理、驗證與行動生成，使中間過程不透明，也難以判斷錯誤來自遺漏資訊、推理失誤、指令遵循問題或答案格式化。固定 workflow 與手動 prompt engineering 亦限制臨床任務適配、模型替換及非程式設計專家的使用。

## 解決方案

作者提出 MARC，以 deterministic、sequential 的 multi-agent orchestration 將臨床任務拆分為 extraction、reasoning、answer generation 與 evaluation 等角色，透過顯式 context passing、標準化 verdict 與中間輸出 logging 建立可追蹤的 handoffs 和 stage-wise failure attribution。其核心創新包括 YAML-based、無需改碼的 pipeline/configuration；可逐 agent 更換模型與 RAG 知識來源；支援 Gemini API 和 Ollama local deployment；以及以 MedGemma 4B 實作的 Decomposer，從自然語言任務描述自動產生角色、子任務與 prompt templates，降低人工 prompt 設計成本。

## 核心貢獻
1. 提出開源且 domain-agnostic 的 MARC multi-agent framework，以 sequential、role-specialized agents 分離資訊擷取、推理、答案格式化與評估，並記錄各階段中間輸出以支援 failure attribution。
2. 提出 Decomposer module，使用 MedGemma 4B 將 plain-language task description 分解為三個 subtasks，並自動產生包含 agents、roles 與 prompt templates 的結構化 JSON 規格。
3. 以 YAML 宣告式設定支援 agent sequence、model assignment、prompt templates 與 optional RAG knowledge sources，並同時支援 Gemini API 與透過 Ollama 的 local CPU-compatible deployment。

## 技術方法

MARC 是以 Python 與 LangChain 實作的 domain-agnostic multi-agent system，採 Level 2 autonomy 的 structured workflow design。每個 agent 包含 language model、task-specific prompt，以及可選的 RAG module；agent name、model identifier、prompt file path 與 context file paths 由 config/agents.yaml 宣告。執行時，Agent 1 僅接收原始輸入，擷取 2–4 個與任務相關的 evidence bullets，不直接作答；Agent 2 接收原始輸入與 Agent 1 的完整輸出，進行 categorization、multi-step reasoning、選項或假設比較，並以標準化 VERDICT 或 FINAL 行結束；Agent 3 接收原始輸入與 Agent 2 輸出，定位 verdict 並原樣回傳，以產生可解析答案。主要 runtime variables 為 {input} 與 {previous_agent_output}。所有 agents 採 zero-shot、temperature=0；prompt 包含角色定義、任務指示、輸出限制與 runtime variables。Decomposer 使用 MedGemma 4B，在單一 conversational turn 中把自然語言任務分解為三個 subtasks，產生包含 agent names、roles 與完整 prompts 的 JSON，並檢查變數綁定、VERDICT 格式及輸出長度限制。代表性 workflow 包括 biomedical QA，以及含 conditional routing 的 radiology pipeline；正常報告可跳過分類階段。框架支援 Gemini API 與 Ollama local deployment，但論文未提供定量評估指標或實驗數據。

## 對我們的啟發
- [ ] 若臨床 workflow 需要可稽核性，可將 extraction、reasoning、decision formatting 與 evaluation 拆成具體階段，並保存每階段輸出，以便定位錯誤來源。
- [ ] YAML-based orchestration 可讓臨床專家在不修改 Python 程式碼的情況下替換模型、提示詞與知識來源，但實際部署仍應進行任務與安全性驗證。
- [ ] 標準化 verdict line 與明確變數綁定能提高輸出可解析性與流程重現性；然而，這種格式控制不等同於臨床正確性或 hallucination prevention，應搭配獨立評估與人工審查。

## 限制與未來工作

作者明確指出，MARC v1 主要採 sequential execution，尚未充分支援 parallel agents、dynamic routing、disagreement resolution、iterative refinement、variable-depth pipeline 與 human-in-the-loop。論文亦未進行 comprehensive empirical benchmark，未比較 single-prompt baselines，未提供 accuracy、reliability、latency、cost、error localization 或 clinician usability 的量化結果。未來將評估更多 clinical tasks、datasets 與 model backends，並研究更彈性的 orchestration。
