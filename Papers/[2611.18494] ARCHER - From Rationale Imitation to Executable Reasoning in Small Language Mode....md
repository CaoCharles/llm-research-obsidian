# ARCHER: From Rationale Imitation to Executable Reasoning in Small Language Models

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2611.18494)
- 📥 [PDF](https://arxiv.org/pdf/2611.18494v1)

## 摘要（中文翻譯）

小型語言模型（SLM）適合在本地、低成本且重視隱私的環境部署，但在需要問題分解、精確計算、工具使用與驗證的數學推理任務上仍不可靠。本文提出 ARCHER（Action-trace Reinforcement for Calculator-grounded Hierarchical Executable Reasoning），一個訓練 SLM 產生可執行且可稽核推理軌跡的兩階段框架。第一階段將自由形式的 chain-of-thought rationale 編譯為具型別的 action trace，包含 reasoning step、calculator call、確定性的 runtime observation、verification action 與 final answer，將監督目標從模仿解釋文字轉為學習工具導向的推理政策。第二階段以 asymmetric hierarchical reinforcement learning 精煉政策，透過分組且條件式閘控的 trajectory reward，分別評估答案正確性、工具 grounding、流程紀律與 trace alignment。在五個標準 sub-10B backbone 上，ARCHER 相較最強工具增強 baseline 的 benchmark accuracy macro-average 提升 5.51 個百分點；MATH-500、AIME-2024 與 AIME-2025 分別提升 8.95、5.33 與 5.34 個百分點。兩個額外 reasoning-specialized 7B backbone 的結果也顯示，即使模型已經過 reasoning-focused reinforcement learning 或 distillation，executable grounding 仍具效益。

## 問題背景

論文聚焦於小型語言模型在數學推理中的不可靠性，尤其是多步分解、精確算術、工具呼叫及結果驗證。既有 rationale distillation 主要模仿自由形式解釋，可能只學到表面形式；工具增強方法則未必教會模型何時呼叫工具、如何形成正確表達式或如何使用 observation。Outcome-only RL 的 credit assignment 稀疏，平坦 process reward 又可能帶來噪聲與錯誤對齊。

## 解決方案

作者提出 ARCHER，將數學推理視為 executable policy learning。TRACE 編譯器把既有 chain-of-thought rationale 轉換成標準化、可執行的 action-observation trajectory，讓模型學習 READ、PLAN、CALL_CALC、OBSERVE、VERIFY、ANSWER 等動作，而不是單純模仿說明文字。接著 HiGRA 使用 asymmetric hierarchical reinforcement learning，以答案正確性為最高優先，依序整合 tool grounding、process discipline 與 gated trace alignment；只有在工具需求或軌跡品質符合條件時，才啟用相應輔助 reward，以降低不相關或衝突訊號造成的最佳化壓力。

## 核心貢獻
1. 將小型模型的數學推理重新表述為 executable policy learning，使用具型別 action 與 deterministic calculator runtime，將推理、工具呼叫、觀察、驗證及終止統一到可稽核軌跡中。
2. 提出 TRACE compiler，將既有 free-form rationale 與 GSM-8K inline calculator annotation 編譯成 calculator-grounded supervision，降低人工撰寫 action trace 的需求。
3. 提出 HiGRA，以 priority-ordered、conditionally gated 的 grouped reward，聯合最佳化答案正確性、工具 grounding、流程紀律與 trace compatibility，並透過 GRPO 進行 trajectory-level refinement。

## 技術方法

每筆資料表示為（x, r, y*），其中 x 是問題、r 是 legacy rationale、y* 是標準答案。TRACE 先分離文字推理與算術片段：文字映射至 READ、PLAN、VERIFY 等動作；算術片段正規化為 calculator expression，形成 CALL_CALC→OBSERVE 的配對，OBSERVE 由 deterministic runtime 產生，最後加入標準化 ANSWER。模型以 LoRA supervised fine-tuning 學習編譯後軌跡；實作使用 rank 8、alpha 16、dropout 0.05、兩個 epoch，最大序列長度 256。HiGRA 從 TRACE checkpoint 初始化，對每個問題採樣一組 trajectory，以 GRPO 的 group-relative advantage 更新政策，不需額外 value model。總 reward 包含 outcome correctness、條件式 tool grounding、process discipline、閘控 alignment，以及 trajectory-length penalty。工具 reward 評估必要呼叫、配對 observation 與 deterministic execution consistency；process reward 評估格式、verification、簡潔性、答案存在與 premature termination；alignment 僅在軌跡已正確或具足夠工具 grounding 時施加。推論時模型逐步輸出 action，CALL_CALC 交由 calculator 執行並插入 OBSERVE，直到 ANSWER 或 12 步上限。實驗使用 GSM-8K 訓練 TRACE 與 HiGRA，並在 GSM-8K、SVAMP、MMLU-Math、MATH、MATH-500、AIME-2024、AIME-2025 與 PolyMATH 評估；主要指標為 final-answer accuracy，GSM-8K 另評估 Tool Score、tool precision/recall、observation consistency、Process Score、valid trace rate 與 trace edit distance。

## 對我們的啟發
- [ ] 若任務具有可驗證的中間計算，訓練目標可從自由形式 rationale 改為明確的 action-observation schema，以提升工具使用的可觀測性與可診斷性。
- [ ] 輔助 reward 不宜一律平坦加總；可依正確性、工具需求與軌跡狀態啟用條件式 reward，避免模型在錯誤計算上被 trace similarity 或格式訊號誤導。
- [ ] 在導入 RL 前先用 executable trace 做 supervised initialization，能先建立穩定的工具互動介面，再以 trajectory reward 改善工具呼叫、觀察一致性與終止行為；這是根據論文兩階段結果可直接採用的工程策略。

## 限制與未來工作

研究主要集中於可可靠執行中間計算、可檢查最終答案的數學任務；TRACE 仍是針對算術的 deterministic compiler，HiGRA reward families 也由人工設計。作者未證明其對非數值領域的泛化。未來工作包括加入 symbolic solver、unit converter、code execution、retrieval 與 proof checking，並進行更廣泛的 trace construction、reward calibration 與 adaptive gating。
