# SheetCompass: Hierarchical Relation Graphs for Agentic Spreadsheet Reasoning

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.14452)
- 📥 [PDF](https://arxiv.org/pdf/2608.14452v1)

## 摘要（中文翻譯）

試算表廣泛用於組織、分析與操作半結構化資料，但 automated spreadsheet reasoning 對大型語言模型（LLM）仍具挑戰。真實工作簿常包含隱含的跨表關聯、細粒度欄位依賴與複雜空間布局。現有方法通常將多維結構扁平化為連續字串，因而遺失工作表內邊界與工作表間語義，使 LLM 無法利用人類專家檢視試算表時所依賴的全域空間脈絡。本文提出 SheetCompass，一個由圖結構引導且由記憶驅動的 agentic spreadsheet reasoning framework。該方法明確建模工作表內外的結構關係，並在記憶中保留與任務相關的資訊，使 agents 能更有效地處理複雜工作簿。

## 問題背景

論文聚焦於 LLM 進行複雜試算表自動化時的結構推理問題。現有方法多把含有二維布局、表格邊界與跨工作表依賴的工作簿轉成 Markdown、JSON 等線性字串，破壞列欄位置、鄰近關係及跨表資料流。LLM 因而難以定位目標欄位、理解隱含關聯並在長流程執行後可靠修正錯誤。

## 解決方案

作者提出 SheetCompass，將 spreadsheet automation 分解為 space reconstruction 與 coordinated reasoning。系統先建立 hierarchical relation graph，以 table 與 column 節點、結構邊及語義邊保存工作表內布局和跨表依賴；再以 expert knowledge memory 提供工具與領域規則，以 reasoning experience memory 累積當前執行錯誤和成功經驗。最後由 explorer 導航與分解任務、programmer 生成受圖約束的程式、reflector 依狀態 checklist 驗證並觸發修正，形成圖引導的閉環 agent workflow。

## 核心貢獻
1. 提出 SheetCompass，將試算表從原始表格轉換為可供 agent 規劃、執行與反思的結構化證據空間，以減少傳統扁平化表示造成的結構資訊遺失。
2. 提出由 table-level 與 column-level 節點構成的 hierarchical contextual graph，透過 structural edges 保留表格布局，並以 semantic edges 表達跨欄位與跨工作表的邏輯關聯。
3. 提出 expert knowledge memory 與 reasoning experience memory 組成的 dual-level memory，並協調 navigational explorer、logical programmer 與 critical reflector 三種 agents 進行定位、程式執行及閉環驗證。

## 技術方法

SheetCompass 將每個工作簿中的多個 table 組成圖 G=(V,E)。節點採兩層階層：table nodes 與 column nodes；欄位節點由 header name 加上代表性原始資料樣本表示，避免建立密集的 cell-level 圖。Structural edges 由確定性解析規則建立，包括 table-to-column inclusion edges，以及依水平位置連接相鄰欄位的 adjacency edges。Semantic alignment 先以預訓練 transformer Φ 將欄位特徵映射為 h_i，再計算欄位間 cosine similarity；同時要求 LLM 評估 primary key、foreign key 等邏輯關係，將兩者依 β 加權，若分數超過信心閾值 α，便建立 semantic edge。記憶分為永久性的 expert knowledge memory，以及記錄當前圖搜尋、sandbox 錯誤與檢查不匹配的 reasoning experience memory；成功軌跡與高價值經驗可回存前者。Explorer 將指令拆成原子子任務，依 cosine threshold λ 選取 seed nodes，使用 BFS 建立相關子圖並取共享子圖以壓縮上下文。Programmer 在 Python interpreter 與 Excel engine sandbox 中，受圖節點約束生成並執行程式。Reflector 將指令轉成 checklist，檢查試算表 metadata state，若不符便回饋並觸發最多 τ 次修正。評估使用 SCB、SB、SheetRM；SCB 與 SheetRM 使用 exec@1、pass@1，SB 使用跨三個獨立測試案例的 soft restriction 與必須全部通過的 hard restriction。

## 關鍵結果

作者在 SCB、SB 與 SheetRM 上比較 Binder、VBA、OS-Copilot、SheetCopilot、SheetAgent 與 SheetCompass。論文報告的 GPT-4 與 GPT-5 結果如下；「/」表示該方法或指標未提供數值。

| Backbone | Method | SCB Exec@1 | SCB Pass@1 | SB Soft | SB Hard | SheetRM Exec@1 | SheetRM Pass@1 |
|---|---|---:|---:|---:|---:|---:|---:|
| GPT-4 | SheetAgent | 94.1 | 61.1 | 17.6 | 13.5 | 92.4 | 31.2 |
| GPT-4 | SheetCompass | 95.1 | 63.2 | 22.6 | 18.3 | 93.7 | 42.5 |
| GPT-5 | SheetAgent | 90.0 | 70.0 | 18.3 | 15.1 | 89.3 | 44.8 |
| GPT-5 | SheetCompass | **96.4** | **71.3** | **24.7** | **22.0** | **94.2** | **52.3** |

以 GPT-5 為 backbone，SheetCompass 相較 SheetAgent 在 SCB Pass@1、SB Soft、SB Hard 與 SheetRM Pass@1 的絕對提升分別為 1.3、6.4、6.9 與 7.5 個百分點。消融實驗顯示，移除 hierarchical graph 後，SCB Pass@1 由 71.3% 降至 56.4%，SheetRM Pass@1 由 52.3% 降至 41.4%，SB Hard 由 22.0% 降至 14.5%。移除 multi-agent 後 SCB Pass@1 為 59.1%，移除 dual-level memory 後為 60.4%。

## 對我們的啟發
- [ ] 對複雜試算表自動化而言，先建立表格與欄位層級的結構索引，再生成程式，可能比直接將整份工作簿序列化後提示 LLM 更穩定。
- [ ] 應將結構驗證與語義驗證分開：table-column topology 有助於定位資料，而跨欄位 semantic links 對跨表依賴與隱含公式尤其重要。
- [ ] 對長流程工具使用任務，可保留當前錯誤、執行狀態與成功軌跡，並由獨立 reflector 根據明確 checklist 驗證輸出，而非只依賴單一 agent 自我確認。

## 限制與未來工作

論文未報告各資料集的實例數、資料切分細節、統計顯著性、完整執行成本與延遲，也未提供不同 LLM backbone 的成本效益分析。semantic edge 依賴預訓練 transformer 與 LLM 評分，但其模型、提示、標註品質及錯誤案例分析未充分說明；此外，論文未量化 graph 建構錯誤或 reflector 造成的反覆修正失敗。
