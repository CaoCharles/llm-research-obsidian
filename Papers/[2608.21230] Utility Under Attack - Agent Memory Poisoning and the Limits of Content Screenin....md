# Utility Under Attack: Agent Memory Poisoning and the Limits of Content Screening and Provenance Ranking

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.21230)
- 📥 [PDF](https://arxiv.org/pdf/2608.21230v1)

## 摘要（中文翻譯）

持久記憶使錯誤資訊具有延續性：一旦錯誤陳述被儲存，未來符合語意的工作階段便可能取回它。我們以單次生成、文字平實、沒有指令、trigger 或 retriever 最佳化的錯誤陳述，衡量此失效模式的成本。在 LongMemEval corpus 中僅污染 1.2%，準確率便由 0.850 降至 0.300。四階段 write-time screening pipeline 對 indirect prompt injection 的 recall 達 0.832，且只標記 1.5% 含 trigger word 的 benign text，卻拒絕了 360 個 poisoned memories 中的 0 個。作者認為，這揭示 content-only screening 的邊界：區分錯誤與正確陳述通常需要超越文本本身的 external grounding。接著評估 provenance-weighted retrieval。系統預設權重與無防禦設定無統計差異（p=0.80）；較強權重只能透過排除 untrusted content 恢復效用。在 untrusted content 主要為 benign 的 mixed-provenance corpus 中，準確率由 0.3167 升至 0.7000；但當 answer-bearing evidence 本身來自 untrusted channel 時，evidence recall 降至 0，準確率降至 0.0417。在測得的 similarity regime 下，additive provenance term 沒有可用設定，因此作者主張改用 bounded occupancy constraints。

## 問題背景

論文研究持久型 agent memory 的 false-fact poisoning：攻擊者只需寫入平實錯誤陳述，便可能在後續相關 session 中持續污染檢索結果。現有 prompt-injection 防禦主要偵測指令、角色操弄或外洩構造，無法直接判定沒有可見惡意 payload 的陳述是否為假。另一方面，provenance-weighted ranking 雖能降低 untrusted memory 的優先級，卻可能無法壓制 query-shaped poison，或因過度懲罰而排除真正有用的 untrusted evidence。

## 解決方案

作者提出 utility-under-attack protocol，將既有 LongMemEval memory corpus 注入弱訊號 false assertions，並以 retained utility、poison context 占比及 poison 首位率評估記憶系統在受攻擊後仍保有多少價值。防禦框架分為 write path 的四階段 content screening，以及 read path 的 provenance-weighted ranking。實驗顯示前者對單純錯誤事實在結構上缺乏判別依據；後者的 shipped weight 太小而無效，提升後則形成近似 hard exclusion。作者因此提出將 provenance 從 additive penalty 改為 bounded occupancy constraint，在 context 中保留受控比例，而不是以 scalar weight 直接壓低所有 untrusted evidence；但該方案尚未實作或評估。

## 核心貢獻
1. 提出 utility-under-attack 評估協定：在既有 LongMemEval corpus 中注入 false-fact poison，並以 retained utility、retrieval diagnostics 與 paired significance testing 衡量記憶系統受損程度。
2. 以 360 筆實驗證明 write-time content screening 對沒有 instruction、trigger 或可見 payload 的 false-fact poisoning 結構性失明；即使 indirect prompt injection recall 為 0.832，仍拒絕 0/360 poisoned memories。
3. 透過 provenance-ranking 的 margin analysis 證明 shipped weight 無效，而 corrected weight 的效用來自排除 untrusted content；mixed-provenance 實驗揭示其可能造成對合法 untrusted evidence 的 denial-of-service。

## 技術方法

研究以 Aegis memory layer 為系統，分別測試 write path、clean retrieval 與 poisoning。Write path 將每筆內容依序通過四階段：輸入結構檢查、PII／credential 偵測、規則式 injection 偵測，以及對 untrusted、unknown、shared/global scope 或 Stage 3 flagged content 條件觸發的 LLM classifier；任一階段標記即拒絕或 flag。Screening benchmark 使用 direct injection、indirect injection、Dolly-15k、synthetic memory entries 與 NotInject 五個 corpus，對十種系統計算 precision、recall、F1、false positive rate、accuracy 與 latency，並進行 per-stage ablation。Memory benchmark 使用 LongMemEval_S 的 500 題與約 50 sessions／題，將每個 conversational round 作為 memory，在 top-k=15 取回後交給 reader，答案由官方 judge prompts 評分。Poisoning 實驗從 120 題產生 360 筆 false memories，約占 corpus 1.2%；每題三輪、重用問題關鍵語句、無 instruction 或 retrieval optimization，並標為 untrusted。比較 clean、無防禦、shipped provenance weights（wt=0.15、ws=0.60）及 corrected weights（wt=0.35、ws=0.45），使用 paired exact McNemar test，另測試 untrusted benign content 為主的 Corpus M 與 answer-bearing evidence 為 untrusted 的 Corpus N。

## 對我們的啟發
- [ ] 對持久記憶系統不能只測 attack success rate；應同時測 clean utility、utility retained、poison 在 context 中的占比、首位率與 evidence recall，否則可能把系統失效或過度防禦誤判為安全。
- [ ] 對純粹 false assertions，write-time scanner 若沒有 external grounding 通常無法僅由文本判定真偽；實務上應將來源、時間、更新衝突、可驗證證據與 abstention／revalidation 納入記憶生命週期，而非只依賴 injection detector。
- [ ] provenance additive penalty 必須先以 similarity margin 推導與校準；權重過小可能完全無效，過大則會把合法 untrusted evidence 一併排除。若採 bounded occupancy constraint，仍需搭配可靠且不可被提升或 laundering 的 origin binding，並以混合來源資料驗證。

## 限制與未來工作

研究只在單一 Aegis 系統、單一 embedding／retriever／reader 與 LongMemEval conversational personal-assistant domain 測試；poison 僅取 120 題，絕對準確率具有抽樣誤差。Corpus M 偏向移除 distractors，Corpus N 則是極端設定。作者提出的 bounded occupancy constraint 尚未實作或評估，也未測試 adaptive attack、其他 embedding similarity 分布、錯誤或可操弄的 trust label，以及 code、clinical、operational memory。
