# SENTRY: Deterministic, Intelligent Risk Assessment for IT Change Management

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.21203)
- 📥 [PDF](https://arxiv.org/pdf/2608.21203v1)

## 摘要（中文翻譯）

大型金融機構的 Technology change management 需要準確、一致且可稽核的風險評估，但許多機構仍依賴由申請人自填的問卷。此類問卷具有主觀性、容易被操弄，且難以區分一般變更與後續引發重大事故的變更。本文提出 SENTRY，一個以 deterministic machine learning pipeline 取代問卷評分的風險評估平台。系統採用 gradient-boosted decision trees（XGBoost）與 hybrid retrieval-augmented generation（RAG），整合結構化營運 metadata、application dependency graphs、歷史 incident records，以及對歷史變更請求進行 semantic 與 lexical search 的結果。Retrieval 階段將非結構化變更文字中的風險訊號壓縮為單一 scalar feature，再交由模型推論，以維持 deterministic 特性，並透過 SHAP values 提供逐筆預測解釋。在企業規模變更資料上，SENTRY 的 ROC AUC 為 0.87、整體 accuracy 為 85%，辨識高風險變更的比例約為既有流程的 3.25 倍。

## 問題背景

論文要解決大型金融機構中 IT change risk assessment 不準確、不一致且難以稽核的問題。既有 self-reported questionnaire 依賴申請人提供資訊，具有主觀性，容易透過理解評分規則來降低表面風險，也未充分納入 downstream dependencies、incident history 與歷史相似變更等上下文，因此許多後續造成重大事故的變更仍被評為低風險。

## 解決方案

作者提出 SENTRY，將 28 個結構化特徵與 hybrid RAG 產生的單一風險特徵輸入 XGBoost classifier。系統從歷史 change requests 的描述、implementation plans、test plans 與 backout plans 產生 embeddings，並結合 lexical search 進行 hybrid retrieval；再依相似變更的 incident severity 計算 deterministic risk score。核心創新是把非結構化文字的語意訊號壓縮成可解釋的 scalar feature，而非直接使用 embeddings 或讓 LLM 產生評分，因而兼顧 deterministic、auditability、SHAP explainability 與預測效能。

## 核心貢獻
1. 提出面向 IT change management 的 SENTRY 平台，以 XGBoost 取代主觀的 questionnaire-based scoring，並輸出三層風險分類與逐筆 SHAP-style feature contributions。
2. 設計 hybrid RAG 管線，結合 dense semantic search、lexical search 與 Reciprocal Rank Fusion，將歷史相似變更及其 incident outcomes 轉換為單一 deterministic hybrid_search_score。
3. 在企業變更資料的 held-out test set 上驗證方法，報告 ROC AUC 0.87、85% overall accuracy，以及相較問卷流程由 20% 提升至 63% 的重大事故變更辨識率。

## 技術方法

SENTRY 由前端、backend API、XGBoost 模型，以及 ITSM 結構化資料庫與 vector database 組成。模型使用 28 個已正規化至 [0,1] 且設有上限的特徵，涵蓋 application context、blast radius、incident history、相似變更與 change type。每筆請求將 short description、description、implementation plan、test plan 和 backout plan 串接後產生 dense embedding；同時以相同文字建立 lexical index。推論時分別取得 cosine similarity 的 top-k 鄰居與 full-text ranking 結果，預設 k=100，再以 Reciprocal Rank Fusion 合併，公式為 rrf_score=α/(60+semantic_rank)+β/(60+lexical_rank)，其中 α=0.4、β=0.6。僅對具有 incident 的鄰居依 incident priority 加權求和，形成 hybrid_search_score。訓練資料包含約 183 筆造成重大事故的正例；負例取自 minor incidents 與無事故變更，維持約 80/20 比例。資料採 stratified split，並以時間過濾避免 retrieval data leakage。Optuna 執行 60 組超參數搜尋，每組使用 5-fold stratified cross-validation，目標為正類 F1 並懲罰 precision-recall 差距。模型以 P≥0.90 判定 High，另以訓練期間選出的 threshold 區分 Medium 與 Low；評估採 ROC AUC、accuracy、precision、recall、F1 與 confusion matrix。

## 對我們的啟發
- [ ] 在受監管環境中，可將 RAG 的 retrieval 能力限制為可重現的特徵工程步驟，避免直接依賴非 deterministic 的 LLM 評分。
- [ ] 對非結構化文字不一定要把高維 embeddings 直接輸入 tabular model；先以 incident-aware retrieval 壓縮為單一風險特徵，有助於保留結構化模型的可解釋性。
- [ ] 高風險偵測應同時檢視 recall 與 precision；論文中的 63% recall 與 0.55 precision 顯示，提升事故捕捉率會帶來額外人工審查負擔，因此模型較適合作為 human decision-support，而非自動核准工具。

## 限制與未來工作

論文指出正例僅約 183 筆，限制模型學習高風險細分類別的能力；模型使用固定歷史 snapshot，尚未實作自動 retraining，vector database 也需手動更新。隨技術環境變化，效能可能衰退；此外，特徵定義、正規化範圍與 thresholds 係針對單一金融機構校準，跨組織部署需重新抽取、校準與訓練。
