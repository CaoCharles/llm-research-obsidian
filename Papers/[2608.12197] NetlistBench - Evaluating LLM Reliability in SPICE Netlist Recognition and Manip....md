# NetlistBench: Evaluating LLM Reliability in SPICE Netlist Recognition and Manipulation

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.12197)
- 📥 [PDF](https://arxiv.org/pdf/2608.12197v1)

## 摘要（中文翻譯）

大型語言模型（LLM）日益被用於電路設計流程，但其在面向 simulator 的 SPICE netlist 識別與操作上的可靠性仍缺乏充分理解，且通常未與高階設計推理分開評估。Netlist 雖是文字，卻透過拓撲與參數編碼結構化電路物件。本文提出 NetlistBench，一個具結構驗證能力的 SPICE netlist 識別與操作 benchmark，包含 2,342 個案例、24 個任務家族，涵蓋參數與 connectivity 識別及編輯、hierarchical 操作、equivalence judgment，以及長程複合編輯。模型輸出由 deterministic、structure-aware oracle 評估。六個 non-thinking LLM 的表現會隨操作層級結構複雜度顯著變化：簡單 local edit 可達 96%–100%，device addition 降至 41%–83%，equivalence judgment 為 49%–90%。啟用 reasoning 能大幅改善較弱模型，但無法消除 structure-preservation failure；隨 edit horizon 增加，表現仍急遽下降。研究指出，netlist reliability 是可信賴 LLM 電路設計自動化的獨立瓶頸。

## 問題背景

現有 LLM 電路評測多聚焦於 syntactic validity、simulation success、specification improvement 或 end-to-end design outcome，難以分辨高階電路推理與低階 netlist corruption。一般 code benchmark 也無法表達 SPICE 的 positional terminal semantics、shared-node connectivity、node identity 與 ordered subcircuit interface。因此，模型是否能正確識別並局部、結構保持地修改 simulator-facing SPICE netlist，仍缺乏直接且可重現的量化評估。

## 解決方案

作者提出 NetlistBench，將 SPICE netlist 視為具 devices、terminals、nodes、parameters、directives 與 hierarchy 的結構化 circuit artifact，分別測試 recognition 與 manipulation。其核心創新是以 deterministic template pipeline 從 flat 與 hierarchical source corpus 產生可驗證案例，並以 canonical IR 和 structure-aware oracle 取代 raw text matching 或單純 simulation success。oracle 要求輸出在 device 集合、terminal-node binding、參數、名稱 locality、directives 及 subcircuit interface 上精確符合 target；另以 VF2 graph-isomorphism 審核 equivalence labels。此設計能系統性比較不同 operation complexity、hierarchy 與 edit horizon 的可靠性。

## 核心貢獻
1. 將 SPICE netlist reliability 定義為 representation-level evaluation 問題，區分結構識別與結構保持的轉換能力，避免與高階電路設計推理、simulation 或 optimization 結果混淆。
2. 提出 NetlistBench，包含 2,342 個案例、24 個 task families，涵蓋 recognition、manipulation、hierarchical operations、equivalence judgment 與長程 compound editing。
3. 建立以 canonical circuit representation 為核心的 deterministic、structure-aware evaluation oracle，使輸出可依 device、terminal binding、node、parameter、directive 與 hierarchy 進行結構驗證，而非只比對文字或 simulation 是否成功。

## 技術方法

NetlistBench 從兩類來源建立資料：AnalogGenie 的 flat CMOS analog netlist，以及 ALIGN 的 hierarchical analog netlist。作者先進行 normalization，再透過 deterministic、template-driven pipeline 套用 task-specific transformation rules、syntax perturbations 與 prompt templates，形成 source netlist、instruction、target 的 self-contained triplet。資料在納入前會驗證 manipulation target 是否只執行指定結構變更，並檢查 recognition 與 equivalence target 是否符合 canonical intermediate representation（IR）。Benchmark 包含 8 個 recognition families 與 16 個 manipulation families，後者包括 connectivity edit、device addition/removal/replacement、parameter edit、rename propagation、3 至 15 步 compound edit，以及 subcircuit 操作。模型以 single-shot、deterministic decoding 呼叫官方 API；六個主要模型關閉 reasoning，另以 DeepSeek-V4-Flash 的 native thinking 作為 reasoning reference。輸出會被 parser 轉為 canonical IR，逐項比對 named devices、device kind、ordered terminal nodes、parameters、directives、subcircuit port interface、internal devices 與 hierarchy；允許有限的 semantics-preserving normalization，例如數值格式正規化及 R/C/L 對稱端點無序比較。Recognition 與 manipulation 皆以 binary pass/fail 計分；equivalence judgment 則比較模型輸出的 binary verdict。等價案例的 ground truth 另以 device–net graph 與 VF2 graph-isomorphism 檢查，確認正負配對標籤，但不直接用於模型 scoring。作者報告 pass rate 與 Wilson 95% confidence interval，並在 n=718 的 paired stratified subset 比較 SPICE、PySpice、direct、native thinking 與 CoT。

## 關鍵結果

主要結果如下；整體與 subtotal 為 case-weighted pass rate，DS+R 為啟用 native reasoning 的 DeepSeek-V4-Flash，且不納入 non-thinking 模型比較。

|---|---|
| Benchmark 規模 | 2,342 cases、24 task families；recognition 800、manipulation 1,542 |
| Non-thinking overall | Claude Sonnet 4.6：82%；GPT-4.1：71%；Gemini 2.5 Flash：64%；Qwen3.6-Flash：47%；Qwen3-30B-A3B：41%；DeepSeek-V4-Flash：55% |
| Non-thinking recognition subtotal | Claude：98%；GPT-4.1：87%；Gemini：74%；Qwen3.6-Flash：62%；Qwen3-30B-A3B：55%；DeepSeek：74% |

## 對我們的啟發
- [ ] 實務上不應將 LLM 視為可未經驗證直接修改 simulator-facing netlist 的 editor；每次編輯後應執行結構驗證，檢查 device 集合、terminal-node binding、參數與 hierarchy 是否出現非預期變化。
- [ ] 長程複合操作的可靠性不能由單一步驟表現推定。對多個相依修改，較適合採用分解式流程，逐步套用、驗證並保留中間狀態，以降低錯誤累積。
- [ ] 若任務涉及 connectivity、terminal role、port order 或 equivalence，應優先提供能顯式表達拓撲的結構化表示；論文的 paired subset 顯示 reasoning 通常比 SPICE 改寫為 PySpice 帶來更一致的整體改善，但兩者都未完全解決結構保持問題。

## 限制與未來工作

研究僅涵蓋 bounded、circuit-block-level 的 AnalogGenie 與 ALIGN 類比 CMOS netlist，未評估 industrial-scale post-layout deck、長上下文處理或數百萬 parasitic statements。亦未完整涵蓋 symbolic .param、複雜 .model、behavioral/controlled sources、include hierarchy、PDK-specific syntax，以及 RF、power、digital 或 mixed-signal netlist。模板化指令與每個 model-case 僅測試一次，也限制了對真實語言變異與輸出分布的涵蓋。
