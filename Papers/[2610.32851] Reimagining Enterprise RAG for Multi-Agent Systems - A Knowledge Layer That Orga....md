# Reimagining Enterprise RAG for Multi-Agent Systems: A Knowledge Layer That Organizes Before It Retrieves

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2610.32851)
- 📥 [PDF](https://arxiv.org/pdf/2610.32851v1)

## 摘要（中文翻譯）

企業正將 agentic AI 部署至 software development lifecycle；這些 agent 需要的是系統實際運作的 behavioral logic，而非面向利害關係人的文件。作者以七-agent reverse-engineering pipeline 處理 241 個 repositories、18 個 services，產生描述 scope、journeys、business rules 與 acceptance criteria 的數千項 artifacts。然而，recovery 並不代表易於使用：offer、eligibility、activation 等詞彙跨服務重複出現，語意相近但操作定義不同，使 flat vector retrieval 可能以高相似度取回錯誤服務的規則。作者因此將 ontology 放在 artifact layer，利用 artifact 的 producer、component、service、domain、type 與 provenance，在讀取內容前先完成消歧。提出的 knowledge layer 包含 self-describing catalog、sparse metadata registry 與 artifact-level navigation hypergraph；查詢先解析為 artifact identifiers，再限制 vector search 的候選集合，使錯誤規則直接排除而非僅被重新排序。系統在一週內建置，支援 SDLC agents 與人工使用者，並用於 100 多個 production defects 的 root-cause analysis，以及將 35 起 release regression failures 歸因至特定規則與服務。

## 問題背景

論文處理企業多服務、多代理 SDLC 系統中的知識組織與精準檢索問題。由 reverse-engineering 產生的 artifacts 含有大量跨服務重複詞彙與近似規則；flat vector retrieval 可能以高相似度取回錯誤服務的 structural twin，且沒有明顯錯誤訊號。傳統 content-level ontology 雖可消歧，卻需要高昂的跨實體對齊與持續維護成本，難以配合 release cadence。

## 解決方案

作者提出 KB Cataloging Framework，將 ontology 從內容中的 entities 移至具 provenance 的 artifacts。系統以 artifact 命名慣例、catalog、sparse metadata registry 與 artifact-level navigation hypergraph，依 service、domain、feature、type 和 workflow 組織知識。查詢先透過 intent classification、alias index 與 hypergraph 導航，解析出一組 artifact identifiers，再在該集合內執行 hybrid dense/BM25 retrieval。其核心創新是「organize before retrieve」：錯誤服務的近似規則不進入 similarity computation，而非在排序後才被壓低；若 confidence gate 判定範圍不足，才退回 full-corpus search。

## 核心貢獻
1. 提出 artifact-level ontology 設計原則，利用 machine-generated artifacts 的 provenance 在內容檢索前完成服務與情境消歧。
2. 提出由 self-describing catalog、sparse metadata registry、artifact-level navigation hypergraph、identifier-constrained retrieval、confidence gate 與 runtime context graphs 組成的 KB Cataloging Framework。
3. 提供 production deployment evidence：系統支援超過 100 個 production defects 的分析與解決，並將 35 起 release regression failures 歸因至特定規則與服務；同時支援多種 SDLC agents、開發者、品質工程師與分析師。

## 技術方法

上游七-agent reverse-engineering pipeline 將 241 個 repositories、18 個 services 的 source code、configuration 與 tests 轉為具來源引用的 structured artifacts。知識層在 ingestion 時執行四步：依 {service}_{domain}_{feature}_{artifact_type}_v{version} 命名；建立 immutable artifact identifier 與 registry record；將 artifact 放入對應 service、domain、feature 的 hypergraph node；再寫入與圖結構一致的 folder hierarchy。registry 的建立欄位包含 producer、run、service、domain、feature、repository、version、lineage 與 confidence；使用後再累積 task types、query intents、co-retrieved artifacts、usefulness、access history 與 supersession 資訊。hypergraph 以 nodes 表示服務內 feature 的 artifact 集合，並以 hyperedges 表示跨多服務的 shared workflow；alias index 將查詢詞彙映射至候選 nodes。查詢流程為 intent classification、hypergraph navigation、candidate scoping、identifier-constrained hybrid dense/BM25 search，以及由 LLM 執行的 confidence gate。每次回答另產生 runtime context graph，記錄 intent、nodes、artifacts、chunks 與 provenance。部署評估涵蓋建置與擴充成本、使用者接受度及 retrieval accuracy；論文提出 widening rate 與 ambiguity-weighted query adjudication 兩項評估，但 accuracy 測量在撰稿時仍進行中。

## 對我們的啟發
- [ ] 若知識由具備穩定 provenance 的 agent 產生，可優先在 artifact、service、domain 與 workflow 層建立可導航結構，避免一開始就承擔完整 entity-level ontology 的對齊成本。
- [ ] 對跨服務詞彙碰撞，應將關鍵消歧條件轉為候選集合的硬性限制；讓錯誤證據不參與相似度計算，通常比單純依賴 reranking 更容易稽核。
- [ ] 在 agent 應用中保留 runtime context graph 與來源引用，能讓開發者沿著規則、endpoint、repository 和 source reference 驗證答案；同時應設計 confidence gate 與 widening path，避免錯誤分類造成靜默失敗。

## 限制與未來工作

方法依賴 machine-generated corpus 與完整 provenance，對 heterogeneous human-authored material 不宣稱具一般性。placement quality 未被獨立測量，錯置 artifact 會影響所有經該節點進入的查詢；系統也受上游 extraction coverage 限制。部署僅來自單一 estate，且由熟悉服務的實務者評判，可能有 optimism bias。未來將加入 composition、boundary、curation agents，並在 code change 後重新 ingest。
