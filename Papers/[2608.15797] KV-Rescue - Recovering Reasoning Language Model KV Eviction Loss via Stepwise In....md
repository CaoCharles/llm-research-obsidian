# KV-Rescue: Recovering Reasoning Language Model KV Eviction Loss via Stepwise Interleaving

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.15797)
- 📥 [PDF](https://arxiv.org/pdf/2608.15797v1)

## 摘要（中文翻譯）

KV-cache eviction 能限制長推理軌跡的記憶體成本，但由於模型只能從部分歷史解碼，因此本質上具有資訊損失。在激進的 eviction budget 下，除了準確率下降，還可能發生 runaway degeneration：模型持續生成不連貫或重複 token，直到達到長度上限。作者指出，許多損失源自缺失上下文造成的 information gap，而非模型容量不足造成的 capability gap。被 eviction 的 7B 模型與保留完整上下文的 1.5B 模型會犯互補錯誤，兩者答案的 oracle 選擇可恢復相對 full-KV 7B 模型準確率差距的 79%。因此作者提出免訓練的 KV-Rescue，利用輕量 full-context helper，逐步交錯兩個模型的推理步驟，並以 entropy 與 compressibility 線上偵測並提前終止不連貫或重複的 base candidates。在五個數學 benchmark、Qwen2.5-Math 7B 與 72B 上，B=64 時平均恢復 eviction 所造成準確率損失的 87%，並使 base-model token generation 平均減少 43%。

## 問題背景

長推理會使 KV cache 成為主要記憶體瓶頸，因此 KV eviction 以固定 budget 保留部分歷史；但被移除的 context 不能在後續解碼中存取，造成準確率下降。budget 足夠小時，模型還會進入不連貫生成或 repetition loop，持續輸出至長度上限。現有 Best-of-N 只從同一個有缺失上下文的 cache 狀態採樣，雖可增加候選，卻無法恢復被 eviction 的資訊。

## 解決方案

作者提出 KV-Rescue，一個 training-free 的雙模型推理框架。它以大型但 KV-evicted 的 base model 保留主要推理能力，以小型 full-context helper 提供未被刪除的歷史資訊；兩者在每個 reasoning step 產生候選，透過 process reward model 選出最高分步驟，交錯形成共享 trajectory。核心創新有二：將不同 context views 的模型互補性從答案層級延伸至 stepwise reasoning，以及在 PRM 選擇前使用 entropy 與 gzip ratio 線上淘汰 base 的失控候選，避免無效長生成。

## 核心貢獻
1. 將 KV eviction 導致的推理損失區分為由歷史上下文缺失造成的 information gap，以及由模型能力造成的 capability gap；實驗顯示被 eviction 的 7B 模型與 full-context 1.5B 模型具有互補錯誤。
2. 提出免訓練的 KV-Rescue stepwise interleaving 框架，讓被 eviction 的大型 base model 與 full-context 輕量 helper 共同生成並交錯提交推理步驟，由 PRM 選擇最佳候選。
3. 提出僅使用解碼期間既有統計量的線上 degeneration detector，以 token entropy 偵測 incoherent generation、以 gzip ratio 偵測 repetition loop，降低失控生成與解碼浪費。

## 技術方法

KV-Rescue 使用 Qwen2.5-Math-7B-Instruct 或 72B-Instruct 作為採用 R-KV eviction 的 base model，使用 full-context Qwen2.5-Math-1.5B-Instruct 作為 helper，並以 Qwen2.5-Math-PRM-7B 對候選推理步驟評分。推理答案被切分為以「\n\n」分隔的 steps；每一步從 base 的 evicted cache 與 helper 的完整 context 各採樣 N 個 candidates，將最多 2N 個候選交給 PRM，選擇分數最高者加入共享 trajectory。若選中 base step，保留其 cache fork；若選中 helper step，base 重新編碼該步並套用 eviction，helper 則持續接收完整共享歷史。對 base candidates 進行線上早停：以最近 token 的 moving-average predictive entropy 超過 7 nats 偵測 incoherent generation；在寬度 800 的文字滑動視窗中，以 gzip ratio 低於 0.18 偵測 repetition loop。被中止的候選不參與 PRM 選擇，而 helper candidates 保證候選池不為空。實驗採 bf16、context cap 4096、temperature 0.8、top-p 0.95、top-k 20，評估 MATH500、AIME2024、AMC2023、GSM8K、OlympiadBench 的 pass@1，並比較 B=64、128、256、512、N=1 或 8，以及 full-KV 與 eviction-only Best-of-N。另以 SnapKV 重複 7B 實驗，並在 A100 SXM 上分析 KV memory、token generation、throughput 與 wall-clock cost。

## 對我們的啟發
- [ ] 若 KV 壓縮造成的主要問題是上下文不可見，而非模型推理能力不足，可透過較小但保留完整上下文的模型補足資訊；實務上可將此策略視為 KV compression 的外掛模組。
- [ ] 單一模型上的 Best-of-N 只能增加同一個缺失上下文狀態下的採樣，無法恢復已被 eviction 的資訊；引入具有不同上下文視圖的候選來源，可能比單純增加採樣數更有效。
- [ ] 部署時應同時監控生成品質與解碼成本。entropy 與 gzip compressibility 可作為低額外成本的早期停止訊號，尤其適合避免 repetition loop 或 incoherent output 導致的長度上限浪費。

## 限制與未來工作

研究主要集中於 Qwen2.5-Math 系列與五個數學 benchmark，且多數資料集只使用單次 run；對一般語言、長上下文 agent 任務及其他模型家族的泛化未被驗證。方法依賴 PRM、額外 helper 與手動 entropy/gzip thresholds，PRM 誤判、helper 成本及閾值跨任務穩定性仍需研究。論文也未評估較漸進的過度冗長推理失敗。
