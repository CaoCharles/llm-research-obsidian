# RedEvoAgent: Automatic Red-Teaming Agent with Experience-Driven Skill Evolution

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.27439)
- 📥 [PDF](https://arxiv.org/pdf/2608.27439v1)

## 摘要（中文翻譯）

LLM-based agents 日益部署於產品級 execution harness 中，jailbreak 可能誘發有害工具使用及持久性狀態變更，其風險高於單純生成不安全文字。現有自動化 red-teaming 方法多依賴固定攻擊；近期 agentic attacker 雖能協調多種 jailbreak tools，並透過 trajectory retrieval 提升能力，但可能因 retrieval bias 重用誤導性經驗，且難以判定各工具對成功的貢獻。完整 trajectory 也會增加 context overhead 並降低可解釋性。本文提出 RedEvoAgent，一種 black-box red-teaming agent，將跨案例攻擊 trajectory 濃縮為精簡、可讀的人類攻擊 skill。該 skill 透過 tool-effectiveness profiling 與 Deciding-Tool Attribution 自適應演化，並以 validation ratchet 僅保留能提升 validation performance 的更新。在多個 benchmark、target model 與 target execution harness 上，RedEvoAgent 優於 fixed 與 agentic baselines，提升 tool efficiency，且能跨 attacker model 與 target execution harness transfer。

## 問題背景

論文處理產品級 LLM agent 的自動化 black-box red-teaming 問題：jailbreak 成功可能導致有害工具呼叫與持久性系統變更。固定式攻擊只能探索有限攻擊空間；trajectory-based agentic 方法則可能受 semantic retrieval bias、工具 credit 不清、低效冗長 context 與低可解釋性影響，造成誤導經驗重用、策略不穩定及效能下降。

## 解決方案

作者提出 RedEvoAgent，將多案例攻擊經驗蒸餾為單一、精簡且人類可讀的 attack skill，供 attacker agent 在 ReAct 流程中選擇 jailbreak tools 與安排攻擊順序。核心創新包括：先以 training split 個別測量各工具，建立 tool-effectiveness profile；再以 Deciding-Tool Attribution 將成功歸因於成功 QUERYTARGET 前立即使用的工具，降低共現偏誤；最後透過 validation ratchet，只有在獨立 validation split 上嚴格優於現有 skill 的候選更新才會被接受，否則保留原 skill 並記錄拒絕資訊。

## 核心貢獻
1. 提出 RedEvoAgent，將跨案例 attack trajectories 蒸餾為可讀、可重用且可演化的自然語言 attack skill，替代推論時直接檢索完整 trajectories。
2. 提出 tool-effectiveness profile 與 Deciding-Tool Attribution，分別提供隔離工具效能訊號及較清楚的成功工具歸因，以降低工具共現與 attacker 偏好造成的策略塌縮。
3. 提出 incumbent-relative validation ratchet：僅接受在獨立 validation split 上嚴格優於目前 skill 的完整更新，並以多 benchmark、target model、harness 及 transfer 實驗驗證效能與工具效率。

## 技術方法

目標 agent 定義為黑箱組合 M_tar=(m_tar,h_tar)，包含 target model 與 execution harness；attacker agent 為 M_att(s)，由 attacker model、ReAct attack loop、toolbox 與 attack skill 組成。工具箱包含 GCG、AutoDAN、AmpleGCG、Template、FlipAttack、RolePlay 及 Prompt Substitution。每一案例中，attacker agent 在最多 B=20 個 loop steps 內交替執行 QUERYTARGET 或工具呼叫；工具會改寫目前 prompt，QUERYTARGET 則提交 prompt 並取得 target response。系統先在 D_tr 上隔離評估每個工具，計算其平均 case score 作為 efficacy profile；接著以目前 skill 收集完整 training trajectories，記錄工具呼叫、候選 prompt、target response 與分數，並標註成功 trajectory 的 deciding tool。Skill evolution 將成功與失敗 trajectory 分成 minibatch，由 distiller agent 提出編輯，再合併為完整候選 skill；候選受 bounded-change constraint，並利用 rejection context 避免重複無效更新。候選在獨立 D_va 上評估，只有分數嚴格高於 incumbent 才接受，接受後重新收集 training experience。資料採 train/validation/test 分割：ASB 為 80/40/280，AgentHarm 為 40/20/148。ASB 報告 ASR 與 refusal rate，AgentHarm 報告 HarmScore 與 refusal rate，另報告每案例平均 attack-tool calls；D_te 僅用於最終評估。

## 關鍵結果

主要結果如下；ASB 的數值為 ASR/RR（%），AgentHarm 的數值為 HarmScore/RR（%）。

| Benchmark / Harness / Target model | RedCodeAgent | MAJIC | RedEvoAgent |
|---|---:|---:|---:|
| ASB / Claude Code / MiniMax-M2.5 | 76.4/21.4 | 74.2/15.1 | **93.2/6.1** |
| ASB / Claude Code / DeepSeek-V4-Flash | 90.7/8.6 | 94.6/2.5 | **99.3/0.0** |
| ASB / Codex / MiniMax-M2.5 | 75.3/23.3 | 71.0/22.6 | **92.8/6.9** |
| AgentHarm / Claude Code / DeepSeek-V4-Flash | 37.5/67.6 | 45.5/32.4 | **74.3/15.9** |
| AgentHarm / Codex / DeepSeek-V4-Flash | 69.4/32.4 | 71.5/25.0 | **74.4/18.0** |

技能消融中，在 ASB、MiniMax-M2.5、Claude Code 上，完整系統 ASR 為 93.2%；移除 Tool-Effectiveness Profile、Trajectory Collection、Deciding-Tool Attribution 後分別降至 76.9%、85.0%、87.5%。Table 2 顯示完整 RedEvoAgent 在所有列出的設定均取得最高攻擊效能，且工具呼叫數最低；例如 ASB/Claude Code/MiniMax-M2.5 為 93.2 ASR、每案例 1.8 次工具呼叫。零樣本 transfer 中，從 Claude Code 移植至 Codex 的 skill 將 ASR 從 No Skill 的 80.8% 提升至 90.5%；移植至 Qwen3-8B 與 Qwen3-4B attacker model 時，分別由 89.7% 提升至 95.3%、由 83.3% 提升至 90.6%。不過 AgentHarm/MiniMax-M2.5/Claude Code 的 R4 更新使 validation HarmScore 由 18.5 升至 28.1，test HarmScore 卻相較 R2 的 28.8 降至 20.8，顯示 validation ratchet 仍可能過度適應 validation split。

## 對我們的啟發
- [ ] 對 agent 安全評測而言，應將成功率與工具成本同時納入；論文結果顯示，具方向性的 skill 不僅提升攻擊效能，也可減少平均 attack-tool calls。
- [ ] 經驗記憶不宜直接依賴 trajectory 相似度；可先以隔離工具測試建立效能先驗，再將 trajectory 用於學習工具排序與條件式切換策略。
- [ ] skill 更新應以獨立 validation set 作為持續整合門檻，並保留被拒候選與分數；但論文的 R4 例外顯示，validation split 的多樣性對避免過度適應仍很重要。

## 限制與未來工作

論文未提供更廣泛模型、harness 或工具箱之外的驗證，也未報告統計顯著性、重複試驗變異及完整成本分析。方法效果依賴 toolbox 的強度與多樣性；此外，AgentHarm/MiniMax-M2.5 案例顯示 validation ratchet 可能過度適應 validation split，且 deciding-tool 的單一步驟歸因未必涵蓋多工具協同效果。
