# RedEvoAgent: Automatic Red-Teaming Agent with Experience-Driven Skill Evolution

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.27439)
- 📥 [PDF](https://arxiv.org/pdf/2608.27439v1)

## 摘要（中文翻譯）

基於 LLM 的 agents 日益部署於產品級 execution harness 中；jailbreak 不僅可能產生不安全文字，還可能觸發有害的 tool use 與持久性狀態變更，因此風險更高。既有 automatic red-teaming 方法多依賴固定攻擊；近期 agentic attacker 雖能協調多種 jailbreak tools，並以 trajectory retrieval 強化攻擊，卻可能因 retrieval bias 與工具貢獻不明而重用誤導經驗，且完整 trajectory 會增加 context 成本並降低可解釋性。作者提出 RedEvoAgent，一種 black-box red-teaming agent，將跨案例攻擊 trajectory 蒸餾為精簡、可讀的人類攻擊 skill。該 skill 透過 tool-effectiveness profiling 與 Deciding-Tool Attribution 自適應演化，並以 validation ratchet 僅保留能提升 validation performance 的更新。多個 benchmark、target model 與 execution harness 的實驗顯示，RedEvoAgent 優於 fixed 與 agentic baselines，提升工具效率，且能跨 attacker model 與 target harness transfer。

## 問題背景

論文處理產品級 LLM agent 的自動化 black-box red-teaming 問題：jailbreak 成功可能導致工具執行與持久狀態改變。固定式攻擊只探索有限攻擊空間；trajectory-based agentic 方法雖可利用歷史經驗，卻受到語義檢索偏差、工具 credit assignment 不清、完整軌跡 context overhead 高及可解釋性低等限制，可能重用無關經驗並造成策略退化。

## 解決方案

作者提出 RedEvoAgent，將多案例攻擊經驗轉換成單一、精簡且人類可讀的 Markdown attack skill，而非在推論時檢索完整 trajectories。框架先以 training split 分別測量各 jailbreak tool，建立 tool-effectiveness profile；再透過 Deciding-Tool Attribution 將成功案例歸因於成功 query 前直接使用的工具，協助蒸餾工具優先級與編排策略。每次 skill rewrite 都形成 candidate，只有在獨立 validation split 上嚴格優於目前最佳 skill 時，才由 validation ratchet 接受，藉此抑制錯誤更新與自我強化的工具選擇偏差。

## 核心貢獻
1. 提出 RedEvoAgent，將跨案例 red-teaming trajectories 蒸餾為可讀、可重用且可演化的單一 attack skill。
2. 提出 Tool-Effectiveness Profile 與 Deciding-Tool Attribution，分別提供獨立工具效能訊號及較清楚的成功工具歸因，降低由工具共現造成的策略偏差。
3. 提出 incumbent-relative validation ratchet，僅接受在獨立 validation split 上嚴格優於目前 skill 的候選更新，並以多 benchmark、target model、execution harness 實驗驗證攻擊效能、工具效率與 transferability。

## 技術方法

目標 agent 定義為 target model 與 execution harness 的組合；attacker agent 採 ReAct 迴圈，使用 GPT-4o mini，工具箱包含 GCG、AutoDAN、AmpleGCG、Template、FlipAttack、RolePlay 與 Prompt Substitution。每一回合可執行 QUERYTARGET，或呼叫工具改寫目前 prompt；每案例最多 B=20 steps，成功或耗盡預算後產生 trajectory 與 benchmark-native score。資料分為 training、validation、test：training 用於工具獨立評估與 trajectory collection，validation 僅用於候選 skill 選擇，test 僅作最終評估。工具效能以 training split 平均 score 計算；成功 trajectory 則由 Deciding-Tool Attribution 標記成功 query 前的直接工具。Skill distiller 分批分析成功與失敗軌跡，結合工具效能、目前 skill 與 rejection context，提出受 bounded-change 限制的完整候選文件。候選在 validation 上測試，只有嚴格提升目前分數才接受，否則保留舊 skill 並記錄候選。實驗使用 ASB（400 cases，80/40/280 split）與 AgentHarm（208 cases，40/20/148 split），涵蓋三個 target models 及 Claude Code、Codex harness；指標為 ASB 的 ASR、RR，AgentHarm 的 HarmScore、RR，以及平均 attack-tool calls。

## 關鍵結果

主要結果如下；ASB 報告 ASR，AgentHarm 報告 HarmScore，數值均為百分比。\n\n| Benchmark / Harness / Target | 強基線 | RedEvoAgent | 工具呼叫（RedEvoAgent） |\n|---|---:|---:|---:|\n| ASB / Claude Code / MiniMax-M2.5 | FlipAttack 91.8 | **93.2** | 1.8（skill ablation） |\n| ASB / Claude Code / DeepSeek-V4-Flash | MAJIC 94.6 | **99.3** | 0.9（skill ablation） |\n| ASB / Codex / MiniMax-M2.5 | FlipAttack 81.1 | **92.8** | 1.8（skill ablation） |\n| AgentHarm / Claude Code / DeepSeek-V4-Flash | FlipAttack 67.9 | **74.3** | 2.2（skill ablation） |\n| AgentHarm / Codex / DeepSeek-V4-Flash | MAJIC 71.5 | **74.4** | 2.6（skill ablation） |\n\n在 ASB、MiniMax-M2.5、Claude Code 的 component ablation 中，完整系統 ASR 為 93.2%；移除 Tool-Effectiveness Profile、Trajectory Collection、Deciding-Tool Attribution 後，分別降至 76.9%、85.0%、87.5%。Skill ablation 顯示 RedEvoAgent 在所有列出的設定中均優於 No Skill 與 Human Skill，且工具呼叫較少。零樣本 transfer 中，來源 skill 使 Qwen3-8B ASR 由 89.7% 升至 95.3%、Qwen3-4B 由 83.3% 升至 90.6%；換至 Codex harness 則由 80.8% 升至 90.5%。但 AgentHarm/MiniMax-M2.5/Claude Code 的第 4 輪更新雖提升 validation HarmScore，test HarmScore 由第 2 輪的 28.8% 降至 20.8%。

## 對我們的啟發
- [ ] 對 agent 安全評測而言，將完整執行軌跡壓縮為高階策略文件，可在保留工具編排資訊的同時降低推論 context 與提升人工審計可讀性；部署時可將 skill 視為可檢查的攻擊策略資產。
- [ ] 工具選擇不宜只依賴成功 trajectory 中的共現頻率；可先做隔離工具評估，再標記直接導致成功的決策工具，以減少 attacker 自身偏好被錯誤寫回策略。
- [ ] 演化機制應採用獨立 validation gate，而非直接採納 distiller 產物；論文中的 AgentHarm/MiniMax 例子顯示，即使 validation 改善，test 仍可能下降，因此 validation split 的多樣性與持續監控很重要。

## 限制與未來工作

論文顯示效能取決於 toolbox 的強度與多樣性，且某些設定出現 validation 改善但 test 退化，反映 ratchet 仍可能過擬合。實驗涵蓋的 benchmark、target model 與 harness 有限；文中未報告統計顯著性、更多隨機種子或更廣泛真實部署環境的結果。
