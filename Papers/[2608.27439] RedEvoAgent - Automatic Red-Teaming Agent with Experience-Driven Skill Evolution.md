# RedEvoAgent: Automatic Red-Teaming Agent with Experience-Driven Skill Evolution

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.27439)
- 📥 [PDF](https://arxiv.org/pdf/2608.27439v1)

## 摘要（中文翻譯）

基於 LLM 的 agents 日益部署於產品級 execution harness，可修改本機檔案、傳輸資料及呼叫外部 API；jailbreak 因而可能觸發有害的 tool use 與持久性狀態變更，風險高於單純產生不安全文字。既有 automatic red-teaming 多依賴固定攻擊；較新的 agentic attacker 雖能協調多種 jailbreak tools，卻可能因 trajectory retrieval 的偏差與不清楚的 tool credit 而重用誤導性經驗，完整 trajectories 亦增加 context 成本並降低可解釋性。本文提出 RedEvoAgent，一種 black-box red-teaming agent，將跨案例攻擊 trajectories 蒸餾為精簡、可讀的人類 attack skill。該 skill 透過 tool-effectiveness profiling、Deciding-Tool Attribution 與 validation ratchet 自適應演化；只有能提升 validation performance 的更新才會保留。多個 benchmark、target model 與 execution harness 的實驗顯示，RedEvoAgent 優於 fixed 與 agentic baselines，並改善 tool efficiency，且能跨 attacker model 與 target harness transfer。

## 問題背景

論文處理產品級 LLM agent 的自動化 black-box red-teaming 問題：jailbreak 可能造成有害工具操作及持久狀態變更。固定式攻擊只探索有限攻擊空間；trajectory-based agentic 方法則可能受 semantic retrieval bias、工具貢獻歸因不清、長上下文成本及低可解釋性影響，導致誤導經驗被反覆採用、策略不穩定甚至崩潰。

## 解決方案

作者提出 RedEvoAgent，將多種 jailbreak methods 封裝為可呼叫的 attack toolbox，並以一份插入 attacker agent system prompt 的 Markdown attack skill 指導工具編排。系統先在 training split 隔離評估各工具，建立 tool-effectiveness profile；再從成功與失敗 trajectories 擷取跨案例策略，並以 Deciding-Tool Attribution 將成功歸因給成功 target query 前直接使用的工具。distiller agent 依據這些資訊提出 bounded-change skill candidate，validation ratchet 僅接受在獨立 validation split 上嚴格優於目前 skill 的更新。

## 核心貢獻
1. 提出 RedEvoAgent，將跨案例攻擊經驗蒸餾為可讀、可重用且可演化的單一 natural-language attack skill，而非在推論時檢索完整 trajectories。
2. 提出 tool-effectiveness profile 與 Deciding-Tool Attribution，分別提供隔離工具效能與成功工具選擇訊號，以降低工具共現造成的錯誤 credit assignment 與策略崩潰。
3. 提出 incumbent-relative validation ratchet：只有在獨立 validation split 上嚴格超越目前 skill 的候選更新才會保留，並以多 target model、benchmark、execution harness 及 transfer 實驗驗證效能與效率。

## 技術方法

目標 agent 定義為黑箱組合 M_tar=(m_tar,h_tar)，由 target model 與 execution harness 提供互動及工具環境；attacker agent M_att(s)=(m_att,h_att(s,T)) 採 ReAct 迴圈，固定 attacker model、harness、toolbox 與 target agent，只更新 skill s。每個案例最多 B=20 個 attacker-agent loop steps；每步可執行 QUERYTARGET，或呼叫七種工具：GCG、AutoDAN、AmpleGCG、Template、FlipAttack、RolePlay 與 Prompt Substitution。工具會改寫目前 prompt，QUERYTARGET 則取得 target response；外部 benchmark scorer 產生案例分數，集合平均值 J_D(s) 作為 effectiveness。資料依 benchmark 切分為 train、validation、test；train 用於工具隔離評估、收集完整 trajectories 與 skill synthesis，validation 只提供 candidate 與 incumbent 的分數比較，test 僅作最終評估。每輪將 trajectories 按成功／失敗分層並切成 minibatches，由 distiller agent 分析、合併編輯建議及重寫完整 skill；拒絕的 candidate 及分數放入 rejection context，成功接受後重新收集 train experience。實驗使用 GPT-4o mini 作 attacker，R=4，SkillOpt minibatch size=8、edit cap L=6。ASB 報告 ASR 與 refusal rate（RR）；AgentHarm 報告 HarmScore 與 RR，另以每案例平均 attack-tool calls 衡量效率。

## 關鍵結果

主要結果如下；ASB 的 ASR、AgentHarm 的 HarmScore 皆依論文定義呈現百分比。

| Benchmark／Harness／Target model | 最強固定工具（數值） | RedCodeAgent | MAJIC | RedEvoAgent |
|---|---:|---:|---:|---:|
| ASB／Claude Code／MiniMax-M2.5 | FlipAttack 91.8 ASR | 76.4 | 74.2 | **93.2** |
| ASB／Claude Code／DeepSeek-V4-Flash | FlipAttack 94.3 ASR | 90.7 | 94.6 | **99.3** |
| ASB／Codex／MiniMax-M2.5 | FlipAttack 81.1 ASR | 75.3 | 71.0 | **92.8** |
| AgentHarm／Claude Code／DeepSeek-V4-Flash | FlipAttack 67.9 HarmScore | 37.5 | 45.5 | **74.3** |
| AgentHarm／Codex／DeepSeek-V4-Flash | FlipAttack 67.3 HarmScore | 69.4 | 71.5 | **74.4** |

消融結果（ASB、MiniMax-M2.5、Claude Code）：完整系統 ASR 為 93.2%；移除 Tool-Effectiveness Profile、Trajectory Collection、Deciding-Tool Attribution 後，分別降至 76.9%、85.0%、87.5%。Skill contribution 實驗中，RedEvoAgent 在所有列出的設定都達到最高攻擊效能；例如 ASB／Claude Code／MiniMax-M2.5 為 93.2% ASR、每案例 1.8 次工具呼叫，而 No Skill 為 77.5%、3.0 次，Human Skill 為 78.3%、3.2 次。零樣本 transfer 中，源自 Claude Code 的 skill 在 Codex 上達 90.5% ASR，相較 No Skill 的 80.8%。但 AgentHarm／Claude Code／MiniMax-M2.5 在第 4 輪雖使 validation HarmScore 從 18.5 升至 28.1，test HarmScore 卻由第 2 輪的 28.8 降至 20.8，顯示 validation ratchet 仍可能出現泛化下降。

## 對我們的啟發
- [ ] 若 agent 對不同 jailbreak tools 呈現不均勻抵抗，將工具效能量測與條件式 escalation 規則寫入高階 skill，可能比固定單一攻擊更有效；論文結果顯示這類設定下攻擊效能與工具使用效率都可提升。
- [ ] 經驗蒸餾時應區分工具共現與直接造成成功的工具，並記錄成功及失敗案例；這可避免 attacker model 的既有偏好被 skill 演化反覆放大。
- [ ] 將策略更新以獨立 validation gate 篩選，並保留被拒候選及其分數，有助於控制 noisy update；但實務上仍應檢查 validation 與 test 行為差異，因論文已觀察到 validation 改善不必然帶來 test 泛化改善。

## 限制與未來工作

論文指出效能依賴 toolbox 的強度與多樣性，且 skill 在 validation 上改善仍可能降低 test 泛化；AgentHarm／MiniMax-M2.5 的第 4 輪即出現此情況。研究僅報告既定 benchmark、target models、harness 與設定，未提供更廣泛資料分布、統計顯著性或不同 validation 設計的系統比較。
