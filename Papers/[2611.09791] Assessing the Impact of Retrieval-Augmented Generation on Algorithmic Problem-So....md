# Assessing the Impact of Retrieval-Augmented Generation on Algorithmic Problem-Solving

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2611.09791)
- 📥 [PDF](https://arxiv.org/pdf/2611.09791v1)

## 摘要（中文翻譯）

競賽程式題對大型語言模型（LLM）提出獨特挑戰，因為模型不僅需要具備程式碼生成能力，也必須進行高階演算法推理。本研究提出專為此類任務設計的 Retrieval-Augmented Generation（RAG）方法，結合 embedding-based retrieval 與 similarity search，從知識資料庫找出相似題目，並透過動態調整門檻降低檢索噪聲。作者使用 CodeContests 資料集進行評估，比較僅提供原始題目、加入隨機訓練題，以及加入相似檢索題目三種條件。此外，研究採用 Min-K membership inference 分析，探討生成程式碼是否受到模型對訓練資料潛在記憶的影響，以區分透過檢索產生的泛化與預訓練資料的隱性回憶。評估指標包括通過率與 CodeForces Elo rating。結果顯示，基於相似度的檢索能實質提升 LLM 在競賽程式設計情境中的表現。

## 問題背景

論文聚焦於 LLM 解決競賽程式題時的困難：此類題目要求理解資料結構、演算法模式與隱藏測試案例，僅具備一般程式碼生成能力往往不足，並可能產生語法或邏輯錯誤。既有評估也常只使用 pass/fail，難以反映題目難度與模型實際能力。作者因此研究：從已解題目中檢索演算法上相似的範例，是否能比零樣本或隨機範例更有效地改善解題表現。

## 解決方案

作者提出一個針對競賽程式設計的 similarity-based RAG 框架。系統先以 all-MiniLM-L6-v2 將題目描述轉為 embedding，再使用 FAISS IndexFlatL2 進行相似度搜尋，從 CodeContests 訓練集挑選最多三個相似且已有驗證解答的題目，附加至測試題提示中。核心創新是 query-dependent 的動態相似度門檻：以最高相似度調整篩選嚴格程度，最低不低於 70%，以在資訊不足時保留候選、資訊高度相似時抑制噪聲。研究另以 Min-K membership inference 分析生成程式碼的潛在資料暴露，補充評估 RAG 增益是否伴隨記憶效應。

## 核心貢獻
1. 提出結合 embedding similarity search、FAISS 與動態相似度門檻的競賽程式設計 RAG 框架，並限制最多三個檢索範例以降低噪聲。
2. 在 CodeContests 的 81 題可檢索測試子集上，系統性比較零樣本、隨機檢索與相似度檢索三種提示策略，並同時使用 pass@1 與 MAP Elo 評估。
3. 引入 Min-K membership inference 作為補充分析，探討生成解答與模型預訓練資料暴露或記憶模式之間的關係。

## 技術方法

資料方面，研究使用 CodeContests，訓練集含 13,328 題，測試集含 165 題；以訓練集作為 RAG 知識庫，並將其中至少檢索到一個相似題目的 81 題測試題納入主要實驗。檢索只使用題目文字描述，不使用解答或標籤來計算相似度。每題先透過 all-MiniLM-L6-v2 取得 embedding，向量經正規化後使用 FAISS 的 IndexFlatL2 搜尋。系統初始相似度門檻為 70%；最高相似度高於 85% 時提高門檻，低於 75% 時放寬，但不低於 70%，且最多回傳三題。六個模型為 DeepSeek-R1、Gemini 2.0 Flash、Claude 3.7 Sonnet、Qwen2.5-Coder-32B、GPT-4o 與 GPT-3.5 Turbo。三種提示條件為零樣本、隨機檢索，以及相似度 RAG；範例包含標題、描述、標籤、相似度與驗證解答。生成程式碼交由 CodeForces judge 執行，主要指標為 pass@1 與以 Bayesian MAP Elo 估計的模型 rating。另對最佳解答進行 Min-K membership inference，使用最低 K% token log-probability 的平均分數，依百分位數門檻分類為 Member 或 Non-member。

## 關鍵結果

主要結果如下（論文報告的是 81 題子集上的平均結果）：

| 評估條件 | 平均 pass@1 | 平均 MAP Elo |
|---|---:|---:|
| Zero-shot | 17.90% | 925 |
| Random retrieval | 17.28% | 927 |
| Similarity-based RAG | 20.37% | 1014 |

| 模型 | Zero-shot | Random retrieval | RAG |
|---|---:|---:|---:|
| DeepSeek-R1 | 61.7% | 59.3% | 64.2% |
| Gemini 2.0 | 18.5% | 18.5% | 22.2% |
| Claude 3.7 Sonnet | 17.3% | 12.3% | 19.8% |
| GPT-4o | 7.4% | 8.6% | 8.6% |
| GPT-3.5 Turbo | 1.2% | 1.2% | 2.5% |
| Qwen2.5-Coder-32B | 1.2% | 3.7% | 4.9% |

作者指出，RAG 相較零樣本平均提升 2.47 個百分點，平均 Elo 提升 89 分；相較隨機檢索則提升 3.09 個百分點與 87 分。DeepSeek-R1 的 RAG pass@1 由 61.7% 提升至 64.2%。分類分析中，DeepSeek-R1 在 number theory 的 Elo 由 1604 提升至 2191，但 data structures 與 combinatorics 等類別出現下降。Min-K 分析顯示，多數被分析程式碼行的 membership confidence 高於 0.5；論文將其解讀為可能接觸過競賽程式碼模式，但未將此視為精確問題—解答配對的證明。

## 對我們的啟發
- [ ] 實務部署 RAG 時，增加範例數量本身不等於提升效果；本研究中隨機檢索低於零樣本，表示檢索相關性與範例品質比單純增加上下文更重要。
- [ ] 可將 pass@1 與題目難度校準後的 Elo 同時使用：前者反映解題數量，後者有助於觀察模型是否能處理較高難度題目。
- [ ] RAG 應保留檢索失敗或低相似度時的回退機制，並針對不同問題類別調整檢索策略；論文結果顯示某些類別受益明顯，但另一些類別可能因誤導性範例而退化。

## 限制與未來工作

研究只評估 165 題測試集中的 81 題可檢索子集，無法直接代表所有測試題。檢索固定使用單一 embedding 模型且最多取三個範例，尚未比較 hybrid retrieval、reranking 或其他提示格式。Min-K 是間接暴露訊號，不能確定程式碼確實來自預訓練資料。未來將擴展至較新、較具污染意識的資料集，並研究模型與類別專屬的檢索策略。
