# TUPLE-Bench: Evaluating and Mitigating Privacy-Utility Trade-offs in Typed Decision Models

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2610.23668)
- 📥 [PDF](https://arxiv.org/pdf/2610.23668v1)

## 摘要（中文翻譯）

Typed decision models 往往不只回傳選定類別，也會公開各候選項目的機率，以及有時額外提供的 confidence score。這些欄位能支援下游決策，但可能揭露超出接收者授權範圍的資訊。本文提出 TUPLE-Bench（Typed decision models’ Utility and Privacy Leakage Evaluation Benchmark），以成對 synthetic cases 測試接收者可得知粗粒度 operational category、但不得得知細粒度原因的情境。九個模型的結果顯示，即使指示模型隱瞞原因，91.88%–99.93%的回應仍會透過直接選擇或 residual scores 揭露原因。即使將原因排除於候選集合之外，完整輸出在 held-out cases 上仍可達62.85%–75.35%的原因恢復率，高於僅提供 selected category 的51.04%–57.64%。完整輸出在全部27個 model-task comparisons 中降低下游成本，但 confidence fields 會增加洩漏，且未穩定降低成本。作者進一步提出 workflow-constrained privacy quantization（WCPQ），在維持指定下游 workflow 行為與成本的同時降低秘密恢復率。研究強調應逐欄位、逐 workflow 稽核 decision interface。

## 問題背景

現有 typed decision interface 的評估多聚焦於 selected label、模型準確率或 confidence calibration，未充分檢查 probabilities、confidence 及 residual scores 是否洩漏接收者無權知道的細粒度原因。單純要求模型輸出 WITHHOLD，或把敏感原因從 production candidates 移除，也不足以保證機密性；同時，全面刪除分數可能損害 routing、review 與 cost-sensitive decision 的效用。因此需要在明確 disclosure contract 下，聯合評估輸出欄位造成的 privacy leakage 與 downstream utility。

## 解決方案

作者提出 TUPLE-Bench，建立三個 operational domains、recipient-specific disclosure contracts，以及共享 public context 和 authorized coarse outcome、但具有不同 protected mechanisms 的 paired synthetic worlds。框架以兩條互補路徑稽核：第一是 refusal probe，檢查模型選擇 WITHHOLD 後，其他分數是否仍可恢復原因；第二是 coarse-to-fine audit，在 protected mechanisms 不出現在候選集合時，分析 choice、choice+confidence、full probabilities 與 full native 等 release views 的秘密推斷與下游成本。為降低洩漏，作者提出 WCPQ，由 trusted backend 將 native response 映射至 codebook 中的量化輸出，僅選取能保留預先指定 workflow 全部行為分支與成本的 codeword，並對 defended outputs 重新訓練攻擊 decoder。

## 核心貢獻
1. 提出 TUPLE-Bench：包含720個 paired synthetic cases、三個 operational domains 與 recipient-specific disclosure contracts，用於同時衡量 typed decision readouts 的 privacy leakage 與 downstream utility。
2. 系統性比較 refusal probe 與 coarse-to-fine release audit，證明即使模型選擇 WITHHOLD，residual scores 仍可能洩漏；即使敏感原因不在候選集合中，probabilities 與 native outputs 仍可支援秘密恢復。
3. 提出 WCPQ，以 workflow behavior signature 約束輸出量化，在指定 workflow 與成本不變的條件下，實證降低秘密恢復率。

## 技術方法

資料集包含 delivery operations、equipment service 與 IT operations 三個 synthetic domains；每個 domain 有四個 authorized coarse classes，以及每類四個 protected mechanisms，共720個 pairs、1,440個 worlds，並按432/144/144 pairs 分為 train/validation/test。每個 pair 固定 X、B、T 與 disclosure contract，只改變 private evidence E 和 mechanism S。decision model 回傳 D=(T-hat,p,c)，其中 p 是 coarse candidates 的 scores，c 是原生 confidence；所有 release views 均由同一份 saved native response 產生。效用以 selective routing、one-step clarification、asymmetric-cost routing 的 mean downstream cost、coverage 與錯誤率評估。隱私則以 supervised secret decoder，在已知 authorized T 與二元 hypotheses H={s0,s1} 下恢復 S，報告 accuracy、log loss 與相對 no-output baseline 的 gain。refusal probe 以16個細粒度 mechanisms 加 WITHHOLD，計算 direct selection 與 withholding 後 residual-score recovery。WCPQ 建立 probability-grid codebook，保留 selected category，並依18個 frozen workflows（3 tasks×6 cost profiles）的完整行為 signature 選擇替代輸出；若無合適 codeword 則 fallback 至原輸出。作者另比較0.1 quantization、temperature smoothing與Gaussian noise，並使用pair-clustered bootstrap intervals。

## 關鍵結果

| 評估面向 | 主要結果 |
|---|---|
| Refusal probe 整體原因恢復 | 九個模型為 **91.88%–99.93%**；其中選擇 WITHHOLD 的模型，其 withheld subgroup recovery 為 **87.53%–99.91%**。 |
| WITHHOLD 行為 | WITHHOLD rate 為 **0.00%–98.96%**；OpenJev 從不 withholding，但 direct recovery 為 **96.94%**。 |
| Choice-only 恢復 | **51.04%–57.64%**，no-output 約為50% baseline。 |
| Full probabilities 恢復 | **62.50%–77.78%**。 |
| Full native 恢復 | **62.85%–75.35%**；相較 choice-only 高 **11.46–23.61 個百分點**。 |
| Full native 下游效用 | 在全部 **27個 model-task comparisons** 中降低 mean business cost，相對 choice-only 的降幅為 **9.52%–75.68%**。 |
| Confidence field | choice+confidence 相較 choice 的 pooled recovery point estimate 在九個模型皆上升 **2.43%–10.42%**，但未一致降低成本。 |
| WCPQ | 相較 native，TypeSafe、OpenJev、Clef 的 recovery 分別降低 **10.07–24.65個百分點**；recovery 為 **58.68%、51.04%、51.74%**，且18組 frozen workflow/cost combinations 的行為與成本均保持不變。 |
| WCPQ coverage | TypeSafe **99.31%**、OpenJev **100%**、Clef **100%**。 |

## 對我們的啟發
- [ ] 決策介面的隱私稽核不應只檢查 selected label 或是否遵守 WITHHOLD；應逐一評估 probabilities、confidence、欄位組合及 residual information。
- [ ] 輸出欄位的取捨應依具體 downstream workflow 評估，而非假設移除所有分數必然更安全或必然降低效用；本文顯示 full outputs 在所有27個比較中降低成本。
- [ ] 可在 trusted backend 實施 workflow-aware post-processing，例如 WCPQ；但其保證只適用於事先指定且 frozen 的 workflows，仍需另外測試 fallback、行為本身與其他攻擊途徑是否洩漏。

## 限制與未來工作

資料全為 AI-generated synthetic cases，成本、checks 與 disclosure contracts 亦是構造設定，不能直接代表真實部署的洩漏率或成本。攻擊者採 passive、closed-set、binary-hypothesis decoding，未涵蓋 open-set、adaptive querying、timing、provider logging 與 repeated-call variability。Bootstrap 亦未納入 decoder refitting 和 selection uncertainty；模型、domain 與 workflow 範圍有限，且 pairs 的 statistical independence 未被證明。
