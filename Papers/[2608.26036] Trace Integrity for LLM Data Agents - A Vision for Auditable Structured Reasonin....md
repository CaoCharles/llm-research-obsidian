# Trace Integrity for LLM Data Agents: A Vision for Auditable Structured Reasoning in Real-World Systems

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.26036)
- 📥 [PDF](https://arxiv.org/pdf/2608.26036v1)

## 摘要（中文翻譯）

答案準確率不足以作為 LLM data agents 的可靠性訊號。在結構化資料任務中，即使答案與 benchmark 參考答案一致，背後也可能是無效的 computation trace。本文提出 Trace Integrity，作為部署可靠性標準，檢驗記錄的計算是否 explicit、executable、schema-valid、operator-faithful、replayable、answer-consistent 且 auditable。作者指出 Structure Gap 是其必要性的根源：自然語言推理與自由形式 rationale 無法穩定指定真實系統所需的 operator-level program。本文以 execution contracts 將 user intent、schema elements、operator plans、assumptions、executable queries、verification status 與 final-answer linkage 綁定，並提出 CAIT (Correct Answer / Invalid Trace) Rate，量化 answer-only evaluation 將計算上不受支持的輸出計為成功的頻率。在 BIRD Mini-Dev 示範中，三種方法的答案準確率為 20%–24%，Trace Integrity Pass Rate 為 39%–43%，CAIT Rate 為 45.8%–59.1%，顯示三者是不同評估訊號。

## 問題背景

論文處理 LLM data agents 在結構化資料任務中的 silent failure：系統可能以錯誤的 filter、join、aggregation、time window 或 grouping key 得到正確或看似合理的答案。現有 answer-only evaluation 只比較最終結果，execution success 也只能表示 query 能執行，無法證明計算符合使用者意圖；自然語言 rationale 同樣不可執行且未必忠實描述實際 computation，因此缺少可檢查、可重播、可稽核的 trace-level reliability criterion。

## 解決方案

作者提出 Trace Integrity，將答案背後的 computation trace 視為一級評估對象。Trace 必須 explicit、executable、schema-valid、operator-faithful、replayable、answer-consistent 與 auditable。為使標準可部署，作者設計 execution contract，結構化記錄 user intent、schema bindings、filters、joins、grouping、metric、operator plan、assumptions、query、verification status 及答案連結；並提出 Isolation Principle，預設先根據問題、schema、metadata 與 policy context 規劃，再接觸 value-level data。最後以 CAIT Rate 衡量正確答案中由無效 trace 支持的比例，揭露 answer-only evaluation 隱藏的可靠性風險。

## 核心貢獻
1. 提出 Trace Integrity 作為 LLM data agents 的部署可靠性標準，將 computation trace 的可明確化、可執行、schema validity、operator faithfulness、可重播、答案一致性與可稽核性納入評估。
2. 提出 execution contract 與 Isolation Principle，將使用者意圖、schema 綁定、操作計畫、假設、查詢及驗證狀態轉化為可驗證、可儲存與可供人工審查的結構化 artifact。
3. 提出 CAIT Rate，並在 100 個 BIRD Mini-Dev examples 上展示正確答案可能由無效 trace 支持，量化 answer-only evaluation 所隱藏的 computationally unsupported successes。

## 技術方法

論文沒有提出特定的新模型架構；proof-of-concept 使用 Claude Haiku 4.5、temperature 0.0，並比較三種 prompting condition：Direct SQL 直接由問題與 schema 生成 SQL；Operation Summary + SQL 先產生簡潔的操作摘要再生成 SQL；Contract-First SQL 先輸出 execution contract，再生成 SQL。實驗取 BIRD Mini-Dev 的 100 個 examples；每題執行 gold SQL 取得 reference result，將 generated SQL 在相同 database 上執行，並把 generated trace 與 normalized gold trace 比較。評估指標包括 Answer Accuracy（generated result 與 gold result 的 row-set 是否相同）、Execution Success（SQL 是否成功執行）、Trace Integrity Pass Rate（trace 是否 executable、schema-valid 且無 critical operator mismatch）、Answer-Trace Consistency，以及 CAIT Rate = N(correct∩invalid) / N(correct)。validator 以 deterministic operator-level checks 判定 critical failure，涵蓋錯誤或缺失 aggregation、filter、join、join path、grouping key、sort/limit、schema reference、不可執行 SQL、answer-trace mismatch，以及 Contract-First 的 contract-query mismatch。作者也說明該檢查器偏向可稽核規則，可能過度標記無法證明等價的合法 SQL rewrite。

## 關鍵結果

主要結果如下；百分比皆為論文報告數值。

| 方法 | Answer Accuracy | Execution Success | Trace Integrity Pass Rate | Answer-Trace Consistency | CAIT Rate |
|---|---:|---:|---:|---:|---:|
| Direct SQL | 20.0% | 84.0% | 39.0% | 84.0% | 55.0% |
| Operation Summary + SQL | 22.0% | 83.0% | 43.0% | 67.0% | 59.1% |
| Contract-First SQL | 24.0% | 82.0% | 40.0% | 82.0% | 45.8% |

在 300 個 method-example predictions 中，共有 51 個 query 無法執行，占 17.0%。CAIT 案例數方面，Direct SQL 為 11、Operation Summary + SQL 為 13、Contract-First SQL 為 11。Contract-First SQL 的答案準確率最高且 CAIT Rate 最低，但 Trace Integrity Pass Rate 不是最高；Operation Summary + SQL 的 Trace Integrity Pass Rate 最高，卻有最高 CAIT Rate。結果支持作者的主張：答案準確率、trace validity 與 silent-failure risk 並不等同。

## 對我們的啟發
- [ ] 實務部署不應只追蹤 answer accuracy 或 execution success；應同步保存 contract、實際 query、schema bindings、執行快照與答案連結，並將 Trace Integrity 作為放行或升級人工審查的條件。
- [ ] 可把 critical mismatch 分類為缺失 filter、錯誤 join、aggregation、grouping、schema reference 或 answer-trace mismatch，將每次失敗轉化為 regression test，而非只記錄一個錯誤答案。
- [ ] 執行 contract 應記錄計畫與實際 query 的一致性；若因 profiling、outlier detection 等任務必須先存取資料值，也應記錄存取理由、權限範圍及計畫變更，以維持可稽核性。

## 限制與未來工作

研究是 vision 加上 scoped proof-of-concept，僅使用 100 個 stratified BIRD Mini-Dev examples、單一 Claude Haiku 4.5 與固定設定，不能據此建立模型或 prompting 的穩定排名。validator 以 deterministic structural checks 為主，非完整 semantic-equivalence checking，可能過度標記合法 SQL rewrite；論文未報告更大規模、多模型或真實企業資料上的結果。
