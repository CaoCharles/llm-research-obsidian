# TaoLive Digital Avatar Agent Technical Report: Training Agents to Evolve with Their Harness

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.15763)
- 📥 [PDF](https://arxiv.org/pdf/2608.15763v1)

## 摘要（中文翻譯）

AI 驅動的數位虛擬主播在直播電商中，必須即時回答商品問題、與觀眾互動並執行不斷變動的商業策略，因此同時要求低延遲、事實正確、回覆有效，以及快速適應活動、合規與風格更新。作者建立可演化的 Harness，將 Skills、Hooks、system prompts 與 tools 與模型權重解耦，使執行行為可在不重新訓練下更新。然而，固定 Harness 上微調的 compact model 可能記憶名稱、schema 與 prompt template，而非遵循當前 Harness；強大的 zero-shot model 又太慢。為此提出 Harness-Aware Training（HAT），將 Harness state 納入訓練分布，透過 task-preserving 的 Harness-State Augmentation（HSA）擾動 Skills、tool schemas、prompt structures 與 interaction constraints，並依序進行 HSA-SFT、General On-Policy Distillation（General OPD）及模擬生產環境的 HSA-based agentic RL。實驗顯示，compact 35B model 在 Live-Stream QA 得分 94.8，在 Harness-Variant QA 得分 94.6，IFEval 為 83.5；單張 NVIDIA H20 上 P50/P95 延遲為 3.407/8.114 秒。

## 問題背景

直播電商 Agent 的商業規則、工具與提示會持續更新，但低延遲又限制了可使用的模型規模。固定 Harness SFT 雖能提升特定領域表現，卻可能記憶 Skill/tool 名稱與 prompt template，導致面對新 Harness 時失效，並造成一般 instruction-following 能力下降；大型 zero-shot model 則被作者測得超過 11 秒的 median latency，test-time adaptation 與反覆 continual learning 也不符合更新與延遲需求。

## 解決方案

作者提出可演化 Harness 與 HAT。Harness 將 Skills、Hooks、system prompt pipeline 和 ToolRegistry 獨立於模型權重，使業務方可透過人工審核流程快速修改策略。HAT 的核心是讓 Harness state 成為訓練分布，而非固定背景；HSA 對 Skill、tool、prompt、Hook 的表面形式與互動限制作保持任務語義的變換，迫使 compact model 閱讀當前功能性指令。完整流程依序為 HSA-SFT、General OPD 與在生產導向 simulator 中的 HSA-RL，兼顧業務能力、Harness 變化適應、一般指令遵循與端到端延遲。

## 核心貢獻
1. 提出可演化的 Harness 架構，將 Skills、Hooks、system prompt pipeline 與 tools 從 policy model 權重中解耦，支援由開發者審核的 Diagnose→Confirm→Edit→Evaluate→Regression Check 更新流程。
2. 提出 Harness-Aware Training（HAT）與 Harness-State Augmentation（HSA），在 SFT 與 agentic RL 階段將多種 Harness 狀態納入訓練，降低固定 Harness 的 surface-form overfitting。
3. 建立涵蓋真實直播互動、Harness 變體、合成工具與 prompt robustness，以及 IFEval 的四類評測，並校準 Harness-based Agent-as-a-Judge；同時報告完整 Agent replay 的實際部署延遲。

## 技術方法

作者將 policy 表示為 πθ(a|x,h)，其中 x 是使用者輸入及業務 context，Harness state h=(S,T,P,K)，分別代表 Skills、tool registry、system prompt 與 Hooks。Runtime 由動態 Skill 載入、prompt assembly、工具呼叫、多輪 policy–tool loop、Hook 驗證/重試及 stop gate 組成。HSA 對五個維度進行 task-preserving 擾動：新增或遮罩 Skills、改名及改寫 Skill descriptions、重排或遮罩規則、改寫 tool names/descriptions、重排 prompt blocks 並調整有效數值限制，以及改變 Hook 的 retry、message structure 與觸發行為；生成後以 Accuracy、Effectiveness 與 consistency check 篩選。訓練第一階段以 10K 個真實直播案例，由 teacher 在原始與 augmented Harness 下產生軌跡，進行 HSA-SFT，並刪除多數中間錯誤 retry 內容、保留少量完整 recovery 軌跡。第二階段在 Tulu3 general instruction data 上，以原始 base model 作 teacher，執行 General OPD 以最小化 student 與 base distribution 的 KL divergence。第三階段在 production-informed simulator 中使用 HSA-RL；環境包含直播情境、Skills、工具 sandbox、Hook、多輪限制及 timeout、malformed response、permission denial 等失敗注入，採 GRPO/GDPO 式分組優化。Reward 包含 Accuracy、Effectiveness、Tool Rationality、Skill Selection，並懲罰過長 CoT。評估包含 T1/T2 各 978 筆真實資料、T3 2,023 筆合成 robustness 案例、IFEval 541 筆及 110 筆部署 replay；指標涵蓋 Accuracy、Effectiveness、工具正確性、prompt 遵循、IFEval 與 wall-clock latency。

## 對我們的啟發
- [ ] 若 runtime 規則、工具 schema 或 prompt 會頻繁變更，應把執行環境版本化並納入訓練分布，而非只在單一固定配置上進行 SFT。
- [ ] HAT 的三階段設計顯示，domain SFT 後可用 General OPD 恢復部分一般 instruction-following，再以多輪 simulator 中的 agentic RL 學習工具錯誤、Hook retry 與 Skill routing 的後果。
- [ ] 評估可演化 Agent 時，不能只測固定 Harness 的任務成功率；應分別檢驗真實業務品質、Harness 變體穩健性、工具與 prompt robustness、一般指令遵循及端到端延遲。

## 限制與未來工作

評測部分依賴 Harness-based Agent-as-a-Judge；雖以 482 筆人工標註資料校準，但論文未完整揭露 Judge 與人類一致性的具體數字。HSA 的變化範圍由作者設計，T3 含 LLM 生成的合成案例，未證明可涵蓋所有未來 Harness。RL、MTP 與部署結果多為單次或有限 replay，且延遲僅代表指定 H20、服務與低 concurrency 設定。
