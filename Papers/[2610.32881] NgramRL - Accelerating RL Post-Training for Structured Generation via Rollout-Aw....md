# NgramRL: Accelerating RL Post-Training for Structured Generation via Rollout-Aware N-gram Speculative Decoding

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2610.32881)
- 📥 [PDF](https://arxiv.org/pdf/2610.32881v1)

## 摘要（中文翻譯）

RL post-training 能提升大型語言模型的推理能力，但成本主要來自自回歸 rollout 生成，可能超過訓練時間的 70%。既有 speculative decoding 不適合此情境：model-based drafter 會消耗有限 GPU 記憶體，且 policy 演化後可能失配；model-free 方法也未明確利用訓練 epoch 間的重複性。作者提出 NgramRL，從同一 prompt 的近期 rollout 歷史建立 per-prompt n-gram drafter，作為高品質且自我更新的 draft source。它不需要 auxiliary model、drafter training 或常駐 GPU drafter state，並透過 target-model verification 保留 rollout 分布。作者進一步設計 adaptive fan-out prefetcher，預測 accepted draft length 與 target-emitted continuation token 等驗證結果，以隱藏 CPU cache lookup 與 scheduling 成本。在兩個模型家族、三種 reasoning 與 structured-generation workload 上，NgramRL 在 warm-cache 情況下每次 target forward 可提交 3.60–7.77 個 token；Spider 上以 candidate budget 16 達到 96.6% outcome coverage，rollout throughput 比 synchronous NgramRL 提升 1.38 倍。

## 問題背景

論文聚焦於 RL post-training 中 rollout generation 的效率瓶頸：GRPO 每個 prompt 需反覆自回歸產生多個 completion，rollout 成本可超過訓練時間 70%。既有 model-based speculative decoding 需要額外模型或 draft heads，消耗 GPU 記憶體，且 policy 更新後容易失配；prompt lookup、REST 等 model-free 方法主要依賴單次生成或固定 datastore，無法利用相同 prompt 跨訓練 step 與 epoch 的重複性。此外，CPU cache lookup 若同步執行會造成 GPU 等待。

## 解決方案

作者提出 NgramRL，一個面向 RL rollout 的 CPU-side、per-prompt n-gram speculative drafter。系統從同一 prompt 的近期 policy rollouts 擷取 n-gram，依 context 儲存可能的 continuation 及頻率，並以 bounded history window 淘汰較舊資料，使 drafter 隨 policy 自我更新。target model 以標準 speculative-sampling correction 驗證 draft，因此理論上維持原始 rollout 分布。為避免 CPU lookup、同步與 scheduling 阻塞 GPU，作者加入 adaptive fan-out prefetcher：依近期 accepted-length 與 bonus-token 統計，對可能的驗證結果分支預先建立 drafts，命中時以 O(1) key probe 取用，未命中則退回 sequential lookup，不改變已提交 token。

## 核心貢獻
1. 辨識並量化 RL post-training 中相同 prompt 跨 training steps 與 epochs 的 temporal locality；作者報告 consecutive-epoch rollout 可覆蓋後續 rollout 的 48–96%，重複 span 為 7–23 tokens。
2. 提出由近期 policy rollouts 建立的 bounded per-prompt n-gram cache，無需 auxiliary model、drafter training 或 persistent GPU-resident drafter state，並透過 target verification 保持 exact sampling。
3. 提出 adaptive fan-out prefetcher 與 causal budget allocator，針對 accepted length 與 bonus token 的可能結果預先建立 drafts，將 CPU lookup 與 GPU verification 重疊；未命中時可退回同步流程而不改變 committed tokens。

## 技術方法

NgramRL 為每個 prompt 維護 cache C_p。每個 training step 後，系統從該 prompt 的 rollouts 擷取 n-gram，n-gram order 介於 n_min 與 n_max；對每個 context 儲存觀察到的 continuation、count 與最近 step，並保留最近 W steps 的資料。解碼時，對目前 context 找最長匹配 n-gram，提出最多 k 個 draft token；若無匹配則標準解碼。Target policy πθ 以 p_acc=min(1,πθ/q) 接受 draft，拒絕時從正 residual distribution 重新取樣，因而保持 target policy 的 token 分布。CPU-GPU 協同部分將下一步 context 可能產生的結果表示為 (j,b)，其中 j 是 accepted draft length，b 是 bonus token。prefetcher 依 trailing causal window 估計 P̂(j) 與各分支 coverage profile ĉ_j(f_j)，在總 candidate budget N 下以 greedy marginal gain 分配各分支 fan-out。命中時 GPU 直接解析預取表；未命中則僅對該 request 執行同步 lookup。實驗以 verl 的 GRPO 與 vLLM rollout engine，在 2× NVIDIA A100 80GB 上進行；每步對 64 prompts 各取 5 completions，訓練 15 epochs，模型為 Qwen3-8B 與 DeepSeek-7B，資料集為 GSM8K、Spider 1.0、CodeContests。比較 PLD、REST 與 SuffixDecoding，draft budget k=16；主要指標是 tokens per decoding step，即每次 target forward 提交的 token 數，另量測 prefetch coverage 與端到端 rollout throughput。

## 關鍵結果

主要結果如下；TPS 為每次 target-model forward 提交的 token 數，格式為「全訓練平均 / 最後 30% 平均」。

| 模型 | 任務 | PLD | REST | SuffixDecoding | NgramRL |
|---|---|---:|---:|---:|---:|
| Qwen3-8B | GSM8K | 1.31 / 1.31 | 1.32 / 1.31 | 2.42 / 2.32 | **4.00 / 4.36** |
| Qwen3-8B | Spider | 1.10 / 1.11 | 1.02 / 1.02 | 4.01 / 4.15 | **5.94 / 7.77** |
| Qwen3-8B | CodeContests | 1.28 / 1.30 | 1.07 / 1.07 | 2.50 / 2.96 | **2.70 / 3.60** |
| DeepSeek-7B | GSM8K | 1.47 / 1.49 | 1.69 / 1.69 | 3.37 / 3.64 | **5.83 / 6.81** |
| DeepSeek-7B | Spider | 1.24 / 1.24 | 1.02 / 1.02 | 3.71 / 3.88 | **6.37 / 7.71** |
| DeepSeek-7B | CodeContests | 1.19 / 1.15 | 1.02 / 1.02 | 3.11 / 3.99 | **3.92 / 6.19** |

其他作者報告結果：NgramRL 在 warm-cache regime 可達 3.60–7.77 TPS，最高相對 SuffixDecoding 提升 1.99 倍、相對 PLD 提升 7.0 倍。Spider 上 candidate budget N=16 時，Qwen3-8B 的 prefetch coverage 為 96.6%，端到端 rollout throughput 為 synchronous NgramRL 的 1.38 倍，接近 1.40 倍 overlap ceiling；DeepSeek-7B coverage 為 99.5%，speedup 為 1.21 倍。論文未報告完整 RL reward、最終任務準確率或收斂速度差異，僅主張 exact verification 使 rollout、reward、advantage 與 gradient 在分布上不變。

## 對我們的啟發
- [ ] 若 RL 訓練反覆重用相同 prompts，應優先檢查跨 step 或 epoch 的 prompt-conditioned temporal locality，而不只依賴單次 context lookup；這可作為 rollout acceleration 的工程切入點。
- [ ] cache 歷史不宜無限制增長：論文的 ablation 顯示 n_max=6、speculation length k=16 位於其測試曲線的 knee，且較小 history window 可在較低記憶體下保留大部分 acceptance；但實際設定仍需依 workload 驗證。
- [ ] 僅加速 cache lookup 不一定能帶來端到端收益；論文指出同步與 scheduling 而非 lookup 本身造成主要 GPU idle，因此 CPU-GPU overlap、miss fallback 與 coverage 預測是部署時的關鍵。

## 限制與未來工作

實驗僅涵蓋兩個模型家族、三個 workload，並以 2×A100 的特定 GRPO、batch 與 rollout 設定評估；論文未提供更大模型、不同硬體、更多 prompt 重訪策略或長期 memory 成本的結果。它也未報告最終 reward、任務準確率與實際訓練總時間縮短幅度；高 entropy 任務的 prefetch speedup 僅 1.05–1.06 倍，顯示收益依重複性而變。
