# KGCaRe: Explainable Complex Conditional Question Answering using Automatic Knowledge Graph Construction and Context Retrieval with LLMs

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.09779)
- 📥 [PDF](https://arxiv.org/pdf/2608.09779v1)

## 摘要（中文翻譯）

使用大型語言模型（LLM）與檢索增強生成（RAG）回答複雜條件式問題仍具挑戰，尤其在專業領域，一般用途 LLM 與傳統 RAG 往往表現不佳。作者提出 KGCaRe，結合從文件與知識圖譜（KG）擷取的非結構化及結構化知識，以提升推理與答案準確性。KGCaRe 透過多提示策略從文件自動建構 LLM 生成的 KG，並將其儲存於圖資料庫；同時把文件嵌入向量資料庫以支援神經檢索。系統以 LLM 引導反覆圖遍歷、擷取相關三元組並剔除無關資訊；若初次遍歷不足，則利用額外線索實體再次遍歷。最後，系統將以路徑形式表示的相關三元組與語義檢索出的文字段落，交由自訂 KGCaRe prompts 生成附帶解釋的答案。作者在兩個複雜條件式 QA 資料集及多個 LLM 上進行評估，並公開軟體流程。

## 問題背景

論文聚焦於專業領域中的複雜條件式問答：問題通常需要從多個文件事實與實體關係中進行條件判斷。作者指出，一般用途 LLM 與傳統 RAG 在此情境下容易表現不佳；僅使用非結構化文字可能不足以支援關係推理，而僅依賴單一路徑的檢索也可能帶入無關上下文。因此，研究探討如何結合文件文字與結構化知識，以改善答案準確性與解釋性。

## 解決方案

作者提出 KGCaRe，一個結合 neural retrieval 與 symbolic reasoning 的混合式框架。系統從文件以多提示策略自動建構 LLM-generated KG，並同步建立文件向量索引。回答問題時，LLM 引導圖譜進行迭代式 traversal，擷取並修剪相關 triples；若初始結果不足，便透過額外 clue entities 重新遍歷。最後，系統把圖譜 triples 的路徑表示與語義檢索文字共同交給自訂 prompts，以產生答案及解釋。其核心創新在於以動態、可補救的圖譜探索，補足單純文字 RAG 的關係推理能力。

## 核心貢獻
1. 提出 KGCaRe 混合式框架，將文件向量檢索與 LLM 生成知識圖譜上的符號式推理結合，用於複雜條件式問答。
2. 提出由 LLM 引導的迭代式圖遍歷機制，能擷取相關三元組、修剪無關資訊，並在必要時利用線索實體重新探索圖譜。
3. 將圖譜路徑上下文與語義檢索文字共同輸入自訂 prompts，生成帶有解釋的答案；並公開實作該方法的軟體流程。

## 技術方法

KGCaRe 採用混合式架構。首先，從文件出發，以多提示 extraction strategy 讓 LLM 產生結構化知識，建構知識圖譜，並將圖譜存入 graph database；同一批文件則被嵌入 vector store，以支援後續 neural retrieval。收到複雜條件式問題後，系統以 LLM 引導知識圖譜的迭代式 traversal，尋找與問題相關的實體與關係，擷取相關 triples，並修剪無關資訊。若初次 traversal 無法提供足夠的回答上下文，系統會使用額外 clue entities 再次遍歷圖譜。接著，系統把圖譜中的相關 triples 以 path form 組織，同時取得語義相關的文字 passages，將兩類上下文共同輸入自訂 KGCaRe prompts，由 LLM 生成答案與解釋。實驗在兩個 complex conditional QA datasets 上進行，使用 Mistral、Mixtral、GPT-3.5 與 GPT-4o，並與 Vanilla LLM、Code Prompt、Text Prompt、Think-on-Graph、Vanilla RAG 及 HybridContextQA 比較。所提供內容未說明具體評估指標、資料切分、資料規模、提示內容、圖遍歷停止條件或數值結果。

論文指出 KGCaRe 在兩個複雜條件式 QA 資料集上，跨 Mistral、Mixtral、GPT-3.5 與 GPT-4o，皆優於 Vanilla LLM、Code Prompt、Text Prompt、Think-on-Graph、Vanilla RAG 與 HybridContextQA 等基線。摘要未提供各資料集、模型、基線或評估指標的具體分數，因此無法呈現數值比較。

## 對我們的啟發
- [ ] 在需要多步條件判斷的專業問答中，可同時保留文字證據與結構化關係，避免只依賴單一檢索形式。
- [ ] 迭代式檢索可作為實務上的補救機制：當初始上下文不足時，利用問題中的線索實體擴大或修正圖遍歷範圍。
- [ ] 若系統需要可解釋答案，可將知識圖譜中的三元組組織成路徑，再與原始文字段落共同提供給生成模型；但部署時仍應另行驗證圖譜抽取與答案忠實度。
