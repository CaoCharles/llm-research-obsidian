# TRAJDEBUG: Tracing Error Lifecycle to Identify Critical Failures in Long-Horizon Agent Trajectories

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.06346)
- 📥 [PDF](https://arxiv.org/pdf/2608.06346v1)

## 摘要（中文翻譯）

基於 LLM 的 agentic systems 已在複雜領域展現能力，但常遭遇錯誤級聯與難以除錯的問題。Critical error detection 的目標，是在失敗 trajectory 中定位最早且對最終失敗負責的錯誤步驟。本研究面臨兩項挑戰：長 trajectory 使判斷單一步驟所需的證據分散於遠距的指令、觀察與歷史上下文；失敗 trajectory 也常包含多個下游影響不同的 local errors，其中部分會被修復、部分無害，只有少數真正造成最終失敗。作者提出 TRAJDEBUG，一個 error-lifecycle tracing framework，結合 multi-granularity history compression 與 evidence-based error identification，並追蹤各錯誤的 resolution status 與 terminal impact，以進行 critical attribution。作者另建立 TRAJERRBENCH，包含來自 τ2-Bench 與 SWE-Bench Pro 的 486 條人工標註失敗 trajectory，涵蓋工具使用與 coding 情境。實驗顯示 TRAJDEBUG 整體優於既有方法，其診斷也能轉化為提升下游 agent success 的可行回饋。

## 問題背景

論文要解決長期 LLM agent trajectory 中 critical error step 的定位問題：找出最早且真正導致最終失敗的錯誤，而非只找任一 local error。現有 holistic prompting 容易受長上下文與分散證據干擾；taxonomy 或 constraint 方法只能找候選；causal 或 graph 方法則未充分表達錯誤後續是否修復及其 terminal impact，因此在多個共存錯誤下容易誤判。

## 解決方案

作者提出 TRAJDEBUG，以 error lifecycle 為核心，將除錯拆成可稽核的三階段。第一階段使用 multi-granularity compression 和 verbatim evidence 條件，找出與 task、history、intra-step 或 environment reference 衝突的 atomic error triggers。第二階段依共同 reference object 聚合 trigger，判斷錯誤是否 resolved、active，以及是否造成 irreversible、semantic 或 budget-debt terminal footprint。第三階段只在具有 terminal relevance 的候選中進行 candidate-set-guided causal attribution，選出最早且對終端失敗負責的步驟。其創新在於把局部錯誤發生、錯誤生命週期與最終責任分離處理。

## 核心貢獻
1. 提出 TRAJDEBUG 三階段 error-lifecycle tracing framework，將 critical error detection 分解為 error trigger detection、error state classification 與 candidate-set-guided causal attribution。
2. 建立 TRAJERRBENCH，收錄 486 條來自 τ2-Bench 與 SWE-Bench Pro 的人工標註失敗 trajectory，涵蓋工具使用、使用者互動與長期 coding 情境。
3. 透過逐 trajectory repair 與 failure-memory transfer 實驗，驗證 critical-error diagnosis 不僅能定位錯誤，也能產生可改善 agent success 的 actionable feedback。

## 技術方法

TRAJDEBUG 的輸入是已知失敗的 agent trajectory，且不使用 success trace、gold outcome 或額外 debugging signal。首先，系統以 LLM 為每一步建立三種 history view：high-detail view 保留指令、action、observation 與局部 reasoning；medium-detail view 摘要 intent、action 與 state update；low-detail view 僅保留進度、重要 entity 與未解決 commitment。Error trigger detection 逐步尋找可由原文引用支持的 mismatch，形式包含錯誤 commitment、被違反 reference、reference category 與 execution phase；reference 可來自 task instruction、trajectory history、同一步內容或 environment anomaly。接著，系統依共享的 reference object 將重複 trigger 聚成 error instance，並判斷 wrong commitment 是 resolved 或 active，以及是否留下 terminal footprint。footprint 包括 irreversible state change、persistent semantic violation，或超過 trajectory 50% 的 budget debt，形成 Clean Resolution、Costly Resolution、Manifest Active 與 Latent Active 四種狀態；僅保留 Costly Resolution 與 Manifest Active 作為候選。最後由 LLM attribution head 在候選 instance 中選出最能解釋 terminal failure 的 instance，輸出其最早步驟；必要時可在嚴格證據要求下進行 out-of-set fallback。評估主要採 exact critical-step accuracy，另報告非對稱 [GT−3,GT] 與對稱 [GT−5,GT+5] localization window。TRAJERRBENCH 有 486 條人工標註失敗 trajectory，其中 τ2-Bench 400 條、SWE-Bench Pro 86 條；每條由三名 annotator 標註並以至少兩人同意形成標籤。

## 對我們的啟發
- [ ] 長期 agent 的除錯不宜只做整條 trajectory 的 holistic judgment；可先以多層次摘要保留遠距脈絡，再以原文證據核驗局部錯誤。
- [ ] 錯誤是否出現不等於錯誤是否造成失敗；應分別追蹤錯誤是否被修復、是否留下不可逆或語意上的 terminal footprint，以及是否消耗大量 recovery budget。
- [ ] 在實務部署中，可將成功定位的 critical error 轉成針對特定步驟的修復指引，或彙整為 failure memory；論文結果顯示這類診斷可支援同任務重試與跨任務遷移。

## 限制與未來工作

作者指出，TRAJDEBUG 仍依賴 LLM 進行錯誤解讀與最終 attribution，會受模型推理能力、domain knowledge 與 calibration 影響。分階段流程也可能因前段 trigger detection 或 state classification 的 false negative 而漏掉真正錯誤；錯誤分析顯示主要失敗來自 Trigger Miss 與 Attribution Miss。
