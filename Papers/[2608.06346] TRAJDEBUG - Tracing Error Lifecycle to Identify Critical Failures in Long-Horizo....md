# TRAJDEBUG: Tracing Error Lifecycle to Identify Critical Failures in Long-Horizon Agent Trajectories

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.06346)
- 📥 [PDF](https://arxiv.org/pdf/2608.06346v1)

## 摘要（中文翻譯）

基於 LLM 的 agentic systems 已在複雜領域展現出強大能力，但也受到 cascading errors 與難以除錯的困擾。Critical error detection 的目標，是在失敗 trajectory 中定位最早且對最終失敗負責的錯誤步驟。此任務有兩項挑戰：長 trajectory 使判斷單一步驟所需的證據分散於遠距的指令、觀察與歷史脈絡；失敗 trajectory 也常包含多個 downstream effect 不同的 local errors，其中部分會被修復、部分無害，只有少數真正導致最終失敗。本文提出 TRAJDEBUG，一個透過 multi-granularity history compression 與 evidence-based error identification 進行長 trajectory 錯誤發現的 error-lifecycle tracing framework，並藉由追蹤每個錯誤的 resolution status 與 terminal impact 進行 critical attribution。作者另建立 TRAJERRBENCH，收錄來自 τ2-Bench 與 SWE-Bench Pro 的 486 條人工標註失敗 trajectory，涵蓋 realistic tool-use 與 coding 情境。實驗顯示 TRAJDEBUG 整體優於既有 baseline，其診斷也能轉化為改善 downstream agent success 的 actionable feedback。

## 問題背景

論文要解決長 horizon LLM agent trajectory 中的 critical error detection：從失敗執行記錄找出最早、真正造成終端失敗的步驟。現有方法或以整條 trajectory 做 holistic judgment，容易受長 context 與分散證據影響；或只偵測 taxonomy/constraint violations，無法區分已修復、無害與持續導致失敗的錯誤；causal attribution 方法則可能把後續 feedback、repair 與多重錯誤的影響判斷得不明確。

## 解決方案

TRAJDEBUG 將除錯建模為 error lifecycle tracing，而非單次整體判斷。第一階段透過 multi-granularity history compression 保留局部原文證據並壓縮遠距歷史，再以 verbatim evidence 驗證每個 error trigger。第二階段依共同 violated reference object 將重複 trigger 聚合為 error instance，追蹤錯誤是否 resolved，以及是否產生 irreversible、semantic 或 budget-debt terminal footprint。第三階段僅在具 terminal relevance 的候選集合上進行 LLM causal attribution，選擇最能解釋終端失敗的 instance 起始步驟。核心創新是把錯誤發現、生命週期狀態與終端責任分離，降低長 context 與多重局部錯誤造成的混淆。

## 核心貢獻
1. 提出 TRAJDEBUG 三階段 error-lifecycle tracing framework，將 critical error detection 分解為 error trigger detection、error state classification 與 candidate-set-guided causal attribution。
2. 建立 TRAJERRBENCH，包含來自 τ2-Bench 的 400 條與 SWE-Bench Pro 的 86 條人工標註失敗 trajectory，平均長度分別為 29.3 與 119.7 steps。
3. 在多個 agent benchmark 上驗證方法，並展示其診斷可用於 per-trajectory repair 與 failure-memory transfer，提升後續任務成功率。

## 技術方法

輸入是一條已知失敗的 trajectory τ=(x1,…,xN)，每個 step 可包含 reasoning、action 或 environment response。作者將 critical error 定義為：若以正確行動替換該步、保留此前步驟並讓後續正確展開，任務即可成功；critical step 是最早的 decisive error。TRAJDEBUG 首先用 LLM 為每個步驟建立三種歷史視圖：high-detail 保留原始 instruction、action、observation 與局部 reasoning；medium-detail 摘要 intent、action 與 state update；low-detail 僅記錄進度、重要 entities 與 unresolved commitments。接著進行 error trigger detection，找出具備可逐字引用證據的錯誤承諾與違反 reference，reference 可來自 task、history、intra-step 或 environment anomaly。相關 triggers 依共同 violated reference object 聚合成 error instance。對每個 instance，分類其是否已被後續明確修復，以及是否留下 terminal footprint：不可逆狀態改變、持續語義違規或超過 trajectory 50% 的 budget debt，形成 Clean Resolution、Costly Resolution、Manifest Active 與 Latent Active 四種狀態。只有 Costly Resolution 與 Manifest Active 進入候選集合，最後由 LLM attribution head 根據 origin step、狀態、footprint 與逐字證據選出 critical step。資料集共 486 條人工標註失敗 trajectory，三位 annotators 以至少兩方一致作為標籤；τ2-Bench 的 Fleiss’ κ 為 0.91，SWE-Bench Pro 為 0.67。主要指標是 exact critical-step accuracy，另報告非對稱與對稱容許窗口，以及將診斷轉為 feedback 後的 task success rate。

## 關鍵結果

主要結果如下；exact critical-step accuracy 僅在預測與人工標註步驟完全一致時算正確。

| 方法 | τ2-Bench | SWE-Bench Pro | 七個資料子集平均 |
|---|---:|---:|---:|
| Qwen3-235B-A22B direct prompting | 42.75% | 17.44% | 25.69% |
| AgentDebugger | 26.00% | 10.47% | 23.72% |
| CHIEF | 26.82% | 2.32% | 18.77% |
| AgentRX | 36.25% | 5.81% | 23.10% |
| TRAJDEBUG | **52.75%** | **24.41%** | **34.11%** |

TRAJDEBUG 在七個資料集中的五個取得最高準確率；相較使用相同 backbone 的 direct prompting，平均提升 8.42 個百分點。在最長的 SWE-Bench Pro（平均 119.70 steps）上，TRAJDEBUG 比相應 direct baseline 高 6.97 個百分點。消融實驗中，移除 multi-granularity compression 後平均準確率由 38.58% 降至 17.56%；移除 evidence-grounded triggers 與 error state classification 後，平均分別降至 33.59% 與 31.27%。在 per-trajectory repair 情境，平均 success rate 由 78.07% 提升至 88.87%，平均提升 10.80 個百分點；failure-memory transfer 則報告平均提升 5.70 個百分點。作者亦報告 automated-intervention window [GT−3, GT] 的平均準確率為 50.2%。

## 對我們的啟發
- [ ] 實務除錯不應只尋找第一個局部錯誤，還應追蹤錯誤是否被修復、是否留下不可逆或語義上的 terminal footprint，以及是否造成 recovery budget debt。
- [ ] 對長 trajectory 採用 high、medium、low 三種粒度的歷史視圖，能在保留可核驗局部證據的同時降低遠距 context 的干擾；這可作為 agent observability pipeline 的設計原則。
- [ ] 若診斷結果要用於 agent 改進，應輸出具體步驟、違反的 reference、終端影響與可執行修復建議，而非僅提供抽象 failure category；論文的 feedback 實驗支持這種設計。

## 限制與未來工作

論文指出，TRAJDEBUG 仍依賴 LLM 進行錯誤解讀與最終 attribution，可能受 reasoning ability、domain knowledge 與 calibration 影響。分階段 pipeline 也可能因早期 trigger detection 或 state classification 的 false negative 而漏掉真正 critical error；錯誤觸發與 attribution miss 分別占失敗案例的 42.1% 與 40.1%。
