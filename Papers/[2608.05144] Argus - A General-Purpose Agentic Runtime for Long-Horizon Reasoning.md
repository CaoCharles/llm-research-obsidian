# Argus: A General-Purpose Agentic Runtime for Long-Horizon Reasoning

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.05144)
- 📥 [PDF](https://arxiv.org/pdf/2608.05144v1)

## 摘要（中文翻譯）

長程推理並非沿著固定路線不斷前進；當證據支持目前方法時，代理應持續執行，而當量測揭示失敗、隱藏限制或目標設定錯誤時，則應能轉向。我們提出 Argus，一個持久且可自我演化的 agentic runtime，由 Manager、Planner、Engineer 與 Reviewer 在可持久化的 project state 上執行有界 missions。Argus 將穩定的 user intent 與可由證據修正的 operational objectives、constraints 和 verification criteria 分離。候選 memories、skills、procedures、verifiers、routing decisions 及 rejected routes，只有經角色負責的審查及可用時的 task-native verification 後，才能納入持久狀態。模型權重保持固定，自我演化透過 runtime state 與 control policy 實現。Argus 在七個 GPT-5.5 benchmark arenas 中，SWE-Bench Pro 約達 78%，高於 Direct Copilot 的 59%，但使用 1.41 倍 aggregate tokens。經 verification-gated self-evolution 後，成熟 SWE-Bench waves 的 solve-input tokens 減少 21%，active workflow time 減少 15%。結果顯示，固定權重的 self-evolving harness 能修正、恢復並累積經驗。

## 問題背景

長程研究常遇到目標逐步釐清、路線失敗、隱藏限制與規格錯誤。傳統 ReAct、SWE-agent、OpenHands 及 autonomous research systems 多假設 objective 已給定，session 受限的代理又會因 context 壓縮或重置而遺失證據。若允許代理任意改變目標，最終結果便難以區分 evidence-backed pivot 與失敗後合理化，造成 goal drift；只固定目標則無法處理真實任務中的 objective refinement。

## 解決方案

作者提出 Argus，一個在 durable project state 上運行的 persistent、self-evolving agentic runtime。其核心是 bounded missions 與四角色權責分離：Manager 管理 intent、contract 和 Stage，Planner 分解任務，Engineer 執行，Reviewer 驗證。系統將 standing user intent 與 operational objective、constraints、verification criteria 分離；任何 material pivot 或 runtime-state 更新，都必須由適當角色審查，並在可用時透過 task-native verifier 證明。候選 memories、skills、procedures、verifiers、routing decisions 與 rejected routes 只有通過 admission gate 才能累積。模型權重不變，但 persistent state 與 control policy 會改變後續搜尋路徑；Stage rollback、blocked verdict 與完整 provenance 則使失敗成為可重用的決策資料。

## 核心貢獻
1. 提出以 Kt=(ι,ot,ct,vt) 表示的長程任務 working contract，區分 standing user intent、operational objective、constraints 與 verification criteria，並以 ManagerAdmit 概念描述證據、權限與 provenance 約束下的 contract refinement。
2. 建立由 Manager、Planner、Engineer、Reviewer 組成的 persistent agentic runtime，以 bounded missions、durable project state、Stage advance/rollback、角色所有權及獨立審查支援 verified pivoting。
3. 提出 verification-gated fixed-model runtime self-evolution：模型參數固定，但經審查的 memories、skills、verifiers、routing decisions 與 rejected routes 可持久化，並以 SWE-Bench Pro 長期軌跡及多個研究垂直案例評估其累積效果。

## 技術方法

Argus 以固定模型權重搭配持久 runtime state 運作。系統包含三個平面：control plane 負責 campaign、排程與 Stage；execution plane 執行 bounded mission；record plane 保存不可變 event record，但不負責判定科學完成。四個 model-driven roles 分工：Manager 維持 standing intent、objective、route 與 Stage；Planner 根據 backlog、runtime state 與 contract 分解任務；Engineer 修改 artifacts、呼叫 tools、執行實驗並回報 measurements；Reviewer 在要求時獨立檢查 artifacts 與 execution records，輸出 done、continue 或 blocked。每輪流程為 M→P→E⇄R→M：Planner 領取一項 bounded task，Engineer 執行，依任務政策進行 Engineer self-review 或 Reviewer review；若 continue 則修正後重做，若 done/blocked/paused 則回到 Manager。系統以 CHECKPOINT.md、artifacts、event log、backlog、memory、skills、tools、verifiers 與 routing 保存跨 session 狀態，並支援 Stage advance、hold、rollback 及 rejected branch。作者以 Kt=(ι,ot,ct,vt) 表示 working contract；若量測與 verdict 支持 material refinement，須經 ManagerAdmit、所需 authority 與 provenance 才更新 contract。評估涵蓋七個 benchmark arenas，包括 SWE-Bench Pro、GPU kernel、language-model training、training speed、research-assistant tasks 與 mathematical data synthesis；另分析 731 個 SWE-Bench Pro tasks 的 tokens、active workflow time、Reviewer intervention、verifier recoveries，以及數學 campaign、paper pipelines 與 upstream kernel adoption。論文也提出 density、research value、process-data dominance 與 discounted reuse value 等理論量，但並非所有量皆以跨任務 controlled experiment 驗證。

## 對我們的啟發
- [ ] 長程代理不應只保存最終答案；應保存帶有量測、審查結果、失敗路線與 provenance 的結構化狀態，讓後續任務能避免重複探索。
- [ ] 目標修改需要明確區分 user intent 與 operational contract，並由證據、角色權限及可追溯紀錄共同約束，以降低 goal drift 風險。
- [ ] 實務部署可採 bounded mission 與明確 escalation point：低風險任務允許 Engineer self-review，高風險或 stage-closing 任務要求獨立 Reviewer，並保留 rollback 與 blocked 狀態而非強迫宣稱成功。

## 限制與未來工作

論文將 runtime self-evolution 的縱向結果明確定位為 observational，而非 controlled ablation，因此無法單獨識別 persistence、Reviewer 或 routing 各元件的因果貢獻。部分案例是內部或質性證據，且未提供 measured zero-touch rate。某些 benchmark reference、完整比較設定與數據規模在提供內容中未報告；未來需進行更嚴格的消融、成本與跨任務 reuse 評估。
