# Enhancing Virtual Agents through SLMs and Edge-Computing: An Exploratory Evaluation of Think and Memory Processes

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.13420)
- 📥 [PDF](https://arxiv.org/pdf/2608.13420v1)

## 摘要（中文翻譯）

具身智能虛擬代理人需要在複雜的虛擬世界與 Metaverse 中持續運作、適應環境並理解上下文，但其認知能力的實作仍具概念與技術挑戰。本文以 Cognitive Embodied Agent Architecture（CEAA）為基礎，探索 Small Language Models（SLMs）在 edge computing 環境中支援 CEAA「Think」與「Memory」流程的可行性。作者在 NVIDIA Jetson Orin NX 上建置 edge-based virtual agent gateway，使用不同尺寸的 Qwen2.5 模型，評估其服務請求 routing、結構化記憶讀取與延遲。模擬實驗顯示，SLM 驅動的原型系統可部分實作 CEAA 的認知協調與記憶處理，讓虛擬代理人的部分認知後端能在資源受限的 edge 環境中，以具情境性的方式運作。

## 問題背景

虛擬代理人常以 scripted behavior、rule-based flow 或 symbolic game AI 運作，雖能處理預定情境，卻難以適應動態輸入、維持跨互動連續性，並整合 perception、memory、reasoning、planning 與 action。大型模型又可能不適合 edge-based、低延遲與資源受限環境。因此本文探討 SLM 是否能在 edge 上部分支援 CEAA 的 Think 與 Memory，完成服務 routing 與結構化記憶處理。

## 解決方案

作者建置 edge-based virtual agent gateway，將 Qwen2.5 SLM 作為 CEAA 認知後端的一部分。Think 以互動意圖分類及服務 routing 實作，模型依使用者請求在 conversation、memory 操作與十種虛擬世界服務間選擇路徑，並輸出結構化 JSON。Memory 則結合 Qwen2.5、LangMem 與 SQLite，從每輪互動抽取可持久化 fact，依 session、時間與內容鍵保存，並透過 relevance 與 recency 決定讀取內容，再交由模型生成回答。核心創新不是完整 CEAA 或完整 embodied cognition，而是以不同 SLM 尺寸在單一 edge 裝置上，實證比較認知 routing、記憶讀取與延遲的取捨。

## 核心貢獻
1. 部分實作 CEAA 的 Think 與 Memory 流程：以服務 routing 代表認知協調，以結構化 fact 的寫入與讀取代表記憶處理。
2. 在 NVIDIA Jetson Orin NX 8GB edge 硬體上，比較 Qwen2.5 0.5B、1.5B 與 3.0B Instruct 模型在 routing、記憶讀取、結構化輸出與延遲方面的表現。
3. 提供受控實驗的初步證據，說明部分虛擬代理人後端認知流程可在本地端運作，但模型尺寸與準確性、反應速度之間存在明顯取捨。

## 技術方法

作者將 Unity-based InterwovenXR 虛擬世界 testbed 與外部 edge-hosted gateway 串接；Unity 負責 embodied-agent 介面，gateway 負責 language processing、memory management、route selection 與 service dispatch。硬體為 NVIDIA Jetson Orin NX 8GB，模型為 Qwen2.5 0.5B、1.5B、3.0B Instruct 的 GGUF Q4_K_M quantisation，透過 llama.cpp 本地服務，context 為 4,096 tokens，最多生成 420 tokens。每個 HTTP request 包含 user prompt 與 session id。模型先將互動分類為 conversation、memory-read、memory-write、service request 或 ambiguous；服務請求則輸出包含 route、intent、confidence 與 rationale 的 JSON。十個預先配置的 route 以每類 100 個、共 1,000 個經作者審閱的 prompts 評估，計算 accuracy、macro precision、macro recall、macro-F1、invalid-output、timeout，以及 mean、median、P95 latency。記憶流程中，所有 session turns 存入 SQLite，LangMem 使用同一模型抽取 concise durable facts，並以 content-keyed items、session id、timestamp 與 metadata 保存；重複 fact 更新既有項目，非一致修正則保留為較新紀錄。記憶測試包含 125 個 fact-introduction turns 與 125 個配對問題，評估 end-to-end read accuracy、memory-write label recall、service leakage 與端到端延遲。答案由 ChatGPT 5.5 High Reasoning 依固定 prompt 評估，再由作者以 model-blinded 方式人工審查。

## 關鍵結果

| 模型 | Routing 準確率 | Routing macro-F1 | Routing 平均延遲 | Memory read 準確率 | Memory-write label recall | Memory 平均延遲 |
|---|---:|---:|---:|---:|---:|---:|
| Qwen2.5-0.5B | 29.4% | 28.9% | 1,504 ms | 72.8%（91/125） | 1.6% | 2,025 ms |
| Qwen2.5-1.5B | 85.4% | 84.3% | 3,349 ms | 78.4%（98/125） | 5.6% | 3,794 ms |
| Qwen2.5-3.0B | 87.7% | 87.8% | 5,067 ms | 93.6%（117/125） | 63.2% | 9,693 ms |

Routing 實驗使用 1,000 個 prompts、10 個 route，每類 100 個。3.0B 的 routing P95 延遲為 6,159 ms，memory P95 延遲為 14,531 ms；其 routing 無 invalid output。0.5B 的 routing accuracy 僅 29.4%，主要出現 route collapse；3.0B 的 memory read accuracy 最高，但延遲顯著增加。論文未報告下游服務實際執行成功率、完整 embodied interaction 的使用者評估，或與 keyword routing、embedding similarity、task-specific fine-tuned SLM 的比較結果。

## 對我們的啟發
- [ ] 若應用重點是服務選擇，1.5B 模型在本文設定下提供較佳的 routing 與延遲折衷；但實際部署仍需依任務需求驗證。
- [ ] 記憶系統的端到端表現不只取決於生成模型，也受到互動分類、fact extraction、persistence、retrieval 與 response generation 共同影響，因此應分階段監測錯誤。
- [ ] 可考慮模組化或 hybrid 配置：以較小模型處理低延遲 orchestration，將記憶密集或語意較複雜的任務交由較大模型；這是根據本文結果提出的實務洞察，而非作者已驗證的部署方案。

## 限制與未來工作

研究僅在受控 test-bed、單一 Jetson Orin NX 8GB 設定與三個 Qwen2.5 變體上進行，且只涵蓋 CEAA 的 Think 與 Memory 部分流程。Prompt 可能無法代表不可預測的真實使用者行為；LLM-as-a-judge 亦可能存在評估偏差。延遲未拆分各處理階段，也未進行完整 embodied user study。未來應比較非生成式 routing 與微調模型，分別評估 extraction、retrieval、correction 與答案正確性，並擴充長期及多類型記憶。
