# Incremental Pooled LLM Evaluation for Cost-Effective Retrieval Model Selection

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2609.02745)
- 📥 [PDF](https://arxiv.org/pdf/2609.02745v1)

## 摘要（中文翻譯）

在 production RAG 系統中選擇 retrieval model，需要可靠的比較評估；然而，大規模取得 relevance judgments 成本高昂，且新候選系統加入後難以重複執行。本文研究 pooled LLM evaluation：由 LLM 評估目前候選系統所檢索文件的聯集；當新系統加入時，只評估其新增文件，並重用既有 judgments，以共同基準計算所有系統的 IR 指標。作者在四個 retrieval benchmarks、涵蓋 dense、sparse 與 hybrid 的 11 個系統上驗證方法，並在 financial news QA 系統中比較 62 種 retrieval configurations。Pooled LLM rankings 與 gold-standard evaluation 高度相關；納入 qrels 的 bootstrap uncertainty 後，97% 的 pairwise system orderings 得以保留。Production 實驗因文件重疊達到 65–80% judgment reuse，評估成本最高降低 4.9 倍，顯示此方法適合 deployed systems 的增量式 retrieval model selection。

## 問題背景

Production RAG 需要反覆比較新的 embedding、dense、sparse 或 hybrid retrieval systems，但傳統 human relevance judgments 成本高、速度慢，難以隨候選系統增加而重建。逐一評估 N 個系統需對 queries×top-k 文件重複判斷，即使不同系統檢索到大量相同文件也無法有效重用；傳統 TREC pooling 又可能把新系統帶來的未判斷文件視為不相關，造成 pool bias。

## 解決方案

作者提出 incremental pooled LLM evaluation。先對所有候選系統檢索結果的文件聯集進行一次 LLM relevance judging，再以共享 judgments 計算每個系統的標準 IR metrics。新系統加入時，只判斷其檢索結果中尚未存在於 pool 的 (query, document) pairs，既有標註完全重用。核心創新在於將 pooling、LLM-as-judge 與增量式 pool growth 結合，以文件重疊降低成本，同時透過判斷新文件避免傳統 pooling 對新穎 retrieval behavior 的系統性懲罰，並以 bootstrap uncertainty 與 permutation tests 檢驗排名可靠性。

## 核心貢獻
1. 提出可隨候選 retrieval systems 增加而擴張的 incremental pooled LLM evaluation workflow，只判斷新系統貢獻的文件並重用既有 qrels。
2. 在四個公開 retrieval benchmarks 上，以 system-level rank correlation、pairwise agreement、bootstrap uncertainty 與 pool-growth permutation tests 驗證排名可靠性；nDCG@10 的 Spearman ρ 為 0.69–0.95。
3. 在 financial news QA production system 中以 pooled judging 評估 62 種配置，達到 79.6% judgment reuse 與 4.9× cost reduction，並直接支援 production retrieval model selection。

## 技術方法

方法以每個 query 從 11 個 retrieval systems 取得 top-100 documents，形成文件聯集 P(q)。對每個唯一的 (q,d) pair 使用 GPT-4.1（temperature 0）獨立判斷，採 3-point graded relevance：0 為不相關、1 為部分相關、2 為高度相關；輸出 JSON，並要求不超過兩行的 reasoning。系統評估時，僅取該系統排名清單中的共享 judgments，計算 P@k、Recall@k、nDCG@k 與 MAP，並與 published human qrels 比較。實驗涵蓋 FiQA、TREC-COVID、Natural Questions 與 FinRAGBench-V；retrieval configuration 包含五個 embedding model families 的 dense、hybrid（dense+sparse 的 reciprocal rank fusion）及 BM25 sparse baseline，支援文本、表格與圖形描述的 layout-aware 處理。作者另以 Claude Sonnet 4.6 檢驗 cross-judge agreement，使用 10,000 次 query bootstrap 估計 pairwise swap probability，並以 500 個隨機系統加入順序測試 pool expansion 的排名反轉。成本以 pooled unique pairs 對比獨立評估的 N×Q×K judgments，reuse rate 為節省比例。

## 對我們的啟發
- [ ] 若團隊會持續加入 embedding 或 query variants，可先以 3–5 個系統建立基礎 pool，之後只評估新系統帶來的 unique (query, document) pairs，以降低重複成本。
- [ ] 模型選擇應同時查看 ranking margin 與 bootstrap uncertainty；當系統差距小於約 0.001 nDCG 時，論文證據顯示 qrels 與 pooled labels 都可能無法可靠區分，不宜過度解讀名次。
- [ ] LLM relevance labels 的絕對分數可能存在資料集與 metrics 的 calibration bias，因此較適合用於相對排序與候選篩選；若要作跨資料集或跨評估活動的絕對品質比較，仍需 human qrels 校準。

## 限制與未來工作

研究主要依賴單一 GPT-4.1 judge；Claude Sonnet 4.6 的完整重判只涵蓋 TREC-COVID。系統範圍限於 single-stage dense、sparse 與 hybrid retrievers，未測試 reranker 或 cross-encoder。macro-averaged rankings 的 pool-growth invariance 只有經驗支持；近乎並列的系統仍可能反轉。
