# EarlyEval: Cheaper Agent Evaluation via Early Outcome Prediction

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2609.02783)
- 📥 [PDF](https://arxiv.org/pdf/2609.02783v1)

## 摘要（中文翻譯）

評估 LLM agents 對其開發至關重要，但成本已高到難以負擔：frontier model 在 agent benchmark 上單次執行可能花費數百至數千美元，且會在反覆開發週期中重複支付。既有方法主要透過 benchmark distillation 減少評估任務數量，卻未降低保留任務的單次執行成本。本文提出 early outcome prediction，作為另一個效率維度，直接削減每項任務內的執行成本。核心觀察是：agent 的最終結果通常可由中間行為在執行完成前預測。作者實作 EarlyEval，以 behavioral、textual 與 reference-solution features 訓練一對 LightGBM success／failure classifiers，當任一分類器跨過校準信心門檻時即停止 agent run，且每步額外成本極低。在 SWE-bench Verified、TerminalBench 與 Toolathlon 上，EarlyEval 在 89%–97% prediction accuracy 下，可減少 13%–26% agent steps，最多降低 44.1% input tokens 與 29.4% output tokens；每個 agent 的 resolve rate 平均僅改變一至兩個百分點。

## 問題背景

LLM agent benchmark 需要多步互動、工具呼叫與不斷增長的上下文，因此單次評估成本可達數百至數千美元；在 prompt、scaffold 或模型反覆迭代時，成本尤其突出。既有 benchmark distillation 只減少任務數量，未處理每個保留任務的 rollout 成本。本文要解決的是：能否根據部分 trajectory，在 agent 完成前可靠推斷最終 success／failure，並降低執行步數與 token 消耗，同時維持 resolve rate 與 agent ranking 的評估忠實度。

## 解決方案

作者提出 EarlyEval，一種在單一 benchmark task 內進行 early outcome prediction 的 plug-and-play framework。它從歷史上已完成且具 outcome labels 的 agent trajectories 建立 prefix-level 訓練資料，並以 behavioral、textual 及可選的 reference-solution features，訓練分離的 LightGBM success predictor 與 failure predictor。線上執行時，每一步重新抽取部分 trajectory features，經 Platt scaling 得到兩個 calibrated confidences；只要任一信心值達到預設 threshold，便立即停止 rollout 並記錄預測結果，否則繼續執行。核心創新是把 evaluation efficiency 從減少任務數量擴展到縮短每項任務，並以 dual-threshold 控制成本與 fidelity 的 trade-off。

## 核心貢獻
1. 提出 early outcome prediction，將 agent evaluation 的效率改善從 benchmark-level task selection 擴展到 task-level rollout early stopping，與 benchmark distillation 互補。
2. 提出 EarlyEval framework，以兩個 LightGBM success／failure classifiers、豐富的 behavioral／textual／reference-solution features，以及 calibrated dual-threshold halting rule 實現低額外開銷的逐步預測。
3. 在 SWE-bench Verified、TerminalBench 與 Toolathlon 上採用 leave-one-agent-out protocol，證明可降低 steps 與 token 消耗，同時大致維持 per-agent resolve rates 與 leaderboard rankings。

## 技術方法

問題形式化為：agent 在 task 上產生 trajectory τ=(e1,…,eT)，完整執行後得到 binary outcome y；EarlyEval 在 k<T 時根據 prefix τ:k 預測 y，必要時提早終止。離線階段收集目標 benchmark 上多個 agent 的完整、具標籤 trajectories，將每條長度 T 的 trajectory 展開為 prefixes，長度不足 10 steps 者丟棄；prefix instances 以 1/(T+1) 加權，避免長 trajectory 主導訓練。特徵分三類：behavioral features 包含活動計數、最近一步、事件時間、工作模式、錯誤與測試狀態；textual features 對 task prompt、action history／recent action、environment feedback／recent feedback 分別以 TF-IDF、word unigram/bigram、SVD 向量化；SWE-bench Verified 另加入 gold descriptors 及 prefix–gold overlap，無 reference solution 的 TerminalBench 與 Toolathlon 則移除該類特徵。模型是兩個 agent-agnostic LightGBM gradient-boosted tree ensembles，分別學習 success 與 failure；採 leave-one-agent-out，並按 trajectory（且按 task 分割）避免洩漏。 validation split 用於 early stopping 與 Platt scaling，將原始分數轉為 calibrated probabilities。線上每步同時評估 p+ 與 p−，若 p+≥s 或 p−≥f 即停止。指標包括 halted accuracy、各 predictor precision、coverage、ΔSteps、ΔToken in/out、每-agent ΔPass@1、平均絕對偏差 Δ|Pass@1|、Spearman ranking correlation ρ 與 ΔRank。

## 關鍵結果

作者在三個 benchmark、超過 21,000 條 outcome-labeled trajectories 上評估；主要結果如下：

| Benchmark／設定 | Threshold | 主要 EarlyEval 設定 | Steps 減少 | Input tokens 減少 | Output tokens 減少 | Prediction accuracy／Δ\|Pass@1\| |
|---|---:|---|---:|---:|---:|---:|
| SWE-bench Verified | 0.95 | Dual | 26.0% | 32.7% | 28.7% | 95.0%／1.1 pp |
| TerminalBench（no same model） | 0.90 | Dual | 25.4% | 42.7% | 27.9% | 論文未在表 III 的 Dual 欄報告 accuracy／2.1 pp |
| TerminalBench（no same scaffold） | 0.85 | Dual | 17.7% | 29.2% | 17.4% | 論文未在表 III 的 Dual 欄報告 accuracy／2.0 pp |
| Toolathlon | 0.90 | Failure-only | 23.0% | 44.1% | 29.4% | 論文未報告 Dual accuracy／0.9 pp |

在 SWE-bench Verified，threshold 0.95 時約 34.8% trajectories 被提前停止，success predictor precision 為 93.9%，failure predictor precision 為 96.7%；agent ranking 的 Spearman ρ=0.991，81% agents 維持完全相同名次。Toolathlon 的 failure predictor precision 為 96.6%，TerminalBench 在 no-same-model 與 no-same-scaffold 設定分別達 89.4% 與 91.8%；ranking ρ 分別為 0.959 與 0.994。降低 threshold 可增加節省但提高失真，例如 SWE-bench 從 0.95 降至 0.75 時，steps 減少由 26.0% 增至 63.4%，Δ|Pass@1| 由 1.1% 增至 4.1%。

## 對我們的啟發
- [ ] 若團隊在固定 benchmark 上反覆比較 agent 版本，可先以歷史完成 trajectories 訓練 outcome predictor，將 EarlyEval 作為開發迭代期的低成本篩選工具；正式、可引用的 benchmark 分數仍應完整執行。
- [ ] threshold 應依用途校準：論文結果顯示較高 threshold 具有較佳 fidelity、較低 threshold 則節省更多；可先設定可接受的 Δ|Pass@1| 上限，再選擇最低可行門檻。
- [ ] 不同 predictor 的可靠度與 scaffold shift 並不一致：failure predictor 在三個 benchmark 較穩健，而 TerminalBench 中未見過 scaffold 會削弱 success prediction，因此部署前應按 benchmark、scaffold 與 predictor 分別驗證。

## 限制與未來工作

EarlyEval 需要目標 benchmark 既有大量完整且具 outcome labels 的 trajectories；新 benchmark 在尚無歷史資料時無法直接使用。reference-solution features 只適用於提供 gold solution 的 benchmark。方法會造成約 1–2 個百分點的 resolve-rate 偏差，因此不應取代正式完整評估；此外，未提供的後續結果中，論文未報告更廣泛 benchmark、跨時間分布漂移或真實貨幣成本的完整驗證。
