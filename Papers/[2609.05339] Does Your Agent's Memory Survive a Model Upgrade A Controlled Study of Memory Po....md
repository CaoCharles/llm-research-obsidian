# Does Your Agent's Memory Survive a Model Upgrade? A Controlled Study of Memory Portability

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2609.05339)
- 📥 [PDF](https://arxiv.org/pdf/2609.05339v1)

## 摘要（中文翻譯）

模型升級是例行工作，但 memory migration 並非如此。Agent 即使沿用相同的 memory store，仍可能因新模型對舊筆記的解讀不同、混合 embedding 版本破壞 retrieval，或缺乏原始證據而無法修復，導致遺忘。本文比較四種記憶形式：保留完整歷史供長上下文閱讀的 LC-RAW、切分後進行 retrieval-augmented generation 的 RAG、由模型壓縮成自然語言筆記的 NOTES，以及正規化為固定 schema knowledge graph 的 KG-fixed。研究使用 48 個含隨機答案代碼的 synthetic histories、exact scoring，以及兩個參數少於 10B 的 open-weight models。結果顯示，KG-fixed 在 writer swap 後的 accuracy 僅變化 +0.0004 ± 0.0020；NOTES 則高度依賴模型，依 migration direction 產生 +9.91 或 −13.28 個百分點變化。RAG 的 50/50 混合 index 僅取得 4.96 個百分點增益，低於完整 re-embedding 的 11.90 個百分點。研究因此強調方向特定的 migration testing、嚴格隔離 embedding space，以及保留 source history 以支援 memory repair。

## 問題背景

論文探討 agent model upgrade 後，既有 memory 是否仍能被新模型正確使用。現有 memory 評估多聚焦於單一模型或 day-one accuracy，未充分區分 writer、reader、retrieval、embedding 與 repair 各階段的損失，也缺少對 writer swap 方向差異、部分 embedding migration 及無原始歷史時修復能力的系統比較。因此，系統可能在資料庫正常運作時悄然遺忘，開發者卻難以判斷問題來自記憶建構、檢索或閱讀。

## 解決方案

作者建立一個受控的 memory portability evaluation framework，將 agent 的歷史 X 固定，分離 writer、reader、embedder 與 repair source 的影響，並比較 LC-RAW、RAG、NOTES、KG-fixed 四種記憶格式。框架以 reader 使用自身建立的 store 作為基準，透過 Retained Performance After Swap（RPAS）衡量跨模型移轉後保留的效能，並以 Cost-to-Recover（CTR）評估不同修復方式達到 90%、95% 與 99% 目標的成本。核心創新是同時測試雙向 model migration、混合 embedding index、store-only 與 raw-retained repair，並用受控證據注入拆解 construction、retrieval 與 reader residual 的損失來源。

## 核心貢獻
1. 建立在相同歷史、相同資源限制與 exact scoring 下比較 LC-RAW、RAG、NOTES、KG-fixed 的 memory portability framework，並分別測量雙向 writer→reader migration。
2. 提出並實證 RPAS 與 CTR 兩項指標，分別衡量 inherited memory 的效能保留與達到新 reader 基準所需的修復成本。
3. 透過 embedding migration、受控 evidence injection 與 repair experiments，指出 NOTES 的主要損失來自 construction、RAG 的主要損失來自 retrieval，並證明 mixed embedding index 與 store-only NOTES repair 的風險。

## 技術方法

研究使用 48 個 synthetic histories，每個 history 含 160 個涵蓋直接事實、時間變化、矛盾、多步關係與 aliases 的問題；entity 與 answer value 採 randomized codes，以避免模型依靠 pretraining，並使用 exact-match scoring，不使用 LLM judge。測試兩個 locally served open-weight models：Llama-3.1-8B-Instruct 與 Qwen2.5-7B-Instruct-1M，採 deterministic reads、低 temperature writes 與固定 seeds。四種格式包括完整歷史的 LC-RAW、以約 512 characters 事件 chunk 並取 cosine top-k=8 的 RAG、受 128 KiB 上限的模型生成 NOTES，以及共享固定 schema 的 subject-predicate-object KG-fixed。RAG embedding migration 比較 bge-large-en v1.0 與 v1.5 的舊 index、完整重嵌入、50/50 mixed index 和 ideal routing。評估指標包括 exact accuracy、直接 accuracy gap、RPAS、writer-swap penalty、retrieval recall、MRR，以及不同修復預算下的 CTR。主要計畫測試以每個 history 為獨立樣本，使用單樣本單尾 t-test、五個百分點 action threshold 與 Holm correction；另以 10,000 次 bootstrap 作後續檢查。診斷測試則分別提供正常 store、正確 stored item 與原始 event，以估計 retrieval、construction 與 reader residual 的損失。

## 對我們的啟發
- [ ] model upgrade 應被視為 memory migration；上線前應讓新 reader 直接讀取舊 store，且必須分別測試每個 migration direction，不能以雙向平均結果掩蓋單一方向的退化。
- [ ] 不同 embedding 版本即使維度相同也不代表位於相容空間；實務上應建立獨立的新 index，完成 full re-embedding 後再切換，或將不同向量空間隔離並按版本路由。
- [ ] 若採用 model-written NOTES，應保留受保護的 raw source history、記錄 writer、prompt、schema 與 embedding provenance，並預先以實際 repair model 測試恢復能力；若重視可修復性，固定 schema 或機械式重建流程更可靠。

## 限制與未來工作

研究僅測試兩個相近規模的 open-weight models、48 個 scripted synthetic histories，以及單一 dense retriever、chunking、top-k 與 embedding migration 設定，未涵蓋大型模型、自然長對話、主觀任務或更長歷史。KG-fixed schema 貼合此 workload，不能推論所有 knowledge graph 都具同等 portability。raw-history repair 也只在一個方向部分成功，且受 repair model 與 output limit 影響。
