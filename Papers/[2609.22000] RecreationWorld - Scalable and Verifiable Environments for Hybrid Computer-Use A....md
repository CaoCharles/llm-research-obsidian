# RecreationWorld: Scalable and Verifiable Environments for Hybrid Computer-Use Agents

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2609.22000)
- 📥 [PDF](https://arxiv.org/pdf/2609.22000v1)

## 摘要（中文翻譯）

Computer-use agents（CUAs）過去主要沿兩條路線發展：透過圖形介面操作應用程式，或透過程式碼與命令列進行軟體開發；然而真實數位工作需要兩者交錯整合。本文研究 hybrid CUAs，讓代理自主決定何時探索介面、實作軟體，以及執行並以視覺方式驗證成果。作者提出 RecreationWorld，一個涵蓋 Ubuntu、macOS、Windows、Android 與 Web 的五平台框架。代理取得一個可執行的 reference，需探索其行為並建造 faithful implementation，且沒有預設工作流程。Reference 可作為 oracle，產生隱藏行為測試與 execution-grounded reward。作者利用高品質 open-source applications 產生可驗證的長軌跡訓練資料；訓練後模型在五個 out-of-distribution coding 與 hybrid computer-use benchmarks 上提升，並更常驗證自身的 rendered outputs。本文亦提出 RecreationBench，包含跨平台 250 個任務，以 programmatic 與 visual assertions 評估多層次互動。GPT-6 Astra 的整體分數為 58.1%，但僅有 2.8% 任務通過全部 programmatic tests。結果顯示代理較能重現靜態介面結構，較難重現互動、計算輸出及複雜軟體結構。

## 問題背景

現有 computer-use benchmarks 多半分開評估 GUI 操作或程式碼開發，無法衡量代理在真實工作中反覆交錯探索介面、撰寫程式、建置執行與視覺驗證的能力。GUI-only 代理通常不能建構介面背後的軟體，terminal-only 代理則缺乏觀察自身輸出介面的能力。既有任務也缺少可大規模、客觀且 implementation-agnostic 的行為驗證，導致長期 hybrid coordination 與自我修正能力未被充分測量。

## 解決方案

作者提出 RecreationWorld，以 application recreation 作為 hybrid CUA 的統一任務：代理只能從執行中的 reference 探索行為，之後自行撰寫、建置、啟動並驗證候選實作，不受指定 workflow 限制。框架支援 Ubuntu、macOS、Windows、Android 與 Web，提供原生 GUI 控制、coding tools、隔離且可重現的 worker，以及可跨長時間 rollout 保存狀態的執行基礎設施。作者進一步提出 RecreationBench，從 reference 的可觀察行為產生隱藏 programmatic 與 visual tests，經 reference replay、穩定性過濾及人工審查後凍結，用於自動且可比較的評分。

## 核心貢獻
1. 提出 RecreationWorld，建立涵蓋 Ubuntu、macOS、Windows、Android 與 Web 的可重現 hybrid CUA 環境，統一支援原生 GUI 操作與 coding tools。
2. 提出以 running reference 為 oracle 的 test construction 與 RecreationBench，透過 programmatic、visual、action-conditioned 及多互動深度 assertions，提供 implementation-agnostic、execution-grounded 評估。
3. 以 35,000 條經 verifier rejection sampling 的 recreation trajectories 進行訓練，並在五個 OOD coding 與 computer-use benchmarks 上觀察到 transfer；同時以 250 個 held-out 任務量化現有模型在跨平台 recreation 上的行為與視覺差距。

## 技術方法

每個 recreation task 提供高層提示、可互動的 running reference、GUI 與軟體開發工具；代理反覆進行 explore、implement、build/launch、visual and behavioral verify 與 revision，最後提交符合平台 build/launch contract 的 source。桌面平台使用原生 accessibility API：Ubuntu 的 AT-SPI、macOS 的 AXUIElement、Windows 的 UI Automation；Android 使用 UiAutomator；Web 使用 DOM/ARIA。評估在乾淨環境重播固定 fixture、初始狀態與互動序列。Prog channel 讀取精確文字、widget state、navigation、persistence 與 computed values；VLM channel 在固定視覺檢查點，以 Qwen3.7-Plus、temperature 0 對 reference-grounded assertions 做 binary verdict。平台內以 application 為單位 macro-average，平台間等權平均，總平均為 Prog 與 VLM 的均值。資料方面，作者從 GitHub、F-Droid 與網站取得並固定版本的 open-source applications，排除訓練與測試重疊；以 Qwen3.8-Max 產生 rollout，透過 task-specific verifiers rejection-sample，每平台選取 7,000 條、共 35,000 條 trajectory，形成 SFT mixture。另評估十個 frontier models，並在 ProgramBench、GameCraft-Bench、Vision2Web、OSWorld 2.0 與 WeaveBench 檢驗 OOD transfer。

## 關鍵結果

主要結果如下：

| 結果項目 | 數據／觀察 |
|---|---:|
| RecreationBench 任務數 | 250（Ubuntu、macOS、Windows、Android、Web 各 50） |
| GPT-6 Astra 整體分數 | 58.06%（摘要四捨五入為 58.1%） |
| GPT-6 Astra Prog 分數 | 58.19% |
| GPT-6 Astra VLM 分數 | 57.92% |
| Claude Opus 5 整體分數 | 44.16% |
| GPT-5.6 Sol 整體分數 | 42.06% |
| GPT-6 Astra 通過 Prog ≥90% 的任務 | 17.60% |
| GPT-6 Astra 通過全部 Prog tests 的任務 | 2.80% |
| RecreationBench 平均 navigation depth | 22.8% 起始面、53.2% 1-hop、24.1% 2+ hops |
| 具有 interaction outcome 的測試案例 | 94.2%；其中要求 exact outcome 者為 40.7% |
| 訓練資料 | 每平台 7,000 條、共 35,000 條 selected trajectories |
| OOD transfer | 兩個訓練 run 在五個 OOD benchmarks 的最後 checkpoint 均高於首次測量 checkpoint；個別提升幅度最高達 17.9 個百分點 |
| 代表性 OOD 分數變化 | Qwen3.7-Plus：ProgramBench 41.9→44.6、GameCraft-Bench 17.9→26.5、Vision2Web 48.2→56.6、OSWorld 2.0 17.4→18.4、WeaveBench 35.7→48.2 |
| 行為變化 | 後期 checkpoint 更常進行 code verification、image inspection，以及 GUI observation/interaction；作者明確指出這些描述性變化不證明因果關係 |

作者另指出，代理通常比互動與計算輸出更容易重現靜態介面結構；生成應用程式相較 reference 明顯更小且更 monolithic。

## 對我們的啟發
- [ ] 若要評估實際軟體代理，不應只測 GUI click success 或程式碼測試通過率；應將探索、實作、執行、視覺檢查與修正放入同一個長期閉環。
- [ ] programmatic assertions 與 visual assertions 應互補使用：前者可檢查精確狀態與計算結果，後者可捕捉 accessibility tree 無法表達的版面、圖示、色彩與視覺層次。
- [ ] 以可執行 reference 產生固定隱藏測試，能降低逐候選人工評審成本；但實務部署仍需同時設計來源隔離、網路限制、replay 檢查與 provenance 偵測，以避免複製 reference 內容而非真正重建行為。

## 限制與未來工作

論文未提供受控的因果實驗，無法證明更多 GUI 探索、視覺驗證或 Bash 使用直接造成分數提升。Web 無法完全 source-blind，Android 仍有封裝檔可被取得的殘餘風險；VLM 評分依賴單一 Qwen3.7-Plus judge。測試範圍也排除了需登入或遠端服務的應用，且部分 isolation、provenance 偵測仍可能被繞過。
