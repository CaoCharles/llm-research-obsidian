    When AI Meets the Web: Prompt Injection Risks in Third-Party AI Chatbot Plugins

    連結

    • 📄 arXiv
    • 📥 PDF
    • 📎 本地 PDF: PDF

    摘要（中文翻譯）

    Prompt injection 攻擊對大型語言模型構成嚴重威脅，先前研究主要聚焦於前沿 LLM 應用（如個人 copilot）。相比之下，更簡單但更普遍的 LLM 應用（如客服聊天機器人）的安全態勢仍缺乏了解。這些應用大多依賴第三方聊天機器人外掛作為商業 LLM API 的中介。本文首次對 17 個被超過 10,000 個公共網站使用的第三方聊天機器人外掛進行大規模研究，揭示實務中先前未知的 prompt injection 風險。首先，8 個外掛（影響 8,000 網站）未強制驗證網站訪客與聊天機器人之間傳輸的對話歷史完整性，使攻擊者可偽造對話歷史（包括假系統訊息），將攻擊效果放大 3-8 倍。其次，15 個外掛提供網頁爬取等工具來豐富聊天機器人上下文，但未區分網站的可信內容（如產品描述）與不可信的第三方內容（如客戶評論），引入間接 prompt injection 風險。約 13% 的電商網站已將其聊天機器人暴露於第三方內容中。

    問題背景

    第三方聊天機器人外掛已廣泛部署於超過 10,000 個公共網站，但其安全態勢幾乎未被研究。這些外掛作為網站與商業 LLM API 的中介，引入了兩個先前未知的安全風險：(1) 對話歷史完整性缺失——攻擊者可偽造系統訊息放大攻擊；(2) 內容信任邊界模糊——爬取工具未區分可信與不可信內容。隨著此類外掛生態在 2025 年擴展約 50%，風險影響範圍持續擴大。

    解決方案

    透過大規模系統化安全評估揭示問題：(1) 分析 17 個外掛的網路通訊協議，識別對話歷史完整性漏洞；(2) 分析 15 個外掛的內容擷取工具，識別信任邊界缺失；(3) 在受控實驗中量化兩類漏洞的攻擊放大效果，考慮系統 prompt 設計和底層 LLM 等因素。研究為第三方 AI 外掛安全建立了首個系統化的評估框架。

    核心貢獻

    1. 首次對第三方聊天機器人外掛生態進行大規模安全研究，揭示 17 個外掛中 8 個存在對話歷史完整性漏洞（影響 8,000 網站），15 個存在內容信任邊界問題
    2. 發現對話歷史偽造可將直接 prompt injection 攻擊效果放大 3-8 倍，系統 prompt 提取成功率從約 0% 提升至 60%，任務劫持成功率從 0-25% 提升至 25-100%
    3. 量化真實世界的間接注入風險：約 13% 的電商網站已將聊天機器人暴露於第三方內容（如客戶評論），建立了攻擊面的實際規模估計

    技術方法

    外掛選擇與規模評估：掃描 2024 年 8 月 Common Crawl 資料，識別使用 17 個第三方外掛的網站（7 個 WordPress 外掛 + 10 個商業外掛）。隨機抽樣 200 個網站進行功能驗證，功能部署率 62.5%。

    漏洞 1（對話歷史偽造）：分析外掛的 HTTP 通訊協議，發現 8 個外掛未驗證對話歷史完整性。攻擊者可直接發送篡改的 POST 請求，注入偽造的系統角色訊息。在受控實驗中測試三類攻擊：系統 prompt 提取、任務劫持、工具劫持。

    漏洞 2（內容信任邊界）：分析 15 個外掛的內容擷取工具，發現它們自動攝取網站內容但未區分可信（產品描述）與不可信（客戶評論）來源。手動分析隨機電商網站，發現 13% 已暴露於此風險。

    受控評估：考慮系統 prompt 設計（有/無安全指引）和底層 LLM（不同模型的魯棒性差異）等因素。

    關鍵結果

    攻擊類型 正常條件 ASR 歷史偽造後 ASR 放大倍數
    系統 prompt 提取（user 角色注入） ~0% ~60%（system 角色注入） —
    任務劫持 0-25% 25-100% 3-8x
    工具劫持 — 20-100% —

    真實世界暴露： - 截至 2025 年 4 月，已識別 ~17,500 個聊天機器人網站 - 2025 年生態擴展約 50% - 7.5% 的網站位於 Tranco Top-1M - 部署涵蓋政府、教育、醫療、金融等關鍵領域 - ~13% 電商網站已暴露於第三方內容注入風險

    對我們的啟發

    • 第三方外掛作為 LLM 安全的薄弱環節被嚴重忽視——外掛開發者的不安全實踐（如未驗證對話歷史）可繞過 LLM 內建的安全防護，這暗示 LLM 安全需要延伸到整個供應鏈
    • 對話歷史完整性是 LLM 安全的基礎假設之一，一旦被破壞，攻擊效果可放大 3-8 倍，這為 LLM 部署架構設計提供了關鍵的安全要求：對話完整性必須在協議層而非應用層保證
    • 13% 的電商網站已暴露於間接注入風險，表明此問題已是現實威脅而非理論風險，需要外掛開發者和平台共同建立內容信任邊界標準

    限制與未來工作

    功能驗證依賴抽樣而非全面自動化，可能低估問題規模。系統 prompt 提取方法本身需利用所識別的漏洞，存在方法論上的循環。未涵蓋低資源語言部署和 Zendesk 等企業解決方案。研究時間點的快照性質——外掛生態快速演化可能使部分發現過時。
