# Test-Time Scaling in Reasoning LLMs: Inference Regimes, Evaluation, and Reproducibility

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.04001)
- 📥 [PDF](https://arxiv.org/pdf/2608.04001v1)

## 摘要（中文翻譯）

大型語言模型在推論時獲得更多計算量後，能解決更困難的推理問題。然而，test-time scaling 涵蓋多種不同的 inference algorithm：沿單一路徑延長 deliberation、取樣完整候選並以 voting 或 verification 聚合，或在未完成的 partial states 上進行 search。這些方法的統計結構、計算成本與失敗模式不同，不能以單一 budget 視為等價。本文以自回歸模型的 implicit prefix tree 為基礎，提出三種 inference regime：single-trajectory sequential scaling、leaf-level scaling with terminal reduction，以及 prefix-level scaling。作者進一步將完整 inference system 作為評估對象，區分 end-to-end performance 與 candidate-bank diagnostics，提出 evaluation profile、protocol-matched compute reporting 與 uncertainty reporting，並區分 exact replay 和 distributional reproducibility。研究也整理 open-weight reasoning ecosystem，於多類 benchmark 上實例化方法，並釋出大規模 reasoning traces 與 verifier、token-level signals。

## 問題背景

現有研究把單一路徑延長、完成候選取樣後聚合，以及 partial-state search 都稱為 test-time scaling，卻常以單一 budget 和最終 accuracy 比較。這忽略不同方法的 proposal distribution、計算成本、候選相依性與失敗模式，也未充分揭露 prompt、decoder、reducer、verifier、stopping rule 和不確定性，因此跨研究結果難以公平解讀與重現。

## 解決方案

作者提出以 implicit prefix tree 為核心的統一框架，按計算發生在單一路徑、完成 leaves 或 unfinished prefixes，區分三種 inference regime，並允許 hybrid systems。評估不只測 checkpoint，而是測完整 inference system；同時分離 candidate-bank 的發現與穩定性診斷、固定 bank 的 aggregation，以及含 stopping 的 causal end-to-end 效能。作者另提出 evaluation profile 與 protocol-matched compute/uncertainty reporting，並以 exact replay、distributional reproducibility 和可釋出的 traces、signals、manifests 規範重現性。

## 核心貢獻
1. 將 test-time scaling 統一形式化為在 autoregressive model implicit prefix tree 上、受預算約束的 inference，並區分 single-trajectory、leaf-level 與 prefix-level 三種結構性 regime。
2. 提出 system-level evaluation principles：將 checkpoint、prompt、decoder、controller/reducer、verifier/judge、budget 與 stopping rule 視為完整評估對象，並分離 end-to-end 結果與 candidate-bank 診斷。
3. 建立 reproducibility 要求，區分 exact replay 與 distributional reproducibility，說明所需的 prompt、解碼設定、seed、模型快照、執行環境與資料產物。

## 技術方法

作者以固定的 autoregressive model pθ 與輸入 x 為起點，將可生成的 finite prefixes 表示為 implicit rooted prefix tree T(x)，並把 inference algorithm A_B 定義為在累積成本不超過 B 下執行 token generation、prefix expansion、verifier/judge call、reduction 等操作。單一路徑 regime 只維持一個 unfinished prefix，由 controller 決定繼續、修改、控制或停止；leaf-level regime 從宣告的 decoding proposal qπ 產生完成候選 bank，再使用 self-consistency、verifier-constrained selection、Best-of-N 或 MBR reducer；prefix-level regime 維護 frontier 與 completed-leaf bank，依 likelihood、outcome value、PRM 或 rollout-based continuation value 進行選擇、擴展、pruning 與 backup，亦涵蓋 beam、best-first 與 MCTS-style search。評估上，作者將 prompt、decoder、sampling gates、temperature、top-k/top-p、seed、stop rule、evidence map、reducer、verifier/judge 與 budget 視為完整 protocol。指標包括 end-to-end accuracy、Acc.@1、Pass@k、all-correct@k、plurality、Best-of-N、ROC AUC，以及候選 bank 的 discovery/stability profile；不確定性使用與實際 protocol 相符的 bootstrap 或其他 interval。實驗涵蓋 broad-knowledge、symbolic reasoning、competition mathematics 與 field-balanced SuperGPQA，並保留完整 response、parsed answer、rule outcome、token alternatives、verifier records、環境與 manifest，以支援 exact replay 或 distributional reproducibility。

## 關鍵結果

論文提供的主要實驗數據如下；數值為作者報告的 descriptive results，且不同表格的成本未必包含 prompt tokens 或 verifier computation。

| Bank／模型設定 | Acc.@1 | Pass@8 | Pass@80 | String-Plur.@80 | Pointwise-BoN@80 |
|---|---:|---:|---:|---:|---:|
| Qwen3.6 | 83.12% | 91.70% | 94.62% | 89.25% | 86.56% |
| gpt-oss low | 32.90% | 56.14% | 72.58% | 45.70% | 58.06% |
| gpt-oss medium | 62.80% | 85.99% | 91.94% | 80.11% | 75.81% |
| gpt-oss high | 73.03% | 88.12% | 93.55% | 85.48% | 81.72% |

| Verifier signal | Trace-level ROC AUC |
|---|---:|
| Compass direct A | 0.983 |
| Compass contextual A | 0.977 |
| Reference-free pointwise Qwen | 0.871 |

在 3,600 題、72 個等量 field 的 SuperGPQA extension 中，gpt-oss high 的 mean accuracy 為 45.03%，Exact Pass@80 為 81.94%，而 all-correct@80 為 9.47%；650 題在 80 次回答中從未答對，341 題每次皆答對。論文亦報告四個 canonical bank 的 Pass@80 95% prompt-bootstrap intervals，但未提供所有 inference regime 的統一 end-to-end 數字。資料規模在文中有不一致表述：摘要寫「over 2 billion」full reasoning traces，貢獻段落與後文多處寫「over 2 million」；依提供內容無法消除此差異。

## 對我們的啟發
- [ ] 比較不同 test-time scaling 方法時，應同時報告生成 token、候選數、verifier/judge calls、搜尋節點與 wall-clock 或其他實際成本，不能只報一個 scalar budget。
- [ ] 若使用 Best-of-N、reranking 或 LLM judge，應把 verifier 的提示、模型、分數語義、tie-breaking、fallback 與 calibration 一併固定，因為候選數增加可能造成 proxy overoptimization，甚至使效能非單調。
- [ ] 應分開報告 Pass@k 等候選發現能力與最終 reducer 的 end-to-end accuracy，並提供 protocol-matched uncertainty；對非 i.i.d. 的 prefix-search bank，不應直接套用 i.i.d. repeated-sampling 的統計解釋。

## 限制與未來工作

論文主要建立分類、評估與重現性框架，並非提出單一最佳 scaling algorithm；不同實驗的成本口徑、資料區段與 evaluator 設定並不完全一致。部分 verifier 是 ordinal 或 reference-assisted，未必 calibrated；prefix search 的統一比較與更廣泛 benchmark 結果仍有限。文中對 trace corpus 規模亦有 over 2 billion 與 over 2 million 的不一致表述。
