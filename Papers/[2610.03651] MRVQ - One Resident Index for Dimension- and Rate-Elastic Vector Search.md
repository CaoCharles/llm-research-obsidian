# MRVQ: One Resident Index for Dimension- and Rate-Elastic Vector Search

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2610.03651)
- 📥 [PDF](https://arxiv.org/pdf/2610.03651v1)

## 摘要（中文翻譯）

Dense retrieval 服務必須在延遲、品質與記憶體預算變動時，切換 embedding-prefix 維度與 index bit rate。各 rate 分別調校 quantizer 可獲得最佳品質，但 retrieval tier 必須同時保存多組 code stream 與 quantizer state。本文提出 Matryoshka Residual Vector Quantization（MRVQ），一種針對 frozen embeddings 的 post-hoc residual quantizer。其最高 rate code 可沿兩個方向截斷：移除 residual stages 以降低 rate，移除 embedding coordinates 以降低維度。因此單一 resident artifact 即可支援所有評估的（dimension, rate）組合。在 FiQA、NFCorpus、四種 embedding families 與 4、8、16-byte codes 上，MRVQ 是評估設計中最低 RAM 者；相較三個分別訓練的 QINCo2 indices 少用 17.8–22.0 倍記憶體，相較精簡 shared-model steelman 少用 1.89–2.02 倍。代價是 per-rate QINCo2 在 FiQA 的 nDCG@10 高 0.026–0.107。MRVQ 仍在相同 code size 下勝過 PQ、OPQ 與 AdANNS-OPQ。作者另評估低建置成本的 PCA-scalar 設計，品質與 RaBitQ 及其延伸方法相當，但中位數 fitting 快 420 倍。

## 問題背景

Dense retrieval 不只需要單一品質與壓縮點，還要在 embedding prefix 維度和 code rate 間彈性切換。現有作法若為每個 rate 分別訓練 quantizer，雖然品質較佳，卻需常駐多組 code stream 與模型狀態，造成顯著記憶體負擔。共享模型可降低部分成本，但仍未同時解決 dimension 與 rate elasticity。本文因此研究能否以單一 resident document code 支援完整操作選單。

## 解決方案

MRVQ 在 frozen embeddings 上 post-hoc fitting 一個 16-stage residual vector quantizer。每個 stage 使用 256 個 codewords、每個索引佔 1 byte；保留前 b 個 residual stages 即得到 b-byte rate，保留前 m 個 embedding coordinates 即得到 prefix dimension m。訓練時以多個服務維度的加權重建誤差共同最佳化，讓同一組 codebooks 同時適應維度選擇。如此只需保存一份最高 rate 的 16-byte code 與一份 codebook state，即可支援所有（m,b）組合。作者並以 PCA 旋轉加 coordinate-wise scalar quantization 作為低建置成本的獨立 operating point。

## 核心貢獻
1. 提出 MRVQ，使單一 post-hoc residual quantizer 的最高 rate code 能同時沿 residual-stage 與 embedding-coordinate 兩軸截斷，支援 dimension- and rate-elastic vector search。
2. 建立完整 rate menu 的 resident-memory accounting，顯示在所評估資料規模與設定下，MRVQ 相較分別訓練 QINCo2 可節省 17.8–22.0× RAM，相較 shared-model steelman 可節省 1.89–2.02×。
3. 以實驗明確量化記憶體與品質的 Pareto trade-off，並報告 PCA-scalar 的低建置成本結果，以及高 rate QINCo2 失效與 ranking-bound predictor 未達門檻等負結果。

## 技術方法

資料使用 BEIR 的 FiQA（57,638 documents、648 queries）與 NFCorpus（3,633 documents、323 queries），搭配 MPNet、Mxbai、Nomic、BGE 四種 frozen embedding families，維度分別為 768 或 1024。MRVQ 設定為 L=16 stages、每 stage K=256 codewords、fp32 codebooks；以 50,000 個 sampled vectors、50 iterations、seed 0 fitting。對每個 embedding family，使用指定 prefix menu，prefix weights uniform，且 16 個 residual stages 等權。其目標函數為各服務 prefix 維度上的重建平方誤差加權和。服務時採 asymmetric scoring，query 保持 floating point；rate menu 為 4、8、16 bytes/vector，dimension 由 coordinate prefix 選擇。比較對象包括 per-rate QINCo2、shared-model QINCo2、PQ、OPQ、AdANNS-OPQ，以及獨立評估的 PCA-scalar、RaBitQ 與 Extended-RaBitQ。主要指標為 nDCG@10；不確定性以 paired per-query bootstrap（一般 5,000 次，RaBitQ study 10,000 次）估計。記憶體採解析式 parameter/code accounting，不包含 optimizer 或 runtime buffers；另測量 PCA 與 OPQ fitting 時間。作者也測試 residual-energy ranking predictor，涵蓋 40 個 cells，並預先設定相關係數與 non-vacuous bound 的接受門檻。

## 對我們的啟發
- [ ] 若部署約束是 resident memory，且需要同時支援多個 embedding prefix 與 code rate，可優先考慮單一 MRVQ artifact；但不應將其記憶體優勢解讀為 latency 或 throughput 優勢。
- [ ] 若最高 nDCG@10 是首要目標，論文結果支持選擇 per-rate QINCo2，因其在 FiQA 所有比較 cells 均優於 MRVQ；實務選型應依記憶體與品質預算取捨。
- [ ] 若主要需求是快速重建或 in-place rebuild，PCA-scalar 是可評估的低建置成本方案；論文顯示其品質與 RaBitQ 系列相當，但 fitting 時間比較並非在 FiQA/NFCorpus 上進行。

## 限制與未來工作

實驗僅涵蓋兩個規模有限的 BEIR 資料集與四種 embedding families，未評估 end-to-end ANN latency、build energy 或 recall–throughput curves。RAM 是解析式 accounting，不是 process RSS。資料規模很大時，MRVQ 相較 shared-model 的優勢會縮小；此外，高 rate QINCo2 有訓練崩潰，ranking predictor 也未達預設接受門檻。
