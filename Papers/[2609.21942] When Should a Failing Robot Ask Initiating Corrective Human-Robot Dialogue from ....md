# When Should a Failing Robot Ask? Initiating Corrective Human-Robot Dialogue from Audited Sensor Evidence

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2609.21942)
- 📥 [PDF](https://arxiv.org/pdf/2609.21942v1)

## 摘要（中文翻譯）

機器人執行任務失敗後，必須先決定自行依診斷行動、查詢其他機載感測器，或打斷人類尋求協助。此決定取決於感測器對失敗原因揭露多少，以及機器人診斷本身的可靠度。作者建立一個每次失敗原因皆由注入而知的模擬 benchmark，並以資料洩漏檢查衡量各感測器的診斷資訊。部分失敗可由影像診斷，另一些則只能由 force data 判定；後者的 force-data 準確率達0.99，而影像方法最高僅0.55。六個 open vision-language models 從影像診斷時，行為更受 prompt 表面與選項順序影響，而非證據；信心也無法反映正確性。將 force data 以文字提供後，四個模型首次超越 majority-class baseline。作者進一步以測得的準確率與詢問成本建立 act、sense、ask 三種行動的 optimal policy，發現模型未能依成本調整詢問率。不過，人類一次回答可使模型在詢問後達到約0.70–0.81的準確率。因此，詢問決策應依測得的準確率與明確成本設計，而不應依賴模型信心。

## 問題背景

論文研究機器人失敗後何時應自行修復、查詢機載感測器，或向人類提問。既有失敗診斷工作通常假設原因可由既有觀測恢復，卻未驗證感測器是否真的包含相關證據；求助與 corrective dialogue 工作則常未以可量化的診斷可靠度和詢問成本決定是否發問。此外，模型的 refusal、confidence 與實際可辨識性是否一致，也缺乏系統評估。

## 解決方案

作者提出以已知失敗原因建立 simulated benchmark，透過 audit 衡量每一類失敗由不同 sensor 可診斷的程度，再測量各模型實際能抽取的準確率。audit 包含 shuffle、transfer 與 separation checks，以排除標籤洩漏、視角或場景 shortcut，以及近重複資料。接著以模型準確率、human answer reliability、sensor consultation cost 與 human question cost，計算 act、sense、ask 三種行動的 expected cost 與 break-even threshold。模型行為則以 reference policy、regret、confidence informativeness 與詢問後任務準確率評估。核心創新不是提出新的 threshold 公式，而是把 audited sensor evidence 與實際模型能力接入可計算、可比較的 dialogue initiation policy。

## 核心貢獻
1. 建立具已知注入原因的 failure benchmark，並以 shuffle、transfer、separation checks 審核 sensor evidence，區分真正可診斷資訊與 shortcut/data leakage。
2. 證明六個 open VLM從影像診斷時多數不超越 majority-class baseline，且 refusal與confidence受 prompt layout 影響，不能反映實際證據或正確性。
3. 提出以 audited evidence、模型測得準確率與明確成本計算 act、sense、ask policy，並以 regret評估模型是否做出成本合理的 corrective dialogue initiation決策。

## 技術方法

資料來自 LIBERO simulator 的 tabletop pick-and-place 任務，每個 failure family有2,200個失敗 episode，其中2,000個用於 audit、200個保留給模型評估；失敗由注入的 cause與severity產生，並記錄 camera frames及 wrist force-torque、gripper aperture、kinematic status等force data。三類失敗為 grasp、detection與placement。感測器資訊以小型 classifier衡量：影像端使用 pixel/PCA、DINOv2 embedding與3D convolution模型，force端使用 force、gripper與軌跡統計；只有通過 shuffled-label、held-out appearance/viewpoint或severity transfer，以及不同simulation run分割的結果，才作為 certificate。六個7B–16B open VLM接受八張frames、任務指令與失敗事實，進行含或不含「cannot be determined」的多選診斷；另測 few-shot、force telemetry十行文字及frames-plus-telemetry。模型評估包含 accuracy、answered-only accuracy、answer rate、三種confidence readout、Spearman correlation與McNemar test。決策階段令模型選擇 ACT或ASK；預設 correct repair成本1、wrong repair成本10、詢問成本3，human回答正確率0.80、無資訊0.15、錯誤0.05，並掃描詢問成本1、3、6、10及加入成本0.5的SENSE。以測得accuracy計算 expected-cost threshold，將模型 realized cost與best fixed reference policy的regret比較。

## 關鍵結果

主要結果如下：

| 項目 | 結果 |
|---|---|
| Grasp：force data classifier | 0.986，通過 audit；在嚴格 severity 配對下為0.97 |
| Grasp：camera classifier | 最高0.545；影像證據接近 plateau，低於多數比較的資訊 certificate |
| Detection：camera classifier | 0.910；held-out appearance 0.844、viewpoint 0.813 |
| Placement：camera classifier | 表面準確率0.998，但 held-out viewpoint降至0.605，因 shortcut 被排除為可信證書 |
| 六模型 frames-only | grasp最高0.343（majority baseline 0.400）；detection最高整體0.17，未達證書0.910 |
| 選項位置影響 | 三個 swept model-family pairs 的 refusal rate由78–100%降至0–6% |
| Force telemetry文字 | 六模型中四個超越grasp majority baseline 0.400：InternVL3 0.514、Pixtral 0.486、Llama 0.543、Cosmos3-Nano 0.457 |
| Human question後準確率 | 四個有 decision-task ask data 的模型，在詢問時達0.70–0.81；Qwen 0.76、Cosmos-Reason2 0.70、Llama 0.76、Cosmos3-Nano 0.81 |
| 成本敏感性 | 參考政策在grasp約accuracy 0.32時，成本1與3應詢問，成本6與10應行動；模型詢問率未隨成本一致變化 |
| Confidence | 多數 stated confidence與正確性或episode decidability無資訊關聯；僅Pixtral token log-probability呈ρ=+0.50 |



## 對我們的啟發
- [ ] 部署前應先做 sensor-to-cause audit；若原因存在於 force、proprioception等模型尚未看到的通道，優先提供可讀的 telemetry 可能比直接打擾人類更有效。
- [ ] 詢問策略應以 held-out calibration accuracy與實際 action cost建立 threshold，並持續檢查詢問率是否隨成本變化；不能把 verbal confidence直接當作 self-knowledge。
- [ ] Human-in-the-loop 的效益不只取決於回答是否正確，也取決於模型能否理解自然語言表述；實務系統應加入回答正規化、確認回合或 cause mapping，避免選項詞彙依賴。

## 限制與未來工作

研究限於 LIBERO 模擬器、三類 tabletop pick-and-place failures、六個7B–16B open VLM與小型測試集；未驗證真實機器人、frontier models或人類觀察者是否能判斷 grasp原因。human reply是固定 scripted answer，問題品質未評分，且只研究一次詢問，尚未涵蓋連續對話、語音、物理狀態變化、示範或 teleoperation。
