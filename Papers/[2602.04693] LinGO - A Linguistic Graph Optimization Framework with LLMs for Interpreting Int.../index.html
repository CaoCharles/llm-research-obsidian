    LinGO: A Linguistic Graph Optimization Framework with LLMs for Interpreting Intents of Online Uncivil Discourse

    連結

    • 📄 arXiv
    • 📥 PDF
    • 📎 本地 PDF: PDF

    摘要（中文翻譯）

    偵測不文明語言對維護安全、包容且民主的線上空間至關重要。然而，現有分類器常將含有不文明線索但實際表達文明意圖的貼文誤判，導致線上有害不文明行為的估計被過度膨脹。本文提出 LinGO，一個結合語言結構與優化技術的 linguistic graph optimization 框架，用於分類不文明語言中多類別的直接與間接表達意圖。LinGO 將語言分解為多步驟語言組件，識別導致最多錯誤的目標步驟，並迭代優化對應的 prompt 與 few-shot example。研究使用 2022 年巴西總統大選期間收集的 Portuguese 資料集，涵蓋四種政治不文明形式（Impoliteness、Hate Speech and Stereotyping、Physical Harm and Violent Political Rhetoric、Threats to Democratic Institutions and Values），每個實例標註六種 civil/uncivil intent。以三個 cost-efficient LLMs（GPT-5-mini、Gemini 2.5 Flash-Lite、Claude 3 Haiku）與四種優化技術（TextGrad、AdalFlow、DSPy、RAG）進行基準測試。結果顯示 LinGO 在所有模型上均優於 zero-shot、CoT、direct optimization 及 fine-tuning baselines，其中 RAG 搭配 Gemini 模型達到最佳整體表現。

    問題背景

    現有 AI 分類器在偵測線上不文明語言時，無法區分「直接表達不文明意圖」與「間接提及不文明內容」（如引用他人仇恨言論進行批評或報導）。這導致所有含不文明元素的文本被一視同仁地歸為有害，嚴重高估了線上有害不文明行為的實際盛行率。間接表達涉及 sarcasm、metaphor、presupposition 等複雜語言結構，即使 LLMs 在 zero-shot 設定下仍難以正確辨識。

    解決方案

    提出 LinGO（Linguistic Graph Optimization）框架，將語言學結構建構為 directed acyclic graph，包含五個推理步驟：(1) 判斷是否引用他人言論、(2) 分析引用內容是否含不文明元素、(3) 判定作者對引用內容的立場（report/intensify/counter/escalate）、(4) 判斷作者自身言論是否含不文明元素、(5) 區分 explicit 或 implicit 不文明。LLM 逐步遍歷此 graph，每步輸出決定下一步走向。框架進一步透過比對 LLM 預測與人工標註的 sub-step 答案，識別錯誤率最高的步驟，並以 TextGrad、AdalFlow、DSPy、RAG 等技術針對性優化該步驟的 prompt 或 demonstration examples。

    核心貢獻

    1. 提出 LinGO 框架，首次將語言學結構（linguistic graph）系統性整合至 LLM 的 prompt optimization pipeline，實現多步驟語言理解與針對性步驟優化
    2. 定義六類不文明語言意圖分類體系（explicit、implicit、reporting、intensifying、countering、escalating），區分直接與間接表達，並建立含 sub-step 標註的 Portuguese 政治不文明語料庫
    3. 系統性比較四種 LLM optimization 技術（TextGrad、AdalFlow、DSPy、RAG）在 linguistic graph 框架下的表現，證明 RAG + Gemini 2.5 Flash-Lite 組合達到最佳 accuracy 0.690 與 weighted F1 0.699

    技術方法

    LinGO 的技術流程分為三階段。第一階段：Linguistic Graph Construction — 基於語言學中的巢狀結構 [author's stance [reference to others' statements/behaviors]]，建構五步驟 directed acyclic graph（DAG），每個 node 對應一個 Q-A 決策函數，node 間的 transition rule 依據前一步答案決定下一步走向，最終到達 leaf node 輸出分類標籤。第二階段：Human Annotation — 標註者依 linguistic graph 步驟為每筆資料提供 sub-step 答案與最終 intent label，形成 reasoning chain（如 STEP 1: YES -> STEP 2: YES -> STEP 3: Report -> LABEL: 3），並以 Gwet's AC2 衡量 inter-coder reliability（達 0.514）。第三階段：Targeted Step Optimization — 以 LLM 對 validation set 產生預測，比對各步驟 mismatch rate，超過 threshold τ=0.1 的步驟進入優化。四種優化技術分工：TextGrad 與 AdalFlow 以 textual gradient descent 優化 prompt text；DSPy 以 metric-driven bootstrapping 優化 demonstrations 與 traces；RAG 以 similarity-based retrieval 優化 demonstrations。迭代多輪（R=5），以 validation performance 選擇最佳 prompt/example 組合進行 test set 評估。

    關鍵結果

    LinGO + RAG + Gemini 2.5 Flash-Lite 達到最佳表現，相較最佳 zero-shot/CoT baseline 提升 +10.7pp accuracy 與 +12.1pp weighted F1，相較最佳 direct optimization 提升 +5.0pp accuracy 與 +3.5pp weighted F1。LinGO 在 GPT-5-mini 與 Gemini 上均持續提升各項優化技術的分數，但在 Claude 3 Haiku 上效果有限（可能因語義理解較弱導致 error propagation）。Fine-tuned open-source models（Mistral-7B、DeepSeek-V2-Lite-Chat、Qwen3-4B）最佳僅達 0.590 accuracy / 0.535 wF1，低於 LinGO。

    Model Method Tool Accuracy wF1
    GPT-5-mini Zero-Shot — 0.518 0.513
    GPT-5-mini CoT — 0.583 0.578
    GPT-5-mini LinGO RAG 0.655 0.677
    Gemini 2.5 Flash-Lite Zero-Shot — 0.335 0.364
    Gemini 2.5 Flash-Lite CoT — 0.380 0.413
    Gemini 2.5 Flash-Lite LinGO RAG 0.690 0.699
    Claude 3 Haiku Zero-Shot — 0.190 0.130
    Claude 3 Haiku CoT — 0.305 0.283
    Claude 3 Haiku LinGO RAG 0.479 0.489
    Qwen3-4B (best FT) Fine-Tuning — 0.590 0.535

    對我們的啟發

    • 將領域知識（如語言學結構）轉化為 multi-step DAG 並嵌入 LLM prompt，可有效提升複雜語義任務的表現，此方法可推廣至法律文本分析、醫療報告解讀等需要結構化推理的場景
    • Targeted step optimization 的策略（診斷各步驟錯誤率、僅優化問題步驟）比全局優化更高效，適用於任何 multi-step LLM pipeline 的 error propagation 問題
    • RAG（similarity-based retrieval of demonstrations）在本研究中持續優於 textual gradient descent 方法（TextGrad、AdalFlow），暗示高品質 few-shot example 的選擇可能比 prompt text 優化更重要

    限制與未來工作

    需要 sub-step 層級的人工標註，增加標註成本；迭代優化在完整資料集上反覆評估，計算開銷較大（單次實驗約 $5-$10）；僅在單一領域（巴西政治）、單一語言（Portuguese）驗證，跨文化與跨語言的泛化性尚未確認。
