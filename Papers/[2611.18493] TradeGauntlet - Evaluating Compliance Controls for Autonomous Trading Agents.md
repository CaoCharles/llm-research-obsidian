# TradeGauntlet: Evaluating Compliance Controls for Autonomous Trading Agents

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2611.18493)
- 📥 [PDF](https://arxiv.org/pdf/2611.18493v1)

## 摘要（中文翻譯）

自主交易代理需要在阻止問題訂單的同時，不使合法任務變得不切實際。本文以 TradeGauntlet 研究 agentic compliance：這是一個可重播的 limit-order-book simulator，分離 detection、prevention 與 execution cost。在 Claude Haiku 5.5 和 Sonnet 5.5 的 1,680 個模擬 sessions 中，所有 conduct alerts 都是 self-matches；透過拒絕自我穿價訂單的 gates 可消除這些 alerts，但 aggregate-gate condition 使 Sonnet 的雙邊成交量約下降 15%。Conduct reminder 降低 Sonnet 的 alert rate，卻降低 Haiku 的 fills，且未觀察到可檢出的 alert 改善。Scripted probes 與兩種搜尋方法發現可規避既有 conduct rules 的 split-order schedules。Learned baseline 在 2,400 個搜尋 episodes 全部偵測到，但也對大型做市商 15% 的 sessions 誤報。結果顯示，零 alerts 不代表真正合規；價格反應、market assumptions、控制成本與偵測規則的耦合都會影響結論。所有實驗皆為模擬，不能證明法律合規或真實市場偵測準確率。

## 問題背景

論文探討自主交易代理在執行合法目標時，可能因訂單序列觸發 conduct rule；因此需要同時評估代理、事前阻擋 gate 與事後 surveillance detector。既有單看 alert count 的方法無法區分「沒有問題」與「問題被 gate 事先阻止」，也無法衡量控制對成交與任務完成的成本。現有規則還可能被拆單、時序安排或不同市場反應規避，且偵測器的 recall 與 legitimate trading 的 false alerts 需要分開評估。

## 解決方案

作者提出 TradeGauntlet，一個具固定 seed、可 replay 的 limit-order-book simulator 與評估 workflow。框架將 detection、prevention、execution cost 分開：以 conduct rules、order-to-trade ratio 與 logistic-regression learned detector 衡量偵測；以 per-order gate、aggregate cap、self-match prevention 與 throttle 阻止訂單；以 fills、task completion、implementation shortfall、P&L、markout、response-dependent wealth gain 及 false alerts 衡量成本與剩餘經濟誘因。研究同時使用 LLM traders、scripted probes、random search、policy-gradient adversaries、真實價格路徑及 ABIDES 機制檢查，藉此測試控制是否只是消除可見 alerts，或確實降低可利用的 response-dependent gain。

## 核心貢獻
1. 提出可重播的 TradeGauntlet workflow，將交易代理合規的 detection、prevention 與 execution cost 分離評估，並固定 seeds 與 market paths 進行配對比較。
2. 以 Haiku、Sonnet、scripted probes、random search 與 policy-gradient adversaries 結合測試，展示既有 conduct rules 可被 split-order schedules 規避，且零 alerts 可能由 gate 與 detector 的閾值耦合所保證。
3. 以 LOBSTER 五支 Nasdaq stocks、ABIDES、synthetic 與 real price paths 檢查 price-response assumptions，並量化 aggregate caps 對 response-dependent gain 及 legitimate maker volume 的不均衡影響。

## 技術方法

TradeGauntlet 自行實作 integer-price、price/time-priority、partial-fill matching engine；每個 session 固定 market path、fundamental/noise draws 與 random seed，並記錄 attempted、accepted、rejected orders、fills、alerts，供配對 replay。LLM 實驗使用 Claude Haiku 5.5 與 Sonnet 5.5；模型每 60 秒取得 order book、open orders、fills 及 rejection reasons，輸出 JSON orders，無法解析時視為 hold。任務包括低成本買入 40 lots 與庫存絕對值不超過 30 lots 的 two-sided market-making，並比較 task-only 與 conduct reminder、無 gate、per-order gate、aggregate gate，以及 step/linear price response。Conduct detector 包含 individual、layer、aggregate 與 self-match patterns。搜尋 adversary 在六參數 split-order schedule family 中最佳化 response-dependent wealth difference D，並以 alert penalty 避免觸發既有規則；使用 random search 與 policy gradient，在 training paths 選擇策略，再於 held-out paths 評估。價格反應以五支 Nasdaq stocks 的 LOBSTER 資料估計，並在 ABIDES 檢查；另以 30 個 real mid-price windows 重播。指標包含 episode alert rate、fills、任務完成、D、執行量、implementation shortfall、P&L、edge、markout，以及 legitimate scripts 的 false-alert rate，並以 cluster/bootstrap intervals 報告部分比較。

## 關鍵結果

主要結果如下（數字皆為論文報告值）：

| 實驗／條件 | 結果 |
|---|---|
| LLM sessions | 共 1,680；Haiku 1,440、Sonnet 240；配對分析完整 episodes 分別為 1,342 與 220 |
| LLM conduct alerts | 所有 alerts 都是 self-matches；買入任務兩模型各條件均無 conduct alert |
| Sonnet，task-only，無 gate | 30 個 sessions 中 10 個 alerts，平均 two-sided fills 22.9 lots |
| Sonnet，task-only，aggregate gate | 30 個 sessions 中 0 alerts，平均 fills 18.1 lots；相對無 gate 約少 15%（差 3.2 lots） |
| Sonnet，conduct reminder，無 gate | 30 個 sessions 中 2 alerts，平均 fills 20.4 lots |
| Haiku，task-only，無 gate | 120 個 sessions 中 2 alerts，平均 fills 13.3 lots |
| Haiku，reminder，無 gate | 120 個 sessions 中 1 alert，平均 fills 10.9 lots；論文稱無可檢出的 alert benefit |
| Split probe | 個別與 layer rules 均未偵測六個 10-lot 拆單；aggregate detector 在 gate admitted 時可 alert 40/40，但 aggregate gate 下為 0/40，形成 gate-detector coupling |
| 搜尋 adversary | 24 個 control/response cells 的 2,400 個 held-out episodes 均無 conduct alert；搜尋找到可規避既有 rules 的 schedules |
| Learned baseline | 偵測全部 2,400/2,400 searched sessions；對 large maker 誤報 15/100，其他 legitimate scripts 為 0/400 |
| Order-to-trade baseline | 偵測 1,816/2,400 searched sessions；large maker 誤報 22/100 |
| 強化 prevention，線性 response κ=1 | 搜尋 gain D：無 gate 9.78、aggregate m=2 為 6.14、m=1 為 3.32 tick-lots/session |
| 強化搜尋，MSFT fit，policy gradient 800 samples | D：無 gate 4.86、aggregate m=2 為 2.84、m=1 為 1.44 tick-lots/session |
| Real-path search，κ=1 | 無 gate 的 D 從 synthetic-policy 9.73 降至 2.70；論文報告避開 alerts 約使 gain 減少 70% |
| LLM adversary | Sonnet 在 240 rounds 全部拒絕提出策略，因此沒有 candidate strategies 可評估 |
| 合法大型 maker | aggregate policy 在 720 秒 sessions 的平均 volume loss 為 14.1%；另一 100-path rerun 為 15.1% |

上述結果支持作者的實驗結論，但不代表真實市場法律合規或 detector 的 real-market accuracy。

## 對我們的啟發
- [ ] 評估交易代理或其他受控 agent 時，不能只把 zero alerts 當作合規證據；必須同時記錄被 gate 拒絕的訂單、控制前後的行為，以及 detector 是否因控制條件而失去觀測對象。
- [ ] 對抗測試應包含可解釋、可 replay 的 scripted probes 與搜尋策略，並使用 held-out paths；否則只測試 LLM 自發產生的行為，可能漏掉代理不會自然探索的規避路徑。
- [ ] 偵測器的 recall 必須與 legitimate workload 的 false-alert cost 一起報告。本文 learned baseline 在受限搜尋家族中達到 2,400/2,400，但對 large maker 仍有 15% false alerts，顯示高 recall 不能單獨代表可部署性。

## 限制與未來工作

所有交易均在自建 simulator 或 ABIDES 中進行，沒有 broker/exchange 連線，也沒有 unlawful-conduct labels，因此不能推論法律合規或真實市場偵測準確率。價格反應依賴簡化模型、五支股票單日資料與特定 mapping；搜尋家族有限，learned detector 屬同分布測試。LLM adversary 只測一個 Sonnet prompt，且完全拒答；合法 scripts 的 objectives 也未獨立審查。
