# Auditable Financial Knowledge Graphs: Schema-Driven Construction and Intrinsic Quality Evaluation

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2611.27835)
- 📥 [PDF](https://arxiv.org/pdf/2611.27835v1)

## 摘要（中文翻譯）

金融文件同時包含敘述性揭露、會計指標、企業結構、管理層評論與具時間依賴性的事實，因此難以由傳統以文字區塊為基礎的 Retrieval-Augmented Generation（RAG）系統完整表示。本文提出一套可稽核、由 schema 驅動的方法，從經一般文件智能服務解析並保留頁面邊界的文件中，建構具時間性的金融 Knowledge Graph（KG）。重疊文件視窗經由分階段 Large Language Model（LLM）流程，抽取結構實體、量化觀察與領域關係；候選圖元素再依預定義 schema 驗證，並透過具範圍感知的精確、正規化、模糊、embedding 與 LLM 輔助 entity resolution 進行整合。系統以時間合併限制、確定性邊去重、衝突感知屬性管理及細粒度 provenance，維持發行人身分、報告期間有效性與來源可追溯性。本文亦提出由七項加權維度、兩項硬性驗證閘門及結構診斷組成的 intrinsic KG quality evaluation framework，將圖品質評估與下游 retrieval 及 answer generation 分離，以支援系統診斷與迭代改善。

## 問題背景

金融文件中的數值、敘述、企業關係與報告期間往往分散於不同段落，傳統 chunk-based RAG 難以保留跨段落關係、multi-hop reasoning 與證據追蹤。GraphRAG 雖可改善結構化檢索，但其可靠性取決於 KG 品質；自動建圖可能產生 hallucinated entities、錯誤方向關係、schema violations、重複或錯誤合併、遺漏及 temporal inconsistencies。既有研究多以最終 QA 表現間接評估圖，難以區分建圖、檢索、推理與生成錯誤。

## 解決方案

作者提出 schema-driven、temporal 且 auditable 的金融 KG 建構與 intrinsic evaluation framework。文件先轉為保留頁面邊界的文字，再以重疊頁面視窗進行分階段 LLM extraction，依序抽取 structural entities、quantitative observations 與 semantic relations。所有輸出皆視為候選，經 schema、型別、端點、數值及時間限制驗證後，採 scope-aware entity resolution、衝突保留、時間安全合併、確定性 edge deduplication 與細粒度 provenance 建圖。核心創新是將 factual grounding、schema compliance、completeness、relationship quality、entity disambiguation 與 temporal consistency 等 intrinsic 品質，獨立於 GraphRAG QA 進行衡量。

## 核心貢獻
1. 提出一套從 page-delimited 金融文件建構 temporal、schema-driven 且 auditable KG 的完整流程，結合 phased LLM extraction、deterministic validation、scope-aware entity resolution、temporal safeguards 與 provenance preservation。
2. 建立金融 KG 的 intrinsic quality evaluation framework，以 factual accuracy、semantic consistency、completeness、information density、relationship quality、entity disambiguation 與 temporal consistency 七項維度，以及 schema/provenance 兩項硬閘門評估圖品質。
3. 在 FinanceBench 公開 150-case subset 上建構並驗證 KG；作者報告 overall KG quality 為 95%、entity coverage 為 98%，並以 GraphRAG 正確回答 123/150 題，準確率為 82.00%。

## 技術方法

資料使用 FinanceBench，完整資料包含 10,231 組 question-answer-evidence triplets、40 家美國上市公司與 368 份 filings；實驗評估採公開的 150-case subset。文件由 Azure Document Intelligence（prebuilt-layout）轉成 page-delimited text，連續 3 頁形成、stride 為 1 的重疊視窗。每個視窗以 GPT-5.4、temperature=0、一般 3 次 retry，分階段抽取 14 類 structural 與 quantitative entities，再分四類抽取 financial、corporate structure、geography、legal relations。候選經欄位、schema、domain-range、數值與端點驗證後，使用 scope-aware key、normalized/fuzzy matching、text-embedding-3-large（threshold 0.88）、模糊相似度（0.7）及必要的 LLM merge verification 解析實體。系統保留不同期間的觀察，進行 temporal reconciliation、edge signature 去重、coreference、orphan linking 與衝突紀錄，且每個 node、edge、property observation 儲存 document、page、window、evidence、period、timestamp、confidence 與 run ID。評估包括 deterministic validation，以及由 GPT-5.5 執行的 factual accuracy、semantic consistency、independent-reference completeness、information density、relationship quality、entity disambiguation 與 temporal consistency；另設 schema/provenance 兩項至少 95% 的硬閘門。加權 KQ 分數權重依序為 FA 25%、SC 15%、CP 15%、ID 15%、RQ 15%、ED 10%、TC 5%。下游則以最多兩跳的 document-scoped GraphRAG 評估 150 個 FinanceBench 問題。

## 對我們的啟發
- [ ] 實務上應將 LLM 抽取結果視為待驗證候選，而非直接寫入 KG；schema、端點型別、數值與時間規則可降低不合法或不受支持的圖元素。
- [ ] 金融 KG 的 provenance 應細化到 node、edge 與 property observation，並保留頁面、證據片段、期間、confidence 與 run ID，才能進行可重現的稽核與錯誤歸因。
- [ ] 下游 QA 分數不宜單獨代表 KG 品質；可先以獨立的 factual grounding、completeness、entity resolution 與 temporal consistency 評估建圖，再分析其對 GraphRAG 的影響。

## 限制與未來工作

論文未提供與其他 KG 建構、VectorRAG 或 GraphRAG 方法的直接 baseline 比較，也未完整揭露各類錯誤歸因的分布。intrinsic 評估部分依賴 GPT-5.5 judge，雖與 GPT-5.4 建構模型分離，仍可能存在 LLM 評審偏差。實驗主要採 FinanceBench 的 150-case subset，對更廣泛文件型態與跨公司泛化能力的驗證有限；未來可增加人工審核、跨模型 judge 與更大規模資料集。
