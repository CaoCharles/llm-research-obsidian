# APort Vault: Benchmarking AI Agent Payment Authorization with the Open Agent Passport

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2609.22076)
- 📥 [PDF](https://arxiv.org/pdf/2609.22076v1)

## 摘要（中文翻譯）

APort Vault 是一個用於評測會使用工具之 AI agent 付款授權能力的 benchmark。研究重播公共 capture-the-flag 活動中，真人針對線上付款 agent 撰寫的 4,371 次攻擊，涵蓋 8 個實驗室的 14 個模型、5 種 policy 設定與兩種 replay track，並比較有無實作 Open Agent Passport（OAP）的 deterministic pre-action check。共完成 225,964 次 evaluation。研究分別報告五類事件：付款請求、成功付款、授權決策、recipient membership，以及付款至 passport 不允許 recipient 的 unpermitted transfer。Levels 2–4 中，model alone 發生 140/76,842 次未授權轉帳；加入 authorization layer 後為 0/69,297，且仍成功執行 25,370 筆付款。作者同時釋出資料集、passport、評分程式與分析腳本。

## 問題背景

現有 agent 安全 benchmark 多以模型是否拒絕攻擊或是否產生工具呼叫為主要指標，無法直接回答部署者最關心的問題：即使模型被攻陷，工具執行前的 authorization layer 是否能阻止真正的 consequential action。單一 refusal 或 judge 分數也會混淆請求、付款成功與政策違規，且未充分處理同一攻擊 session 造成的相關性。本文因此評估相同攻擊、模型與 prompt 在有無工具邊界 enforcement 時的實際付款結果。

## 解決方案

作者提出 APort Vault benchmark，將真人在公開 CTF 中針對 live payment agent 的攻擊重播至多模型、多 policy level、多輪次與兩種架構。核心比較變項是：model alone 讓 transfer_funds call 直接執行，或在模型與工具之間加入實作 Open Agent Passport（OAP）的 deterministic pre-action authorization check。研究不把結果壓縮成單一成功率，而是分離 payment request、successful payment、policy decision、recipient membership 與 unpermitted transfer 五個事件，並以實際 executed tool calls 作為主要 deterministic metric；同時以 clustered bootstrap、matched triples 及 session-level upper bound 評估不確定性。

## 核心貢獻
1. 建立含 4,371 個真人 CTF 攻擊、14 個模型、5 個 policy levels、兩種 replay tracks 與兩種 enforcement architectures 的 APort Vault payment-authorization benchmark，並釋出 225,964 筆 evaluation 與分析工具。
2. 提出並實證五階段結果記錄方式，區分付款請求、成功付款、授權決策、recipient membership 與 unpermitted transfer，避免以單一 refusal 或 attack-success rate 混淆不同事件。
3. 在相同模型、prompt 與 replay track 的 matched comparison 中，顯示 OAP deterministic pre-action check 將 Levels 2–4 的未授權轉帳由 105 次降至 0 次，同時保留政策允許的付款執行。

## 技術方法

資料來自 2026 年公開 capture-the-flag 付款 agent 活動：由 1,128 個 source sessions 產生 4,371 個真人攻擊，移除空白與含個資提交後納入分析。攻擊分布於五個 policy levels；Levels 2–4 允許特定 allowlisted recipients，Level 1 基本上為 wildcard recipient，Level 5 不授予付款能力。每次攻擊重播至 14 個模型、兩種 track（僅 attacker 最終訊息的 single-turn，以及保留完整訊息序列的 multi-turn），並在 model-alone 與 authorization-layer 兩種架構下執行。兩架構維持模型版本、prompt、decode settings 與 tool schema 相同；layer 會在 transfer_funds call 執行前依 OAP passport 檢查 recipient、金額、limits、audit code 等條件，拒絕的 call 不會執行。主要指標直接讀取 executed tool calls，不依賴 LLM judge；另以兩個 judge 作為 audit。研究分別記錄 request、successful payment、policy allow/deny、recipient 是否在 allowlist 及 unpermitted transfer。統計上以 source session 為 cluster，使用 1,500 次 percentile bootstrap；零事件同時報告 exact one-sided upper bound 與 per-session rule-of-three bound，matched comparisons 則固定 model、prompt 與 track。

## 關鍵結果

| 評估項目 | Model alone | Behind OAP layer |
|---|---:|---:|
| Levels 2–4：payment requests | 28,543 / 76,842（37.1%） | 25,527 / 69,297 |
| Levels 2–4：successful payments | 28,521 | 25,370 |
| Levels 2–4：unpermitted transfers | 140 / 76,842（0.182%） | 0 / 69,297 |
| Matched Levels 2–4：unpermitted transfers | 105 / 68,970 | 0 / 68,970 |
| Levels 2–4：policy-evaluated transfer calls | 未適用 | 25,453 allowed、187 denied |
| 其中因 forbidden recipient 而拒絕 | 未適用 | 148 calls |
| 零事件的 per-session 95% upper bound | 未適用 | 0.38%（790 sessions） |
| Level 4 單輪 payment-request rate | 71.2%–84.3%（14 個模型） | 論文未報告逐模型 layer 對照 |
| Level 5 successful payments | 5,362 / 22,320 | 0 / 20,109 |

作者指出，OAP layer 並非透過全面壓低請求或拒絕所有付款達成結果：Levels 2–4 的 matched request-rate paired difference 為 +0.084 percentage points，95% interval 為 [-0.020, +0.189]；layer 後仍有 25,370 筆成功付款。Level 4 的 1,293 個 prompts 中，809 個（62.6%）讓全部 14 個模型提出請求，且均支付至該 level 的 allowlisted recipient，因此不能視為攻擊成功。140 次 model-alone 違規轉帳集中於 24/790 sessions，其中單一 session 佔 67 次；multi-turn Level 2 的 113 次結果中，111 次來自 103 個 forged-receipt attempts。LLM judge 的 pooled inter-judge kappa 為 0.772，但 Level 3 僅 0.167；因此 headline metric 採 deterministic tool-call outcome。

## 對我們的啟發
- [ ] 對涉及金錢或其他可驗證副作用的 agent，應將 enforcement architecture 納入實驗變項，並以實際狀態變更而非模型拒答作為主要安全指標。
- [ ] 評估資料應保留 request、tool execution、policy decision 與 authorization result 等階段；付款請求本身不等於 compromise，成功執行也不必然等於政策違規。
- [ ] 攻擊結果應按 source session、攻擊技術與 replay track 分析並進行 clustering；本文中少數 session 與 forged-receipt cohort 集中了大部分違規結果，單一模型 leaderboard 會掩蓋這種結構。

## 限制與未來工作

研究限於模擬銀行、單一 transfer tool 與付款場景，不能直接推論至資料外洩、程式碼執行或 multi-agent delegation。攻擊者為自選 CTF 參與者，每個 cell 僅單次執行，跨 provider 的 decode defaults 未統一，且 multi-turn coverage 不完整。Level 4 local engine 比 published pack 更嚴格；預註冊的人工作者驗證 slice 未完成，模型污染也僅被部分排除。
