# Flide: Accelerating Decision Inference with Exact State Forking

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2610.42148)
- 📥 [PDF](https://arxiv.org/pdf/2610.42148v1)

## 摘要（中文翻譯）

Decision model（如 Jev）已成為 LLM agent systems 的重要範式，能以輕量且可靠的分類推理支援快速的 System One 執行。然而，現有以生成為導向的 inference engine 無法有效支援此類工作負載，面臨嚴重的 prefix 重算開銷，或因加入分隔符而扭曲輸出機率。本文提出 Flide，一種高效率且精確的 inference engine，將 decision request 的邏輯樹結構與單一扁平 token stream 中的實體執行分離。透過 ForkAttention，Flide 使用 GPU 常駐索引處理 standard attention 與 recurrent Gated DeltaNet layers 的 request dependencies，保證在精確算術下每個 query branch 都等同於獨立 forward pass。Flide 亦支援多樣 request 混合、CUDA graph replay，以及從先前 pass 儲存的 checkpoint 恢復不斷增長的 agent history。在 public hybrid 與 decision models 上，Flide 相較 vLLM 和 SGLang 最快可達 9.5 倍速度，並在 total variation distance 上最接近 float32 reference。

## 問題背景

Decision models 通常以一個共享 state 回答多個 categorical questions，但現有 generation-oriented engines 將每個問題視為獨立序列，造成共享 prefix 重複計算、tokenization 與 scheduling 開銷；hybrid model 的 recurrent state 也只能粗粒度恢復。SGLang multi-item scoring 雖共享 state，卻加入 delimiter token，改變問題輸入與輸出機率。動態 batching 的浮點 reduction 順序亦可能使相同請求產生不穩定決策。

## 解決方案

作者提出 Flide（Flat-Graph Inference for Decision Models），將每個 request 保留為由共享 state trunk 與多個 question branches 組成的邏輯樹，再把多個 request 扁平化為單一 GPU token stream。ForkAttention 以 GPU-resident metadata 描述 branch dependency，使 full attention 只讀取自身 trunk 與 branch，使 Gated DeltaNet 從對應 trunk recurrent state 與 convolution window 重新分叉。Flide 進一步以 stream-length buckets 預錄少量 CUDA graphs，透過 metadata 支援不同 request mixtures；並以 checkpoint 支援 agent history 增量恢復，以及以 optional batch-invariant mode 提供 bitwise determinism。

## 核心貢獻
1. 指出 decision serving 的重複計算與答案偏移，根源在於 request 的邏輯樹結構與 GPU 實體執行結構耦合。
2. 提出 ForkAttention 與 flat-stream execution，在 standard attention 與 Gated DeltaNet 中以 GPU metadata 實現精確 state forking，理論上保證 causal model 的 branch hidden states 等同 standalone execution。
3. 提出 GPU-resident metadata、可重播 CUDA graphs、incremental state checkpoints 與 optional batch-invariant mode，並在 hybrid、full-attention、dedicated decision 與 multimodal workloads 上驗證速度與答案 fidelity。

## 技術方法

輸入 request 定義為共享 state s 與多個問題 q_i；s 是所有 standalone prompts 共同的最長前綴，模型在每個問題末端 hidden state 上，對選項 O_i 進行 softmax readout。Flide 將 state segments 置於扁平 stream 前端，再排列各 request 的 question branches；每個 token 帶有 request index、branch index 與 sequential position。對 full-attention layers，ForkAttention 僅允許同一 request 的 trunk 或同一 branch 中、且位置不晚於 query 的 key；sliding-window layer 再加入窗口限制。對 Gated DeltaNet，先處理所有 state segments 取得各 trunk 的 recurrent state 與 convolution window，再以 state indices 讓各 question segment 從正確 trunk 狀態開始，避免 sibling branch 互相污染。GPU-resident metadata 儲存 segment lengths、positions、key ranges 與 state indices，使不同拓撲共用按 stream capacity 捕捉的 CUDA graphs；selective readout 僅計算問題末端的輸出列。對增長中的 agent history，系統儲存指定 checkpoint 的 float32 recurrent states、convolution windows，以及 full-attention 的 keys/values，後續只重算 mutable tail 與新 token。評估使用 RACE、QuALITY、MultiRC、Decision Index、GQA 與 SWE-agent trajectories，比較 vLLM、SGLang、SGLang multi-item scoring、vllm-jev 與 RadixFlow。指標包括 median latency、C8/C32/C64 throughput、top-answer agreement、accuracy、stability、total variation、P99 probability change、threshold flip，以及 identical bits。

| Qwen3.5-4B、約 2,000-token state、64 questions | Flide 比 vLLM 快 12.7 倍 | 共享 state 僅計算一次 |
| Open-Jev-2B，平均 workloads | Flide latency 13.0 ms、C64 256.4 req/s；vllm-jev latency 49.8 ms、C64 83.4 req/s | Flide 約三倍以上吞吐優勢 |
| Open-Jev-9B，平均 workloads | Flide latency 17.1 ms、C64 100.7 req/s；vllm-jev latency 49.8 ms、C64 83.4 req/s | 論文報告在短輸入約三倍速度，長 prompt 仍具優勢 |
| Qwen3.5 平均 top-answer agreement | Flide：單問題 RACE 99.8%、QuALITY 99.1%；多問題 RACE 99.6%、QuALITY 99.3%、MultiRC 99.7% | 各 workload 均最接近 float32 reference 或並列最佳 |

## 對我們的啟發
- [ ] 若多個 categorical queries 共享長 context，應優先設計為一次 trunk 計算、多個隔離 branches，而不是把每個 query 當成獨立 generation sequence。
- [ ] 為保持 decision probability 的語義，應避免以 delimiter 或其他額外 token 實作 batching；邏輯依賴關係應放在 metadata、attention indexing 或 recurrent-state routing 中。
- [ ] 對 latency-sensitive agent serving，CUDA graph replay、selective readout、checkpointed recurrent state 與 batch-invariant execution 可分別降低 launch、輸出層、歷史重算與負載造成的數值不穩定；但是否採用 invariant mode 需衡量其最多約 10% throughput 成本。

## 限制與未來工作

論文主要在單張 NVIDIA H200、指定 Qwen3.5、Gemma 4 與若干 decision models 上評估，未報告多 GPU、分散式部署、更多硬體或更廣泛模型架構的結果。精確性理論保證限定於 causal model 與 exact arithmetic；實際浮點誤差仍需測試。論文亦未提供完整成本、工程維運與長期服務穩定性的分析。
