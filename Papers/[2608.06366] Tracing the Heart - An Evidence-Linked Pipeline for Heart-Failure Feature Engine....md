# Tracing the Heart: An Evidence-Linked Pipeline for Heart-Failure Feature Engineering

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.06366)
- 📥 [PDF](https://arxiv.org/pdf/2608.06366v1)

## 摘要（中文翻譯）

電子健康紀錄（EHR）feature engineering 是臨床研究與 AI 的主要瓶頸，約占資料科學家工作量的 39–45%。在心衰竭情境中，資料分散於不同 EHR 表格，且需要結合疾病專屬、以 guideline 為基礎的臨床推理。現有 rule-based 與 large language model（LLM）方法僅能部分自動化，且在可維護性與 evidence traceability 方面有所不足。作者提出 Nimblemind Multi-Agent System（nMAS），一個 evidence-linked、rubric-grounded 的自動化心衰竭 feature-engineering pipeline，並以來自九個 EHR source tables 的 500 筆 dummy patient records 進行評估。nMAS 產生 132 個 structured features 與 70 個 rubric-scored aggregated features，並檢查結構完整性、rubric compliance 與 provenance，再由受限制的 LLM 進行稽核。加入 aggregated features 後，HFrEF phenotype 的 held-out AUROC 從 0.895 提升至 0.963，HFpEF 則從 0.870 提升至 0.910；獨立 LLM rubric 評估達最高分的 81.5%。結果顯示自動化且可稽核的複雜心血管 EHR feature engineering 具可行性，但目前仍受限於單一機構資料，需外部驗證。

## 問題背景

臨床 EHR 的診斷、藥物、檢驗、影像、程序與社會史分散在不同表格，心衰竭特徵還需依 guideline 進行縱向整合與臨床解釋。既有通用 rule-based 方法偏向資料清理，LLM 方法則可能缺乏臨床文獻依據、可維護性與逐項 provenance，難以產生可重現且可稽核的 phenotype、severity、GDMT 與 care-gap 特徵。

## 解決方案

作者提出 nMAS，將資料處理、臨床知識表示與模型稽核分離。系統先以 Achievability Agent 判斷資料能否支持目標特徵，再標準化、去重、時間聚合九個 EHR tables，建立一列一人的 patient-level table。其核心是由 guideline literature 支持、經 cardiologist 審核且版本化的 scoring rubric，將直接證據、支持性檢驗、歷史資訊、行為與跨系統 comorbidity modifiers 組合成可解釋分數或 care-gap。每個結果均附 source columns、貢獻元件、分數與可用性。最後由受 whitelist 限制的 LLM auditor 進行最小更正，並以 deterministic QA 檢查結構、公式、互斥性、missingness 與 provenance，形成 evidence-linked、可追蹤的自動化流程。

## 核心貢獻
1. 提出 nMAS evidence-linked、rubric-grounded 的 multi-agent feature-engineering pipeline，將 EHR 整理、臨床規則、證據追蹤與 LLM 稽核整合為可重複流程。
2. 將九個異質 EHR source tables 轉換為單一 patient-level dataset，產生 132 個 structured columns 與 70 個具 evidence trace 的高階 aggregated features。
3. 透過結構與 provenance QA、跨權重與特徵消融、XGBoost 下游 phenotyping，以及獨立 LLM construct-validity 評估，從多個面向檢驗功能與臨床合理性。

## 技術方法

nMAS 由多個受規則與 rubric 約束的 agent 組成。流程先由 Achievability Agent 檢查目標特徵是否有足夠 source data；若缺少必要輸入，回報 unsupported 而不推測數值。Query Parser 再依設定的 field definitions 與 rubric 導向 pipeline。本文聚焦 feature-engineering pipeline：Stage 1 對九個 EHR tables 進行標準化、去除空白與 null token、統一 patient identifier 與 ISO datetime，依臨床事件鍵去重，接著各表獨立做 patient-level temporal aggregation，再合併為每位患者一列。連續量測保留 missingness 並加入 availability indicators；EF range 會拆成 low、high、midpoint，計算最低、最高及最近值，並標示衝突。臨床推理層將診斷、藥物、實驗室、行為與程序轉成 flags；phenotype 優先使用 numeric EF，缺失時才使用 ICD-10 diagnosis，且不進行 EF 過度推斷。Stage 2 依 versioned rubric 產生 disease severity、cardiovascular risk、五類 comorbid burden、demographic vulnerability、care-gap 等 aggregated features。七類分數由元件加權、上限 100，並映射為 low/medium/high；每項保留 components、points、解釋、source columns 與 input availability。所有候選列再由本地 Qwen 2.5-1.5B-Instruct auditor 檢查，僅允許修改 whitelist 欄位。評估包括結構、rubric、monotonicity 與 provenance QA；下游以 XGBoost 進行 HFrEF 與 HFpEF 對 phenotype-unknown 的二元分類，採 5-fold stratified CV 重複 10 次，報告 Accuracy、AUROC、F1 與 global TreeSHAP。另以 Claude Opus 4.8 依五維 rubric 評估 evidence support、methodological soundness、reproducibility 與 EHR reliability，並進行 category、weight、missingness 與 direct-evidence 消融。

## 關鍵結果

主要結果如下（數值為 5-fold cross-validation 重複 10 次之 test folds 平均值 ± 標準差）：

| 任務 | 特徵組 | Accuracy | AUROC | F1 |
|---|---|---:|---:|---:|
| HFrEF | Baseline | 0.776 ± 0.065 | 0.895 ± 0.046 | 0.776 ± 0.063 |
| HFrEF | Aggregated | 0.896 ± 0.049 | 0.963 ± 0.028 | 0.894 ± 0.052 |
| HFpEF | Baseline | 0.752 ± 0.056 | 0.870 ± 0.042 | 0.758 ± 0.058 |
| HFpEF | Aggregated | 0.809 ± 0.061 | 0.910 ± 0.040 | 0.812 ± 0.059 |

HFrEF 加入 aggregated features 後，Accuracy、AUROC、F1 分別提升 0.120、0.068、0.118；HFpEF 分別提升 0.057、0.040、0.054。資料整併後為 500 位患者各一列，產生 132 個 structured columns；Stage 2 產生 70 個 aggregated columns，全部 500 列均經 Qwen 2.5-1.5B-Instruct 稽核。數值 EF 僅有 15 位患者（3.0%）。Claude Opus 4.8 的 construct-validity 評估總分為最高分的 81.5%，但 care recommendation 類別分數最低，論文摘錄僅明確報告為 38.5，未完整呈現其分母或所有分類細節。等權重 rubric 消融使 HFrEF/HFpEF AUROC 分別下降 0.060/0.041；direct evidence only 則分別下降 0.065/0.040。

## 對我們的啟發
- [ ] 對需要 LLM 參與的臨床資料工程，應將模型輸出限制在明確 whitelist 與可驗證欄位，並保護 evidence trace 與 explanation 等不可任意修改的欄位。
- [ ] 缺失值不應直接視為陰性或零值；論文以 availability indicators 與保留 missingness 的方式，避免未測量資料被誤解為正常或低風險。
- [ ] 下游 AUROC 提升不能單獨證明臨床有效性；應同時檢查 label overlap、外部證據支持、可重現性、資料可靠性與 clinician-adjudicated ground truth。

## 限制與未來工作

研究僅使用單一機構、500 筆 dummy cohort，統計效力與外部泛化性有限；分類對象是 phenotype-unknown 而非非心衰竭對照，且部分 aggregated features 可能與標籤重疊。未進行外部臨床驗證、前瞻性影響或病人 outcome 評估。部分特徵依賴 regular expression，完整 cohort 也未由臨床醫師逐筆審查。未來需使用大型多機構、時間分離資料、clinician-adjudicated phenotypes，並評估臨床工作流程與 outcome。
