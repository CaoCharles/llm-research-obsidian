# Tracing the Heart: An Evidence-Linked Pipeline for Heart-Failure Feature Engineering

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.06366)
- 📥 [PDF](https://arxiv.org/pdf/2608.06366v1)

## 摘要（中文翻譯）

電子健康記錄（EHR）特徵工程是臨床研究與 AI 的主要瓶頸，約占資料科學家工作量的 39–45%；在心衰竭情境尤其明顯，因為必須整合分散的 EHR 資料與疾病特定、以指引為基礎的臨床推理。作者提出 Nimblemind Multi-Agent System（nMAS），一個具 evidence-linked 與 rubric-grounded 特性的自動化心衰竭特徵工程流程，並在來自九個 EHR 來源表的 500 筆 dummy patient records 上評估。nMAS 產生 132 個 structured features 與 70 個 rubric-scored aggregated features，並檢查結構完整性、rubric 遵循度與 provenance，再由受限 LLM 進行稽核。加入 aggregated features 後，HFrEF phenotyping 的 held-out AUROC 由 0.895 提升至 0.963，HFpEF 則由 0.870 提升至 0.910；獨立 LLM rubric 評估達最高分的 81.5%。然而，研究僅使用單一機構 cohort，仍需 external validation。

## 問題背景

EHR 特徵工程需從 diagnoses、medications、laboratories、imaging、procedures 與行為紀錄等異質且縱向分散的資料中，建立具臨床意義、可重現且可稽核的 patient-level variables。既有 rule-based framework 多為疾病無關且維護成本高；LLM 方法雖具彈性，卻可能缺乏 guideline grounding、證據追蹤與對 unsupported outputs 的控制，無法完整支援心衰竭 phenotype、severity、GDMT 與 care-gap 特徵。

## 解決方案

作者提出 Nimblemind Multi-Agent System（nMAS），以 Achievability Agent、Query Parser、資料標準化與聚合模組、clinical reasoning layer、deterministic rubric scoring engine 及 restricted LLM auditor 組成 evidence-linked pipeline。其核心創新是把臨床指引轉為 versioned JSON rubric，明確定義條件、權重、證據階層與缺失處理，再將每項衍生特徵連結至 source columns、實際貢獻元件、輸入可用性與 supporting references。LLM 不負責無限制地產生臨床結論，而是在候選列生成後，僅能依 whitelist 修正特定欄位；結構、rubric、monotonicity 與 provenance 則由 deterministic checks 驗證，兼顧自動化、可解釋性與可審計性。

## 核心貢獻
1. 提出 nMAS evidence-linked、rubric-grounded 的多代理特徵工程流程，將 EHR 清理、時間聚合、臨床規則評分與受限 LLM 稽核整合為可追溯管線。
2. 將九個 EHR source tables 轉換為一人一列的 patient-level dataset，產生 132 個結構化欄位與 70 個高階 rubric-scored aggregated features；每個聚合特徵保留來源欄位、貢獻元件、點數與文獻依據。
3. 透過下游 HFrEF/HFpEF phenotyping、SHAP、rubric design ablation 與獨立 LLM construct-validity assessment，評估特徵的預測效益、臨床可解釋性與證據支持程度。

## 技術方法

nMAS 的輸入是九個 EHR source tables，涵蓋 demographics、diagnoses、medications、echocardiogram、surgeries、laboratories、ejection-fraction flowsheet 與 social history。首先由 Achievability Agent 檢查目標特徵是否有足夠輸入；Query Parser 再依 versioned rubric 與 field definitions 路由流程。Stage 1 對各表進行標準化，包括清除空白、統一 null tokens、轉換大寫 identifiers、解析 ISO datetime，並依 clinically meaningful event key 去重；之後各來源獨立做 patient-level temporal aggregation，計算 counts、first/latest timestamps 與 flags，最後合併為每位患者一列。EF range 會解析為 low、high 與 midpoint，並保留 availability indicators；缺失連續值不填為零。Stage 2 以由 2023 年後 22 篇文獻、經 cardiologist 審核的 rubric，對 disease severity、cardiovascular risk、五類 comorbid burden、demographic vulnerability、care gaps 等特徵進行 deterministic scoring；多數分數上限為 100，並映射為 low、medium、high。EF phenotype 使用 numeric EF precedence，無 EF 時才採 ICD-10 diagnosis fallback。所有候選列再由 Qwen 2.5-1.5B-Instruct restricted auditor 檢查，僅可修改 whitelist 欄位，evidence traces 與 explanations 受保護。品質保證包含唯一 patient ID、join、缺失值、rubric、monotonicity 與 provenance 檢查。下游以 XGBoost 評估 HFrEF 與 HFpEF phenotyping，並使用 accuracy、AUROC、F1、global TreeSHAP、ablation，以及 Claude Opus 4.8 的五維 construct-validity rubric 評估。

## 關鍵結果

| 任務 | 特徵集合 | Accuracy | AUROC | F1 |
|---|---|---:|---:|---:|
| HFrEF | Baseline | 0.776±0.065 | 0.895±0.046 | 0.776±0.063 |
| HFrEF | Aggregated | 0.896±0.049 | 0.963±0.028 | 0.894±0.052 |
| HFpEF | Baseline | 0.752±0.056 | 0.870±0.042 | 0.758±0.058 |
| HFpEF | Aggregated | 0.809±0.061 | 0.910±0.040 | 0.812±0.059 |

模型使用 XGBoost，採 5-fold stratified cross-validation、重複 10 次，共 50 次 test evaluations；同一任務中 baseline 與 aggregated features 使用相同 folds。HFrEF 加入 aggregated features 後 Accuracy、AUROC、F1 分別增加 0.120、0.068、0.118；HFpEF 分別增加 0.057、0.040、0.054。Stage 1 產生 132 個 structured columns，Stage 2 產生 70 個 composite columns；數值 EF 僅 15/500（3.0%）患者可用。獨立 Claude Opus 4.8 construct-validity rubric 的整體 normalized score 為 81.5%，但 care recommendation features 得分最低，為 38.5%（論文摘錄未提供所有類別的完整分數）。等權重 rubric 使 HFrEF AUROC 下降 0.060（p=0.0059），HFpEF 下降 0.041（p=0.0007）；direct-evidence-only ablation 則分別下降 0.065（p=0.0037）與 0.040（p=0.0003）。

## 對我們的啟發
- [ ] 對臨床 EHR pipeline 而言，將 clinical knowledge rubric 與執行程式分離，並進行版本控制，可讓指引更新時不必重建整個資料處理基礎設施。
- [ ] Evidence traceability 不應只保存模型輸出，也應連結至 source columns、輸入可用性、計分元件與 supporting literature；這有助於人工審查、錯誤定位及後續 reproducibility。
- [ ] 本研究顯示 rubric-derived features 的性能提升可能受特徵與 phenotype label 的重疊影響，因此實務部署前應採用 clinician-adjudicated labels、temporal validation、multi-institutional validation，並明確檢查 label leakage。

## 限制與未來工作

研究僅在單一機構、500 筆 dummy patient records 上進行，統計效力與外部泛化性有限；phenotyping 是以 phenotype-unknown 而非 non-HF controls 為對照。部分 aggregated features 可能與 labels 重疊，造成 label leakage 或 predictor-construction concerns。研究未評估 external clinical validity、prospective impact 或 patient outcomes；部分共病與行為特徵依賴 regular-expression matching，且完整 cohort 未經臨床醫師逐筆審查。未來需進行大型多機構、時間分離、臨床醫師判定標籤與前瞻性工作流程驗證。
