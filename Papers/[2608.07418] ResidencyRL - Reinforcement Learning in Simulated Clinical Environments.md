# ResidencyRL: Reinforcement Learning in Simulated Clinical Environments

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.07418)
- 📥 [PDF](https://arxiv.org/pdf/2608.07418v1)

## 摘要（中文翻譯）

在醫學教育中，醫師透過住院醫師訓練，將學術知識轉化為臨床專業，歷經數千次就診、不同來源的回饋，以及逐步增加的自主性。臨床推理很大程度依賴病人問診：醫師 eliciting history、修正診斷假設，並在不確定性下決定處置。雖然 LLM 在靜態醫學 benchmark 表現優異，但最佳化完整且連續的臨床決策序列仍不成熟。本文提出 ResidencyRL，透過 simulated multi-turn clinical encounters 訓練臨床 AI agent，每條 trajectory 最多包含 60 次對話與 8 次工具呼叫。方法結合具複雜及 adversarial 行為的 LLM patient simulator，以及涵蓋診斷準確度、處置品質、溝通、文件紀錄與安全性的 structured reward。在保留測試中，模型於 adversarial 條件下將診斷準確度由 81.0% 提升至 88.0%，提高 7.0 個百分點，並使遺漏 red flag 的比率降低 31%。盲測專家偏好訓練後 agent 的比例為 87.6%。能力也轉移至 AMIE multi-visit、AgentClinic 與 CRAFT-MD 等未見 benchmark，但仍需真實臨床流程的前瞻性驗證。

## 問題背景

現有 LLM 醫療能力多由靜態問答或短輪對話 benchmark 衡量，難以最佳化臨床 encounter 中連續的資訊蒐集、假設修正、分流、處置與文件決策。既有多輪 RL 工作通常限於不超過 12 輪，且只處理對話、診斷詢問或檢查下單等孤立子任務，無法充分處理隱藏資訊、患者抗拒、adversarial manipulation、premature closure 與安全性。

## 解決方案

作者提出 ResidencyRL，將完整臨床 encounter 建模為部分可觀測、長期互動環境：policy agent 與具人口、健康識讀、資訊不對稱及 adversarial 行為的 LLM patient simulator 對話，並透過 documentation API 執行診斷、鑑別診斷、urgency、management、患者摘要與 SOAP note。方法以 57K 生成情境建立課程，結合 general、targeted history-taking 和 safety case；再用涵蓋臨床品質與安全 penalty 的 hierarchical structured reward，透過 GRPO 從平行 trajectory 更新政策。核心創新是把自然語言問診、工具互動、臨床管理、文件和安全目標放入同一個長期 RL objective。

## 核心貢獻
1. 提出 ResidencyRL，一種以線上 multi-turn reinforcement learning 和 GRPO 訓練完整臨床問診、文件紀錄與管理決策的 agentic 方法，處理最長 60 次對話及 8 次工具互動。
2. 建立包含 routine telehealth、targeted history-taking 與 adversarial safety 的情境生成及模擬環境，並以 structured autorater reward 同時評估診斷、管理、問診、溝通、文件與安全性。
3. 在保留的 adversarial 情境及多個外部 benchmark 上觀察到程序性能力泛化，並由 97 名 board-certified clinicians 進行 blinded side-by-side 評估。

## 技術方法

ResidencyRL 以 Gemini 3.5 Flash 初始化的 policy agent，與 Gemini 3.5 Flash 驅動的 patient simulator 互動；每個 episode 最多 60 次訊息、8 次額外工具呼叫，論文圖示平均約 55 個 agent steps。情境生成分四階段：先抽樣人口、Big Five 行為特徵、健康識讀、對話 effort、疾病與複雜度；再由 Gemini 3.1 Pro 依 DDXPlus evidence 生成病史、症狀、ground-truth diagnosis 與 ranked differential；接著以獨立 LLM judge 檢查一致性、臨床真實性、鑑別診斷、人口適切性及完整性，予以 accept、modify 或 reject；最後以 character-trigram TF-IDF，對摘要 cosine similarity 超過 0.9 者去重。訓練情境分為 general telehealth（83%）、targeted intake/history（15%）及 adversarial（2%）。環境提供 chart review、primary diagnosis、differential、urgency、management plan、patient-facing summary、SOAP note 與 terminate 等 API。LLM autorater 以 scenario ground truth 為參照，對 Diagnosis、Management、Intake、Communication 等軸以 1–5 Likert 評分並正規化，另加入 hallucination、contraindication、documentation、style、length 與安全旗標等 penalty；總 reward 為 primary reward 減 penalty，範圍為 [-3,3]。政策以 Group Relative Policy Optimization（GRPO）透過同一情境的平行 rollouts 更新。評估涵蓋 held-out in-domain、adversarial、AMIE Mx、unseen oncology、AgentClinic、CRAFT-MD，以及 97 名專家的 blinded side-by-side 比較。

## 關鍵結果

| 評估項目 | Base model | ResidencyRL | 論文報告的變化 |
|---|---:|---:|---:|
| Adversarial 診斷準確度（rubric ≥4/5） | 81.0% | 88.0% | 提升 7.0 個百分點 |
| Adversarial missed red flags | 未提供具體數值 | 未提供具體數值 | 降低 31% |
| Management quality（1–5 Likert） | 3.98 | 4.52 | 提升 0.54 |
| Patient-centered communication：responding to emotions | 2.63 | 3.06 | 提升 0.43 |
| AMIE Mx：management reasoning | 80.1% | 88.4% | 提升 8.3 個百分點 |
| AMIE Mx：patient communication | 83.7% | 92.2% | 提升 8.5 個百分點 |
| 專家 blinded side-by-side overall preference（n=97） | 12.4% | 87.6% | 訓練後 agent 勝率 87.6% |
| 專家評估：information gathering preference | 論文未報告具體 baseline 勝率 | 90.7% win rate | ResidencyRL 勝率 90.7% |

論文另指出，ResidencyRL 在 AMIE Mx 六個 clinical axes 均優於 base model，並在 unseen oncology、AgentClinic 與 CRAFT-MD 上呈現一致方向的改善；但這些項目的完整數值多數未報告。

## 對我們的啟發
- [ ] 若要評估臨床 agent，不應只測單輪醫學問答；應將資訊蒐集、工具使用、診斷、分流、處置與文件紀錄納入同一條 trajectory。
- [ ] 針對 premature closure，可在 simulator 中設計必須透過特定問題才能揭露的 hidden information，並把 red-flag 遺漏、未詢問資料及不安全處置設為明確 penalty。
- [ ] 自動評分可擴展長期 RL 訓練，但高風險醫療用途仍應結合獨立專家盲測、來源可追溯的文件檢查，以及真實工作流程中的前瞻性驗證。

## 限制與未來工作

作者明確指出，模擬器不會建模治療後的下游生理效果，管理品質主要由 LLM autorater 依 scenario ground truth 評分；情境與患者行為也受生成和 prompt 設計限制。部分外部 benchmark 僅報告方向性改善，未提供完整數字。最重要的是尚無 real-world workflow 的 prospective validation，因此臨床效用與病人層級安全性仍未確立。
