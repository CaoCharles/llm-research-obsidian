# The Low Frequency Trap: Video Language Models Fail at Simple Event Bookkeeping

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.06361)
- 📥 [PDF](https://arxiv.org/pdf/2608.06361v1)

## 摘要（中文翻譯）

真實世界影片 benchmark 雖涵蓋廣泛情境，但固定片段同時混合事件數量、頻率、持續時間與視覺複雜度，使失敗原因難以分離。既有程式化 benchmark 雖具較佳控制性，主要只評分最終答案，未以可執行 ground truth 稽核模型回報的事件。本文提出 trace-grounded parametric profiling，在三項受控影片任務——彈跳球接觸牆面、視覺閃爍與類別狀態轉換——中評估事件計數。研究生成 2,190 部影片，改變事件數 N 與頻率 F，同時固定 rendering；每部影片均附有可執行事件 trace，用於估計 capability surface 與進行 timestamp-level evaluation。結果顯示分階段且依事件表徵而異的時間失敗：Gemini 3.6 Flash 能在 0.5、1.0 Hz 下可靠計數最多 12 個持續狀態轉換，但對瞬時閃爍沒有可靠的正計數區域。高數量、高頻率時，僅 0.2% 的最終計數正確，且只找回 18.1% 真實事件。增加取樣率可提升 Bounce Ball 最終準確率，卻不保證 trace faithful recovery。

## 問題背景

現有真實影片 benchmark 將事件數、頻率、持續時間、視覺複雜度、鏡頭運動與語義內容混在一起，單一 final-answer accuracy 難以判斷模型究竟漏看事件、定位錯誤、無法保留序列，還是聚合計數失敗。既有程式化 benchmark 雖能控制條件，卻通常不稽核模型回報的中間事件是否符合 ground truth，可能把 unsupported correct counts 誤判為真正的 temporal reasoning。

## 解決方案

作者提出 trace-grounded parametric profiling。核心做法是在 rendering 時建立與事件排程一致的 executable trace，沿 N×F 網格生成 matched videos，並以 80% reliability threshold 映射模型的 capability surface。模型不只輸出最終計數，也可輸出 timestamped event sequence；研究將其與 ground-truth trace 以頻率相依時間窗對齊，分解 precision、recall、F1、VOR、ACR 與 RFR。再以提高 sampling rate、提供 event-centered keyframes 及改變 prompting 的受控干預，區分 visual access、event localization、sequence retention 與 count aggregation。

## 核心貢獻
1. 提出 trace-grounded parametric profiling，以事件數 N 與頻率 F 建立二維 capability surfaces，取代單一 aggregate accuracy。
2. 建立三類程式化影片與 executable event traces，將 final-answer exact match 與 timestamp-level precision、recall、F1 及計數偏差分開評估。
3. 透過 dense sampling、event-centered keyframes 與多種 prompting interventions，診斷事件存取、定位、序列保留及最終聚合等失敗階段，並以 TransRAC 自然影片檢查低計數成功集中現象是否延續。

## 技術方法

作者以程式化 renderer 生成三類 24 秒影片：Bounce Ball 的 wall contacts、Blinking 的脈衝事件，以及 State Machine 的 categorical transitions。每部影片由 domain、事件數 N、頻率 F 與 random seed 決定；seed 改變顏色、幾何、軌跡、初始狀態、方向與開始延遲，但保留事件排程。N 取 0、1、2、3、4、5、6、8、10、12，F 取 0.5 至 4.0 Hz；每個 `(N,F)` 生成 10 部影片，三個 domain 共 2,190 部。renderer 同步輸出 executable trace `T*`，記錄事件時間、事件類型、前後狀態與累積計數。主要模型為支援 native video input 的 Gemini 3.6 Flash，補充比較 Qwen3-VL-235B；兩者使用各自 native video interface 與 zero-shot template，Gemini 輸入 1 FPS、Qwen 輸入 2 FPS。基線要求最終計數，trace 條件則要求模型回報 timestamped events 與 final count。事件以 `δ(F)=1/(2F)` 的 rate-relative window 一對一對齊，計算 final exact accuracy、precision、recall、F1 與 VOR=M/N；另以 ACR 衡量低 trace F1 卻答對的 accidental correctness，以 RFR 衡量 trace F1≥0.80 卻答錯的 aggregation failure。可靠邊界以每 cell 十個 seed 至少八個正確，即 80% threshold，並採 contiguous-prefix 規則避免孤立成功造成誤判。干預包括 1–16 FPS sampling、每個真實事件附近的 oracle keyframes，以及 direct answer、structured trace、multi-turn verification、Thinking/CoT 和 role prompting；最後以 151 部 TransRAC 自然重複動作影片按事件數分箱檢查轉移現象。

## 關鍵結果

| Gemini 可靠計數邊界（80% threshold） | State Machine 在 0.5、1.0 Hz 可達 N=12；1.5 Hz 降至 N=2；更高頻率通常限於 N=1。Bounce Ball 僅在 0.5 Hz 達 N=10；Blinking 沒有可靠正計數區域 |
| Gemini 各 domain final EM | Bounce Ball 19.6%；Blinking 6.4%；State Machine 37.1%；macro average 21.1% |
| Gemini 各 domain trace F1 | Bounce Ball 36.6%；Blinking 18.6%；State Machine 53.9%；macro average 36.4% |
| 高數量、高頻率區域 | final EM 僅 0.2%；trace recall 18.1%；VOR=0.28，顯示嚴重低報 |
| Bounce Ball，dense sampling | 由 native sampling 的 19.6% 提升至 4 FPS 的 29.3%；但 4 FPS trace F1 僅 3.7%，且 28.3% 試次屬於低 fidelity trace 下的正確答案 |

## 對我們的啟發
- [ ] 評估重複事件時不應只報告最終整數；應要求模型輸出可對齊的事件序列，並同時計算 precision、recall、F1 與 VOR，以辨識漏報、誤報及 unsupported correct counts。
- [ ] 取樣率提升可能提高 final-answer accuracy，卻降低 trace fidelity；因此部署或 benchmark 設計應將答案正確性與證據恢復分開呈現，避免把偶然正確視為可靠的時間理解。
- [ ] 事件表徵會顯著影響可測得能力：持續狀態轉換比瞬時閃爍更容易被模型存取；測試套件應涵蓋 persistent 與 transient events，並掃描不同 N、F，而非只使用單一影片難度。

## 限制與未來工作

研究使用乾淨、規律且重複的事件；固定 F 增加 N 也會增加 active span，因此無法完全分離事件負載與保留跨度。合成實驗主要分析 Gemini，Qwen 僅作補充；自然影片不控制頻率，也沒有 executable trace。模型回報的 trace 是行為證據，不等同於 latent computation。
