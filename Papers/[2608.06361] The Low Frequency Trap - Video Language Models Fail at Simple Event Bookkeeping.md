# The Low Frequency Trap: Video Language Models Fail at Simple Event Bookkeeping

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.06361)
- 📥 [PDF](https://arxiv.org/pdf/2608.06361v1)

## 摘要（中文翻譯）

真實世界的 video benchmarks 涵蓋面廣，但固定片段往往同時混入事件數量、頻率、持續時間與視覺複雜度，使失敗原因難以隔離。既有 programmatic benchmarks 雖可控制條件，通常只評分最終答案，未檢查模型回報的事件是否符合可執行 ground truth。本文提出 trace-grounded parametric profiling，用於三種受控 video event counting 任務：彈跳球接觸牆面、視覺閃爍，以及類別狀態轉換。作者在 2,190 部影片中改變事件數 N 與頻率 F，同時固定 rendering；每部影片均附有 executable event trace，以估計 capability surface 並進行 timestamp-level evaluation。結果顯示 temporal failure 分階段發生且取決於事件表徵：在 80% reliability threshold 下，Gemini 3.6 Flash 可於 0.5 與 1.0 Hz 穩定計數 persistent state transitions，最多達 12 個事件，但對 transient blinking 沒有可靠的正事件區域。高數量、高頻率條件下，僅 0.2% 的最終計數正確，且只恢復 18.1% 的真實事件。提高 sampling rate 可提升 Bounce Ball 最終準確率，卻不一定帶來 faithful event recovery。

## 問題背景

現有 real-world video benchmarks 將事件數、頻率、持續時間、影片長度與視覺複雜度混在一起，模型失敗時難以判斷是看不到事件、無法定位、無法保留序列，還是最終累加出錯。既有受控 benchmark 多只評分 final answer，未檢查模型回報事件是否與 executable ground truth 對齊，因此可能把 unsupported correct counts 誤判為真正的 temporal reasoning。

## 解決方案

作者提出 trace-grounded parametric profiling，將事件數 N 與頻率 F 作為可獨立掃描的 temporal demand 參數，在固定 rendering、semantics 與 task rules 的條件下建立 N×F capability surface。每部合成影片同步產生 executable event trace，模型除回報最終計數外也回報 timestamped events，再透過 rate-relative 一對一 alignment 計算 precision、recall、F1 與 VOR。此框架把 aggregate scoring 擴展為事件級診斷，並以 denser sampling、oracle-like event-centered keyframes 與多種 prompting intervention 區分 visual access、event localization、sequence retention 及 aggregation failure。

## 核心貢獻
1. 提出 trace-grounded parametric profiling，透過事件數 N 與頻率 F 的二維 capability surfaces，取代單一 aggregate accuracy 以定位 video temporal failure。
2. 建立包含 bouncing-ball wall contacts、visual blinks 與 categorical state transitions 的受控 benchmark，共 2,190 部影片；每部影片配有可執行的 event trace。
3. 以 timestamp-level alignment 同時評估 final count 與模型回報事件的 precision、recall、F1、VOR，並使用 sampling、event-centered keyframes 與 prompting interventions 分析失敗來源。

## 技術方法

作者以程式化 renderer 生成三類 24 秒影片：Bounce Ball 的 wall contact、Blinking 的 pulse，以及 State Machine 的 categorical transition。事件數 N 取 {0,1,2,3,4,5,6,8,10,12}，頻率 F 取 0.5 至 4.0 Hz 共八個值；每個 (domain,N,F) 組合生成 10 個不同 seed，總計每 domain 730 部、三個 domain 共 2,190 部。seed 改變顏色、幾何、軌跡、初始狀態、方向與 start delay，但保留事件排程。每部影片由 renderer 產生 executable trace，記錄事件時間、類型、前後狀態與 cumulative count。主要模型為 Gemini 3.6 Flash，baseline 使用其 native video interface、約 1 FPS 輸入與 zero-shot domain prompt；Qwen3-VL-235B 以 2 FPS 作 supplementary cross-system check。模型可被要求回傳最終計數及 timestamped event sequence。預測事件與 ground truth 以 rate-relative window δ(F)=1/(2F) 一對一對齊，再計算 final exact-match accuracy、trace precision P、recall R、F1 與 Visual Observation Ratio VOR=M/N；另以 ACR 衡量正確答案但低 fidelity trace，以及 RFR 衡量高 fidelity trace 卻答錯。作者以每格 10 個 seed 中至少 8 個正確作為 80% reliability threshold，並依 contiguous-prefix rule 求 count/frequency boundaries。診斷介入包括提高 sampling density、提供每個真實事件前後 0.1 秒的 event-centered keyframes，以及 direct answer、structured trace、multi-turn verification、thinking/CoT 和 role prompting。最後以 151 部 TransRAC natural repeated-event clips 檢查低 count 集中成功的模式是否延伸至真實影片。

## 關鍵結果

主要結果如下：

| 評估項目 | 結果 |
|---|---|
| 評估規模 | 3 個受控任務、2,190 部影片；每個 domain 730 部 |
| Gemini 3.6 Flash：State Machine | 在 0.5、1.0 Hz 下，80% reliability threshold 可穩定計數至 N=12；N=2 時可達 1.5 Hz，N≥3 時頻率邊界為 1.0 Hz |
| Gemini 3.6 Flash：Bounce Ball | 0.5 Hz 下 count boundary 達 N=10；由 1.0 至 4.0 Hz 的第一個正事件 count 即未達 80% threshold |
| Gemini 3.6 Flash：Blinking | 沒有可靠的正事件 count 或 frequency region |
| 三 domain 平均 | Final exact match 21.1%；timestamp precision 58.0%；recall 31.2%；trace F1 36.4%；VOR 0.68 |
| Bounce Ball | Final EM 19.6%；Trace F1 36.6%；VOR 0.71 |
| Blinking | Final EM 6.4%；Trace F1 18.6%；VOR 0.60 |
| State Machine | Final EM 37.1%；Trace F1 53.9%；VOR 0.74 |
| 高 count、高 frequency | Final counts 僅 0.2% 正確；trace recall 18.1%；VOR 0.28；trace precision 70.7%；trace F1 27.7% |
| Bounce Ball，dense sampling | 從原生設定的 19.6% 提升至 4 FPS 的 29.3%，但 trace F1 僅 3.7%，且 28.3% 試驗為低 fidelity trace 下的正確答案 |
| Bounce Ball，event-centered keyframes | Final EM 68.6%，但 Trace F1 9.7%；68.3% 試驗在低 fidelity trace 下答對 |
| Bounce Ball，prompting | 各 prompting 方式準確率為 19.3%–20.4%，未擴大可靠 count 或 frequency region |
| Natural-video transfer | TransRAC 的 151 部影片中，準確率集中於 N≤4；論文未報告可穩定的高 count region |
| Qwen3-VL-235B | Bounce Ball 與 Blinking 沒有廣泛可靠區域；State Machine 僅在孤立的 2.5 與 3.5 Hz cells 達到 N=1，且 0.5 Hz 即失敗 |

上述數據來自論文的 capability surfaces、Table 1 與 natural-video transfer evaluation。

## 對我們的啟發
- [ ] 對 video evaluation 而言，應同時要求模型輸出事件時間序列與最終計數，並以 executable ground truth 檢查 trace fidelity，避免正確整數掩蓋漏報、誤報或錯誤累加。
- [ ] 評測應以 event count 與 frequency 建立 capability surface，而不是只報告跨不同影片條件的平均分數；80% reliability boundary 可作為明確的操作性能力門檻。
- [ ] 增加 frame sampling 或提供事件中心 keyframes 可能提高 final-answer accuracy，但不代表模型真正恢復事件序列；部署或比較模型時應同步監測 precision、recall、F1 與 VOR。

## 限制與未來工作

研究使用乾淨且規律、間隔固定的重複事件；固定 24 秒影片中，提高 N 同時增加 event load 與 active span，因而不能完全分離兩者。synthetic profiling 主要分析 Gemini 3.6 Flash，Qwen 僅作補充檢查。natural-video 實驗無法獨立控制 frequency，也沒有 executable traces，且模型回報 trace 只是行為證據，不代表 latent computation。
