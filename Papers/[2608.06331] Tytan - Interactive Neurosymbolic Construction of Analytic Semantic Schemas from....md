# Tytan: Interactive Neurosymbolic Construction of Analytic Semantic Schemas from Relational Data

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.06331)
- 📥 [PDF](https://arxiv.org/pdf/2608.06331v1)

## 摘要（中文翻譯）

從自然語言查詢介面到自動報告生成，資料分析工具都需要資料的語義描述，包括其中包含的真實世界實體、欄位所扮演的度量或識別角色，以及資料表如何連接成分析單位。目前這類 semantic layer 通常由人工撰寫，形成知識取得瓶頸，限制分析系統擴展，也使非技術使用者依賴專家，並可能產生錯誤。本文提出 TYTAN，能從 relational database 及可選的簡短使用者描述，自動建構 analytic semantic schema。TYTAN結合資料庫的 symbolic analysis 與 LLM-based semantic inference，用於實體提議、角色分配、命名與關係推論；當證據不足時，會向使用者提出具體的自然語言澄清問題。作者以 coverage、retrieval correctness 與 characterization accuracy 三個面向評估。七個具 reference schema 的資料庫達到100%覆蓋，1,678/1,678項自動產生的 retrieval claims 均成功執行，語義角色與參考結果一致率為92–100%；在無宣告 keys 的盲測資料庫中，TYTAN恢復完整實體結構，並滿足五位獨立盲 annotators 所提出的全部可滿足期望。

## 問題背景

論文處理 relational database 缺乏可供分析工具使用的 semantic layer 問題：人工建立 entity、attribute、analytic role、keys 與 joins 成本高、難以擴展且容易過時或出錯。傳統 symbolic methods 能發現結構、型別與候選 keys，卻難以理解欄位語義、junction table 或分析角色；純 LLM 方法則可能幻覺欄位、捏造 joins，且多步驟推論不一致。因此需要兼具語義理解、資料 grounding、可執行性驗證與人機協作的建構方法。

## 解決方案

作者提出 TYTAN，一個 interactive neurosymbolic schema-construction system，輸出稱為 ring 的 self-constrained JSON analytic semantic schema。其核心是讓 LLM 負責 entity proposal、attribute mapping、semantic role、命名與 join plausibility 等需要語義理解的工作，再由 deterministic database procedures 驗證所有關鍵主張：欄位必須存在、joins 須有 value overlap、keys 須在資料中唯一、型別須符合 metadata 或觀察值。系統以 iterative coverage sweep 補足遺漏的 tables/columns，並將跨 entity 可達欄位與 aggregation path 明確編碼。對資料無法決定的 table role、column mapping 或 analytic type，TYTAN提出 targeted natural-language clarification；使用者可回答，也可採用預設值完成流程。創新在於把 schema 的功能效用與可執行 retrieval contract 納入生成與評估，而非只追求概念結構或欄位分類相似度。

## 核心貢獻
1. 將 analytic schema construction 明確定義為一項任務，要求生成的 schema 同時支援分析規劃、資料驗證與自然語言結果描述。
2. 提出 TYTAN interactive neurosymbolic pipeline，交錯使用資料庫結構分析、LLM語義推論、deterministic grounding/verification 與 targeted clarification。
3. 提出以 coverage、retrieval correctness 和 characterization accuracy 為核心的 functional evaluation framework，並在七個 reference domains 與一個盲測資料庫上進行評估。

## 技術方法

TYTAN輸入 relational database instance、宣告的 tables/columns/constraints、cardinalities、null rates、distinct samples，以及可選的一句資料描述。第一階段進行 deterministic structural profiling；若輸入是 CSV 或 Excel，先載入 relational store，但通常沒有 primary/foreign keys，只能依賴資料值證據。第二階段由具 schema-constrained output 的 LLM 提議 domain entities、attributes、analytic roles、名稱與可能 joins，再將概念對應到實際 tables、columns、types 和 sample values；未對應的 tables 會被分類為 entity、link table、passthrough lookup 或 technical table，未對應欄位則在 coverage sweep 中補入。第三階段執行 grounding 與驗證：undeclared joins 必須通過完整 distinct-value overlap、key-role guards、numeric-measure 排除、候選 referent 數量限制，以及 LLM plausibility confidence threshold；entity id 則以 declared key 或全資料 uniqueness/non-null 檢查驗證，必要時搜尋單欄或 composite key。系統分離 storage type 與 analytic role，使用 metadata 與觀察值修正 storage type，但不因數字外觀自動把 zip code 等欄位變成 Numeric。之後產生 labels、descriptions、reference templates 和跨 entity aggregable attributes。若 table role、column mapping 或 analytic type 仍不明確，便提出 targeted clarification，依答案重建局部 schema。輸出是可執行的 JSON ring。評估分為：與 expert reference 比較 entity/attribute/relationship coverage；執行每個 ring 自產的 identifier、mapping、join 與 reference-resolution claims；以及比較 mapped attributes 的 semantic characterization，另以無宣告 keys 的 FIFA blind database 和獨立 annotators 測試泛化。

作者指出，少量角色差異經檢查後來自 reference，而非 TYTAN；但論文也明確說明，這些結果評估的是 schema construction，不是下游 analytic query 或報告本身的正確性。

## 對我們的啟發
- [ ] 對需要自動建立 semantic layer 的系統，應讓 LLM 只負責語義判斷，並以資料庫中的 uniqueness、value overlap、欄位存在性與樣本值驗證其輸出，降低幻覺與錯誤 join 的風險。
- [ ] 評估 schema 不宜只比較名稱或結構相似度；應直接執行 schema 產生的 retrieval instructions，並分別衡量覆蓋、可執行性與語義角色正確性。
- [ ] 對 enrollment 等既可能是 entity、也可能是 junction table 的模糊結構，互動式澄清問題比強制自動決策更合適；同時保留 conservative defaults，才能在無使用者回覆時完成流程。

## 限制與未來工作

論文目前只評估八個資料庫，且七個 reference schema 由作者建立或修訂，可能限制外部泛化性。Self-generated retrieval tests 無法發現 schema 遺漏的內容；LLM blind annotators 也可能與生成器共享模型偏差。系統對同一對資料表的平行 joins 在 aggregable path search 中目前只遍歷其中一條，作者列為未來工作。此外，論文未報告與其他 schema-recovery 方法的量化 baseline、成本、延遲或澄清問題數量。
