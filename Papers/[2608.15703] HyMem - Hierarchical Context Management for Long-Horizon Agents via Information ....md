# HyMem: Hierarchical Context Management for Long-Horizon Agents via Information Isolation

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.15703)
- 📥 [PDF](https://arxiv.org/pdf/2608.15703v1)

## 摘要（中文翻譯）

大型語言模型（LLM）代理人在複雜、長時程任務上常表現不佳，原因是互動累積後，context 日益混雜。詳細執行軌跡與中間輸出會佔據主要篇幅，使模型難以保留及運用高階規劃資訊。現有方法多在單一扁平 context 上進行 compression 或 retrieval，未能清楚分離不同功能的資訊，並可能損害推理。本文提出 HyMem，一個以 information isolation 為核心的 hierarchical context management framework，將 context 依功能分層，分離高階規劃、執行與複雜分析。isolated reasoning module 在獨立空間處理複雜子任務，避免中間推理軌跡進入持久化規劃 context；memory management module 則以 structured summaries 保存任務進度。實驗顯示，搭配 DeepSeek-V4 時，HyMem 在 GAIA 與 Browsecomp-plus 的平均 Pass@1 分別為 66.7% 與 61.3%，較最強 baseline 高 6.1 與 4.7 個百分點。

## 問題背景

複雜長時程 agent 同時需要高階策略規劃、低階工具執行與多步證據分析，但 ReAct 等 flat context 將它們交錯保存。執行軌跡、raw tool outputs、重試與中間推理會快速增長，稀疏的目標、限制與關鍵事實因 context dilution 而被掩蓋。既有 compression 或 external retrieval 通常在資訊已混合後處理，可能遺失推理鏈、破壞時間邏輯，且難以區分策略訊號與執行噪聲。

## 解決方案

作者提出 HyMem，以 typed context isolation 將代理人的資訊按功能分層。Planner 維持跨任務的高階決策狀態；Executor 在短暫獨立空間執行工具並將 raw observations 蒸餾成結構化 RESULTS；isolated reasoning module 在另一個暫時空間處理 multi-hop、假設驗證與衝突證據整合，只回傳結論及支援資訊，不把中間推理寫入 Planner。Memory Management 以 episode、working、tool 三種 structured memory 保存里程碑、目前目標、缺口與工具經驗，並在 context refresh 時重新注入。核心創新不是單純壓縮已混合的軌跡，而是從資訊產生與跨層傳遞的介面上阻止執行細節進入持久化規劃 context。

## 核心貢獻
1. 將長時程代理人的 context dilution 形式化為稀疏規劃訊號與密集執行軌跡之間的 information-density mismatch，提出 hierarchical context isolation 作為設計原則。
2. 提出 training-free 的 HyMem inference-time framework，以明確邊界分離 Planner、Executor、isolated reasoning 與 memory management，僅允許 schema-constrained 訊息跨層傳遞。
3. 在 GAIA 與 Browsecomp-plus 上評估 HyMem，並透過不同 backbone、資源分析、context growth 分析及 ablation study，驗證 isolated reasoning 與 structured memory 的互補作用。

## 技術方法

HyMem 是包裝 frozen base LLM 的 training-free、inference-time controller。其 persistent Planner context 包含 system prompt、query、episode memory、working memory、tool memory，以及先前 session 的 typed returns；Executor 與 isolated reasoning context 則按需建立並在回傳後丟棄。Planner 每一步輸出四種控制動作之一：TASK、ISOREASON、FOLD 或 ANSWER。TASK 將子任務交給 Executor；Executor 在 bounded tool-call loop 中處理 raw observations，透過 relevance-conditioned distillation 移除導航文字、重複段落、格式雜訊與工具錯誤 boilerplate，保留實體、日期、數值、來源與證據，再以 RESULTS schema 回傳 findings、evidence、sources、status、gaps。需要 multi-hop analysis、假設檢查或衝突證據整合時，Planner 呼叫 ISOREASON；該模組可使用工具，但中間推理只留在獨立 context，最後回傳 conclusion、supporting facts、sources、confidence 與 assumptions。Memory Management 維護 episode、working、tool 三種可重寫記憶，分別保存已完成里程碑與驗證事實、目前目標與未解缺口、有效或失敗的工具使用經驗。FOLD 可由 Planner 顯式觸發，或在 Planner context 使用率超過 0.99、Executor invocation 達 5、連續失敗達 3、Planner turns 達 8、tool calls 達 10 時觸發。評估使用 GAIA validation text-only 子集（165 題）與 Browsecomp-plus 平衡抽樣 150 題，指標為 Pass@1，並比較 Qwen3-32B、DeepSeek-V4 搭配 ReAct、Summary、ReSum、A-MEM、THREAD 與 HyMem；另分析 token consumption、tool-call count、context growth，並進行移除 isolated reasoning 或 memory management 的消融。

## 關鍵結果

主要數據如下；表中數字為 Pass@1（%），GAIA 欄位依 Level 1/2/3 與平均值呈現，Browsecomp-plus 依 Easy/Medium/Hard 與平均值呈現。

| Backbone / Framework | GAIA L1 | GAIA L2 | GAIA L3 | GAIA Avg. | Browse Easy | Browse Medium | Browse Hard | Browse Avg. |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| DeepSeek-V4 ReAct | 66.6 | 56.1 | 36.8 | 56.6 | 94.0 | 62.0 | 14.0 | 56.6 |
| DeepSeek-V4 ReSum | 76.2 | 54.5 | 47.4 | 60.6 | 78.0 | 46.0 | 6.0 | 43.3 |
| DeepSeek-V4 HyMem | **77.0** | **65.2** | **49.1** | **66.7** | 90.0 | **64.0** | **30.0** | **61.3** |
| Qwen3-32B ReAct | 19.0 | 10.6 | 0.0 | 11.8 | 70.0 | 24.0 | 2.0 | 32.0 |
| Qwen3-32B HyMem | **45.2** | **30.3** | **15.8** | **33.0** | 48.0 | 24.0 | **4.0** | 25.3 |

DeepSeek-V4 HyMem 相較 ReAct 在 GAIA 平均提升 10.1 個百分點，相較 ReSum 提升 6.1 個百分點；在 Browsecomp-plus 平均為 61.3%，較 ReAct 高 4.7 個百分點，Hard 由 14.0% 提升至 30.0%。消融結果：Browsecomp-plus 上移除 isolated reasoning 為 58.0%（下降 5.0 個百分點），移除 memory management 為 54.0%（下降 9.0 個百分點）；GAIA（Qwen3-32B）兩者移除後皆為 13.4%，完整 HyMem 為 32.0%。論文未報告統計顯著性檢定或各試驗的變異數。

## 對我們的啟發
- [ ] 長時程 agent 的 context management 不宜只在扁平軌跡變長後進行 compression；在資訊產生時即按規劃、執行與子任務推理分流，可能更能保護高價值決策訊號。
- [ ] 架構隔離與記憶連續性是不同功能：isolated reasoning 可避免推理噪聲污染 Planner，而 episode、working、tool memory 則保存里程碑、未解缺口與工具經驗，兩者不能簡單互相替代。
- [ ] 評估長時程 agent 時，除 Pass@1 外，應同步觀察 persistent planner context、總 token consumption、tool-call count 與不同難度表現；本文結果顯示效能提升主要體現在中高難度任務，但跨 backbone 並不一致。

## 限制與未來工作

論文指出，HyMem 的效果依賴 backbone 遵循 typed control instructions 並產生可靠 structured returns 的能力，跨模型與 benchmark 的增益並不一致；Qwen3-32B 在 Browsecomp-plus 未勝過 ReAct。實驗僅涵蓋 GAIA text-only 與 Browsecomp-plus 150 題子集，且未報告統計顯著性。未來工作包括 adaptive routing、改進 memory-folding policy、降低 auxiliary distillation 成本，以及處理互動式多輪任務中的 user-intent 變化。
