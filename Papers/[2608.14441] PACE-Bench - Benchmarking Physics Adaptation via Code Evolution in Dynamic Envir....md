# PACE-Bench: Benchmarking Physics Adaptation via Code Evolution in Dynamic Environments

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.14441)
- 📥 [PDF](https://arxiv.org/pdf/2608.14441v1)

## 摘要（中文翻譯）

Self-evolving agents 能從互動經驗改善未來行為，但現有評測通常在固定執行條件下最佳化，未測試環境改變後的恢復能力。本文提出 PACE-Bench（Physics Adaptation via Code Evolution），一個以 simulator 為基礎的 benchmark，涵蓋六個物理領域、144 個 source-to-target adaptation pairs。每個 pair 將具有相同目標與介面的 source environment 連接至經突變的 target environment；原本在 source 中成功的 code-driven design 會在 target 中失敗，agent 必須在有限的 attempt budget 內，利用 diagnostic sandbox feedback 反覆修改並驗證設計。作者比較四種 paradigm 的十種 self-evolving methods。結果顯示 benchmark 尚未飽和：Reflexion + Qwen3-14B 在完整 benchmark 的成功率為 35.9%，GPT-5.5 在 Statics 子集、完整 budget 下達到 66.7%。Simulator-grounded reflection 比未驗證的 self-revision 更可靠；memory 可能使 agent 錨定早期設計，而 broad tree search 雖能探索，卻常無法收斂。即使揭露精確的物理變化，效能上限仍未提高，顯示核心瓶頸是 mechanism redesign，而非單純的 parameter inference。

## 問題背景

現有 self-evolving agent benchmarks 多聚焦於固定執行條件下的 task stream improvement、knowledge transfer 或 held-out generalization，未評估同一目標與介面在環境物理條件改變、原有 executable design 失效後，agent 能否診斷過時假設並重設機制。既有 physical benchmarks 也多只測 design、feedback 或 environment variation 的單一面向，因此缺乏可控且可驗證的 dynamic adaptation 評測。

## 解決方案

作者提出 PACE-Bench，將可執行的 code-driven physical design 與 controlled environment mutation 結合。每個任務先提供在 source environment 成功、但在 target environment 必然失效的設計，再讓 self-evolving agent 在 20 次互動內，根據 simulator 回傳的 constraints、分數與診斷訊息反覆修改程式。資料集以六個 physics domains、36 個 base tasks 和四級 target mutations 建構，並透過 reference solutions 與多層 audit 確認 target 可解且 source solution 不可直接重用。核心創新是將 hidden physical change inference 與 mechanism redesign 放在同一個可重現的 code evolution protocol 中。

## 核心貢獻
1. 提出 PACE-Bench，系統性評估物理環境變化後，agent 對既有 executable design 進行自我適應與 code evolution 的能力。
2. 建立涵蓋六個物理領域、36 個 base tasks、144 個 source-to-target pairs 的可重現 simulator-grounded 評測套件，並確保每個 target environment 具有可驗證的 reference solution。
3. 比較四種 paradigm 的十種 self-evolving methods，並透過 code similarity、九類錯誤 taxonomy、參數揭露與 video feedback 實驗分析 exploration、exploitation、設計錨定及收斂問題。

## 技術方法

PACE-Bench 的基本單位是 source-to-target pair。每個 base task 具有固定 context template C 與五個 environments：source E0 及四個依難度遞增的 mutated environments E1–E4。Prompt 提供自然語言任務描述、constraints、success criteria 與 permitted primitive APIs；設計是定義 build_agent() 與 agent_action() 的 Python program，並在 Box2D sandbox 中執行。每次執行回傳 constraint satisfaction fraction v、task score s 與 diagnostic report d，例如 peak joint force、failure timestamp 或失效位置。Agent 從 source design x0 開始，在 target task 中最多提交 20 個候選程式；第 t 次生成會條件於 task context、Uniform Suffix（列出可能變動的變數但不指出實際變化）及過往候選、分數與診斷歷史。最終分數是所有 attempts 的最高 st，Pass@2 與 Score@2 則由兩次獨立 runs 計算。資料建構分三階段：生成六個物理 domains、每 domain 六個 base tasks；以 modular architecture 與 Claude Code 2 衍生各 environment 的 reference solutions；最後進行 cross-module consistency、variable exposure、API exclusivity、feedback 與 solvability audits，並以 Qwen3-4B 兩次獨立失敗校準難度。實驗以 Qwen3-4B、8B、14B 在完整 benchmark 比較 Vanilla 與十種 methods，並在 Statics 子集測試 Qwen3-32B、DeepSeek-V4-Pro 與 GPT-5.5。方法涵蓋 context-based 的 Reflexion、Self-Refine；memory-augmented 的 ACE、ExpeL、ReasoningBank；inference-time search 的 ToT、CodeEvolve；以及 parameter-based 的 SEAL、RAGEN、TTT-Discover。另以 code similarity、九類失敗 taxonomy、Change-Hidden/Change-Exposed 與 VLM 產生的 video feedback 分析失敗機制。

## 關鍵結果

主要結果如下（Pass@2 為兩次獨立 runs 中至少一次成功的 pair 比例；Score@2 為兩次 run 的最佳分數平均）：

| 設定 | Pass@2 (%) | Score@2 |
|---|---:|---:|
| Vanilla + Qwen3-4B（完整 benchmark） | 11.5 | 10.7 |
| Reflexion + Qwen3-4B（完整 benchmark） | 19.5 | 14.6 |
| Vanilla + Qwen3-8B（完整 benchmark） | 15.6 | 12.0 |
| Reflexion + Qwen3-8B（完整 benchmark） | 26.6 | 18.1 |
| Vanilla + Qwen3-14B（完整 benchmark） | 32.0 | 25.5 |
| Reflexion + Qwen3-14B（完整 benchmark） | 35.9 | 28.0 |
| Vanilla + Qwen3-4B（Statics，20 attempts） | 8.3 | 12.0 |
| Vanilla + Qwen3-14B（Statics，20 attempts） | 37.5 | 27.3 |
| Vanilla + Qwen3-32B（Statics，20 attempts） | 37.5 | 28.4 |
| Vanilla + DeepSeek-V4-Pro（Statics，20 attempts） | 45.8 | 48.7 |
| Vanilla + GPT-5.5（Statics，20 attempts） | 66.7 | 78.1 |

在完整 benchmark 中，Reflexion + Qwen3-14B 是表 2 的最佳 self-evolving configuration，但仍只成功 35.9% 的 pairs。Qwen3-32B 在 Statics 的 Pass@2 未超越 Qwen3-14B。方法比較顯示，Self-Refine 在 Qwen3-14B 僅達 7.1% Pass@2；ToT 在 Qwen3-4B 達 23.4%，但隨模型增大至 Qwen3-14B 降至 20.3%。Kinematics 的成本正規化比較中，ToT 的 Score/Hr 為 45.7、46.4、57.8，分別高於其他方法的多數設定。從 scratch 建構的 Pass@2 為 11.3–18.3%，source environment 為 32.3%，target environments 為 6.4–13.4%。作者報告的 Change-Exposed 實驗中，最佳結果（Reflexion-14B，14.6%）仍低於 Change-Hidden 的 Reflexion-8B（17.9%）。

## 對我們的啟發
- [ ] 實務上應將每次 code revision 都接入可執行 simulator 或測試環境，以驗證修改是否真正改善，而不是只依賴 LLM 的內部 self-critique。
- [ ] 自我演化系統需要同時處理設計多樣性與收斂：memory retrieval 應避免反覆強化早期方案，search 則應加入更明確的方向性選擇與停止條件。
- [ ] 改善診斷資訊不必然解決問題；當 agent 已知道環境改變內容時仍表現受限，系統設計應優先培養機制重構與因果 redesign 能力，而非只進行參數調整。

## 限制與未來工作

PACE-Bench 只評估受控的 2D Box2D simulation，結果未必能轉移至 3D environment 或具有 noisy sensing、actuation 的真實 robot。固定的 20-attempt budget 未涵蓋長期適應。受計算成本限制，frontier model、parameter disclosure 與 visual feedback 僅涵蓋部分 domains、methods；未來可擴展至更豐富的 simulator、real hardware、更長 adaptation horizon 及更廣泛模型。
