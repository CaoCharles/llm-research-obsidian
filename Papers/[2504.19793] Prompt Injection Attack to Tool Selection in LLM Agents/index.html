    Prompt Injection Attack to Tool Selection in LLM Agents

    連結

    • 📄 arXiv
    • 📥 PDF
    • 📎 本地 PDF: PDF

    摘要（中文翻譯）

    工具選擇是 LLM agent 的關鍵元件，常見方法透過「檢索→選擇」兩步驟從工具庫中為給定任務挑選最適工具。本文提出 ToolHijacker，一種在 no-box（完全黑箱）場景下針對工具選擇的新型 prompt injection 攻擊。ToolHijacker 將惡意工具文件注入工具庫，操縱 LLM agent 的工具選擇過程，使其對攻擊者指定的目標任務持續選擇惡意工具。具體而言，將惡意工具文件的生成建模為優化問題，提出兩階段優化策略。大規模實驗顯示 ToolHijacker 高度有效，在工具選擇場景中顯著優於現有手動和自動化 prompt injection 攻擊。進一步測試多種防禦方法（StruQ、SecAlign、DataSentinel 等），結果表明現有防禦均不足以應對此攻擊。

    問題背景

    LLM agent 的工具選擇機制依賴「檢索→選擇」兩步驟，但此管線對工具庫中的惡意文件缺乏防禦。在 no-box 場景下（攻擊者不知道目標 LLM、檢索器或工具庫內容），攻擊者能否透過注入精心設計的工具文件來劫持 agent 的工具選擇？現有 prompt injection 方法未專門針對工具選擇環節，而通用攻擊應用於此場景效果有限。

    解決方案

    ToolHijacker 將攻擊分解為兩階段優化：(1) 檢索階段——優化工具描述以最大化與目標任務的語義相似度，確保惡意工具進入 top-k 檢索結果（使用 LLM 生成或 HotFlip token 級優化）；(2) 選擇階段——生成說服 LLM 從候選工具中選擇惡意工具的文字（使用樹狀 prompt 生成或多損失函數優化，含對齊、一致性、困惑度損失）。攻擊在影子框架上開發，透過可遷移性攻擊未知目標系統。

    核心貢獻

    1. 提出首個專門針對 LLM agent 工具選擇機制的 prompt injection 攻擊 ToolHijacker，在 no-box 場景下達到 96.7%（MetaTool）和 88.2%（ToolBench）的攻擊成功率
    2. 設計兩階段優化策略分別攻克檢索和選擇環節，gradient-free 版本在 8 個 LLM 上展現強跨模型遷移性
    3. 系統評估 6 種防禦方法（StruQ、SecAlign、DataSentinel 等），發現所有現有防禦均不足以應對此攻擊，揭示 agent 工具選擇安全的嚴重空白

    技術方法

    攻擊框架（兩階段）： 1. 檢索優化： - Gradient-free：使用 LLM 生成高語義相似度的工具描述 - Gradient-based：使用 HotFlip 進行 token 級優化 - 目標：惡意工具進入 top-k 檢索結果（AHR 100%）

    1. 選擇優化：
    2. Gradient-free：樹狀結構生成說服性文字
    3. Gradient-based：多損失函數（alignment loss + consistency loss + perplexity loss）
    4. 目標：LLM 從候選中選擇惡意工具

    影子框架：使用可存取的模型（如 GPT-3.5）作為影子，開發攻擊後遷移至目標系統

    實驗設置： - 資料集：MetaTool、ToolBench - 目標 LLM：Llama-2-7B、Llama-3-8B/70B、Claude-3-Haiku/Sonnet、GPT-3.5/4o - 檢索器：text-embedding-ada-002、Contriever、Sentence-BERT - 防禦：StruQ、SecAlign、Known-answer detection、DataSentinel、PPL detection

    關鍵結果

    方法 MetaTool ASR ToolBench ASR
    JudgeDeceiver 30.2% —
    PoisonedRAG 39.3% —
    ToolHijacker (gradient-free) 96.7% 88.2%
    ToolHijacker (gradient-based) 92.2% 83.9%

    防禦有效性： | 防禦方法 | 對 gradient-free 的 ASR | 對 gradient-based 的 ASR | |----------|------------------------|-------------------------| | StruQ | 99.6% | — | | SecAlign | 97.5% | — | | DataSentinel | 80-100% FNR | — | | PPL Detection | — | 90% FNR |

    所有現有防禦均無法有效阻止 ToolHijacker，攻擊成功率仍維持在極高水平。

    對我們的啟發

    • 工具選擇作為 agent 架構的關鍵環節，其安全性幾乎未被防禦——ToolHijacker 96.7% 的 ASR 和所有防禦的失敗表明，這是 agent 安全中最薄弱的環節之一，需要全新的防禦範式
    • 兩階段攻擊（檢索劫持 + 選擇操縱）的分解策略可推廣至其他 RAG 管線的攻擊，任何依賴「檢索→生成」架構的系統都面臨類似的工具/文件注入風險
    • Gradient-free 攻擊的強跨模型遷移性（在影子模型上開發，攻擊 8 個不同 LLM 均有效）表明 LLM 的工具選擇決策存在跨架構的共通脆弱模式

    限制與未來工作

    影子框架的效果依賴影子模型與目標系統的架構相似度，差異過大時性能下降。Gradient-based 優化降低工具文件的可讀性。大型工具庫（ToolBench vs MetaTool）增加檢索挑戰。僅考慮單一惡意工具注入，多工具注入場景未評估。
