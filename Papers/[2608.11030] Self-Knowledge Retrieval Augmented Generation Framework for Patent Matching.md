# Self-Knowledge Retrieval Augmented Generation Framework for Patent Matching

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.11030)
- 📥 [PDF](https://arxiv.org/pdf/2608.11030v1)

## 摘要（中文翻譯）

基於大型語言模型（LLM）的專利檢索與匹配對智慧財產權保護十分重要。然而，專利文件結構複雜、技術術語密集，且包含文字與圖像等多模態資訊，使傳統方法難以辨識專利間的細微差異。現有 LLM 專利匹配方法通常依賴領域預訓練或 instruction tuning，需付出高昂的人工標註成本，並可能造成 catastrophic forgetting。RAG 雖能引入外部知識，卻未充分發揮 LLM 自動解析專利及挖掘深層語義關係的能力。本文提出 Self-Knowledge RAG framework，從專利匹配查詢中自主擷取關鍵技術實體，建立階層式 ontology，據此進行 query expansion 與精確檢索。方法結合 FAISS retrieval 與 generative matching，利用 self-knowledge 增強模型對專利創新的理解，並在真實專利資料集上提升檢索與匹配準確率。

## 問題背景

專利文件具有複雜結構、密集技術術語及文字與圖像等多模態資訊，傳統關鍵詞或嵌入方法難以辨識細微的創新相似性。領域預訓練與 instruction tuning 需要大量人工資料，且有 catastrophic forgetting 風險；一般 RAG 雖引入外部專利知識，卻可能受檢索噪聲影響，未充分利用 LLM 自動解析專利、建立跨專利語義關係及改善查詢表示的能力。

## 解決方案

作者提出 Self-Knowledge RAG framework，讓 LLM 先從查詢專利摘要自主挖掘技術實體與階層式 ontology，再將這些資訊用於 query expansion。擴展後的查詢透過 bge-large-v1.5 編碼，交由 FAISS 從專利庫檢索 top-K 相似文件；最後把原始摘要、自挖掘知識、ontology 與檢索內容整合成 context-aware prompt，由 LLM 執行 generative matching。核心創新在於把 LLM 從僅接收檢索結果的被動生成器，轉變為主動的專利資訊解析與檢索引導器，結合微觀實體、宏觀 ontology 與外部上下文以支援匹配。

## 核心貢獻
1. 提出基於 LLM 的 patent self-knowledge mining strategy，從目標專利摘要中自動擷取關鍵技術實體並建立 entity-ontology 關係。
2. 提出 self-knowledge guided RAG framework，以自動挖掘的實體資訊擴展查詢，改善 FAISS 向量檢索，並將原始專利、ontology 與檢索上下文交由 LLM 進行生成式匹配。
3. 在包含中英文、8 個 IPC 類別及 1,000 個匹配實例的 PatentMatch 資料集上，與 vanilla LLM、CoT、一般 RAG 及領域專用模型比較，驗證方法的有效性。

## 技術方法

任務設定是：給定查詢專利 p_q 與 N 個候選專利，模型輸出創新相似度最高的候選專利識別碼。框架採用「Preparation–Retrieval–Reasoning」三階段。第一階段以 LLM 和客製化 instruction 解析查詢及候選專利摘要，抽取具體技術實體，例如技術概念、元件模組與核心方法；接著根據抽取結果建立階層式 ontology。論文說明 ontology 主要借助 IPC 的階層概念，並以 technology、function、application 等層次組織資訊。第二階段將查詢專利的實體串接成 TIR，與原始摘要合併形成 expanded query；使用 bge-large-v1.5 將查詢及候選專利編碼，並以 FAISS 建立向量索引，透過 cosine similarity 進行 K-nearest-neighbor 檢索，取得 top-K 候選專利。第三階段把原始查詢摘要、自挖掘的實體與 ontology、FAISS 檢索結果及任務指令整合為 RAG prompt，要求同一 backbone LLM 以 patent examiner 角色，依據技術領域、功能、應用與元件結構判斷最相似候選。資料集為 PatentMatch 的 1,000 個真實專利匹配實例，包含 500 篇中文與 500 篇英文專利，涵蓋 8 個 IPC 類別；另使用 300,000 篇專利作為檢索庫。評估指標為 Accuracy，並比較 Qwen2-Instruct-7B、GLM-4-Chat-9B、Qwen2.5-Instruct-14B 的 vanilla、CoT、一般 RAG 與本文方法，以及 MoZi、PatentGPT 和 PatentGPT-Dense。

## 關鍵結果

論文以 Accuracy 為主要指標，報告結果如下：

| 模型／方法 | English | Chinese | Overall |
|---|---:|---:|---:|
| MoZi-7B | 25.8 | 29.0 | 27.4 |
| PatentGPT-1.5B | 26.2 | 論文未報告 | 論文未報告 |
| PatentGPT-1.0-Dense-70B | 66.2 | 72.0 | 69.1 |
| Qwen2-Instruct-7B Vanilla | 31.4 | 47.0 | 39.2 |
| Qwen2-Instruct-7B CoT | 32.8 | 49.2 | 41.0 |
| Qwen2-Instruct-7B RAG | 49.2 | 68.2 | 58.7 |
| Qwen2-Instruct-7B Ours | 34.4 | 69.8 | 52.1 |
| GLM-4-Chat-9B Vanilla | 66.4 | 65.0 | 65.7 |
| GLM-4-Chat-9B CoT | 68.0 | 65.6 | 66.8 |
| GLM-4-Chat-9B RAG | 75.8 | 69.4 | 72.6 |
| GLM-4-Chat-9B Ours | 83.6 | 79.0 | 81.3 |
| Qwen2.5-Instruct-14B Vanilla | 63.8 | 70.0 | 66.9 |
| Qwen2.5-Instruct-14B CoT | 64.0 | 71.2 | 67.6 |
| Qwen2.5-Instruct-14B RAG | 70.8 | 64.2 | 67.5 |

作者指出，GLM-4-Chat-9B 搭配本文方法取得最高 Overall Accuracy 81.3；Qwen2.5-Instruct-14B 搭配本文方法達 80.7。與相同 backbone 的一般 RAG 相比，GLM-4-Chat-9B 由 72.6 提升至 81.3，Qwen2.5-Instruct-14B 由 67.5 提升至 80.7；Qwen2-Instruct-7B 的本文方法結果為 52.1，低於其一般 RAG 的 58.7。上述數據顯示方法在不同 backbone 上並非一致優於一般 RAG。

## 對我們的啟發
- [ ] 實務上可將 LLM 產生的技術實體作為向量檢索前的 query expansion，以補足專利摘要表述不完整或語義稀疏的問題。
- [ ] 可將細粒度實體與較高層級 ontology 同時放入生成提示，讓匹配判斷兼顧元件、功能、應用與技術領域，而非只依賴表面詞彙相似度。
- [ ] 部署此方法時應分別檢查自動抽取、FAISS top-K 檢索及最終 LLM 判斷的錯誤來源；論文報告整體 Accuracy，但未提供各階段的獨立評估。

## 限制與未來工作

資料集僅包含 1,000 個匹配實例，候選知識庫為 300,000 篇專利；實驗主要使用摘要與文字資訊，尚未整合專利圖像等 multimodal data。論文未報告 entity extraction、ontology construction、top-K retrieval 的獨立指標、消融實驗或統計顯著性，也未說明方法在更大規模及其他領域的泛化性。作者將 dynamic ontology generation 與多模態資料整合作為未來工作。
