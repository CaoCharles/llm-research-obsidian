# ProgRouter: Online Progress-Guided Orchestration for Multi-Agent LLM Workflows under Quality-Cost Tradeoffs

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.25992)
- 📥 [PDF](https://arxiv.org/pdf/2608.25992v1)

## 摘要（中文翻譯）

多代理 LLM 工作流透過專業化 agent 的協作推理處理複雜、開放式任務，但反覆呼叫 LLM 與累積長期上下文會造成高昂的 token、計算、能源與延遲成本。既有 cascade routing 多在查詢層級做一次性決策，無法因應多步工作流中隨任務進度、剩餘難度與成本要求變化的路由需求。本文提出 ProgRouter，一個線上、由進度引導的 orchestration framework，在各工作流步驟自適應選擇 LLM agent，以維持解題品質並遵守時間與成本預算。方法結合多視角任務進度評分器、結構化與語意雙路徑進度預測器，以及 adaptive meta-gating，估計候選 LLM 的進度增益，再聯合考量進度缺口、任務時間預算與長期成本效率進行路由。在 HumanEval Plus、MBPP、MATH-500 與 ASQA 上，ProgRouter 相較關鍵 baseline 降低 operating cost，同時維持良好任務表現。

## 問題背景

論文處理多代理 LLM 工作流中的線上、逐步模型選擇問題。現有 cascade routing 多採查詢層級的一次性決策，無法根據中間 workflow state、已完成子任務、剩餘難度與協作需求動態調整。若始終使用強模型，可能過早耗盡成本；若過度保守，則可能因能力不足造成停滯與品質不可逆下降。因此需要在未知未來步驟下，同時滿足每任務時間／成本預算及長期平均成本限制。

## 解決方案

作者提出 ProgRouter，讓 coordinator 維持包含目標、進度、推理痕跡與 agent 輸出的 ledger，並在每次 worker role 已確定後，從該角色可用的 model zoo 中選擇 LLM。核心包括多視角進度評分器、結構化與語意雙路徑 progress-gain predictor，以及 adaptive meta-gating。路由分數同時納入剩餘進度缺口、預測進度增益、任務時間／成本預算與 virtual cost queue；另以 ε-greedy 線上探索收集實際進度增益並週期性更新預測器，逐步由探索轉向利用。

## 核心貢獻
1. 提出適用於多代理、多步工作流的 online step-wise LLM routing formulation，將任務品質、每任務時間／成本預算與長期平均 operating cost 納入同一約束最佳化問題。
2. 提出結合 coarse outcome regime、subtask completion、progress trend 與 state quality 的 multi-view task progress scorer，提供比稀疏最終結果更密集的中間監督訊號。
3. 提出 structured／semantic dual-path progress predictor 與 adaptive meta-gating，並結合 progress-gap-aware scoring、budget penalty、virtual cost queue 與 ε-greedy online learning。

## 技術方法

工作流由 coordinator C、預定義 worker roles R 與可供各角色選擇的異質 LLM 集合 M 組成；每次 dispatch 依目前狀態 st 與角色 rt 選擇 mt，產生下一狀態。多視角 scorer 將狀態映射至 g(st)∈[0,1]，結合四種資訊：invalid、recoverable、partial success、complete 四類 outcome regime 的 base score；子任務／約束完成比例；最近步驟的進度趨勢；以及狀態轉移的語意與結構品質。預測器對每個候選 LLM 估計進度增益 ŷt：structured path 使用進度、完成狀態、趨勢與 dispatch history 等 tabular features，由 tree-based regressor 預測；semantic path 將 coordinator 產生的狀態摘要以輕量 sentence embedding 編碼，再由另一 regressor 預測；meta-learner 自適應整合兩者。路由分數為 V(1−g(st))ŷt−Qw(E(mt)−Ē)−cΓtΓ(mt)−cEtE(mt)，其中 Qw 透過 virtual queue 控制長期平均成本，cΓt 與 cEt 隨累積預算消耗增加。每步以 argmax 選擇模型；以 ε 機率探索，執行後用 g(st+1)−g(st) 作為訓練目標。評估涵蓋 HumanEval Plus、MBPP、MATH-500 的 pass rate，以及 ASQA 的 citation precision，並量測 GPU energy（Joule）與 workflow time。

## 關鍵結果

主要結果如下；表中僅列出論文報告且符合長期平均能源限制的 ProgRouter 與代表性 baseline 數據。

| 資料集（Ē） | 方法 | 品質 | Energy (J) | Time (s) |
|---|---|---:|---:|---:|
| HumanEval Plus (4800 J) | ProgRouter | Pass 93.0% | 4796 | 13.7 |
|  | MasRouter | Pass 90.9% | 4483 | 13.2 |
|  | CASCADIA | Pass 84.8% | 4658 | 16.6 |
| MBPP (4500 J) | ProgRouter | Pass 79.4% | 3376 | 10.3 |
|  | MasRouter | Pass 67.8% | 3700 | 11.5 |
|  | CASCADIA | Pass 78.5% | 3857 | 13.3 |
| MATH-500 (7000 J) | ProgRouter | Pass 84.3% | 6112 | 19.0 |
|  | CASCADIA | Pass 87.8% | 6875 | 24.6 |
|  | MasRouter | Pass 73.6% | 8294（違反 Ē） | 24.0 |
| ASQA (19000 J) | ProgRouter | Citation precision 92.1% | 18373 | 61.6 |
|  | MasRouter | Citation precision 89.8% | 16368 | 55.3 |
|  | CASCADIA | Citation precision 89.8% | 27857（違反 Ē） | 82.1 |

HumanEval Plus 上，移除 predictor 後 pass rate 由 93.0% 降至 89.0%；完整雙路徑加 meta-learner 的離線 progress prediction MAE 為 0.0720，優於 structured-only 的 0.0967、semantic-only 的 0.0788 與平均融合的 0.0843。

## 對我們的啟發
- [ ] 實務部署多代理工作流時，模型路由不宜只在請求開始時決定；可依中間狀態與子任務完成度，在每個 agent dispatch step 重新選擇模型。
- [ ] 成本控制應同時處理單一任務預算與跨任務長期平均偏差；論文中的 per-task budget penalty 與 virtual queue 可作為服務層策略設計參考。
- [ ] 進度訊號本身不足以支援穩健路由：論文消融顯示，若只做貪婪 progress-per-cost 選擇，HumanEval Plus 僅達 17.7% pass 且耗能 7797 J，因此應聯合考量剩餘進度缺口、預算消耗與未來成本後果。

## 限制與未來工作

評估僅涵蓋 HumanEval Plus、MBPP、MATH-500 與 ASQA，尚未驗證 web navigation、tool-augmented QA 等其他 agentic setting。multi-view progress scorer 仍需依領域指定 observable milestones 與 outcome regimes；如何完全端到端地自動學習進度表示，留待未來研究。
