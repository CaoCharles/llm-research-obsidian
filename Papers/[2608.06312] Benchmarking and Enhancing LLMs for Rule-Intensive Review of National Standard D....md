# Benchmarking and Enhancing LLMs for Rule-Intensive Review of National Standard Documents

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.06312)
- 📥 [PDF](https://arxiv.org/pdf/2608.06312v1)

## 摘要（中文翻譯）

大型語言模型（LLM）日益支援複雜專業任務，但其在規則密集型文件審查上的能力仍缺乏系統評估。中國 GB/T 國家標準文件篇幅長、結構嚴謹，並受適用範圍、術語、規範性措辭與跨章節一致性等明確規則約束，因此提供了具代表性的測試場景。本文提出 GB/T-Bench，首個用於國家標準文件結構化審查的 benchmark，建立涵蓋文件結構、範圍一致性、規範模態、術語一致性及規範性引用的 GB/T Review Taxonomy，細分為 25 種可診斷錯誤。作者結合確定性規則與受約束的 LLM 改寫，處理 488 份文件並產生 7,306 個可追溯錯誤實例；同時提出要求錯誤位置、審查維度與錯誤類型完全匹配的評估協定，以及文件層級覆蓋率指標。進一步提出 GB/T-Reviewer 多代理框架，協調全局檢查、維度專家、錯誤類型代理、規則掃描與結果驗證。14 個 LLM 的實驗顯示，最佳單一模型 CMCS 僅 0.3280，專家為 0.6640；GB/T-Reviewer 將最佳 CMCS 提升至 0.5094，顯示結構化技能協調有助於規則密集型專業文件審查。

## 問題背景

現有專業文件 benchmark 多數評估知識理解、問答、檢索或合規判斷，通常把規則文本視為輸入規範，未評估文件本身是否違反結構、範圍、措辭、術語與引用規則。國家標準文件的審查需要完整文件理解、精確定位、細粒度分類及跨章節驗證，且自然錯誤蒐集與專家標註成本高，因此缺乏可追溯、可診斷、可規模化的評測基礎。

## 解決方案

作者提出兩部分解決方案。第一是 GB/T-Bench，以五維 taxonomy 與 25 種錯誤類型定義審查空間，透過 deterministic rules 和 constrained LLM rewriting 對真實 GB/T 文件注入可控錯誤，並以位置、維度、類型的 exact diagnosis 進行評估。第二是 GB/T-Reviewer，將審查知識轉為多層次專業技能：Direct-All Reviewer 提供全局覆蓋，Dimension Specialists 進行維度分工，Error-Type Agents 聚焦高風險細分類型，rule/local scanners 提供可計算證據；最終由 prediction module 驗證、融合、去重並標準化輸出。

## 核心貢獻
1. 提出 GB/T-Bench：以五個審查維度與 25 種細粒度錯誤類型，建立國家標準文件內在品質審查 benchmark。
2. 提出結合確定性規則與受約束 LLM 改寫的 counterexample generation 機制，產生具錯誤位置、類型與原文對照的可追溯資料。
3. 提出 diagnosis-oriented 評估協定與 CMCS、DMTR_k 等指標，並以 GB/T-Reviewer 多代理框架驗證專業審查技能分解與協調的效益。

## 技術方法

論文先依據 GB/T drafting requirements 與專家審查實務建立兩層 GB/T Review Taxonomy，包含五個維度：Structure（D_STR）、Scope（D_SCP）、Normative Modality Strength（D_NMS）、Terminology（D_TER）及 Normative Reference（D_NREF），共 25 種錯誤類型。資料建構流程先解析 488 份文件與 64,991 個 sections，再以 dimension-guided error injection 產生反例：結構與格式錯誤使用 deterministic rules，語義錯誤則使用具規則約束的 LLM rewriting；每個實例保留原文、污染後文本、錯誤位置、維度、類型與描述。三名受訓研究生進行端到端品質控制，並由兩名領域專家與三名研究生驗證最終資料的 30%。評估採 diagnosis-level exact matching，只有 section location、review dimension 與 error type 三者同時正確才算命中；使用 Recall、DMTR_k（至少診斷 k 個錯誤的文件比例）及同時懲罰漏報與冗餘預測的 CMCS。GB/T-Reviewer 包含 GB/T parsing module、expert review module 與 prediction module。解析器保留 section number、title 與 content；審查模組並行使用 Direct-All Reviewer、五類 Dimension Specialists、選定高風險 Error-Type Agents，以及模態、術語和引用的 rule/local scanners；預測模組再進行 taxonomy validity filtering、confidence-based fusion、合併、去重、位置細化與輸出標準化。作者在 14 個閉源與開源 LLM 上比較單一 prompt、人工審查及多代理設定，並以 GPT-5.5 進行模組消融。

## 關鍵結果

| 設定／模型 | DMTR_10 | Recall | CMCS |
|---|---:|---:|---:|
| Human Review | 0.8479 | 0.8308 | 0.6640 |
| 最佳單一閉源模型 GPT-5.6-sol | 0.2174 | 0.5203 | 0.3280 |
| 最佳單一開源模型 DeepSeek-v4-Pro | 0.0492 | 0.3961 | 0.2269 |
| GB/T-Reviewer + GPT-5.5 | 0.7860 | 0.7314 | 0.5094 |
| 閉源模型平均：Single Prompt | 0.1256 | 0.4172 | 0.2504 |
| 閉源模型平均：GB/T-Reviewer | 0.5080 | 0.6311 | 0.4160 |
| 開源模型平均：Single Prompt | 0.0291 | 0.3043 | 0.1671 |
| 開源模型平均：GB/T-Reviewer | 0.2827 | 0.5276 | 0.3186 |

資料集包含 488 份文件、64,991 個 sections、7,306 個錯誤實例，平均每份文件 14.97 個錯誤。人工驗證中，維度標籤 exact agreement 為 96.33%、Cohen’s κ 為 0.947；錯誤類型 exact agreement 為 95.92%、κ 為 0.955。消融實驗顯示，移除 Direct-All Reviewer 的效能下降最大；移除維度專家、錯誤類型代理或規則／局部 scanner 也會造成下降。

## 對我們的啟發
- [ ] 對規則密集型文件，應將審查目標拆分為結構、範圍、模態、術語與引用等明確技能，而非只依賴單一全局 prompt。
- [ ] 評測專業審查系統時，僅計算是否找出錯誤不足以反映實用性；應同時要求錯誤位置、維度與細分類型匹配，並對漏報與冗餘報告施加懲罰。
- [ ] 確定性 scanner 可處理術語索引、模態詞、章節編號與引用關係等可計算線索，再由 LLM 進行語義判斷，形成可解釋且互補的混合式審查流程。

## 限制與未來工作

論文主要以 GB/T 文件及人工注入的 counterexamples 評估，未提供自然發生錯誤與其他國家標準或專業領域上的外部泛化結果。資料生成包含受約束 LLM 改寫，可能使錯誤分布與真實審查不同；此外，論文未完整報告各代理的成本、延遲、隨機性控制、統計顯著性及不同注入策略的獨立影響。未來可加入真實缺陷、多領域資料與更完整的成本—效能分析。
