# Large Language Models for HVAC Operations in Building Energy Systems: A Critical Review of Methods, Applications, and Deployment Readiness

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2609.05314)
- 📥 [PDF](https://arxiv.org/pdf/2609.05314v1)

## 摘要（中文翻譯）

建築自動化系統（BAS）產生大量感測器資料，卻因點位命名異質、metadata 缺失及文件分散，難以轉化為可操作的洞見。本系統性回顧分析 2023 年至 2026 年 3 月發表的 66 篇 LLM 用於 HVAC operations 的同儕審查研究，並依五類應用與三類 LLM 方法進行編碼，同時評估證據真實性、部署成熟度，以及 LLM 與實體 HVAC 決策之間的責任邊界。研究集中於 building energy modelling（BEM），共 32 篇；load forecasting 研究數量過少，尚不足以形成子領域結論。僅 4 篇研究達到 pilot-level evidence，且沒有研究報告持續性的實際營運部署。沒有研究可被分類為可立即產業採用，3 篇屬於近期可行，63 篇仍為研究階段。現有證據主要支持 LLM 擔任語意與工作流程層，而非自主 HVAC 控制器。近期可試行的受限用途包括點位名稱正規化、文件導向的操作員支援、BEM 工作流程協助，以及圍繞 physics-based controllers 的建議介面。未來應優先建立現場驗證 benchmark、評估受營運限制的 orchestration，並發展具有限延遲與可驗證安全性質的 LLM–MPC/RL 架構。

## 問題背景

HVAC 營運資料分散於 BAS 點位、設備手冊、BIM、ontology、維護紀錄與感測器歷史資料中；異質命名、缺少 metadata、文件不可直接被分析工具使用，使故障診斷、模型建立與控制部署受阻。既有 ML、MPC 與 RL 雖在模擬環境具成效，卻面臨跨設備泛化、信任、整合、延遲、可稽核性與治理問題。現有文獻亦缺乏將應用任務、LLM 方法、證據真實性、部署成熟度及責任邊界共同分析的系統性框架。

## 解決方案

作者提出一套針對 LLM-for-HVAC operations 的系統性回顧與部署評估框架。研究將 66 篇主要研究依五個應用家族分類：fault detection and diagnosis、energy load forecasting、BEM and simulation、control and optimisation、thermal comfort and occupant interaction；並依三種整合方法分類：M1 prompting and supervised adaptation、M2 context-grounded orchestration、M3 multimodal input。框架進一步以 evidence type、deployment readiness、responsibility boundary 與 safety/governance reporting 評估研究是否具備實務可部署性。核心觀點是將 LLM 放置於 semantic and workflow layer，負責解讀、對齊、檢索與路由異質資訊，再透過 schema/unit checks、retrieval grounding、human review、simulation、MPC、RL 或 BAS 工具將輸出與實體控制隔離，避免未受限制的自主致動。

## 核心貢獻
1. 建立涵蓋 66 篇研究的 A1–A5 應用分類與 M1–M3 方法分類，並以 A×M map 描述 LLM 在 HVAC operations 的研究分布與結構性缺口。
2. 提出結合 evidence realism、closed-loop validation、部署成熟度與 responsibility boundary 的 deployment-readiness 評估，明確區分 ready-now、near-term 與 research-only。
3. 提出以 LLM 作為 semantic and workflow layer、由人員或 physics-based controller 負責實體決策的安全邊界，並整理文件接地、點位正規化、BEM 協助與控制建議等受限用途。

## 技術方法

研究以 Scopus 建立文獻 corpus，搜尋式結合 large language model、LLM、GPT、ChatGPT、generative AI、RAG 等詞，並與 HVAC、building energy、building performance 或 building management system 等詞交集；納入 2023 年起至 2026 年 3 月 31 日索引的英文、同儕審查 article、review 與 conference paper。初始取得 142 筆，經標題摘要篩選排除 38 筆，再對 104 筆全文評估，排除 38 筆後納入 66 篇 primary studies。每篇研究指定一個主要 application category，並依主要整合邏輯指定 M1–M3；具 run-time retrieval、database、tool interface、memory 或 orchestration loop 者歸入 M2，僅以 vision–language encoder 處理非文字輸入者歸入 M3。證據類型分為 conceptual、simulation-only、lab study、retrospective field data、pilot deployment 與 operational deployment。部署成熟度分為 ready-now、near-term、research-only；責任邊界則區分 LLM advisory–human decides、LLM generates–human reviews、LLM autonomous–low risk 與 LLM autonomous–high risk。另以 data realism、experimental or field realism、closed-loop validation、reproducibility、safety/governance reporting 五項準則輔助判讀。論文未提出統一的跨研究效能統計或 meta-analysis；F1、R²、MAE、RMSE、energy savings 等僅作為個別研究可能使用的指標，不能直接形成整體比較。

## 關鍵結果

| 評估項目 | 論文報告結果 |
|---|---|
| 納入研究數 | 66 篇 primary studies |
| 應用分布 | A1 FDD：9；A2 Forecast：3；A3 BEM：32；A4 Control：15；A5 Comfort：7 |
| 方法分布趨勢 | 文獻由 M1 prompting/fine-tuning 逐漸轉向 M2 context-grounded orchestration；M3 multimodal 仍較少 |
| 最大交叉類別 | A3 × M2，共 15 篇 |
| 證據類型 | Simulation-only：30；Retrospective field：23；Lab study：9；Pilot deployment：4 |
| 持續營運部署 | 論文未報告任何 sustained operational deployment |
| 部署成熟度 | Ready-now：0；Near-term：3；Research-only：63 |
| 近期可試行用途 | Point-name normalisation、document-grounded operator support、BEM workflow assistance、physics-based controller 周邊的 advisory interface |
| 適用技術邊界 | ML、MPC、RL 與 ontology-based tools 仍較適合高頻控制、短期數值 forecasting 與 well-posed ontology mapping |

## 對我們的啟發
- [ ] 若要導入 HVAC LLM，應優先選擇可由人員審核、低風險且不直接控制安全關鍵設備的語意與工作流程任務，而非讓 LLM 直接取代 MPC、RL 或 BAS 控制邏輯。
- [ ] 企業評估 RAG 或 agentic HVAC 系統時，不能只看回答正確率或單次節能率，還應驗證 retrieval 品質、工具使用、延遲、錯誤傳播、schema/unit checks、fallback 與操作員覆核流程。
- [ ] 建立 field-validated benchmark 與跨設備測試特別重要；論文指出 AHU、chiller 資料主導現有 FDD 研究，heat-pump 的 LLM FDD、forecasting 與 control 仍是明顯缺口。

## 限制與未來工作

研究受限於單一 Scopus、英文與同儕審查文獻範圍，可能遺漏快速變動的 arXiv、GitHub 與產業部署證據。2026 年僅涵蓋第一季，且 coding 由單一 reviewer 執行。各研究任務、資料與指標差異大，論文未提供統一 meta-analysis；未來應進行現場驗證、受營運限制的 orchestration 評估，以及具有限延遲、可驗證安全性質的 LLM–MPC/RL 整合。
