# Beyond Retrieval: Analytic Memory for Multimodal Agents

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2607.29440)
- 📥 [PDF](https://arxiv.org/pdf/2607.29440v1)

## 摘要（中文翻譯）

長期 multimodal memory 不僅需要擷取相關資訊，也必須能對跨互動累積的觀察進行計算。現有系統多著重 retrieval memory，透過摘要與索引，以不同粒度回傳與查詢相關的歷史資訊。本論文提出互補的 analytic memory 概念，將重複出現的 multimodal 觀察組織成可查詢結構，支援 filtering、aggregation、ranking 與 temporal comparison。作者提出 AdaMM，聯合支援 retrieval 與 analytic memory。AdaMM 不依賴應用程式預先定義的 schema，而是從對話、影像與 contextual metadata 擷取具 provenance 連結的 attribute-value observations，發掘重複欄位結構並將其 materialize，以供分析存取。推論時，memory-aware planner 將查詢分解為 retrieval 與 analytic operations，並將各操作路由至適當工具。在 MemEye 與 MemGallery 兩個長期 multimodal memory benchmark 上，AdaMM 的效能最高分別提升 11.3% 與 7.3%。

## 問題背景

長期 multimodal agent histories 會累積對話、影像、文件與 contextual observations，超出模型有限的 context window。現有 retrieval-oriented memory 擅長找出語意相關記憶，卻不保證取得完整且正確範圍的紀錄；當問題需要跨回合 filtering、aggregation、ranking 或 temporal comparison 時，小型擷取集會遺漏資料，大型擷取集則消耗 context budget 並引入冗餘，形成 retrieval–analysis mismatch。

## 解決方案

作者提出 AdaMM，將 retrieval memory 與 analytic memory 結合。系統從對話、影像及 metadata 擷取具 provenance 的 attribute-value observations，不依賴應用程式預先指定 schema，而是透過頻繁模式與共現一致性發掘 recurring schemas，並將其 materialize 為可執行分析的 tables；同時以 topic、episode、event 階層保存開放式語意記憶。推論時，memory-aware planner 根據 query 與目前 memory metadata，選擇並組合 semantic retrieval、event localization 及表格分析工具，透過 progressive execution 完成依賴式多步查詢。

## 核心貢獻
1. 指出長期 multimodal agent memory 中的 retrieval–analysis mismatch：單純以相關性擷取記憶，難以可靠支援完整範圍的 filtering、aggregation、ranking 與 temporal selection。
2. 提出 AdaMM，從多模態互動中擷取具 provenance 的 attribute-value pairs，透過 candidate pattern mining、schema discovery 與 schema evolution 建立 schema-induced analytic memory，並與階層式 retrieval memory 並行運作。
3. 提出 memory-aware joint query planning，結合 planning context、high-level plan generation 與 progressive tool execution，根據查詢及目前可用的 memory 結構組合 semantic retrieval 與 deterministic analytics。

## 技術方法

論文將互動歷史表示為按時間排列的 multimodal interaction rounds，每回合包含 dialogue、visual observations 與 temporal information。AdaMM 建立兩類互補記憶：analytic memory 與三層 topic→episode→event 的 retrieval memory。建立 analytic memory 時，LLM-based Extractor 從每回合對話及影像擷取 attribute-value-provenance tuples，保留來源對應的文字 span 或影像證據。接著以 Apriori 式 candidate pattern mining 計算 attribute set 的 support；符合 all-confidence 的 inclusion-maximal candidates 被納入新 schema，既有 schema 則以 extension confidence 判斷是否加入穩定出現的新欄位。每個 schema 被 materialize 成表格，欄位為 attributes、列為匹配互動，並附加 order 與 time；欄位型別、表名及描述由 language model 推定，未觀察值留空。Retrieval memory 則保存開放式事件及其多模態證據、時間與 provenance。查詢時，系統以表格及 episode metadata 建立 planning context，使用 semantic encoder cosine similarity 與 token similarity 排序候選記憶，再由 LLM planner 產生最多三步的 high-level plan。工具包括 analytic memory 的 LOOKUP、FILTER、COMPUTE、RANK，以及 retrieval memory 的 SEMANTICMATCH、EVENTLOCATE。工具呼叫採 progressive execution，後續參數可使用前一步結果。最後 answer model 根據計畫與工具輸出產生回答。評估使用 MemEye 的 EM、BLEU-1、LLM-Judge，以及 MemGallery 的 F1、BLEU-1、LLM-Judge；結果平均自三次執行。

## 關鍵結果

論文在 MemEye 與 MemGallery 上，以 GPT-4.1-nano 及 GPT-5.4-mini 作為 answer backbone，結果如下；所有指標皆為越高越好。

| Backbone | 方法 | MemEye EM | MemEye BLEU-1 | MemEye LLM-Judge | MemGallery F1 | MemGallery BLEU-1 | MemGallery LLM-Judge |
|---|---|---:|---:|---:|---:|---:|---:|
| GPT-4.1-nano | UniversalRAG | 43.1 | 16.5 | 40.2 | 57.7 | 52.4 | 67.0 |
| GPT-4.1-nano | AdaMM | **50.4** | **21.2** | **48.0** | **62.6** | **56.7** | **74.3** |
| GPT-5.4-mini | UniversalRAG | 62.4 | 30.4 | 48.6 | 65.6 | 60.8 | 77.4 |
| GPT-5.4-mini | AdaMM | **65.5** | **35.9** | **60.7** | **69.1** | **64.1** | **83.9** |

相較於同一 backbone 下的最強競爭結果，作者報告 GPT-4.1-nano 的 AdaMM 在 MemEye MCQ 與 open-ended 分別提升 7.3 與 5.8 個百分點，MemGallery 的 F1、BLEU-1 與 LLM-Judge 分別提升 4.2、4.3 與 7.0 個百分點；GPT-5.4-mini 則在 MemEye 提升 3.2 與 11.3 個百分點，MemGallery 提升 2.6、2.2 與 5.2 個百分點。消融結果顯示，移除 analytic memory 使整體下降 4.6%，Health 下降 14.9%；移除 retrieval memory 使整體下降 7.5%，Brand 下降 9.9%。移除 planning context 使整體下降 3.3%，預先實例化全部工具呼叫則使 Health 與 Brand 分別下降 4.2% 與 3.2%。

## 對我們的啟發
- [ ] 若應用需要回答平均值、趨勢、排名或時間區間比較，應保存可計算的結構化觀察，而不只建立向量索引或摘要。
- [ ] analytic memory 與 retrieval memory 的職責應分離：前者處理可重複欄位上的精確運算，後者保留開放式事件、語意關係及視覺細節。
- [ ] 多步驟 memory query 可採用先產生抽象計畫、再依中間結果逐步實例化工具參數的策略，以支援後續操作依賴前一步輸出的情境。

## 限制與未來工作

作者指出，analytic memory 依賴多模態 record fragments 的擷取；欄位錯誤或遺漏可能傳播至 schema induction、表格建立及後續計算。未來可加入 confidence-aware extraction 與跨回合一致性檢查。此外，AdaMM 使用預先定義的 access tools，遇到 domain-specific operations 時需人工擴充；未來可研究能安全合成、驗證並整合新工具的 self-evolving tool framework。
