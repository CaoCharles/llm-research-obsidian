# ParVL: Parallel Scaling and Expandable Compute Allocation for Multimodal LLMs

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.04010)
- 📥 [PDF](https://arxiv.org/pdf/2608.04010v1)

## 摘要（中文翻譯）

現有 Multimodal Large Language Models（MLLMs）的 scaling strategies 通常擴增模型參數，或增加 sequential inference computation，因此分別帶來顯著的記憶體或延遲成本。更重要的是，多數方法無法改變 Vision Transformer（ViT）與 Large Language Model（LLM）元件之間僵化且固定的計算分配，限制了 task-specific optimization。為此，本文提出 Parallel Vision-Language（ParVL）scaling framework，透過在多個 vision 與 language branches 之間重用既有 ViT 和 LLM backbone 參數，擴增 parallel computation。在固定 backbone 參數預算下，作者研究額外共享-backbone computation 應如何分配至 vision 與 language modalities。每個 parallel stream 以 branch-specific prefix parameters 建立於共享 backbone 之上，並以約 13B tokens 進行 end-to-end full-parameter supervised fine-tuning。實驗系統分析 ViT encoder 與 LLM decoder 的計算分配取捨，顯示 ParVL 整體表現優於相同訓練配方的 single-branch baselines，且最佳 vision-language allocation 會隨任務而變化。

## 問題背景

現有 MLLM scaling 多透過增加參數或延長 sequential inference，分別造成儲存/記憶體或延遲成本；而且 ViT 與 LLM 的計算比例通常在設計時固定，無法依任務調整。高解析文件理解可能需要更多 visual computation，長程推理則可能需要更多 language computation，因此本文要解決固定參數預算下，如何以 parameter reuse 擴增計算並彈性分配兩種 modality 的資源。

## 解決方案

作者提出 ParVL，將 MLLM parallel scaling 形式化為二維的 vision-language compute-allocation problem。它在共享 ViT 與 LLM backbone 上建立可平行執行的 branches，以 branch-specific KV prefixes 產生差異化表徵，再以 vision-side 與 language-side token-wise MLP aggregators 融合分支結果。Pv 與 Pl 可獨立設定，因而能比較 vision-heavy、language-heavy、balanced 等配置；整體以 full-parameter SFT 聯合最佳化。此設計在維持共享參數的同時增加有效計算，並進一步支援 sparse routing 與 Shared KV 的效率探索。

## 核心貢獻
1. 提出 ParVL parallel scaling framework，以 branch-specific KV prefixes、共享 ViT/LLM backbone 與 modality-specific token-wise aggregation，分別控制 vision 與 language branch 數量。
2. 在 1B、2B、8B 規模及九個 benchmark 上，系統比較九種 vision-language branch-count configurations，證明最佳計算分配依任務而異。
3. 提供 accuracy、latency 與 memory 的受控分析，並探索 top-1 sparse router 與 Shared KV cache 等推論效率機制。

## 技術方法

ParVL 以 Pv 個共享參數的 ViT branches 與 Pl 個共享參數的 LLM branches 進行 parallel computation。各 branch 在每個 prefix-conditioned attention layer 使用 branch-specific learnable key/value prefixes，保留共享的 attention projection 與 backbone；prefix 只加入 key/value，query 維持原序列。ViT branches 的 token 對齊 hidden states先經 modality-specific two-layer SiLU MLP，逐 token 預測 branch 權重，再以 softmax 加可選 uniform smoothing 完成 aggregation；移除 class token、進行 pixel shuffle，並經 InternVL connector 投影至 LLM embedding space。相同視覺表示與文字 embedding 複製給所有 LLM branches，語言 states 再以另一個 token-wise MLP aggregation 融合，最後通過共享 language-modeling head。所有 backbone、prefix、aggregator 與 connector 以 full-parameter SFT 聯合訓練，使用約 13B tokens、4.6M instances、單一 epoch，資料為 InternVL3.5 SFT collection 的 1/20 subsample；loss 對有效 response tokens 加權，樣本權重為 1/√n。實驗設定 Pv、Pl ∈ {1,2,4}，涵蓋 MMMUdev-val、四個數學/邏輯 benchmark 與四個 OCR/文件 benchmark，報告 General、Math、OCR 及九項等權 Average。另比較 prefix 與 LoRA、mean 與 MLP aggregation、dense 與 top-1 routing，以及不同 batch size 下的 latency 與 peak GPU memory。

## 關鍵結果

主要結果如下；公共模型使用不同 training recipes，僅作參考，受控比較為同一模型規模內的 single-branch baseline 與 ParVL。

| 模型/配置 | General | Math | OCR | All |
|---|---:|---:|---:|---:|
| 1B Baseline 1:1 | 40.3 | 26.0 | 75.6 | 49.6 |
| 1B ParVL 1:4 | 39.8 | 27.6 | 75.7 | 50.3 |
| 1B ParVL 4:4 | 39.0 | 28.0 | 75.9 | 50.5 |
| 2B Baseline 1:1 | 46.4 | 30.3 | 80.6 | 54.4 |
| 2B ParVL 2:2 | 46.1 | 30.6 | 81.1 | 54.7 |
| 8B Baseline 1:1 | 56.9 | 41.2 | 85.3 | 62.5 |
| 8B ParVL 2:2 | 57.8 | 42.0 | 85.4 | 63.0 |

在 1B branch allocation heatmap 中，General 最佳為 2:2（41.1）、Math 最佳為 4:4（28.0）、OCR 最佳為 2:4（76.3）。4:4 checkpoint 的 top-1 learned router 將 All 從 random pair 的 49.5 提升至 50.2，dense aggregation 為 50.5。batch size 8 時，標準 4:4 相對 1:1 的 latency 為 1.22 倍、memory 為 2.12 倍；Shared KV 則為 1.62 倍 latency、1.47 倍 memory。

## 對我們的啟發
- [ ] 若部署任務偏重文件、OCR 或視覺證據整合，可實驗增加 ViT branches；若偏重語言側數學或推理，也應單獨評估增加 LLM branches，而不宜假設 4:4 永遠最佳。
- [ ] 評估多分支模型時，應同時報告 accuracy、FLOPs、latency 與 peak memory；論文顯示 1:4 在 1B 的 overall 為 50.3，低於 4:4 的 50.5，但成本較低。
- [ ] 若硬體支援平行執行，branch reuse 可在參數僅增加最多 4% 的情況下擴增計算；但 batch 增大時記憶體成長明顯，sparse routing 或 Shared KV 可作為成本—效能折衷。

## 限制與未來工作

研究只使用 InternVL3.5 backbone 的 1B、2B、8B 規模，且採 supervised fine-tuning；訓練資料為 InternVL3.5 SFT collection 的 1/20 子集與單一 data mixture。尚未驗證更廣泛 backbone、更大規模、pretraining、不同 data scaling 或真實部署 workload。效率數據也僅來自單張 NVIDIA H200、指定輸入與生成長度。
