# RobustRLlib: A Unified Library and Benchmark for Robust Reinforcement Learning Algorithms

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2610.32971)
- 📥 [PDF](https://arxiv.org/pdf/2610.32971v1)

## 摘要（中文翻譯）

Robust reinforcement learning（Robust RL）對可靠的真實世界部署至關重要，因為政策可能在多樣化的分布偏移與干擾下失效。現有 Robust RL 演算法具備豐富的機制與原則，但其廣泛應用受到兩項主要障礙限制：演算法可重用性有限，以及實證能力邊界尚不清楚。本文提出 RobustRLlib，一個以演算法為中心的函式庫與 benchmark，整合 17 個具代表性的 robust online、offline 與 safe RL 演算法，並以統一介面提升可重用性；同時建立涵蓋多種真實世界偏移、進階 humanoid 與 vision-language-action 任務的評估平台。透過 273 組 perturbation configurations 的系統性評估，作者描繪當前 Robust RL 演算法的能力圖譜，指出其有效範圍與仍存在的 robustness gaps。RobustRLlib 以開源、易用、可重現且可擴充的程式碼庫，支援既有方法應用至新問題，以及新 robust RL 演算法的開發。

## 問題背景

論文聚焦於 Robust RL 在真實部署中的可重用性與能力邊界問題。現有 robust 演算法分散於不同實作與訓練流程，缺乏統一介面，導致方法難以移植與公平比較。此外，各方法通常只在原始任務及特定 shift scenario 中驗證，因此無法系統性回答方法在何種偏移下有效、偏移加劇時何時失效，以及單一 shift robustness 是否能延伸至複合偏移。

## 解決方案

作者提出 RobustRLlib，將 robust online、offline 與 safe RL 演算法置於統一的 algorithm-centric library 中，依 learning method、claimed target shift 與 base algorithm 組織，並以共同訓練及評估介面提高重用性與可比較性。平台另提供可擴充的 disruptor toolbox，能對 observation、action、dynamics、reward/cost、latency 與 semantics 施加 stochastic、adversarial、parametric、non-stationary 及 composition 型干擾。相同介面可延伸至 Isaac Lab humanoid 與 VLA robotic tasks，形成涵蓋標準控制、進階機器人及複合部署偏移的能力評估框架。

## 核心貢獻
1. 整合 17 個具代表性的 robust online、offline 與 safe RL 演算法，並以 learning method、target shift 及 base algorithm 建立統一、可重用的 library。
2. 提出可組合的 disruptor toolbox，涵蓋 observation、action、dynamics、reward/cost、latency 與 semantic shifts，以及 stochastic、adversarial、parametric、non-stationary 與 compound modes。
3. 透過 273 組 perturbation configurations、標準控制任務及進階 humanoid/VLA 任務，建立 current robust RL 的 capability map，揭示方法增益、shift-specific strengths 與複合偏移下的 robustness gaps。

## 技術方法

RobustRLlib 將方法分為 offline RL、online RL 與 robust safe RL。Offline track 包含 RFQI、RORL、ATLA、RSC-IQL、RAMBO、ROMB、FWM 與 PLR-PVL 等；online track 包含 ATLA、ATLA-SA、RSC、RARL 與 domain randomization（DR）；safe track 包含 RAMU 與 SPiDR。方法依 robustness 介入位置區分為 learner-centric、data-centric 或 environment-centric。評估中的 disruptor 以 specification tuple 描述 source、factor、magnitude、resampling rule、schedule 與 seed，干擾可作用於 MDP 元素、控制延遲及任務語義，亦可組合成 compound shifts。實驗使用四類任務：Locomotion、Manipulation、Navigation 與 Vehicle Control；library-wide grid 評估 20 個演算法、220 組 perturbation configurations，另以 44 組配置進行 shift-isolated 分析，並延伸至 Isaac Lab 與 VLA 任務。每個方法使用五個 training seeds、每個條件 20 個 paired evaluation episodes；策略訓練完成後固定，再於相同 shift grid 評估。主要指標為未截斷 normalized score：S=100(R̄−Rmin)/(Rmax−Rmin)；safe RL 同時衡量 task performance 與 cost constraint satisfaction。

## 關鍵結果

| 評估面向 | 論文報告結果 |
|---|---|
| 整體 robust–standard 差距 | Robust RL 在四個 shift levels 均優於 standard RL；優勢由 Q1 的 **+10.3** 分縮小至 Q4 的 **+5.1** 分，且兩者皆隨 shift 強度增加而下降。 |
| 評估規模 | Library-wide grid 涵蓋 **20 個演算法、220 組** perturbation configurations；shift-isolated evaluation 涵蓋 **44 組**；摘要另報告系統性評估共 **273 組**配置。 |
| Online 方法增益 | Learner-centric online 的 paired gain 為 **+5.5**，environment-centric online 為 **+6.6**；其 95% seed-level bootstrap intervals 分別為 **[+2.8,+8.3]** 與 **[+3.8,+9.6]**。 |
| Offline 方法增益 | Learner-centric offline 的 paired gain 為 **+3.8 [ +0.8,+6.4 ]**；data-centric 為 **−0.1 [−2.7,+2.1]**；generative model 為 **+2.5 [−0.3,+4.9]**。 |
| Dynamics shift | 明確建模 dynamics shift 的 environment-centric online 方法與 generative offline 方法，在各自 online/offline 設定的 controlled dynamic shifts 下表現最強；論文未報告統一的單一分數。 |
| 複合偏移 | Hopper 與 Pusher 的 compound shifts 均使 RORL 與 ATLA-SA-PPO 的表現低於 nominal，且低於各組成單一 shift；論文未報告此處的統一百分比數字。 |
| Robust safe RL | Drawer 任務中，DR-PPO 與 SPiDR-PPO 的 performance 均為 **99.6%**，但 DR-PPO 有 **0%** episodes 位於 joint-limit cost budget 內，SPiDR-PPO 為 **84%**。 |
| VLA robustness | 最大測試 shift level 下，VLA policy 相對 nominal 的 performance retention：gravity **0.95**、image blur **0.33**；brightness **0.88**。 |
| 目標 shift 與實際優勢 | 作者指出 claimed target shift 無法可靠預測 empirical strengths；排名取決於 task、shift mode 與具體 perturbation。 |

## 對我們的啟發
- [ ] 部署前不應僅依據演算法宣稱的 target shift 選擇方法；應在與實際任務、shift mode 及 severity 相符的配置上進行獨立評估。
- [ ] 複合偏移可能比任何單一偏移更嚴重，因此 sim-to-real 或機器人部署測試應同時涵蓋 dynamics、latency、observation、action 與 semantic factors，而非只測一種 noise。
- [ ] 安全部署不能只看 return 或 performance；Isaac Lab 結果顯示，應同時報告 success/performance 與 cost-budget satisfaction，否則高任務分數不代表具備安全性。

## 限制與未來工作

論文主要在模擬控制、Isaac Lab 與 VLA closed-loop simulator 中評估，未提供廣泛真實硬體部署結果。不同演算法的訓練假設、base learner 與資料存取方式仍不完全一致，跨類別比較可能受此影響。部分結果僅以圖表或相對描述呈現，未報告所有配置的逐項數值；論文也未展示每個方法在更大規模資料、更多真實任務或未見 shift 分布上的泛化能力。
