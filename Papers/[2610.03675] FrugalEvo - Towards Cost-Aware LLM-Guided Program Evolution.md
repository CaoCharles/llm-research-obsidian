# FrugalEvo: Towards Cost-Aware LLM-Guided Program Evolution

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2610.03675)
- 📥 [PDF](https://arxiv.org/pdf/2610.03675v1)

## 摘要（中文翻譯）

LLM-guided evolutionary methods（如 AlphaEvolve）已成為處理圓打包等高難度計算最佳化問題的有力方法。然而，既有工作通常在固定迭代次數下最佳化效能增益，未充分考慮實際成本。本文主張，實用的最佳化應最大化單位成本的效能增益，並提出 FrugalEvo：由較強但較昂貴的 LLM 探索解題策略，再由較便宜的 LLM 實作策略、產生程式並反覆改良。此外，作者設計 cache-efficient 的演化流程，透過 harness 與 prompt 的前綴共享提升快取重用率。本文提出 Budget-Aware Area Under the Curve（BA-AUC），以累積 LLM 成本為橫軸、截至該成本的最佳分數為縱軸，衡量固定預算內的整體搜尋效率。在 20 個數學、系統與演算法最佳化任務上，FrugalEvo 多數情況匹配或超越既有方法，並在圓打包任務以低成本達到具競爭力的結果。

## 問題背景

既有 LLM-guided program evolution 多以固定迭代次數、候選程式數量或 evaluator 呼叫次數衡量進步，因此較高的最終分數可能只是投入更多推理成本的結果，無法反映實務上的效益。論文要解決的問題是：在固定 LLM 成本預算下，如何兼顧探索能力、程式實作品質與搜尋速度，最大化最佳化解的品質及成本效益。

## 解決方案

作者提出 FrugalEvo，將候選程式生成拆成策略探索與程式實作兩階段。高成本、較強的 LLM 負責根據 incumbent、任務描述、評估回饋與搜尋記憶提出多個具體且不同機制的策略；低成本 LLM 則負責逐一實作、評分排序及連續修正。框架另包含 low-cost cold start、island-based MAP-Elites 搜尋記憶，以及將固定內容、較少變動內容與動態回饋依序排列的 cache-efficient prompt。作者以 BA-AUC 衡量固定成本區間內的 best-so-far 品質曲線。

## 核心貢獻
1. 提出 BA-AUC，將 best-so-far 解品質對累積 LLM 成本的曲線積分，用於衡量固定預算下的搜尋效率，而不只比較固定迭代數的最終分數。
2. 提出 FrugalEvo 的雙模型協作框架，由高成本 LLM 探索策略、低成本 LLM 實作與連續修正，並結合 cold start、策略排序及 MAP-Elites 搜尋記憶。
3. 設計 cache-efficient prompt 與演化 harness，透過共享 prompt 前綴降低輸入 token 成本，並在 20 個數學、systems 與 algorithmic optimization 任務上進行實證評估。

## 技術方法

FrugalEvo 以初始程式 x₀、程式空間 X、任務 evaluator 與固定 LLM 預算 B 為輸入。第一階段是 cold start：低成本 LLM 反覆改良初始程式，直到分數停滯，將最佳程式設為 incumbent。接著 high-cost LLM 分析任務描述與 evaluator，並結合 incumbent、程式資料庫、歷史策略、成功與失敗回饋，提出 K 個不同策略；每個策略需說明 mechanism family、替換範圍、計算預算及預期增益。low-cost LLM 對每個策略產生一個初始實作並以 evaluator 排序，再依序進行最多 M 次連續 refinement；每次失敗的評估回饋會加入下一次 prompt，若改善 incumbent 即更新 parent，否則轉換策略。搜尋記憶使用 island-based MAP-Elites 維持候選多樣性。Prompt 將固定任務指令放在前方，接著放較穩定的範例與 elite 程式，最後放頻繁變動的回饋，以提升 prefix cache reuse。實驗涵蓋 5 個數學、5 個 systems 與 10 個 ALE-Bench-Lite 演算法最佳化任務，使用 GPT-5.6 Terra/Luna 或 GLM-5.3/Flash，與 OpenEvolve、ShinkaEvolve、AdaEvolve、EvoX 比較。BA-AUC(B) 定義為 0 到 B 的 best-so-far 分數曲線積分；若執行提前結束，分數延伸至 B，若超出預算則截斷。

## 對我們的啟發
- [ ] 若任務可自動執行與評分，可將昂貴模型集中於高層次策略探索，將大量程式修改與除錯交給便宜模型，以提升固定預算下的候選覆蓋率。
- [ ] 評測 agent 或最佳化系統時，應同時報告最終品質與 performance-cost curve；BA-AUC 可作為衡量早期收益、搜尋速度與預算利用率的補充指標。
- [ ] Prompt caching 不只是部署層面的最佳化，也應反向影響搜尋上下文設計：把穩定資訊放在前綴、把動態回饋放在末端，可降低重複演化步驟的輸入成本。

## 限制與未來工作

方法主要適用於候選解能在程式環境中自動執行與評分的計算最佳化任務，難以直接延伸至需實體實驗或 wet-lab 評估的領域。策略探索指令目前由人工針對計算最佳化任務設計，尚未自動從任務產生。作者未來計畫處理實體互動領域，並自動生成策略探索指令。
