# HazardWeaver: Scientific Route Selection for Hazard Analysis Agents

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2610.03591)
- 📥 [PDF](https://arxiv.org/pdf/2610.03591v1)

## 摘要（中文翻譯）

理解與評估自然災害對防災準備與風險降低至關重要。大型語言模型（LLM）的進展促使研究者發展能整合科學資料、模型與工具的 hazard analysis agents。然而，自動化分析要求 agent 判斷某一事件適用哪些科學方法，以及在現有資料與工具下哪些方法可執行；當新證據與執行結果出現時，這些條件可能改變，agent 必須重新考慮選擇。本文將問題形式化為 state-dependent scientific route selection，提出 HazardWeaver。系統先由 Hazard Knowledge Compiler 擷取與證據連結的科學適用性條件，再以 Hazard Capability Graph 表示可執行能力並檢查輸入輸出相容性。Hazard Weaver Agent 據此選擇適用且可執行的 route、執行 workflow，並隨分析狀態變化修訂決策。作者另提出 Hazard Weaver Benchmark，包含七個單一災害領域與四類多災害互動的 141 個實例，評估輸出正確性、route 有效性與有理據的 abstention。實驗顯示 HazardWeaver 優於既有 agent systems，且在存在多個合格 route 的任務上提升最大。程式碼已公開。

## 問題背景

論文處理 hazard analysis agent 的 state-dependent scientific route selection：給定災害任務與當前分析狀態，agent 必須選擇既符合科學適用條件、又能由現有資料與工具執行的 route，並在狀態改變後重新選擇。既有 hazard models 的適用假設分散於文獻與文件，workflow 系統也未充分表達異質資產間的科學相容性；一般 AutoML 或 LLM agent 多聚焦於固定目標的模型、程式或 workflow 搜尋，無法充分處理執行期間的 route 失效、替代與合理 abstention。

## 解決方案

作者提出 HazardWeaver evidence-to-execution 架構，由三個互補元件組成。Hazard Knowledge Compiler（HKC）從論文、報告與指南擷取、正規化並保留 provenance 的科學條件，依任務證據判定 route 為 APPLICABLE、INAPPLICABLE 或 UNDETERMINED。Hazard Capability Graph（HCG）將資料集、模型、公式、轉換與軟體表示為具型別輸入輸出的 executable capabilities，僅允許註冊的相容關係連接。Hazard Weaver Agent（HWA）取 HKC 適用性與 HCG 可達性的交集，選擇並執行 route，在每一步更新 analysis state 後重算 eligible routes，必要時進行復原、能力替換或 abstain。核心創新是把科學適用性、可執行組合與動態 route 修訂整合，並以 route-aware benchmark 同時評估 artifact 與決策有效性。

## 核心貢獻
1. 將 hazard analysis 形式化為 state-dependent scientific route selection，要求 route 同時滿足 evidence-based scientific applicability 與 capability reachability，並在執行過程中持續更新。
2. 提出由 Hazard Knowledge Compiler、Hazard Capability Graph 與 Hazard Weaver Agent 組成的 evidence-grounded adaptive agent system，將文獻條件、typed capability composition 與可修訂 workflow 統一。
3. 建立 Hazard Weaver Benchmark：141 個 sealed instances 覆蓋七個 single-hazard domains、四類 multi-hazard interactions，並以 artifact correctness、route validity、provenance、執行有效性與 justified abstention 進行 route-aware 評估。

## 技術方法

形式化上，任務實例 q 包含 hazard setting、task、事件環境 context、輸出規格與 information cutoff；分析狀態 s_k=(X_k,C_k,b_k) 分別記錄可用原始或衍生 artifacts、能力可用性與剩餘資源。HKC 對每個 route family 建立條件集合，條件涵蓋假設、所需觀測、適用範圍、尺度、不確定性與失效情況，並將各條件判定為 SATISFIED、VIOLATED 或 UNRESOLVED；只有全部滿足時 route 才具科學適用性。HCG 建立 typed directed graph，能力 port 以變數、單位、欄位、空間與時間支援、解析度等八類資訊描述；輸出與輸入只有在註冊相容關係成立時才能連接，聚合、插值、downscaling 與 thresholding 等資訊變更必須顯式表示。HWA 在每個決策步驟計算兩者交集，選擇 route、實例化 workflow 並執行模型、solver、公式與轉換；每次執行後更新狀態並重新評估，若無 eligible route，則在預算內探索資訊請求、轉換、能力替換與替代 workflow，否則 abstain。HWB 含 141 個 sealed instances，涵蓋 90 個 single-hazard、51 個 multi-hazard，且 45 個僅有一條 route、96 個有多條 route。主要指標 Decision-Constrained Accuracy（DCA）同時要求 artifact 正確、route 在承諾時有效、provenance、型別、時間 cutoff 與預算有效；abstention 只有在允許的 recovery 無法到達有效 route 時才得分。

## 關鍵結果

主要結果如下；DCA 為作者的主要指標，括號中的數值為論文報告的 Wilson 95% 信賴區間。

| 方法／設定 | Single-hazard DCA | Multi-hazard DCA | One route DCA | Multiple routes DCA | Overall DCA |
|---|---:|---:|---:|---:|---:|
| Plan-and-Solve | 41.1% | 41.2% | 57.8% | 33.3% | 41.1% |
| HazardWeaver | 91.1% | 86.3% | 80.0% | 93.8% | 89.4% |
| 最佳 baseline（Plan-and-Solve） | — | — | — | — | 41.1% |

| 消融／設定 | DCA 結果 |
|---|---:|
| Llama：完整 HazardWeaver（96 個 multiple-route instances） | 93.8%（90/96） |
| Llama：移除 HKC conditions | 45.8%（44/96） |
| Llama：HCG untyped | 47.9%（46/96） |
| 五 backbone pooled：固定 route eligibility | 16.0%（32/200） |
| 五 backbone pooled：更新 route eligibility | 41.5%（83/200） |

跨 backbone 的 overall DCA 為：OLMo 60.3%、Mixtral 70.2%、Gemma 79.4%、DeepSeek 86.5%、Llama 89.4%。對所有 baseline 的 paired McNemar tests 均達顯著；例如相較 Plan-and-Solve，HazardWeaver 有 75 個獨有成功案例，baseline 僅有 7 個。

## 對我們的啟發
- [ ] 對科學型 agent 而言，工具數量或一般規劃能力不足以保證可靠性；應把方法假設、適用範圍、輸入輸出型別與 provenance 設為可檢查的結構化約束。
- [ ] 多步驟 workflow 不應只在初始狀態規劃一次；每次工具執行產生新 evidence、artifact 或失敗訊號後，都應重新計算可行 route，並保留替代 route 而非直接放棄。
- [ ] 評測 agent 時應把最終輸出正確性與產出該輸出的決策過程分開衡量，納入 route validity、時間 cutoff、能力相容性與合理 abstention，避免偶然正確的 artifact 被視為完整成功。

## 限制與未來工作

系統依賴 frozen capability catalog 與 evidence index；HKC 條件受 benchmark 建置時的文獻、Route Cards 與註冊 route 限制，新證據、標準或模型需重新編譯與 sealing。HWB 僅含 141 個實例，未涵蓋所有地區、事件、感測器與營運限制；論文也指出 recovery 搜尋失敗不等於形式化證明不存在可行 route，因此實際預報與緊急決策仍需更新證據、地方校準與領域審查。
