# WikiSkill: Compiling Agent Experience into Persistent Knowledge for Skill Evolution

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.27454)
- 📥 [PDF](https://arxiv.org/pdf/2608.27454v1)

## 摘要（中文翻譯）

Agent skills 將專門知識與工作流程封裝為可重用資源，以擴展 AI agent 的能力。近期研究可從 agent 經驗中自動發現 skills，使 agent 能透過互動逐步適應；然而，支援 skill 開發的洞見通常散落在各次最佳化歷史中，難以在不同迭代間系統性重用。本文提出 WikiSkill，一個讓 agent skills 與持久化知識庫（wiki）共同演化的框架。WikiSkill 分離原始執行經驗、累積知識與可執行 skills，並持續將經驗整合至 wiki，供後續 skill 更新建立於其上。在多個 benchmark 與模型上的實驗顯示，WikiSkill 穩定優於現有 skill-evolution 方法，且在多數模型與 benchmark 設定中優於無 skill baseline。研究也發現 skill evolution 能補充模型 scaling；skills 可跨模型與模型家族有效轉移，甚至其他模型演化出的 skills 可能勝過自行演化的 skills。消融實驗證實，wiki 的持久化知識累積是有效 skill evolution 的關鍵。

## 問題背景

論文聚焦於如何讓 LLM agent 從反覆執行任務的經驗中，持續產生、修正並重用可執行 skills。現有 EvoSkill、Trace2Skill 與 SkillOpt 等方法雖會保存提案、軌跡分析或評估回饋，但已學得的知識未被獨立整理成持續演化的知識表示，因此洞見分散於最佳化歷史，容易重複失敗、難以累積與跨迭代利用。

## 解決方案

作者提出 WikiSkill，將 agent workspace 分成 Raw Layer、Wiki Layer 與 Skills Layer。Raw Layer 不可變地保存完整執行軌跡；Wiki Layer 由 Wiki Maintainer 進行根因分析，將成功策略、失敗模式、解法、演化日誌與 skill 影響記錄編譯成持久化、可累積的結構化知識；Skills Layer 則保存供推論時直接使用的程序性 skills。每輪由 Inference Agent 執行 rollout，Wiki Maintainer 更新 wiki，Skill Proposer 透過 ReAct 讀取 wiki 與選定軌跡提出單一 skill 更新，再由 validation gating 決定接受或 rollback。技能可回滾，但 wiki 永不重置，形成原始經驗、知識與程序之間的持續閉環。

## 核心貢獻
1. 提出 WikiSkill 三層知識架構，將不可變 raw traces、持久化且累積的 wiki，以及可執行 skills 明確分離，並讓 wiki 在 skill rollback 後仍保留。
2. 在五個跨領域 benchmark 與五個模型上，系統性證明 WikiSkill 的平均表現優於 No skill 與 Trace2Skill、EvoSkill、SkillOpt 等既有方法；消融實驗確認持久知識累積是主要效益來源。
3. 分析 skill evolution 與模型能力及跨模型轉移的關係，顯示較強模型通常能從 skills 獲得更大收益，且他模型演化的 skill 可能優於 self-evolved skill，但轉移效果取決於程序是否通用及目標模型的執行能力。

## 技術方法

問題設定將資料集 D 分為不重疊的 training、validation、testing splits；agent 使用工具 U 與目前 skill set 執行多步軌跡，並以任務特定 scoring function 計算平均表現。WikiSkill 從空的 skills 與 wiki 開始，重複進行四步迭代。第一，Inference Agent 將所有 active skills 直接注入 system prompt，在 training set rollout；訓練期間禁止讀取 wiki，以避免 agent 直接取得知識而降低軌跡對 skill 開發的資訊量。第二，Wiki Maintainer 從成功與失敗軌跡中抽樣，做 root-cause analysis，新增或 patch pattern pages、index 與 evolution log。第三，Skill Proposer 先讀取 wiki index、skill-impact tracker 及任務結果摘要，再以 read_file 工具按需查閱 pattern 與 raw traces，透過 ReAct 提出建立或增量修改單一 skill 的 proposal。第四，將候選 skill set 在 validation split 評估；只有當分數嚴格高於目前最佳 validation 分數時才接受，否則回復 skills。無論接受與否，系統都將提案 diff、validation score 與結果寫入持久化 wiki。實驗涵蓋 LiveMath、SealQA、SpreadSheetBench、OfficeQA 與 ALFWorld，使用 Qwen-3.5-4B/9B、Qwen-3.6-27B、Gemma-4-31B 與 Gemini-3.5-Flash；比較 No skill、Trace2Skill、EvoSkill、SkillOpt 與 WikiSkill，三次獨立演化後取平均，並以 paired bootstrap test（1,000 次，p<0.05）檢驗差異。

## 關鍵結果

主要結果如下；表中數值為測試集 accuracy（%），Avg. 為五個 benchmark 平均值。

| 推論模型 | No skill Avg. | 最佳既有方法 Avg. | WikiSkill Avg. | WikiSkill 相對 No skill |
|---|---:|---:|---:|---:|
| Qwen-3.5-4B | 26.2 | 35.2（SkillOpt） | 38.5 | +12.3
| Qwen-3.5-9B | 29.9 | 42.3（EvoSkill） | 47.4 | +17.5
| Qwen-3.6-27B | 39.4 | 53.3（EvoSkill） | 63.3 | +23.9
| Gemma-4-31B | 41.3 | 49.1（SkillOpt） | 54.9 | +13.6
| Gemini-3.5-Flash | 49.5 | 56.1（EvoSkill） | 68.1 | +18.6

代表性單項結果：Gemini-3.5-Flash 在 LiveMath 由 33.0 提升至 72.6，在 SpreadSheetBench 由 50.5 提升至 76.6；Qwen-3.6-27B 在 SpreadSheetBench 由 40.8 提升至 81.7、ALFWorld 由 52.8 提升至 77.6。Qwen-3.5-9B 使用 WikiSkill 的平均 47.4% 高於 Qwen-3.6-27B 無 skill 的 39.4%。跨模型轉移方面，Qwen-3.6-27B 演化的 skill 使 Qwen-3.5-9B 在 ALFWorld 達 70.2%，高於其自演化 skill 的 63.4%；但也存在負向轉移，例如 Qwen-3.5-4B skill 使 Gemini-3.5-Flash 的 SpreadSheetBench 從 50.5% 降至 18.1%。

消融結果（Gemini-3.5-Flash 平均）：Inference Agent 不讀 wiki、Skill Proposer 也不讀 wiki 為 48.7%；僅 Proposer 讀取持久 wiki 為 63.7%；若 Inference Agent 也讀 wiki，則為 60.9%。

## 對我們的啟發
- [ ] 在 agent 持續改進系統中，應將執行軌跡、可執行策略與診斷知識分層保存；即使某次 skill 更新被 rollback，根因分析與失敗提案仍應保留，避免重複探索相同錯誤。
- [ ] Skill proposer 應使用結構化索引、歷史接受／拒絕紀錄與按需讀取軌跡，而非把所有歷史一次塞入 context；這能在控制 context 成本的同時支援跨迭代的根因分析。
- [ ] Skill 不應直接假設跨模型通用。部署前應進行 cross-model transfer 評估，特別檢查低階 workaround、冗餘工具呼叫與互動步數限制造成的 negative transfer，並依目標模型的執行能力調整或篩選 skill。

## 限制與未來工作

論文未完整提供所有資料集規模、各方法的總計算成本與更廣泛的模型／任務分布，因此成本效益與外部有效性仍有限。實驗主要採 system-prompt 直接注入 skills，未評估 skill retrieval 或 triggering 失敗。Wiki 內容由 LLM maintainer 產生，也可能受抽樣軌跡與模型偏差影響；跨模型轉移雖有成功案例，但同時存在明顯負向轉移。
