# Beyond F1: Evaluating Coverage and Failure Recovery in AI Model Security Scanners

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.27424)
- 📥 [PDF](https://arxiv.org/pdf/2608.27424v1)

## 摘要（中文翻譯）

靜態掃描器日益用於識別 machine-learning artifacts 中可執行或其他不安全內容，但傳統評估指標通常只描述掃描器成功產生可用安全判定的案例。本文以受控、由 artifacts 支持的 benchmark，評估 ModelScan、ModelAudit 與 Fickling。資料集包含 170 個聚焦 Pickle 與 PyTorch 的 artifacts，分屬 145 個 specimen families；其中 135 個具有二元安全 ground truth，另有 10 個刻意製造且不具標籤的 malformed artifacts。研究明確區分 non-N/A coverage、analysis completion、definitive security decisions、non-security findings 與 unsupported outcomes。在有標籤的 families 中，ModelAudit 對全部 135 個 family 產生 definitive decisions，Fickling 為 110 個，ModelScan 為 67 個。以產生 definitive judgment 的案例為條件，ModelScan 的 precision、recall 與 F1 均為 100%。Fickling 沒有超越 ModelAudit 與 ModelScan 組合的 unique true-positive families。對於 ModelScan 無法完成分析的 48 個 malicious families，ModelAudit 與 Fickling 均產生符合 ground truth 的 detections。結果顯示，必須分離 judgment accuracy 與 judgment availability，以及 incremental detection coverage 與工具層級的 redundancy。

## 問題背景

現有 scanner 評估過度依賴 precision、recall 與 F1，這些 conditional metrics 只衡量掃描器成功完成分析並給出安全判定後的正確性，無法反映 not applicable、scan incomplete 或 execution error 造成的判定不可用問題。因此，工具可能取得完美 F1，卻只能覆蓋部分標註資料。本文要解決的是如何同時衡量安全判定正確性、實際決策覆蓋率、跨工具的增量偵測與失敗恢復能力。

## 解決方案

作者提出 family-aware 的 scanner benchmark evaluation methodology，將掃描結果拆分為 observed non-N/A coverage、analysis completion、definitive security decision、non-security finding、scan incomplete、scanner error 與 not applicable 等操作狀態。研究以 frozen、artifact-backed 的 Pickle/PyTorch synthetic corpus 為基礎，並在 specimen-family 層級分配 ground truth，避免重新命名變體造成 pseudoreplication。除 conditional precision、recall、F1、specificity 與 FPR 外，作者新增 corpus-wide 與 labeled-family decision coverage，並以 family-level overlap 分析 unique detection 與 failure-mode redundancy；另測試 ModelScan 不完整分析時的跨 scanner recovery、檔名／副檔名變換穩定性及 latency。核心創新是把『判定是否正確』與『是否能產生判定』明確分離。

## 核心貢獻
1. 提出 family-aware 評估方法，將 non-N/A coverage、completion、definitive decision 與 conditional detection accuracy 分離，避免單一 F1 掩蓋分析不可用性。
2. 在固定的 170-artifact、145-family Pickle/PyTorch benchmark 上，系統性比較 ModelScan、ModelAudit 與 Fickling，並公開 execution records、raw outputs、adjudication ledger 與計算腳本以支援重現。
3. 以 family-level overlap 與 recovery analysis 區分增量偵測和失敗模式冗餘，顯示 Fickling 雖無 unique TP coverage，仍可在 ModelScan 失敗時提供恢復性偵測。

## 技術方法

研究未涉及可訓練的模型架構；評估對象是固定版本的三個 open-source static scanners：ModelScan 0.8.6、ModelAudit 0.2.52 與 Fickling 0.1.12。Frozen corpus 共 170 個 artifacts、145 個 specimen families，包含 70 個 malicious families、65 個 benign families 與 10 個 ground truth unknown 的 malformed/truncated Pickle families；格式分布為 130 Pickle、30 PyTorch checkpoint 與 10 Pickle container artifacts。所有 artifacts 先建立 inventory 並計算 SHA-256，重新命名變體依其 underlying specimen 歸入同一 family。實驗在 offline、telemetry disabled、two workers 環境執行，scanner timeout 分別為 60、10、5 秒，共 510 次 executions。Ground truth 來自 frozen corpus manifest，而非 scanner 輸出；security finding 需真正對應 benchmark security condition，其他結構或 licensing 警告歸為 non-security finding。結果狀態包括 detected、clean、not applicable、scan incomplete、scanner error 與 non-security finding。作者計算 observed non-N/A coverage、analysis completion、definitive decision coverage；後者以 TP、FP、TN、FN 的總和除以 corpus 或 labeled families。Conditional metrics 僅在 definitive judgments 上計算 precision、recall、F1、specificity 與 FPR。另以 family-level union、ModelScan incomplete family 的 ground-truth-consistent recovery、15 個 filename/extension rename comparisons，以及 170 次執行的 median/P95 latency 評估實務特性。

ModelAudit 已偵測全部 70 個 malicious families，因此加入 ModelScan 或 Fickling 的 union 未增加 malicious detection coverage，也未改變 60/65 的 benign false-positive union。15 個 rename comparisons 均維持原 scanner decision。

## 對我們的啟發
- [ ] 部署 scanner 時不應只看 conditional F1；應同時設定 labeled-family decision coverage、scan incomplete rate 與 unsupported-format handling 的服務水準。
- [ ] 多 scanner 組合的價值可能來自 failure recovery，而非增加 unique detections；路由策略應針對主要工具的 incomplete outcomes 啟用異質工具 fallback。
- [ ] 評估 benign custom serialization 時，應分開呈現 specimen-level false positives 與 conservative capability warnings，並依實際阻擋政策衡量 alert burden 與可接受風險。

## 限制與未來工作

資料集僅涵蓋 Pickle/PyTorch，且 145 個 families 均為 synthetic、deterministic constructions 或 transformed variants，不能代表真實 malware、adaptive adversaries 或 zero-day exploits。10 個 malformed families 沒有 binary labels；scanner 為固定版本。Rename 測試只有 15 個 comparisons，latency 未保留硬體 telemetry。未來將擴展至自然產生的惡意 artifacts、adversarial evasion、更廣 serialization ecosystems、長期版本變化與 deployment-level policy studies。
