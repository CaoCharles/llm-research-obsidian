# Beyond F1: Evaluating Coverage and Failure Recovery in AI Model Security Scanners

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.27424)
- 📥 [PDF](https://arxiv.org/pdf/2608.27424v1)

## 摘要（中文翻譯）

Static scanner 日益被用來識別 machine-learning artifacts 中可執行或其他不安全內容，但傳統評估指標通常只描述 scanner 成功產生可用安全判斷的案例。本文以受控、由 artifact 支持的 benchmark，評估 ModelScan、ModelAudit 與 Fickling；資料集包含 170 個聚焦 Pickle 與 PyTorch 的 artifacts，分屬 145 個 specimen families，其中 135 個具有二元安全 ground truth，另有 10 個刻意製作且無標籤的 malformed artifacts。研究明確區分 non-N/A coverage、analysis completion、definitive security decisions、non-security findings 與 unsupported outcomes。在有標籤 families 上，ModelAudit 對全部 135 個 family 產生 definitive decisions（100%），Fickling 為 110 個（81.5%），ModelScan 為 67 個（49.6%）。在已作出 definitive judgment 的條件下，ModelScan 的 precision、recall 與 F1 均為 100%。Fickling 未提供超出 ModelAudit 與 ModelScan 組合的 unique true-positive family。對 ModelScan 無法完成分析的 48 個 malicious families，ModelAudit 與 Fickling 均產生符合 ground truth 的 detection。結果顯示，必須分離 judgment accuracy 與 judgment availability，以及 incremental detection coverage 與 tool-level redundancy。

## 問題背景

現有 scanner 評估常以 precision、recall 或 F1 概括效能，但這些 conditional metrics 只衡量 scanner 已產生 definitive judgment 的案例，無法反映 unsupported、incomplete 或 execution error 導致的判斷不可用問題。對 model artifacts 而言，實務上既需要知道判斷是否正確，也需要知道 scanner 能否完成分析，以及多個工具能否在主要工具失效時提供可靠 recovery。

## 解決方案

作者提出 family-aware、artifact-backed 的受控評估框架，將 scanner 輸出拆分為 observed non-N/A coverage、analysis completion、definitive security judgment、non-security finding、scan incomplete 與 scanner error 等 operational states，並同時報告 corpus-wide 與 labeled-family decision coverage，以及只在 definitive judgments 上計算的 conditional detection metrics。框架進一步以 family-level overlap 分析 unique detection 與 redundancy，評估其他 scanner 對 ModelScan incomplete cases 的 ground-truth-consistent recovery，並納入 false-positive semantics、latency 與 filename/extension robustness。其核心創新是把 judgment correctness、judgment availability、增量偵測與失效復原分開衡量，而非以單一 F1 代表整體效能。

## 核心貢獻
1. 定義 family-aware 評估方法，分離 observed non-N/A coverage、analysis completion、definitive security decisions、non-security findings 與 execution failures，並同時呈現 conditional accuracy 與 decision availability。
2. 在固定的 170-artifact、145-family Pickle/PyTorch benchmark 上，系統比較 ModelScan、ModelAudit 與 Fickling 的安全判斷、覆蓋率、誤報、延遲與 rename robustness。
3. 透過 family-level overlap 與 recovery analysis，區分 scanner 的 incremental detection coverage 和 failure-mode redundancy，證明 Fickling 雖無新增 unique family detection，仍能支援 ModelScan incomplete malicious cases 的復原。

## 技術方法

研究使用 frozen synthetic corpus，包含 170 個 artifacts、145 個 specimen families：70 個 malicious、65 個 benign、10 個刻意 malformed 且沒有 binary ground truth。資料聚焦 Pickle/PyTorch，包含 130 個 Pickle artifacts、30 個 PyTorch checkpoints 與 10 個 Pickle containers；family 是安全效能分析的主要單位，避免 renamed variants 造成 pseudoreplication。評估固定 ModelScan 0.8.6、ModelAudit 0.2.52 與 Fickling 0.1.12，離線執行、telemetry disabled、two workers，scanner-specific timeout 分別為 60、10、5 秒，共 510 次 scanner/artifact executions。論文沒有提出或比較 machine-learning 模型架構；評估對象是三個 static scanners。每個觀察依 stdout、stderr、exit status 與 findings adjudicate 為 detected、clean、not applicable、scan incomplete、scanner error 或 non-security finding。以 family-level ground truth 計算 observed non-N/A coverage、completion、definitive decision count，並報告 corpus-wide decision rate 與 labeled-family decision rate。Precision、recall、F1、specificity 與 FPR 僅對 definitive judgments 計算。另分析 scanner overlap、union detection、ModelScan incomplete cases 的 operational recovery、15 個 filename/extension rename comparisons，以及 170 次 executions 的 median 與 P95 latency。

補充結果：ModelScan 的 corpus-wide decision rate 為 46.2%（67/145）；ModelAudit 偵測全部 70 個 malicious families。ModelAudit 與 ModelScan 的 union，以及三工具 union，皆偵測 70/70 malicious families，並有 60/65 benign families 被誤標。Fickling 相對於 ModelAudit 加 ModelScan 的組合增加 0 個 unique TP 與 0 個 unique FP。ModelScan incomplete 的 48 個 malicious families 中，ModelAudit 與 Fickling 各自偵測 48/48。ModelAudit 的 benign FPR 為 92.3%，Fickling 為 100%，ModelScan 為 0%（均為 definitive benign judgments 的 conditional FPR）。Latency median/P95：Fickling 64.90/80.98 ms、ModelAudit 963.21 ms/2.08 s、ModelScan 14.30/16.26 s。15 個 rename comparisons 全部維持原 scanner decision。

## 對我們的啟發
- [ ] 部署 scanner 時不應只看 F1；應把 labeled-family decision rate、incomplete、unsupported 與 error 另列為可觀測的可用性指標。
- [ ] 若主要工具分析失敗，可配置異質 scanner 作 fallback，但 recovery 應以 ground truth 或明確安全政策驗證，不能因另一工具產生警告就視為正確復原。
- [ ] 評估 benign custom serialization 時，應分開呈現 specimen-level false positive 與 conservative capability flagging，並依阻擋政策、人工審查成本及可接受的 alert burden 選擇工具。

## 限制與未來工作

研究僅涵蓋 Pickle/PyTorch，資料為 synthetic、deterministic artifacts，且 10 個 malformed families 無 binary labels；結果不能代表任意 production 分布、真實 malware、adaptive adversaries 或 zero-day。工具為固定版本，rename 實驗僅 15 次，latency 未保留硬體 telemetry。未涵蓋 weight-space backdoor、data poisoning 或 runtime security。作者未來將擴展至自然產生的惡意 artifacts、adversarial evasion、更廣 serialization ecosystems、縱向版本與 deployment-level policy。
