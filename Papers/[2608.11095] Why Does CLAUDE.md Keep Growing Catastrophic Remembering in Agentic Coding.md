# Why Does CLAUDE.md Keep Growing? Catastrophic Remembering in Agentic Coding

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.11095)
- 📥 [PDF](https://arxiv.org/pdf/2608.11095v1)

## 摘要（中文翻譯）

Agentic coding 的 README（如 CLAUDE.md）在真實儲存庫中會無限制增長，通常直到儲存庫停止維護，或有人整份重寫才停止。作者將原因追溯至不完善的 recall：新增 instruction 的成本總是很低，但當 instruction 的 rationale 消失後，要在不冒 correctness regression 風險下刪除它，對含有 |D| 個 instructions 的 prompt 而言，需付出 O(2^|D|) 的代價。作者稱此現象為 catastrophic remembering，是 continual learning 中 catastrophic forgetting 的反面。研究首先分析 1,867 個 repositories 中 247,694 個 instruction lifetimes，發現 prompt 在生命週期內增長 226%，每次 commit 淨增 4.9 個 instructions，且 instruction 越老越不易被刪除。接著，作者反轉 IFEval，建立具有已知最佳 prompt 的可驗證世界；結果顯示，包含 latent reasoning 的 prompt comments 可移除 99.3% 的 excess instructions，使增長由 211.3% 降至 1.4%。在 WildIFEval 上，comments 更可使真實世界的 instruction-following 提升最多 23.1%。

## 問題背景

Agentic README 具有實際效益，但 instruction 會持續累積，造成 context 干擾與 instruction-following 下降。現有 line diff 或檔案大小分析無法追蹤單一 instruction 的生命史，也缺乏可辨識刪除原因的機制；逐條刪除需要難以負擔的 counterfactual tests，整份重寫則只重置大小，不能消除再次增長的根因。論文要判斷這種 growth 是否源自 rationale 遺失，並尋找能在不降低 correctness 下控制 prompt 大小的方法。

## 解決方案

作者提出 catastrophic remembering：instruction 本身仍被保留，但其新增 rationale 會在多次編輯與多人接手後逐漸不可恢復，使維護者傾向新增而不刪除。解決方案是引入 prompt comments，將 instruction 與 executor 分離：instruction 告訴 agent 做什麼，comment 僅提供未來 maintainer 閱讀的 why。Informative comment 需保存觸發失敗、對原因的 hypothesis、實際 outcome、反覆出現次數、已被否證的方法，以及必要時被刪除 instruction 的原文。作者以反轉 IFEval 建立已知 minimum cover 的 evaluation，檢驗 comments 是否能使 prompt 在相同 correctness 下收斂至較小集合，並以 WildIFEval 測量其對真實 instruction-following 的改善。

## 核心貢獻
1. 提出 catastrophic remembering 概念與理論模型，將 agentic prompt 的無限制增長歸因於 latent reasoning 隨時間衰退，而非單純 instruction staleness 或 content fragility。
2. 在 1,867 個公開 GitHub repositories、247,694 個 instruction lifetimes 上進行生命史分析，使用 instruction matching、deletion hazard、frailty model 與多作者交互作用檢驗增長機制。
3. 反轉 IFEval 使 minimum cover 可觀測，並以 informative prompt comments 保存 failure、hypothesis、outcome 與 falsified lineage；實驗顯示 comments 可使 prompt 接近最佳大小並改善 instruction-following。

## 技術方法

論文分為理論、觀察性 repository 分析與受控實驗。理論上，將 prompt 視為 instruction set D，任務具有不可直接觀測的 constraint set C；executor 只回傳經 verifier 檢查的 censored、stochastic feedback。作者定義 minimum cover D⋆，並用 correctness（constraint satisfaction）與 excess size |D|/|D⋆|−1 評估 prompt。由於逐條刪除可能受到 redundancy 影響，完整判斷 instruction 是否 excess 需探測所有 subsets，成本為 O(2^|D|)；若保存新增時的 latent reasoning，則可近似降至 O(1)。作者以 recoverability ρ(a) 描述 rationale 隨 instruction age 衰退，並推導 deletion hazard h(a)≈ρ̄(a)s(a)，從而說明新增速度超過刪除速度時 prompt 會發散。資料方面，作者重建 1,867 個 GitHub repositories 的完整 context-file histories，得到 1,801 個 multi-version files、299,440 個 transitions 與 247,694 個 instruction spells；以 markdown 結構與句子邊界切分 clause-level imperatives，再用 similarity matcher 跨版本追蹤 instruction，並以 Nelson–Aalen、repository-stratified bootstrap、gamma frailty model 及 author-count interaction 分析 deletion hazard。受控部分反轉 IFEval：隱藏原始 instructions，保留 verifiers，把原任務摘要成 objective，讓 maintainer 在多輪僅憑 noisy、censored feedback 重建 prompt。Control 不提供 comments，Placebo 提供 comment-shaped noise，Treatment 提供含 failure、hypothesis、outcome 與 falsified lineage 的 informative comments；executor 會剝除 comments。另以 WildIFEval 加入跨項目 noisy instructions，評估真實 prose constraints 的 instruction-following；此處使用 arm-blind LLM judge，並以第二個 judge 重評 6,336 個 verdicts。

## 對我們的啟發
- [ ] 實務上可為每個 agentic instruction 增加只供維護者閱讀的 rationale comment，記錄觸發失敗、推測原因、驗證結果與被否證的替代方案。
- [ ] Prompt 維護不應只依賴逐條刪除；應建立可追蹤的 provenance 與 outcome 紀錄，並將 comment 與 instruction 一起版本化，以降低未來判斷刪除風險。
- [ ] 論文的安全提醒值得採用：comments 本身不會刪除 instruction，但根據 comments 自動刪除可能誤刪仍具價值的規則，因此安全關鍵指令應保留人工審核。

## 限制與未來工作

研究侷限包括：50% rewrite threshold、migration censoring 與 instruction matcher 主要以 50 個人工標註 transitions 驗證；受控實驗的 prompt cover 僅約 2–3 個 instructions，不能直接代表 median 39 個 instructions 的真實檔案。WildIFEval 使用 LLM judge，沒有 ground truth。資料只涵蓋公開 GitHub 與英文 context files；研究也未證明 comments 在大型真實 repository 中能長期阻止 ratchet，未來需進行更長期、跨語言與人工審核研究。
