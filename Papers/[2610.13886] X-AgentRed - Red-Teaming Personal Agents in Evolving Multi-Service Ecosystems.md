# X-AgentRed: Red-Teaming Personal Agents in Evolving Multi-Service Ecosystems

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2610.13886)
- 📥 [PDF](https://arxiv.org/pdf/2610.13886v1)

## 摘要（中文翻譯）

Personal agents 越來越透過 tools 連接網路與應用程式中的多項服務；當工具行動的效果跨服務累積並互相作用時，即使執行的是 benign user request，也可能產生非預期或有害結果。現有 red-teaming 方法多依賴 LLM 從任務與環境描述生成路徑，或將人類／LLM 指定的有害目標拆成看似良性的行動組合，容易偏向訓練資料中熟悉的工具組合，忽略新穎的跨服務互動。作者提出 X-AgentRed，一個 self-evolving red-teaming framework，利用工具依賴圖 HarmFlow，根據 effects、potential harms 與 execution preconditions 探索工具路徑，再以執行回饋進行工具替換與 blocked path 的 precondition refinement。於四個 frontier agentic models 上，X-AgentRed 的 harmful path rate 為 STAC 的 1.77 倍，平均 tool coverage 為其 2.99 倍。

## 問題背景

論文要解決 personal agents 在多服務生態系中因工具效果累積、權限與資訊跨服務傳遞而產生 compositional failures 的發現問題。既有方法主要依賴 LLM 直接生成工具鏈，或分解預先指定的有害目標；這些方法可能偏好訓練資料中熟悉的組合，因而不足以系統探索新穎的跨服務路徑，且難以隨執行中發現的 blocked steps 與漏洞持續擴展搜尋。

## 解決方案

作者提出 X-AgentRed，先由 red-teaming agent 分析每個 tool 的執行前提、效果與可促成的 harm，建立 HarmFlow directed graph；若某工具的 effect 可滿足另一工具的 precondition，便建立依賴邊。框架從 harm-associated tools 反向 random walk 取樣 recipe，再將工具路徑具體化為含 benign user request、initial environment state 與 target harm 的 realistic scenario。執行後，對成功造成 harm 的路徑以圖上的鄰近工具替換非核心工具，擴大服務組合；對 blocked path 則修正未滿足的 precondition 並重建前置步驟，以促成後續執行。其核心創新是將明確依賴結構與 execution-feedback-driven self-improvement 結合，降低單純 LLM 生成的探索偏差。

## 核心貢獻
1. 提出 X-AgentRed self-evolving red-teaming framework，針對 personal agents 的跨服務 compositional harm 進行系統探索。
2. 建立 HarmFlow graph，以 tool effects、potential harms 與 execution preconditions 建模工具依賴，並透過 backward random walks 產生跨服務 recipes。
3. 提出以執行回饋進行 successful-path tool substitution 與 blocked-path precondition refinement 的自我改進機制，並在四個 target agents 上以 HPR 與 tool coverage 證明其相較 STAC、TRACE 的探索效果。

## 技術方法

問題形式化為 scenario x=(u,s0,h)，其中 u 是可安全完成的 benign request，s0 是初始環境狀態，h 是未被使用者請求或授權的 target harm；目標 agent 看不到 h 並在 914 個 tools 的模擬生態系中執行。每個 tool t 由 Pt、Et、Ht 表示，分別是 execution preconditions、effects 與 potential harms。若 ti 的 effect 可滿足 tj 的 precondition，便在 HarmFlow graph 建立 ti→tj；圖含 914 個節點與 29,367 條 admitted edges。對每個 harm，從相關終端工具開始進行 backward random walk，最多取樣 12 個 planned steps，再配合 10 類 harms 與 12 類 harm-inducing factors，由 red-teaming agent 產生 benign request 與 initial state。目標 agent 執行 scenario，最多接受依方法設定的 adaptive follow-up；兩個 LLM judges（Claude Opus 5、GPT-5.6 Sol）必須同時確認 material harm、合理的 harm-inducing condition，以及所有 user requests 均為 benign，才計為成功。主要指標是 HPR，即 confirmed harmful scenarios 除以 candidate scenarios；另評估 tool coverage、每 episode 的 distinct tools/services、tool-call length、top-ten concentration、Jaccard overlap 與 generation calls。實驗在 30 services、914 tools 的 ToolSimulator 上，四個 target agents 各由每種方法產生 250 個 candidate scenarios，並與 STAC、TRACE 比較。

## 關鍵結果

主要結果如下（HPR 為兩位 judges 同意後的比例；tool coverage 為使用過的 914 個 tools 百分比）：

| Target agent | TRACE HPR | STAC HPR | X-AgentRed HPR | TRACE coverage | STAC coverage | X-AgentRed coverage |
|---|---:|---:|---:|---:|---:|---:|
| Claude Opus 4.8 | 0.4% | 6.0% | 7.6% | 19.4% | 15.1% | 37.1% |
| GPT-5.6 Sol | 2.4% | 14.0% | 19.6% | 23.3% | 14.0% | 47.6% |
| DeepSeek-V4-Pro | 2.0% | 9.6% | 18.0% | 17.5% | 12.4% | 37.4% |
| GLM-5.2 | 6.0% | 12.4% | 31.6% | 34.6% | 14.2% | 43.8% |
| 平均 | 2.7% | 10.5% | 19.2% | 23.7% | 13.9% | 41.5% |

- X-AgentRed 平均 HPR 是 STAC 的 1.77 倍、TRACE 的 10.36 倍；平均 tool coverage 是 STAC 的 2.99 倍、TRACE 的 1.84 倍。
- 四個 target 合計 confirmed harmful scenarios：X-AgentRed 192、STAC 105、TRACE 27。
- 平均每 episode 的 distinct tools/services 為 13.1/5.0；STAC 為 4.6/2.7，TRACE 為 2.0/1.9。
- 平均 tool calls 為 23.2，STAC 為 7.8，TRACE 為 3.3。
- generation calls 每 scenario：X-AgentRed 22.10、STAC 55.00、TRACE 103.24；但論文明確指出不包含 target execution、模擬與 outcome evaluation 的成本。
- self-improvement 分析中，recipe diversification HPR 為 27.7%，random sampling 為 18.0%；refinement 在先前失敗路徑上的 HPR 為 15.5%，兩種策略合計占平均 32.8% 的 confirmed harmful outcomes。

## 對我們的啟發
- [ ] 實務上的 agent red-teaming 不應只測試單一服務或熟悉的固定工具鏈，應建立跨服務的 effect–precondition dependency graph，以系統搜尋權限、資訊與狀態的組合傳播。
- [ ] 評測流程可將 harm discovery 與 coverage 同時納入：高 HPR 表示較容易發現失敗，而 tool/service coverage、top-tool concentration 與路徑重疊則可檢查是否只反覆攻擊少數熟悉工具。
- [ ] 執行失敗不應直接丟棄；記錄 blocked step 與未滿足的 precondition，並重建前置流程，可能把不可執行的候選路徑轉化為可驗證的風險情境。

## 限制與未來工作

論文明確指出，服務或工具變更時，維護 HarmFlow graph 會產生額外計算成本，需更新工具表示並重新評估受影響的依賴。實驗僅在單一 simulated ecosystem、每種設定單次執行，且主要以 LLM judges 的一致判定作為 harm 標準；judge sensitivity 顯示採 OR 聚合時 HPR 會比 AND 高 15.2–30.4 個百分點。部分 diversity 指標只反映結構差異，未能隔離真正不同的因果失敗機制。
