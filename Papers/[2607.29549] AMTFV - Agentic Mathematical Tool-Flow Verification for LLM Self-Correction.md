# AMTFV: Agentic Mathematical Tool-Flow Verification for LLM Self-Correction

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2607.29549)
- 📥 [PDF](https://arxiv.org/pdf/2607.29549v1)

## 摘要（中文翻譯）

大型語言模型（LLM）已展現強大的數學解題能力，但可靠驗證候選答案仍具挑戰。現有方法主要透過自然語言反思修訂輸出，或直接生成驗證程式；前者難以穩定支援精確計算，後者則過早將數學建模與低階實作耦合。本文提出 AMTFV（Agentic Mathematical Tool-Flow Verification），以 Mathematical Tool Flow（MTF）作為中斷—執行—恢復介面，將驗證建模與具體執行分離，並透過數學工具箱支援精確計算。驗證 agent 先建立工作流程，將需可靠執行的數學物件與計算意圖編碼為 MTF 請求，再交由數學工具箱 agent 解析、產生可執行呼叫並執行。工具輸出可用於候選答案判定、答案修訂及驗證流程修訂。作者在五個數學推理資料集與七種 DeepSeek、GPT、Gemini 模型設定上評估，結果顯示 AMTFV 整體優於本文比較的代表性基線；單一模型設定下，相較最強基線平均準確率最高提升 8.3 個百分點，且在中、高驗證複雜度樣本上的增益更大。

## 問題背景

LLM 即使產生看似合理的數學答案，也可能因算術錯誤、錯誤假設、遺漏約束、不完整枚舉或錯判最優性而失效，因此需要能檢查並修正候選答案的 backward verification。自然語言反思缺乏可靠的精確計算與外部證據；直接生成 Python 等驗證程式，則把數學目標建模、約束抽象與低階實作過早混在一起，容易引入程式邊界、精度及實作錯誤，亦不利於定位失敗原因。

## 解決方案

作者提出 AMTFV，以 Mathematical Tool Flow（MTF）作為數學驗證的中間表示與互動介面。驗證 agent 不直接撰寫完整程式，而是描述上下文、數學物件與所需回傳操作，例如精確值、符號差、完整解集合、基數、全域最優或可滿足性。數學工具箱 agent 再將此意圖編譯為適當工具呼叫並執行。工具結果回到 agent 後，用於候選答案判定、答案修訂，以及在局部檢查不足時修訂驗證工作流程。核心創新是把「驗證什麼」與「如何執行」分離，同時以可檢視的結構化結果形成驗證—修正閉環。

## 核心貢獻
1. 提出 Mathematical Tool Flow（MTF）這個中間介面，採用中斷—執行—恢復互動模式，將數學驗證目標建模與低階工具執行分離，避免過早生成程式碼。
2. 設計數學工具箱 agent，將包含上下文、數學物件與回傳操作的 MTF 請求，轉換為適合 SymPy、iter_tools、Fraction 或約束求解工具的可執行呼叫，並回傳可追蹤的計算結果。
3. 建立包含候選驗證、答案修訂與驗證工作流程修訂的 agentic 閉環，並在五個數學推理資料集、七種模型設定上驗證其效果。

## 技術方法

AMTFV 接收問題 q、初始回應 y₀ 與抽取出的候選答案 a₀。系統由左側驗證與修正模組、中央 MTF 介面，以及右側數學工具呼叫與執行模組組成。驗證 agent（Aver）先建立驗證工作流程 V，檢查候選是否滿足原題的約束與目標；若需符號化簡、精確運算、完整枚舉、最佳化或約束求解，便輸出以 <tool_flow> 標記包覆的 MTF 請求。MTF 以三元組表示：上下文 Γ、待計算或驗證的數學物件 M，以及要求的回傳操作 ρ，例如 cardinality、simplify、solutions、global optimum 或 satisfiability。生成請求後，模型生成會中斷，數學工具箱 agent（Atool）解析請求、選擇後端工具並產生可執行呼叫；後端使用 SymPy、iter_tools、Fraction 等工具進行符號、枚舉或精確算術執行，再將結果寫入 execution record R 並恢復模型推理。若候選未通過，答案修訂 agent（Aans）根據 q、V 與 R 產生回饋及新回應；若候選未改變，流程修訂 agent（Aflow）診斷驗證覆蓋範圍並更新工作流程。最多進行三輪外部迭代，成功驗證或達到上限即停止。實驗使用 AIME 2024、AIME 2025、BRUMO 2025、HMMT February 2025 與 AMO Bench，共 170 題；比較自然語言修正、CoT-Tool、ProgCo、ProgCo-Py 與 AMTFV。除 Initial Score 外，各方法共享同一初始回應與候選答案，主要評估指標為最終答案準確率，並分析校正狀態轉移與以 MTF 呼叫數定義的驗證複雜度。

## 關鍵結果

主要結果如下；Avg 為五個資料集依樣本數加權的平均最終答案準確率。

| 模型設定 | Initial Score | ProgCo | ProgCo-Py | AMTFV | AMTFV 相對較佳 ProgCo 基線 |
|---|---:|---:|---:|---:|---:|
| DeepSeek-Flash | 44.1% | 51.2% | 52.9% | 61.2% | +8.3 個百分點 |
| DeepSeek-Flash-Think | 88.8% | 87.6% | 88.2% | 89.4% | +1.2 個百分點 |
| DeepSeek-Pro | 38.8% | 44.7% | 49.4% | 57.1% | +7.7 個百分點 |

在三種 DeepSeek 設定中，AMTFV 的平均準確率均最高；相對初始答案的提升分別為 +17.1、+0.6 與 +18.3 個百分點。跨七種模型設定的比較中，論文報告 AMTFV 每一種設定皆高於 ProgCo 與 ProgCo-Py 中較佳者，提升幅度介於 +0.6 至 +8.3 個百分點。於 1,190 個模型—問題實例的校正狀態分析中，AMTFV 的錯誤轉正率 W→C 為 18.4%，高於 ProgCo 的 9.4% 與 ProgCo-Py 的 12.2%；正確轉錯率 C→W 為 2.8%，低於 ProgCo 的 3.7% 與 ProgCo-Py 的 4.2%。依 MTF 呼叫數劃分複雜度後，AMTFV 在中、高複雜度區間的正規化準確率增益分別為 39.2% 與 84.6%；論文未提供低複雜度區間的具體 AMTFV 增益數字。

## 對我們的啟發
- [ ] 實務上應先明確定義要驗證的數學物件、約束與計算目標，再交由工具決定具體執行方式；這比讓模型直接撰寫一次性驗證程式更容易檢查與除錯。
- [ ] 工具回傳不應只有布林值。案例顯示，同時回傳中間數學量、精確值、最終判定與候選比對結果，有助於定位錯誤並支援後續修訂。
- [ ] 驗證流程應涵蓋全域性質，例如最小性、完整枚舉、全域最優與可滿足性，而不只是檢查候選答案是否符合部分局部條件；論文結果顯示 AMTFV 在中、高驗證複雜度樣本上的優勢更明顯。

## 限制與未來工作

論文的評估集中於五個數學競賽型資料集、共 170 題，且主要指標是最終答案準確率；未報告完整的成本、延遲、工具失敗率或統計顯著性分析。框架也依賴模型正確建構 MTF 目標，工具箱能力與可處理的數學任務範圍可能限制泛化。作者提出未來將延伸至科學領域的專用工具系統。
