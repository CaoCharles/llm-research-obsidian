# AMTFV: Agentic Mathematical Tool-Flow Verification for LLM Self-Correction

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2607.29549)
- 📥 [PDF](https://arxiv.org/pdf/2607.29549v1)

## 摘要（中文翻譯）

大型語言模型（LLM）已展現強大的數學解題能力，但可靠驗證候選答案仍具挑戰。現有代表性方法主要透過自然語言反思修訂輸出，或直接生成驗證程式；前者難以穩定支援精確計算，後者則過早將數學建模與低階實作耦合。本文提出 AMTFV（Agentic Mathematical Tool-Flow Verification），以 Mathematical Tool Flow（MTF）作為中斷—執行—恢復介面，將驗證建模與具體執行分離，並透過數學工具箱支援精確計算。驗證 agent 先建立工作流程，將數學物件與計算意圖編碼為 MTF 請求，再交由數學工具箱 agent 解析、產生可執行呼叫並進行後端計算。工具輸出可支援候選答案判定、答案修訂及驗證流程修訂。作者在五個數學推理資料集及七種 DeepSeek、GPT、Gemini 模型設定上評估 AMTFV；結果顯示其整體優於本文評估的代表性基線，單一模型設定下相較最強基線最高提升 8.3 個百分點，且在中、高驗證複雜度樣本上的增益更大。

## 問題背景

LLM 即使產生正確答案，也可能因算術錯誤、錯誤假設、遺漏約束、不完整枚舉或錯判最優性而不可靠。自然語言 reflection 缺乏穩定的精確計算與外部證據；直接生成 Python 等驗證程式，則把數學目標建模、約束抽象化與低階實作過早混在一起，容易引入迴圈邊界、數值精度及程式錯誤，且難以定位失敗原因。因此需要兼具可檢查數學語義、精確工具執行與自我修正能力的 backward verification 框架。

## 解決方案

作者提出 AMTFV，以 MTF 作為數學驗證與工具執行之間的中間表示。驗證 agent 不直接撰寫完整程式，而是描述 context、數學 object 與 return operation，明確指定要驗證的符號等價、完整集合、可行性、最優值或精確數值。數學工具箱 agent 再將此意圖編譯為適合的工具呼叫並交由後端執行。結果會回到驗證與修訂模組，用於判定候選答案、產生修訂回應，或重新設計不足的驗證流程。核心創新是將高階驗證建模、專用精確執行及多輪 agentic correction 形成可追蹤的閉環。

## 核心貢獻
1. 提出 Mathematical Tool Flow（MTF）這一中間介面，以中斷—執行—恢復模式分離數學驗證目標建模與低階程式執行。
2. 設計數學工具箱 agent，負責解析 MTF 請求、選擇 SymPy、enumeration、Fraction 或 constraint-solving 等工具，並將結果回傳驗證與修訂模組。
3. 在五個數學推理資料集、七種 DeepSeek、GPT 與 Gemini 模型設定上進行評估，並分析錯誤修正、正確答案保存及驗證複雜度。

## 技術方法

AMTFV 接收問題 q、初始回應 y 及其中抽取的候選答案 a。系統由驗證 agent、答案修訂 agent、驗證流程修訂 agent、MTF 介面、數學工具箱 agent 與後端組成。每輪首先由驗證 agent 根據問題、目前回應、候選答案及前一輪流程，建立驗證工作流程，檢查約束與目標；若涉及符號化簡、精確計算、枚舉、最佳化或可滿足性，便輸出 <tool_flow> 請求。MTF 以 context、object、return specification 表示計算意圖，例如變數假設、待計算表達式或約束系統，以及要求返回化簡結果、解集合、基數、全域最優值或 satisfiability。工具箱 agent 解析請求、選擇 SymPy、itertools、Fraction 或其他後端工具，產生呼叫並執行；結果連同請求、工具、輸入與輸出寫入 execution record。若候選未通過驗證，答案修訂 agent 使用問題、流程與紀錄產生回饋並修改回應；若候選未被改變，流程修訂 agent 檢查驗證覆蓋範圍，補充全域約束、完整枚舉或最佳性檢查。新候選會在下一輪重新驗證，最多 max_turn=3，成功即停止。實驗使用 AIME 2024、AIME 2025、BRUMO 2025、HMMT February 2025 與 AMO Bench，共 170 題；比較自然語言修訂、CoT-Tool、ProgCo、ProgCo-Py 與 AMTFV。除 Initial Score 外，各方法共享相同初始回應與候選答案，主要指標為最終答案準確率，並分析 correction-state transition 與以 MTF 呼叫數定義的驗證複雜度。

## 關鍵結果

主要結果如下；Avg 為五個資料集依樣本數加權的平均準確率。

| Base-model 設定 | Initial Score | ProgCo | ProgCo-Py | AMTFV | AMTFV 相對 Initial |
|---|---:|---:|---:|---:|---:|
| DeepSeek-Flash | 44.1% | 51.2% | 52.9% | **61.2%** | +17.1 個百分點 |
| DeepSeek-Flash-Think | 88.8% | 87.6% | 88.2% | **89.4%** | +0.6 個百分點 |
| DeepSeek-Pro | 38.8% | 44.7% | 49.4% | **57.1%** | +18.3 個百分點 |

作者另報告：AMTFV 在七種模型設定中每一種都排名最高，相對 ProgCo 與 ProgCo-Py 中較佳者的提升介於 0.6 至 8.3 個百分點。跨七種模型、170 題共 1190 個 model–problem instances 的修正狀態分析中，AMTFV 的 W→C 比率為 18.4%，ProgCo 為 9.4%，ProgCo-Py 為 12.2%；C→W 比率則為 2.8%，低於 ProgCo 的 3.7% 與 ProgCo-Py 的 4.2%。按 MTF 呼叫次數劃分的中、高複雜度區間中，AMTFV 的正規化增益分別為 39.2% 與 84.6%，相較 ProgCo-Py 約高 20.0 與 29.2 個百分點。

## 對我們的啟發
- [ ] 實務上可先要求 LLM 明確表示待驗證的數學物件、約束與返回量，再由專用工具執行，而不是直接讓模型生成任意驗證程式。
- [ ] 驗證工具應回傳可追蹤的中間結果，例如完整集合、精確分數、最優值或可滿足性，而不只是布林值；這有助於定位錯誤並支援後續修訂。
- [ ] 對涉及最小性、完整枚舉、全域最優或精確算術的任務，應採用閉環流程：候選判定、答案修訂、必要時驗證工作流程修訂，並控制迭代上限以降低過度修訂風險。

## 限制與未來工作

研究僅涵蓋五個數學資料集、共 170 題，且主要評估數學工具箱情境；論文未提供更廣泛領域、成本效能或統計顯著性分析。框架仍依賴 LLM 正確建立驗證流程與 MTF 請求。作者的未來工作是擴展至需要可靠驗證與計算的科學及其他領域。
