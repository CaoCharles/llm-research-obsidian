# Diagram-MMU: A Multi-Modal Benchmark for Scientific Diagrams

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.12262)
- 📥 [PDF](https://arxiv.org/pdf/2608.12262v1)

## 摘要（中文翻譯）

Multimodal Large Language Models（MLLMs）日益具備支援科學寫作與協作的能力，例如 OpenAI Prism 可將科學圖表直接轉換為 LaTeX TikZ 程式碼。本文提出 Diagram-MMU，一個評估 MLLM 科學圖表解析與理解能力的多模態 benchmark，包含 3.7k 個人工整理圖表，以及跨六個領域、經人工驗證的 18.3k 個問題。benchmark 涵蓋三項常見於 vibe writing workspace 的任務：diagram-to-code parsing、diagram-to-code editing 與 diagram question answering，並為各任務加入 agentic evaluation。對 12 個 MLLM 的實驗顯示，diagram-to-code 任務比 diagram question answering 更困難；模型能對圖表進行推理，卻難以準確解析與編輯圖表。Agentic setting 通常提升 parsing 與 editing，但降低 question answering 表現；Claude-4.6 Opus 則在三項任務皆持續改善。

## 問題背景

現有 diagram benchmark 多集中於 charts，常使用 Python、SVG 或 HTML，且通常只評估 parsing、editing 或問答其中一項，缺少同一圖表上的跨任務比較，也未測試模型如何使用工具、管理中間狀態與規劃。這使其難以反映 LaTeX 科學寫作工作流中的實際需求，尤其無法區分圖像看似相似、程式碼可編譯與物件語義及空間位置正確等不同層次的能力。

## 解決方案

作者提出 Diagram-MMU，將 TikZ 作為貼近 Overleaf 與科學寫作環境的統一程式碼表示，收錄六種科學圖表並以模板與人工審查建立 parsing、editing、QA 資料。其核心是多層評估：以圖像指標衡量外觀，以 CrystalBLEU 衡量 TikZ 語法相似度，再從編譯後 SVG 萃取 SOM，計算物件類型、文字、顏色及位置的 F1。除此之外，作者建立 MCP TikZ 搜尋工具，並以 16 種設定拆解 context utilization、tool use、state management 與 planning 等 agentic 能力。

## 核心貢獻
1. 提出 Diagram-MMU，建立涵蓋 charts、planar geometry、3D shapes、graphs、chemistry 與 circuits 六類科學圖表的 TikZ benchmark，共 3,744 個獨特圖表與 18,305 個評估樣本。
2. 統一評估 diagram-to-code parsing、diagram-to-code editing 與 diagram question answering，並設計 16 種 foundational 與 agentic evaluation settings。
3. 針對 code generation 提出三層評估：rendered image、TikZ code syntax，以及由 SVG 萃取的 Semantic Object Model（SOM）物件層級 F1，並分析 type、text、color 與 bounding box。

## 技術方法

資料方面，作者從 TikZ/PGF、PGFPlots、CircuiTikZ、TKZ-Euclide、ChemFig、TikZ-Network 官方手冊，以及 texample.net、TeX Stack Exchange 和 GitHub tikz_favorites 蒐集 6,849 份程式碼。流程先移除與圖表無關的前置內容，使用 pdflatex、lualatex 或 xelatex 編譯，並比對原始與簡化版本的 rendered image；編譯失敗、圖像不一致、近重複或過於簡單的樣本會被刪除，再分類至六個領域，最後保留 3,744 個圖表。13 名研究生交叉驗證資料與問題，形成 18,305 個樣本。D2C-P 要求模型根據圖像與指定 preamble 產生可執行 LaTeX/TikZ；D2C-E 要求在文字、顏色、scope 或 layout 等維度修改圖表；DQA 則包含描述、標準推理與 what-if 問題。作者評估 12 個 MLLM，並在六模型、300 個圖表的子集上測試 16 種設定。D2C 任務以 rendered image 的 SSIM、CLIP、FID、LPIPS，code-level 的 CrystalBLEU，以及 SOM 的 type、text、color、bbox F1 評估；editing 另分 preserve-only 與 edit-only。DQA 使用 accuracy，由 Qwen3-Next-80B-A3B-Instruct 擷取答案並進行二元評分。Agentic 工具為以 MCP server 提供的 TikZ 搜尋服務，另測試物件上下文、先產生 TikZ code 的狀態管理，以及工具與上下文協同的 planning。論文未提供新的 MLLM 架構；研究重點是 benchmark 與評估流程。

## 關鍵結果

主要結果如下（數值為論文 Table 5 與 Table 6 報告；D2C-P/D2C-E 的 F1avg 與 CrystalBLEU 為百分比）：

| 模型 | D2C-P F1avg | D2C-P CrystalBLEU | D2C-E F1avg（全部/保留/編輯） | DQA Acc. |
|---|---:|---:|---|---:|
| Gemini-3.0 Pro | 54.64 | 32.76 | 53.60（65.12/44.77） | 86.46 |
| Claude-4.6 Opus | 52.23 | 31.27 | 51.18（62.56/43.59） | 68.75 |
| GPT-5.2 | 51.35 | 28.81 | 46.15（55.59/38.75） | 81.67 |
| Qwen3-VL-235B-A22B | 55.11 | 37.92 | 52.25（63.79/43.05） | 63.60 |
| Kimi-K2.5 | 57.48 | 36.13 | 52.13（63.12/42.11） | 79.74 |
| Qwen3-VL-8B | 44.66 | 33.31 | 19.00（21.26/16.29） | 47.12 |

論文指出，DQA 最高可達 86%，而 D2C-P 物件層級 F1約為 31–57%；因此模型的圖表推理能力優於解析與程式碼生成。D2C-P 中 bounding-box F1普遍最低，例如 GPT-5.2 為 8.0、Claude-4.6 Opus 為 9.2。Agentic evaluation 的 300 圖表子集顯示：Claude-4.6 Opus 在 D2C-P 使用工具後 F1avg 增加 2.2，在 D2C-E 增加 4.4；Gemini-3.1 Pro 的 D2C-P 工具設定下降 4.3，且回應率下降 25.0%。DQA 的 planning 設定對多數模型造成退化，幅度為 −0.3 至 −8.8 accuracy points；只有 Claude-4.6 Opus 在整體 agentic 趨勢上持續改善。

## 對我們的啟發
- [ ] 若應用於科學寫作工作流，不能以圖像相似度或問答正確率代表程式碼重建品質；應同時檢查是否可編譯、物件語義與空間位置。
- [ ] 模型通常能利用文字編輯指令改善局部修改，但新增物件與精確定位仍是瓶頸，因此實務系統可優先採用保留原始 code、再執行受限編輯的流程。
- [ ] 工具增強不必然提升效果；應設置查詢目標、停止條件與上下文管理，否則過度檢索可能造成 context rot、輸出失敗與問答退化。

## 限制與未來工作

論文的 agentic evaluation 只涵蓋特定的 context utilization、tool use、state management 與 planning，未涵蓋長程任務分解、異質多工具協作、執行回饋、自我修正或人機互動。資料與程式碼表示主要限於 TikZ，未涵蓋 Python、SVG、HTML 或其他 LaTeX 套件；DQA 也尚未納入論文圖說與完整上下文，專家級問題則列為未來方向。
