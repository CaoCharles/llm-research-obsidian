# Compact Documentation for Coding Agents: A Benchmark, an Optimizer, and Why It Does Not Transfer

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2609.31587)
- 📥 [PDF](https://arxiv.org/pdf/2609.31587v1)

## 摘要（中文翻譯）

本文探討自然語言文件是否能協助 coding agents 解決軟體問題，並建立用於產生與評估文件的工具。作者提出 roundtrip benchmark：根據程式碼描述重新生成程式，並以原始測試是否通過評估描述的 fidelity。實驗顯示，完整性比長度更能決定描述品質。作者進一步將 benchmark 分數作為最佳化訊號，找到可達到完整 fidelity、且能泛化至未見檔案的描述提示。然後，作者在兩個模型家族與十個 repository 上測試文件是否能改善真實 issue resolution，並以 positive control 證明評估可偵測真實改善。結果顯示，當 source code 已存在時，無論是靜態 compact documentation 或 retrieved context，都沒有勝過僅提供 issue；文件僅在 source 無法載入時發揮明顯作用。

## 問題背景

大型 repository 無法完整載入 coding agent 的 context，因此 agent 可能需要依賴高階程式碼描述。然而，現有文件工具通常偏重 API 摘要、使用範例或可讀性，可能遺漏測試與重新實作所需的 imports、內部常數、私有成員及精確行為。論文要回答兩個問題：如何客觀衡量描述是否完整，以及高 fidelity 文件是否真的能改善真實 repository issue resolution。

## 解決方案

作者提出以 code→natural-language description→code 的 roundtrip benchmark 評估描述品質：將描述交給另一個模型重新生成檔案，再以原始 unit tests 的通過比例作為 fidelity，並同時計算 description density 衡量壓縮程度。接著以 benchmark 分數最佳化 describe prompt，透過 proposer 提出候選提示、在訓練 fixtures 上評分並保留較佳者，促使描述同時完整且精簡。最佳化後的提示要求精確列出 imports、常數、型別、signature、defaults、屬性、控制流程、回傳路徑與例外條件。最後，作者將文件置於 source withheld 與 source present 兩種情境，檢驗 roundtrip 改善是否能轉移到真實 issue resolution。

## 核心貢獻
1. 提出以 code→description→code 並結合原始 unit tests 的 roundtrip benchmark，將自然語言描述的功能完整性轉化為可執行評估，並加入 description density 與 contamination controls。
2. 以 roundtrip fidelity 作為最佳化訊號搜尋 describe prompt；最佳化後提示達到 training fixtures 的完整 fidelity，並在 held-out fixtures 上由 0.5 提升至 1.0。
3. 透過兩個模型家族、十個 repository、SWE-ContextBench 與 positive control，系統性刻畫文件效益邊界：source 無法載入時文件有用，source 已可讀時靜態文件與 retrieved context 不優於 issue alone。

## 技術方法

資料取自 SWE-bench Verified，先以腳本篩選 gold patch 僅修改一個非測試 source file、test patch 指定 oracle tests，並經環境驗證後形成 11 個 sympy fixtures；另有 3 個手工建立、契約資訊僅存在於文件中的 codebase。評估採三階段：describe model 從完整檔案產生自然語言描述，但看不到測試；regenerate model 僅接收描述、package scaffold 與公開 symbol contract，重新產生檔案；evaluate 階段執行原始 tests。主要指標是 fidelity，即通過原始測試的比例，以及 density，即描述 tokens 除以原始程式碼 tokens。描述最佳化使用 hill-climbing：Proposer（gemini-2.5-pro，temperature 0.4）重寫 describe prompt，describe 與 regenerate 階段使用 Flash、temperature 0；目標函數為平均 fidelity 減去以 300 字正規化、權重 λ=0.1 的長度懲罰。訓練集含 3 個 fixtures，held-out 集含 2 個。下游評估涵蓋 source withheld 的 11 個 fixtures，以及 source present 的 Kind-B 與 SWE-ContextBench Lite；比較 issue only、compact description、full description 和 retrieved context，並以 fail-to-pass 與 pass-to-pass tests 判定 issue 是否解決。另使用 positive control 驗證 harness 能偵測 context 帶來的改善。

## 關鍵結果

| 實驗情境／指標 | 結果 |
|---|---:|
| 11 個 fixture 的平均 roundtrip fidelity | 0.32 ± 0.35 |
| roundtrip fidelity 與 description density 的 Pearson correlation | 0.88 |
| 完整描述、38 words | 5/5 通過（弱 agent comprehension task） |
| 完整描述、664 words | 5/5 通過（與 compact 相同） |
| 最佳化前 held-out fidelity | 0.50 |
| 最佳化後 held-out fidelity | 1.00 |
| Source withheld：issue only 平均 test-pass fraction | 0.08 |
| Source withheld：baseline description | 0.21 |
| Source withheld：optimized description | 0.71 |
| Source present：Qwen 3.6，issue only／compact | 14/43／11/43 |
| Source present：Gemini 3.1 Pro django，issue only／compact／full | 9/15／8/15／4/15 |
| SWE-ContextBench Lite，Gemini 3.8 Flash：issue only／compact／retrieved context | 33/58／29/58／30/58 |
| Editing without loading file：無描述／有描述 | 17/33／14/33 runs resolved，平均 pass fraction 皆為 0.94 |

核心結論是：完整性主導 roundtrip fidelity；最佳化描述能在 source withheld 時大幅替代原始程式碼，但在 source present 時沒有穩健收益，完整文件甚至可能誘使 agent 重寫檔案而非進行最小修補。

## 對我們的啟發
- [ ] 文件產生器的目標應與使用情境一致：若目標是從文件重建程式，必須涵蓋 imports、精確常數、私有成員、signature、例外與所有回傳路徑，而不只是面向人類讀者的 API 摘要。
- [ ] 在 coding agent pipeline 中，應先判斷原始程式碼是否能被模型載入與理解；source 已在 context 時，追加完整文件可能造成冗餘或 distractor effect，宜採最小且任務相關的 context。
- [ ] 可將 executable roundtrip tests 作為 documentation optimizer 的回饋訊號，但需注意 benchmark 對 regenerate model 能力敏感，且 roundtrip 分數改善不必然轉移至 source-present 的 issue resolution。

## 限制與未來工作

Roundtrip benchmark 僅有 11 個 fixtures、單一 Python 專案家族及 3 個手工 codebase，樣本不足以支撐廣泛統計結論。最佳化僅使用少量 fixtures、少數迭代與單一 proposer；benchmark 也依賴足夠強的 regenerate model。下游 paired evaluation 會排除未產生可評分 edit 的任務，且部分強模型複製實驗集中於 django。未來應擴展至更多語言、repository、模型與真正的 repository-scale context 壓縮情境。
