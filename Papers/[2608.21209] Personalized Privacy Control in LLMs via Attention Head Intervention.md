# Personalized Privacy Control in LLMs via Attention Head Intervention

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.21209)
- 📥 [PDF](https://arxiv.org/pdf/2608.21209v1)

## 摘要（中文翻譯）

代理式 AI 的興起使大型語言模型（LLM）能存取多樣的使用者資料，也帶來嚴重的隱私風險。過去的 contextual privacy 研究主要檢驗模型是否依據情境相關規範調節資訊揭露；然而，即使處於相同情境，不同使用者可接受的揭露界線仍可能不同。本文提出 personalized privacy，將使用者特定的揭露偏好納入隱私控制，並提出 P3Bench（Personalized Privacy Preservation Benchmark），將 contextual privacy policies 擴充為 personalized disclosure policies。實驗顯示，單靠 prompt-based policies 無法可靠執行個人化隱私規則；Qwen2.5-7B 與 Gemma3-4B 的平均 policy ignorance ratio 分別為 51.25% 與 74.28%。為改善此問題，本文提出 REPAIR，一種 robust inference-time attention head intervention 方法，將模型揭露行為調整至更符合政策的回應，並顯著降低模型未遵循使用者隱私偏好的情況。

## 問題背景

本文處理 LLM agent 在執行任務、存取使用者資料時，無法依據個別使用者偏好控制資訊揭露的問題。既有 contextual privacy 只根據任務情境判定哪些資訊適合分享，未充分考慮同一情境下不同使用者的容忍度。作者實驗指出，將個人政策直接放入 prompt 仍會造成 over-refusal 與 over-sharing，模型的既有揭露先驗可能凌駕於新提供的使用者政策。

## 解決方案

作者提出 personalized privacy 概念與 P3Bench，將情境中可揭露的欄位進一步依使用者偏好分為可存取與拒絕欄位。技術上提出 REPAIR：先以 linear probes 從 attention head activations 辨識 policy-conditioned disclosure state，再為 Disclosure、Policy-Refusal 與 Base-Refusal 建立狀態相關的介入表示。推論時透過多個選定 attention heads 的 majority voting 預測狀態，並採取 refusal patching 或 disclosure steering，無須重新訓練模型即可使輸出更符合個人政策。

## 核心貢獻
1. 提出 personalized privacy 定義，將 contextual privacy 中的情境相關性與使用者特定揭露偏好結合。
2. 建立 P3Bench：由 AirGapAgent-R 延伸而來，涵蓋四種語意政策、隨機欄位政策、26 個個人欄位與多種任務情境，用於評估個人化隱私控制。
3. 提出 REPAIR inference-time attention head intervention，透過 policy-relevant head probing、狀態預測、拒答 patching 與揭露 steering，在不重新訓練模型下改善政策遵循。

## 技術方法

P3Bench 延伸 AirGapAgent-R，使用 17 個 synthetic user profiles、26 個個人欄位、8 個情境與 3 個任務領域，建立四種政策：只允許姓名的 Privacy-Max、允許聯絡資訊的 Contact-Open、允許健康資訊的 Health-Open，以及允許偏好資訊的 Preference-Open；另測試隨機混合欄位政策。任務標註包含 Disclosure、Policy-Refusal、Base-Refusal 三種狀態，但可觀察行為統一為 ANSWER 或 REFUSE。REPAIR 先在 calibration set 中擷取最後輸入 token 的各層各 head activation，對每個 head 訓練 logistic-regression probe，以 AUROC 衡量其辨識 disclosure state 的能力，選取 top-k policy-relevant heads。接著對正確 gold output 的 forward pass 計算各狀態平均 activation：兩種拒答狀態直接建立 patching vectors；Disclosure 則以 Disclosure 平均表示減去兩種拒答平均表示，並作 L2 normalization，形成 steering direction。推論時先以選定 heads 的 probe 進行 majority voting，再於生成各步對選定 heads 套用 policy refusal、base refusal patch，或以係數 α 加上 disclosure direction。評估指標為 over-refusal（OR）、over-sharing（OS）及 Policy Error Distance（PED＝√(OR²＋OS²)），另以 PIR 衡量個人政策要求改變行為時模型仍維持無政策輸出的比例。比較方法包括 Direct Prompting、Zero-shot CoT、CAST 與 AdaSteer。

## 關鍵結果

主要結果如下；OR、OS 與 PED 均以百分比表示，數值越低越好。

直接 prompting 的平均 PIR 為 Qwen2.5-7B 51.25%、Gemma3-4B 74.28%；Gemma3-4B 使用 REPAIR 後平均 PIR 為 37.94%。在隨機欄位政策上，REPAIR 於可存取欄位數為 4、8、16 時皆降低 OR、OS 與 PED。以 Qwen2.5-7B 比較 head 選擇方式時，AUROC-based selection 的 PED 在四種政策均低於 random selection；作者亦報告 REPAIR-G 在四種政策中的三種取得較低 PED。

## 對我們的啟發
- [ ] 實務上的隱私控制不應只依賴情境判斷或 prompt 指令，還需要明確表達並檢驗每位使用者的欄位級允許與拒絕偏好。
- [ ] 同時監測 over-refusal 與 over-sharing 很重要；只降低其中一項可能只是把模型推向過度拒答或過度揭露，PED 可作為整體錯誤的補充指標。
- [ ] 若採用模型內部介入方法，應先以可驗證的 probing 找出與政策狀態相關的稀疏 heads，再進行狀態自適應控制，而非對任意模組施加一致方向的 steering。

## 限制與未來工作

作者指出，P3Bench 涵蓋的 PII 欄位與情境仍有限，主要聚焦於結構化個人欄位，未充分涵蓋敏感經驗、人際情況等非結構化揭露。未來需擴展更廣泛的 PII 類別與更真實的互動情境，並處理難以用預定义欄位表示的開放式隱私偏好。
