# CPU-ARC: Agentic Reasoning Caching for on-CPU Reasoning Reuse

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2611.09891)
- 📥 [PDF](https://arxiv.org/pdf/2611.09891v1)

## 摘要（中文翻譯）

大型語言模型（LLM）經常重複解決相似問題，將任務求解與方案執行混為一談，因而每次都必須從頭推理。本文指出，一旦某項任務已完成推理，將其方案套用至新的問題實例，通常只需很少的語言模型介入即可高效完成。作者提出 agentic reasoning caching，從 LLM reasoning traces 建構可在 CPU 上執行的 agentic reasoning caches（ARCs）。在多項困難數學與科學任務上，ARC 的表現與 frontier LLM 相當，並具備完整可解釋性、可持續訓練、對輸入擾動的穩健性；相較來源模型，每次呼叫成本降低 16–291 倍。

## 問題背景

LLM 對具有相同指令、計畫或推理結構但 payload 不同的查詢，往往逐次重新理解與推理，造成重複成本。既有 monolithic caching 對措辭或參數擾動不穩健，semantic matching 可能犧牲正確性；modular caching 雖較能泛化，仍需完整的新生成，且難以在檢查後保證結果正確。本文要解決的是如何將一次昂貴推理轉化為可重用、可審查且低成本的執行邏輯。

## 解決方案

作者提出 agentic reasoning caching，將來源模型的對話與推理軌跡轉換為由 semantic functions 組成的程式網路。每個函式以自然語言描述輸入、輸出與呼叫關係，而非依賴固定變數名稱，因此可在語義等價、措辭改變或參數重設的問題間重用。建構時由 builder model 完成輸入輸出隔離、推理分解、參數辨識、規劃與實作，並以測試及 judge 驗證；執行時主要依賴 CPU 程式、小型 target model、向量檢索與必要的工具呼叫。成熟後可編譯為移除動態檢索的獨立 Python 模組。

## 核心貢獻
1. 提出 agentic reasoning caching，將 LLM reasoning transcript 轉換為可重用、可組合且可審查的 semantic-function 程式網路，形成 ARC。
2. 在 MATH-500、AIME、GPQA Diamond、GSM8K、MMLU-Pro 與 SciBench 上，系統性評估正確性、source fidelity、措辭與參數擾動穩健性及成本。
3. 提出動態 ARC 到 compiled Python module 的編譯方式，並展示以小型 target model（包括微調的 Llama 3.2 1B）支援低成本執行。

## 技術方法

系統定義 source model S、builder model B、target model T 與 judge J。B 從 S 的查詢與 reasoning transcript 建立 ARC，流程包括：(1) 分離使用者輸入與預期輸出；(2) 將推理分解為階層式邏輯操作；(3) 辨識可變參數、其描述、格式範例與有效範圍；(4) 規劃 semantic functions 的依賴圖與根函式；(5) 逐一實作、靜態檢查、以原始參數測試，並由 J 比對 transcript 與 golden label。執行時先以 Embedding Gemma 與 FAISS 進行 entry-point similarity search，命中後由 T 抽取參數，再在 Context 的分層記憶體中執行 root function。load、do、narrate、lm、extract、convert 與 invoke_tool 是主要 runtime primitives；do 以自然語言發現子函式，narrate 保存可讀推理軌跡。實驗使用 Claude Opus 4.5 作為 S 與 B，T 先用 Claude Haiku 4.5，後使用微調的 Llama 3.2 1B；評估 MATH-500、AIME 2024–2026、GPQA Diamond、GSM8K、MMLU-Pro 與 SciBench。指標包括 source/cache golden-label accuracy、cache–source transcript fidelity、phrasal、parametric 與 combined perturbation pass rate，以及 source、builder、target 成本、建構倍數與節省倍數。

## 對我們的啟發
- [ ] 實務部署可採用 gated fallback：先嘗試 ARC，命中且執行成功時直接回傳，未命中或發生錯誤則交由完整 LLM 處理；這能將快取風險限制在個別任務範圍內。
- [ ] 快取項目應保存參數描述、有效範圍、函式依賴與 narration，而不只是完整回答；如此較容易進行人工或 AI 審查、除錯與版本管理。
- [ ] 建構成本顯著高於單次 source solve，ARC 的經濟性依賴後續重用次數；導入時應優先選擇高頻、推理結構穩定且可明確參數化的 agent workload，並持續驗證命中後正確性。

## 限制與未來工作

論文的 A1、A2 假設未被普遍證明，且建構成本為 source 成本的 12.1–83.7 倍。評估的擾動由模型產生並經 judges 篩選，且只在原始 cache 已符合 golden label 的樣本上測試；因此未報告真實生產流量下的命中率、長期更新效果或所有任務類型的表現。
