# BitDecoding-FP4: Native FP4 KV Cache Decoding via Algorithm-System Co-Design

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2611.09825)
- 📥 [PDF](https://arxiv.org/pdf/2611.09825v1)

## 摘要（中文翻譯）

長上下文 LLM serving 中，key-value（KV）cache 主導記憶體容量與頻寬。雖然 NVFP4、MXFP4 等 4-bit microscaling format 能縮小 cache，並在 FP4 Tensor Core 上執行 attention，但現有系統多採用 vanilla quantization，造成嚴重準確率下降；重視準確率的 4-bit 方法則依賴 vector codebook，lookup 開銷會降低 decoding throughput。本文提出 BitDecoding-FP4，一套準確且高效的 native FP4 KV decoding algorithm–system co-design。方法包括 Dual-Residual Query Quantization、Underflow-Aware Probability Scaling 與 Outlier-Aware Key Quantization，並以 transposed softmax、fused probability quantization 和 stacked query MMA 消除系統瓶頸。在多種 dense、MoE、GQA 與 MLA 模型上，NVFP4 與 BF16 KV 的平均準確率差距小於 0.5 分，MXFP4 小於 1 分；在 NVIDIA B300 上，Qwen3-4B 與 Qwen3-30B-A3B 的 peak serving throughput 為 BF16 KV 的 2.4–3.0 倍。

## 問題背景

論文要解決長上下文 autoregressive decoding 中 KV cache 的記憶體與頻寬瓶頸，以及 native FP4 attention 的準確率與吞吐量難以兼顧問題。現有 TRT-LLM-NVFP4 等方法直接使用 vanilla quantization，長上下文準確率明顯下降；TurboQuant 等準確率導向方法依賴 vector codebook，線上 lookup 與 reconstruction 開銷又會嚴重拖慢 GPU decoding。

## 解決方案

作者提出 BitDecoding-FP4，將 FP4 KV quantization、attention kernel 與 serving engine 共同設計。演算法方面，以 Dual-Residual Query Quantization 將 query 表示為兩個 FP4 tensor，降低 query logit error；以 Underflow-Aware Probability Scaling 避免長上下文 softmax probability 的 E4M3 scale underflow；以 static smoothing、Hadamard rotation 與 block-scale search 抑制 key outlier。系統方面，使用 transposed softmax、fused probability quantization 與 stacked query MMA，使兩個 query residual term 以單一窄型 FP4 MMA 處理，並整合 paged mixed-precision KV cache。

## 核心貢獻
1. 提出三項 accuracy-preserving FP4 quantization 技術：Dual-Residual Query Quantization、Underflow-Aware Probability Scaling 與 Outlier-Aware Key Quantization。
2. 提出 transposed softmax、fused probability quantization 與 stacked query MMA，使完整準確率 recipe 的 kernel overhead 控制在論文所報告的約 4% 以內。
3. 將 native FP4 decoding 整合 paged mixed-precision KV cache 與 vLLM，於 dense、MoE、GQA、MLA 模型及 RL rollout 中展示接近 BF16 KV 的準確率與較高 serving efficiency。

## 技術方法

方法先對 key 做離線 per-head mean smoothing，再施加 normalized Walsh–Hadamard rotation；key 與 value 以 microscaling FP4 儲存，NVFP4 使用 16-element block、E4M3 scale，MXFP4 使用 32-element block、E8M0 power-of-two scale。對 rotated query，先量化 q(1)，再量化殘差 q−q(1)，解碼時計算兩次 FP4 query–key product並在 softmax 前以 FP32 合併。online softmax 對 probability 先乘常數 c=8，並依 block maximum 選擇以 2 或 6 作為 FP4 scale maximum，降低 E4M3 underflow。key scale 則在兩個候選 scale 中以 block reconstruction MSE 選擇。Kernel 將 score layout 轉置，使 reduction 沿 key 平行化，並把 probability quantization 融入 warp butterfly shuffle；query 的第二項則堆疊於第一項的 zero padding。Serving engine 以 paged cache 儲存 FP4 pages，最近 token 與 attention sink 保留 BF16，並透過 device-side control kernel 管理 slot 與 page promotion。評估涵蓋 Qwen3-4B、Qwen3-30B-A3B、GLM-4.7-FP8 與 Hy4-preview，使用 LongBench Pro、MRCR、RULER-NIAH、AIME、LiveCodeBench、GPQA，以及 RL rollout validation accuracy；指標包括 task accuracy、TPOT、kernel latency、throughput、KV memory footprint 與 teacher-forced KL。

## 對我們的啟發
- [ ] 若低位元 attention 的主要誤差來自 query、probability underflow 與 key outlier，應分別設計誤差控制，而非只替換單一 quantizer。
- [ ] 當 Tensor Core 計算加速後，softmax reduction、probability quantization 與 metadata management 可能成為主要瓶頸；量化演算法必須與 kernel layout 和記憶體管理共同設計。
- [ ] 在長上下文 serving 中，保留 BF16 attention sink 與最近 token、將完整頁面轉為 FP4，是兼顧數值穩定性、paged cache 相容性與容量利用率的實作策略。

## 限制與未來工作

論文的吞吐量與 kernel 結果主要在 NVIDIA B300、RTX PRO 5000 及特定 vLLM/CuTe-DSL 實作上測試，硬體與軟體可移植性未被充分驗證。校準需針對 checkpoint 與 context window 進行；對更多模型、不同 GPU、極低於 4-bit 的格式，以及更廣泛 RL 設定的結果，論文未報告。
