# GuardrailAgent: An Agentic Framework for Jailbreak Defense

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2611.09734)
- 📥 [PDF](https://arxiv.org/pdf/2611.09734v1)

## 摘要（中文翻譯）

儘管大型語言模型（LLM）接受了旨在符合人類價值的安全訓練，仍可能受到 jailbreak attacks 攻擊，繞過內建防護並產生攻擊者要求的惡意行為。現有防禦多為靜態方法，難以適應新型或未知的攻擊策略，韌性有限。為此，作者提出多代理防禦框架 GuardrailAgent，提供具適應性的端到端保護。系統會自主蒐集並摘要攻擊特徵，建立持續更新的 knowledge base，支援輸入側與輸出側偵測；feedback module 則將誤分類案例納入迭代改進，且成本有限。在超過十種代表性 jailbreak 上，框架達到 93.1% 的輸入側偵測率、93.9% 的整體偵測率及 95.8% 的 F1 score，並能快速適應未見攻擊。結果顯示，GuardrailAgent 能在 jailbreak 策略持續演化時維持 LLM 安全性。

## 問題背景

論文處理 LLM 防禦 jailbreak attacks 時，既有安全微調、固定規則與外部 safeguard 多依賴既知 prompts、資料集或訓練分布，面對快速出現的未知攻擊時容易產生 out-of-distribution 失效，且無法及時自我更新。作者因此聚焦於黑箱條件下，如何同時提升輸入與輸出側的偵測能力、適應新攻擊，並維持 benign queries 的模型效用。

## 解決方案

作者提出 GuardrailAgent，一個由 InputAgent 與 OutputAgent 組成的多代理、兩階段防禦框架。InputAgent 使用 Prompt KB 儲存具體 jailbreak prompts，並以相似度進行 instance-level 比對；使用 Material KB 儲存由論文與技術報告摘要出的攻擊策略，進行 strategy-level 分析。通過輸入檢查的 prompt 才會送入目標 LLM，OutputAgent 再利用 Response KB 檢查生成回應，形成輸入與輸出雙側防護。核心創新是外部資源演化與內部 feedback loop：系統週期性蒐集資料與研究材料，並將輸入側漏檢但輸出側成功攔截的案例回饋至 Prompt KB，以持續改善對未見攻擊的泛化能力。

## 核心貢獻
1. 提出 GuardrailAgent 多代理框架，整合 InputAgent 與 OutputAgent，對 user prompts 與模型 responses 提供雙側端到端 jailbreak 防禦。
2. 建立 Prompt KB、Material KB 與 Response KB，結合 instance-level similarity、strategy-level analysis 與 response pattern analysis，以支援對既知及部分未見攻擊的辨識。
3. 提出外部資源演化與內部 feedback loop，實驗顯示系統可在無外部知識更新時，處理約 90 個 adversarial prompts 後將平均輸入側 DSR 提升至 0.800。

## 技術方法

GuardrailAgent 在 black-box 假設下運作，只分析 user prompt 與 target LLM response。線上流程先由 InputAgent 執行 Prompt Analysis Tool，將輸入與 Prompt KB 中最相似的前三個 jailbreak prompts 比對；若未被標記，再由 Material Analysis Tool 根據 Material KB 評估其是否符合已知攻擊策略。任一階段判定為惡意即拒絕，否則送入目標模型。若模型回應已是 refusal，OutputAgent 直接保留；否則透過 Response Analysis Tool 與 Response KB 比對，判斷是否含有被 jailbreak 的回應模式。三個 KB 分別由公開資料集、in-the-wild 資源、研究論文與技術文章建立；外部更新會依可設定週期搜尋資料集及 arXiv 材料，內部更新則將 InputAgent 漏檢但 OutputAgent 捕獲的 prompt 納入候選知識。實驗以 ChatGLM3-6B、Vicuna-7B、GPT-3.5-turbo 為 target models，agent 主要由 GPT-4.1-mini 驅動，另以 Gemini-2.5-flash 做泛化測試。資料涵蓋 JailbreakRadar、WildJailbreak、超過十種攻擊策略與 1,000 筆 benign queries。指標包括輸入側與整體 detection success rate（DSRinput、DSRoverall）、weighted F1、false positive rate、Input Miss Rate、Output Detection Rate，以及 runtime 與 token cost。

## 對我們的啟發
- [ ] 實務部署時可採用輸入攔截加輸出審查的分層架構，避免單一輸入分類器漏檢後直接讓不安全回應流向使用者。
- [ ] 知識庫不應只保存完整攻擊 prompt；論文結果顯示，將研究材料摘要為 strategy-level entries 可補足單純相似度檢索對新變體的不足。
- [ ] 應將漏檢但在輸出側捕獲的案例納入受控 feedback 流程，同時監測 false positives；論文中的 benign 測試顯示，較保守的 retrieval matching 仍會造成 1.6% 誤報。

## 限制與未來工作

作者指出，框架目前主要依賴 similarity-based retrieval 與 literature-guided analysis，對需要更深層語意理解或進階推理的攻擊可能較弱。自動更新也帶來資料治理、隱私、代理 prompt injection 與防禦策略公開後遭反制等風險。論文未提供更長期實際部署、持續自適應攻防或所有新型攻擊上的完整結果，未來可替換更強分析模組。
