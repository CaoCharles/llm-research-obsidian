# CORAL: An LLM-Native Harness for Production Recommender Systems

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2609.02730)
- 📥 [PDF](https://arxiv.org/pdf/2609.02730v1)

## 摘要（中文翻譯）

生產環境中的推薦系統影響數十億使用者所接觸的內容；隨著內容、使用者行為與上游模型持續變化，檢索、排序與服務設定必須不斷重新最佳化。傳統上由工程師透過 online experiments 測試變更，速度慢且受人力限制。CORAL（Constraint-Optimized Recommender via an Agentic Loop）是一個 LLM-native harness，讓 agent 持續閉環操作 live recommender：每個週期觀察運行訊號，利用過往決策與結果的 memory 進行推理，並呼叫包含 numerical optimizer 的工具，在固定 operating budget 內重新配置系統。部署後的量測結果會回饋至下一週期。作者將問題形式化為 partially observed、non-stationary、constrained optimization；policy 不需參數更新，即可依自身歷史行動的效果進行 in-context 改進。兩個大型社交平台的 A/B experiments 顯示，一個部署在不增加 serving cost 下提升 engagement，另一個在 engagement 不下降下降低 serving cost，涵蓋 engagement–efficiency frontier。

## 問題背景

生產推薦系統由 retrieval、ranking 與 serving 等多階段元件組成，許多資源配置與政策仍依賴工程師反覆提出假設、開發及執行 online experiments。現有流程每次只探索設計空間的一小部分，週期慢、成本高且偏向在發生回歸後才反應，導致部分設定長期不被更新，在內容、行為與上游模型漂移時偏離最佳點。論文因此要解決 live recommender 的持續、受約束、自動化最佳化問題。

## 解決方案

作者提出 CORAL，一個包圍通用 LLM 的 agentic harness，而非讓 LLM 直接處理每次推薦請求。其核心是固定週期的 closed loop：agent 觀察推薦系統訊號，從 persistent memory 取回過去的觀察、評估、決策與歸因結果，分析後提出各 control unit 的有限調整，再由 deterministic constrained optimizer 將提案投影至 budget-feasible configuration，並透過 guardrails 驗證後部署到 live recommender。完整週期以 A/B measurement 取得效果，再寫回 memory。創新在於把 LLM 的異質訊號推理與記憶能力，和數值可行性、邊界變更及安全控制結合，使 policy 不需 retraining 也能依歷史結果 in context 適應非平穩環境。

## 核心貢獻
1. 將 live recommender 的持續 agent-driven optimization 形式化為 partially observed、non-stationary、constrained optimization，並讓 LLM policy 透過自身行動結果進行 in-context refinement。
2. 提出 CORAL harness，整合 persistent memory、LLM reasoning、deterministic analysis／attribution 工具、constrained optimizer、guardrails 與固定 cadence 的 closed loop。
3. 在兩個大型社交平台以 A/B experiments 驗證同一 harness：一個案例提升 engagement（包括 low-signal 與新使用者），另一個降低 serving cost 且 engagement 未顯著下降。

## 技術方法

論文將每個週期的系統設定表示為 s，業務目標為 J_t(s)，成本為 c_t(s)，並要求 c_t(s)≤B；agent policy π 依觀察 o_t 與 memory M_t 產生 s_t，目標是最小化相對於每週期最佳可行設定的 cumulative shortfall。控制面由三類 memory 組成：observation store 保存各單元原始統計及變化，assessment store 保存 LLM 的文字化綜合判斷，decision store 保存歷史設定及其歸因結果。工具包括 analysis、retrieval、attribution、constrained optimizer 與 apply configuration。流程固定為 Observe、Reason and recall、Optimize and deploy、Measure effect、Update memory，避免由模型自行控制流程。部署週期 k=3 天，memory horizon m=3 cycles；每個設定維持完整週期，再以前後期間比較及 A/B experiment 量測效果。第一個案例將 retrieval sources 視為 control units，以 bounded continuous multiplier 分配固定 retrieval budget，指標為 video-viewing sessions 與 watch time。第二個案例將 user segments 視為 control units，從 ordered discrete treatment menu 分配 serving compute budget，觀察 engagement 與 serving cost。論文亦估算每週期約 8–10 次 LLM calls、每次約 1,500–2,000 input tokens 與 2,500 output tokens，但 pipeline 未記錄實際 token usage。

## 關鍵結果

| 部署／輪次 | 評估方式 | 主要結果 |
|---|---|---|
| Retrieval-budget，R1 | A/B experiment；zero-shot proposal | Watch time **+0.13%**；sessions **neutral** |
| Retrieval-budget，R2 | A/B experiment | Watch time **neutral**；sessions **neutral** |
| Retrieval-budget，R3／全體使用者 | A/B experiment，數百萬使用者 | Video-viewing sessions **+0.16%**；total watch time **+0.15%**；無額外 serving cost |
| Retrieval-budget，最大市場 | A/B experiment | Sessions **+0.77%** |
| Retrieval-budget，新加入且 low-signal 使用者 | A/B experiment | Video-viewing sessions **+0.23%** |
| Serving-capacity，第一輪 | A/B experiment，數百萬使用者 | 大幅降低 serving cost，節省數百萬美元 annualized capacity expenditure；engagement **論文未報告具體變化數字** |
| Serving-capacity，第二輪 | A/B experiment | 在 engagement statistically unchanged 下，將 savings 較第一輪再增加 **44%** |
| 推理成本 | 作者估算 | 每個部署的 end-to-end inference cost 約為數十美元；實際 token usage **論文未報告** |

作者指出第二輪 retrieval 配置曾過度修正，因此結果並非每輪單調改善；整體而言，決策效果隨 loop 迭代而改善。

## 對我們的啟發
- [ ] 若將 LLM 限定於異質訊號的判斷與提案，並把 budget feasibility 交給 deterministic optimizer，可降低語言模型產生數值不合法配置的風險。
- [ ] 對生產 agent 應保存觀察、文字評估、歷史決策及歸因結果，讓每次部署的實際效果成為下一週期的決策依據，而非僅定期重新執行相同 prompt。
- [ ] 針對 low-signal 或新使用者採用分段配置，而非只學習全體使用者的 global allocation，有助於處理聚合指標可能掩蓋的族群差異；但仍應以線上實驗驗證各分段的因果效果。

## 限制與未來工作

論文指出目前仍需 human supervision，guardrails 尚待強化以降低人工監督。兩個案例都集中於推薦資源的 constrained allocation，尚未驗證 retrieval 或 ranking logic 等不同類型控制桿。此外，A/B experiments 雖能量測真實效果，成本高且依賴特定生產環境；部署前的標準化 agent-optimization 評估方法仍未建立。
