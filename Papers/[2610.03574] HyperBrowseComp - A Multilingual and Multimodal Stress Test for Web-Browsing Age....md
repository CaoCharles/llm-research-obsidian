# HyperBrowseComp: A Multilingual and Multimodal Stress Test for Web-Browsing Agents

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2610.03574)
- 📥 [PDF](https://arxiv.org/pdf/2610.03574v1)

## 摘要（中文翻譯）

本文提出 HyperBrowseComp，一個多語言、多模態的 web-browsing agent 評測基準，包含 13 種語言的 423 道人工撰寫且經人類驗證的問題，作者為母語者或高熟練度使用者。每題都要求一個簡潔且可公開驗證的答案，但答案發現通常需要尋找冷門證據、追蹤多步線索，或檢查影片、掃描文件、圖片、地圖等異質來源。為降低問題僅依賴模型參數知識即可回答的可能性，作者先以無網路模型進行難度篩選。研究以 provider-native search、Exa 與 OWL 等設定，在共同 agent protocol 下評估多個模型，並對部分題目進行人類評測，以比較正確率與搜尋成本。HyperBrowseComp旨在測試 agent 跨語言、跨證據模態進行持續資訊搜尋、證據連接與驗證的能力。

## 問題背景

現有 web-browsing 評測多偏重英語與純文字，或只控制單一語言、單一模態；部分資料也可能因模型參數知識累積而失去辨識力。這些基準較難衡量 agent 是否能在開放網路中發現隱含線索、跨影片、地圖、PDF、圖片等來源完成多跳證據鏈。論文因此要解決多語言、多模態且具長程資訊搜尋需求的嚴格評測問題。

## 解決方案

作者提出 HyperBrowseComp，建立 423 題、13 語言、涵蓋多種網路證據型態的人工基準。每題由語言使用者從可驗證答案與支持證據出發設計，附有標準答案、可接受別名、URL、精確證據位置與解題路徑，再由第二位標註者驗證唯一性、可存取性與難度。資料另經七個無網路模型審核，排除可能依靠參數記憶回答的題目。評測同時比較原生搜尋、共同 Exa 檢索介面與 OWL 多代理 harness，將模型能力與搜尋系統效應分離觀察。

## 核心貢獻
1. 提出 HyperBrowseComp，提供 423 道由母語或高熟練度使用者撰寫、涵蓋 13 語言的開放網路瀏覽題目。
2. 將多語言問題與影片、音訊、圖片、PDF、掃描書籍、表格、圖表及地圖等異質證據結合，評測多跳資訊發現與證據連接能力。
3. 在共同 agent protocol 下比較原生搜尋、Exa 與 OWL，並同時報告準確率、token、時間、工具失敗與人類表現，揭示 retrieval harness 對結果的顯著影響。

## 技術方法

資料建立採人工出題與雙人驗證。題目要求單一、簡短、可區分的答案；來源須公開可存取，不得要求付款、登入或私人社群。作者記錄答案別名、來源語言、URL、頁碼、表格或圖表、影片時間戳、音訊區間及地圖位置等證據。七個無網路模型先回答候選題；若至少兩個模型答對，或一個模型答對且答案高度具體，題目即被排除，最終由 500 題左右保留 423 題。資料涵蓋 13 語言、8 類模態與 13 個主要領域，約 64.3% 題目需要至少一種非文字模態。實驗使用五個 frontier LLM，設定包括 provider-native search、Exa，以及具 task manager、coordinator、researcher、synthesizer 的 OWL workforce。前兩者採最多 25 個 research steps 的 ReAct 交替流程；模型自行產生查詢、呼叫搜尋與抓取工具。OWL則使用多代理與多模態瀏覽工具。最終以 LLM judge 對問題、完整回答與參考答案進行二元正確性判定，並統計正確率、token、時間與工具失敗。另在印尼、泰國、越南各抽 10 題進行可瀏覽但不可使用 LLM 的人類評測。

## 關鍵結果

主要結果如下；所有數字均為論文報告值。

| 設定／模型 | 答對數 | 準確率 | Token總量 | 總時間 |
|---|---:|---:|---:|---:|
| Built-in Gemini 3.7 Flash | 134/423 | 31.68% | 14.1M | 129.5小時 |
| Built-in Gemini 3.1 Pro | 108/423 | 25.53% | 10.2M | 45.3小時 |
| Exa GPT-5.6 Sol | 113/423 | 26.71% | 928.8M | 75.1小時 |
| Exa Gemini 3.7 Flash | 94/423 | 22.22% | 663.9M | 22.7小時 |
| OWL Gemini 3.7 Flash | 75/423 | 17.73% | 195.3M | 125.1小時 |

- 原生搜尋下，五個模型共同評測的 423 題中，有 244 題（57.68%）沒有任何模型答對；只有 21 題被五個模型全部答對。
- 最佳設定為 Built-in Gemini 3.7 Flash，準確率 31.68%，顯示目前 web-enabled agents 仍有顯著改進空間。
- Exa 對 GPT-5.6 Sol 的準確率高於其原生搜尋（26.71% 對 19.15%），但使 Gemini 3.1 Pro 與 Gemini 3.7 Flash 降至 18.20% 與 22.22%，顯示模型與原生搜尋環境存在共同適配。
- OWL 有 93 次終止性執行失敗；若只計完成案例，Gemini 3.7 Flash 準確率為 22.73%，仍低於原生搜尋的 31.68%。
- 30 題人類評測中，人類答對 15 題，最佳模型在同一子集答對 13 題；人類平均耗時 89.5 分鐘，中位數 54.57 分鐘。

## 對我們的啟發
- [ ] 評估 web agent 時不應只報告模型名稱；搜尋引擎、抓取工具、瀏覽流程與失敗處理會大幅改變結果，應固定或明確拆分 model 與 harness 的效應。
- [ ] 若要測試真正的 evidence discovery，題目應保留可驗證的短答案，但要求跨來源、跨模態與多步線索推理，避免僅測量常識記憶或單次檢索。
- [ ] 部署研究型 agent 時，除正確率外應追蹤 token、延遲、工具呼叫與終止失敗；論文結果顯示更高成本不必然帶來更高準確率。

## 限制與未來工作

基準刻意設計為壓力測試，不能代表日常搜尋分布；開放網路的頁面、排名、地區可用性與工具行為也會隨時間改變。語言覆蓋仍有限，各語言題目難度未完全標準化。模型評估僅涵蓋五個系統，Exa與OWL的比較也不完整。未來可在固定資源預算下擴大模型、檢索器與 harness 的系統性比較。
