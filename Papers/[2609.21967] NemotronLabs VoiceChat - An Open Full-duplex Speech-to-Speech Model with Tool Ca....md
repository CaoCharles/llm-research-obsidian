# NemotronLabs VoiceChat: An Open Full-duplex Speech-to-Speech Model with Tool Calling Capabilities

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2609.21967)
- 📥 [PDF](https://arxiv.org/pdf/2609.21967v1)

## 摘要（中文翻譯）

本文提出 NemotronLabs VoiceChat，一個開放權重、全雙工 speech-to-speech 模型，原生支援 tool calling。模型結合 streaming speech encoder、decoder-only language model、平行的 agent text 與 structured function-call 輸出串流、用於增量使用者轉錄的 auxiliary RNN-T 分支，以及 streaming TTS decoder，使系統能在統一的 streaming 架構中持續聆聽、轉錄、推理、呼叫工具與說話，同時保留自然對話所需的時間行為。在 Full-Duplex-Bench 1.0 中，模型於受評估的開放權重系統取得最低的 pause-handling takeover rate、使用者打斷後 100% takeover，以及 4.33/5 的打斷後回應品質；在 1.5 中，對 user backchannel 有 93% 的回應續接率。模型在 VoiceBench 取得 55.1 normalized average，並在 Full-Duplex-Bench 3.0 達到 82.5% tool-selection F1，但 argument accuracy 與端到端工具執行仍有改善空間。

## 問題背景

傳統 speech agent 多採 ASR、LLM 與 TTS 串接，通常依賴 VAD 等待使用者說完，因此屬於 half-duplex，難以處理重疊說話、backchannel、停頓與 barge-in。既有 full-duplex speech model 雖改善即時輪替與打斷處理，卻較少能在不中斷自然對話的情況下可靠執行一般工具呼叫。開放研究尤其缺乏同時整合 speech understanding、speech generation、turn-taking 與 structured action 的統一模型。

## 解決方案

作者提出 NemotronLabs VoiceChat，以 streaming FastConformer speech encoder 將使用者語音映射至 decoder-only Nemotron-Nano-9B-v2 LLM。模型使用平行且專門化的 agent-text 與 function-call channels，避免將異質 action token 序列化到單一 autoregressive channel；另以共享語音表徵的 auxiliary RNN-T 產生增量使用者轉錄，並由獨立的 streaming VoiceChat-TTS 將 agent text 轉成持續音訊。工具呼叫採明確的 <SOTC>、<EOTC>、<EOTR> 狀態協定，runtime 可非同步執行工具、播放預設 filler message，再注入工具結果並繼續生成。

## 核心貢獻
1. 提出一個開放的統一 full-duplex speech-to-speech 架構，將 streaming speech encoder、LLM、TTS、使用者增量轉錄與工具呼叫整合於持續時間軸。
2. 以平行的 agent-text 與 function-call 專用輸出串流，以及明確的工具邊界 token 與非同步 runtime，支援在自然語音互動期間進行一般工具呼叫。
3. 透過 FDB 1.0、FDB 1.5、VoiceBench 與 FDB 3.0，系統性展示 turn-taking、backchannel、語音智能、工具選擇與端到端工具使用的性能取捨。

## 技術方法

架構上，16-kHz 音訊先轉為 128-bin log-Mel features，經 600M 參數、24 層 cache-aware FastConformer；因果 subsampling 每 80 ms 產生一個 encoder state，並以 70-frame left context、無 right context 進行 streaming。投影後的表徵供 LLM 直接進行 speech-conditioned response generation；raw states 則供兩層、640 維 RNN-T 分支進行增量轉錄。LLM 以音訊、前一個 agent-text token 與前一個 function token 的加權融合表徵，同時預測文字與 function channel。訓練分 CPT 與 SFT：CPT 使用語音化 pseudo-dialogue 與 text-only corpus；SFT 混合 duplex chat、自然語音對話、tool calling、安全與 instruction-following 資料，並加入 early interruption、backchannel injection、text-channel delay、噪音、RIR、MIR 與 codec augmentation。SFT 目標為 0.5(文字 loss+function loss)+0.5 T2T loss，function padding 用於抑制誤觸發。工具資料將 assistant call 與 tool response 對齊至共同時間軸，response token 僅作 context、不計 loss。TTS 使用 977M 參數的持續 streaming decoder、22-kHz codec 與 31-level RVQ，支援 BOS、padding、interruption 控制。評估涵蓋 FDB 1.0 的 pause、smooth turn-taking、interruption TOR/latency/品質，FDB 1.5 的 backchannel 行為，VoiceBench 的知識、推理、指令與安全，以及 FDB 3.0 的 tool-selection F1、argument accuracy 與 Pass@1；另報告 ASR WER、TTS WER/SECS/SQuIM-MOS 與推論延遲。

## 對我們的啟發
- [ ] 對即時 voice agent 而言，工具路由與參數正確性應分開評估；本文 82.5% tool-selection F1 但僅 42.2% argument accuracy，顯示選對工具不代表能可靠完成呼叫。
- [ ] 將 action channel 與對話文字 channel 平行化，有助於維持低延遲與自然輪替；產品設計可採類似的結構化事件流，而非把工具指令混入一般語音回覆。
- [ ] 工具執行期間的 filler message 能降低等待時的沉默感，但目前模型在執行工具時無法處理 barge-in；實務部署仍需設計可取消、可中斷並可恢復的工具執行狀態。

## 限制與未來工作

模型音訊上下文約限於兩分鐘，長對話記憶不可靠；工具數量增加時性能下降，實務建議每次不超過五個工具，並且 simultaneous multi-tool invocation 尚不穩定。模型可能跳過工具、產生虛構參數或直接依內部知識回答；長工具回應會延遲語音，工具執行期間也不支援 barge-in。噪音、混響及競爭語音環境下的 robustness 有限。未來工作包括改善 argument grounding、多步工具組合、可中斷工具執行、記憶、推理與 alignment。
