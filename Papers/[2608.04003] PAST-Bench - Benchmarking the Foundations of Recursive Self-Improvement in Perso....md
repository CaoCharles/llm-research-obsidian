# PAST-Bench: Benchmarking the Foundations of Recursive Self-Improvement in Personal Agents

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.04003)
- 📥 [PDF](https://arxiv.org/pdf/2608.04003v1)

## 摘要（中文翻譯）

Recursive self-improvement 要求 agent 將累積經驗轉化為未來更好的行為。Personal AI agents 會跨 session 保留偏好、任務歷史、tool routines 與 learned skills，因此提供研究此能力的具體環境；然而，保留的經驗是否真正改善後續表現，尚未被系統性測試。本文提出 PAST-Bench，透過在 matched conditions 下切換 retained experience，評估 agent 在 ordered fresh-session tasks 中的進步及其是否遵循 save、retrieve、update pathway。Benchmark 涵蓋 26 個 scenarios、204 個 episodes，以及 memory、procedural reuse、information gathering、update 四種能力。跨七個 base models 與四個 agent frameworks 的結果顯示，改善確實存在但依能力而異；相同 task-score gain 的 agent，其 pathway evidence 可能顯著不同。作者進一步提出 Hermes+，在 agent loop 五個階段加入 targeted interventions，提高 retained-experience gain 與 pathway evidence，並在過時狀態更新任務上改善最明顯，但效果仍取決於能力與模型。

## 問題背景

現有 agent benchmark 多以 fresh session 的單次任務分數為主，無法判斷後續進步是否由 retained experience 造成；memory、skill 與 architecture 評測也常只檢驗單一元件，缺少 matched persistence controls 與跨 session attribution。論文因此要回答：agent 是否能保存、找回、正確應用並更新先前經驗，使同一 user 的未來任務表現改善。

## 解決方案

作者提出 PAST-Bench，以四類能力與 ordered fresh-session task families 測試 online self-evolution。早期 episode 提供保存經驗的機會，後續 episode 在移除 trigger wording 的情況下測試 reuse，並以 persistence-on/off、distractor、stale、wrong-mechanism 等 controls 分離 retained-state effect。除 task-score gap 外，benchmark 還檢查 artifacts 與 telemetry 的 pathway evidence。作者再依診斷結果提出 Hermes+：以 E1–E5 分別介入 planning、memory rendering、skill routing、retrieval gate 與 episode closeout，作為可 ablate 的診斷型 framework baseline。

## 核心貢獻
1. 提出 PAST-Bench，以 task-family trajectory 為評估單位，透過 fresh-session sequence 與 matched persistence-on/off controls，測量 retained experience 是否造成後續任務改善。
2. 建立 task score 與 mechanism-evidence score 的雙軸評估，結合 persistent artifacts、runtime telemetry 與 attribution analysis，診斷 save、retrieve、apply、update 各階段是否實際運作。
3. 根據診斷結果提出 Hermes+，在 Plan、Render、Route、Gate、Close 五個 agent-loop stages 加入介入機制，並透過單機制 ablation、互動診斷與跨模型測試分析其效果。

## 技術方法

PAST-Bench 將評估單位從單一任務改為 task family trajectory。每個 family 由 ordered fresh-session episodes 組成，episode 間清除 volatile context，只允許透過 framework 的 persistent substrate 傳遞 memory records、skills、profile state、session-history indices、saved artifacts 或 home-state fixtures。Benchmark 涵蓋 26 個 scenarios、204 個 episodes：Memory 5/41、Procedural Reuse 8/64、Information Gathering 6/48、Update 7/51。流程包含 cold、learn/update、evaluation 與 control episodes；control 包括 no-retention、distractor、stale 與 wrong-mechanism。每個 matched pair 固定 model、task、prompt、grader、tool stack、seed、context window、output limits、agent limits 與 compaction policy，只切換 retained state access。主要指標為 family-balanced persistence gap Δ = S(w/ evolve) − S(w/o evolve)，其中 per-episode task score 位於 [0,1]，capability 結果對 families 做 macro-average；控制 episode 的上界用於檢查 shortcut 與錯誤歸因。第二指標 Mechanism-evidence score 根據 memory write/read、skill creation/patching/use、session search、retrieval timing、artifact diffs 與 update-correctness signals，衡量表現是否沿預期 pathway 產生。實驗固定 Hermes 比較七個 base models，並固定 MiniMax-M2.7 比較四個 frameworks。Hermes+ 在 Plan 加入 consultation check（E1）、Render 使用 typed memory bindings（E2）、Route 建立 ranked/patchable skills（E3）、Gate 強制 retrieval-before-answer（E4）、Close 執行 authoritative overwrite 與 synchronous flush（E5），再以單機制 ablation、full combination、focused interaction 與跨模型測試分析。Task score 使用 LLM judge；論文另報告三次 runs 的均值與標準差。

## 關鍵結果

| 比較設定 | Memory Δ | Procedural Δ | Information Δ | Update Δ | Overall Δ | Mech. |
|---|---:|---:|---:|---:|---:|---:|
| Hermes + GLM-5.1 | +0.23 | +0.09 | +0.11 | +0.36 | +0.20 | 0.70 |
| Hermes + Kimi K2.6 | +0.33 | +0.03 | +0.05 | +0.27 | +0.17 | 0.72 |
| Hermes + GPT-5.4 | +0.37 | +0.19 | +0.07 | +0.34 | +0.24 | 0.80 |
| Hermes + Claude Sonnet 4.6 | +0.32 | +0.10 | +0.10 | +0.29 | +0.20 | 0.76 |
| Hermes（MiniMax-M2.7） | +0.26 | +0.05 | +0.09 | +0.12 | +0.13 | 0.64 |
| Hermes+（MiniMax-M2.7） | +0.27 | −0.02 | +0.12 | +0.24 | +0.15 | 0.73 |

作者報告：七個 base models 在 Hermes 上的 Overall Δ 為 +0.13 至 +0.24；固定 MiniMax-M2.7 比較 frameworks 時，nanobot、ZeroClaw、Agent-Zero、Hermes、Hermes+ 的 Overall Δ 分別為 +0.13、+0.12、−0.08、+0.13、+0.15，Mechanism evidence 分別為 0.57、0.55、0.39、0.64、0.73。Hermes+ 相較 Hermes 的 Overall Δ 平均值為 +0.15 對 +0.13，但三次 run 的差異小於 run-to-run variation（Hermes +0.13±0.04；Hermes+ +0.15±0.06），作者不將其解讀為穩定的整體提升。Update gap 則由 +0.12 提升至 +0.24。Hermes+ 每 episode 約使用 31,859 tokens，Hermes 為 12,615；wall-clock time 分別為 77.4 秒與 70.5 秒。

## 對我們的啟發
- [ ] 實務部署 persistent agent 時，不應只比較跨 session 的任務成功率；應同時記錄 memory write/read、skill reuse、session search、artifact diff 與 update events，以確認收益是否來自預期的 persistence pathway。
- [ ] 評估應採用 matched persistence-on/off 設計，並加入 no-retention、distractor、stale 與 wrong-mechanism controls，降低 prompt shortcut、錯誤來源與過時記憶造成的誤歸因。
- [ ] 整體平均 gain 可能掩蓋能力間的回歸，因此應分別檢視 memory、procedural reuse、information gathering、update；Hermes+ 的結果也顯示，結構化狀態與 closeout/update 流程對過時資訊替換特別重要。

## 限制與未來工作

論文將 PAST-Bench 定位為 initial foundation，task suite 的 ecological validity 與 temporal scope 仍有限，未來需擴大場景與長期評估。Hermes+ 的整體 +0.02 差異小於 run-to-run variation，且 Procedural 在部分設定下降、跨模型轉移不一致。Mechanism evidence 需要可觀測 telemetry；黑箱 agent 只能計算 task score 與 Δ。
