# Hierarchical Graph Memory for LLM Agents with Path-level Localization and Rewrite

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.05095)
- 📥 [PDF](https://arxiv.org/pdf/2608.05095v1)

## 摘要（中文翻譯）

長期推理的 Agent 需要能隨著新事實與外部回饋持續到來而高效、有效更新的記憶。近期方法採用 graph memory，以結構化方式支援 multi-hop retrieval 與 reasoning；然而，現有方法通常將所有記憶存放於 flat graph 中，累積的歷史記憶會引入不相關 context，並提高 evidence selection 的 retrieval 成本。此外，這些方法多半獨立更新各個 memory unit，若相關變化涉及多個單元，便需要反覆進行 unit-wise rewrite。為此，本文提出 HiGram，一個具備 path-level localization 與 rewriting 的 evolving hierarchical graph memory framework。HiGram 以由上層節點與 MemoryUnits 組成的 coarse-to-fine 架構組織記憶，以減少 retrieval 時的不相關資訊；再透過 query-與 update-conditioned MicroGraph 定位 support subgraph 與 evidence path；最後，在局部證據路徑內協調更新 intra-unit memory 與 inter-unit dependencies。LoCoMo 與 MemConflict 實驗顯示，HiGram 在 answer quality、token efficiency，以及 dynamic、static、conditional conflicts 下的 answer accuracy 與 query-valid evidence selection 均優於基線。

## 問題背景

長期記憶持續累積新事實、修正與回饋，但現有 graph memory 多採 flat graph，搜尋整體歷史記憶會帶入不相關 context，增加 evidence selection 與 token 成本。另一方面，現有更新通常逐一修改 MemoryUnit，無法一次處理沿證據路徑傳播的依賴變化，可能留下過時依賴，因而需要重複 rewrite。

## 解決方案

作者提出 HiGram，將記憶組織成由 subject、object category、context 等 upper-level nodes 及細粒度 MemoryUnits 組成的 hierarchical graph memory。其核心是 MicroGraph-based path-level localization：由 query 與 update 建立 temporary MemoryUnits，抽取 anchors，選取相關 MicroGraphs 與 support subgraph，再從中定位受影響的 evidence path。之後採用 coordinated rewriting，在同一局部路徑內同步更新 MemoryUnit 內部狀態與 inter-unit dependencies，保留歷史狀態並移除不再被有效證據支持的依賴。

## 核心貢獻
1. 提出 HiGram hierarchical graph memory，以 subject、object category 與 context 上層節點組織細粒度 MemoryUnits，形成 coarse-to-fine 的記憶存取結構。
2. 提出 MicroGraph-based path-level localization，根據 query 與 update 建立 temporary MemoryUnits、抽取 anchors，先選擇相關 MicroGraphs 與 support subgraph，再定位受影響的 evidence path。
3. 提出 coordinated rewriting，在局部 evidence path 內同步修訂 MemoryUnit 的內部狀態與 MemoryUnit 間的 dependency structures，以維持有效的證據依賴。

## 技術方法

HiGram 維護階層式 graph memory G_t=(V_t,E_t)。節點包含 subject nodes、object-category nodes、context nodes 與 MemoryUnits；邊包含三類上層組織連結及 MemoryUnit 之間的 directed dependency edges。每個 MemoryUnit 保存 subject、relation、object、object category、transaction time、context、confidence、current status 等資訊；status 可為 active、superseded、outdated 或 pending，非 active 單元保留歷史但不參與 localization。給定 query q_t 與 update u_t，系統先建立不直接寫入圖中的 temporary MemoryUnits，抽取 subject/object-category anchors，依 anchor matching 與 object-category compatibility 選取 top-K_g MicroGraphs，組成 support subgraph。接著在其中枚舉最多 K_p 條由 dependency 或有效結構關係連接的 MemoryUnit paths，依 attribute matching、dependency consistency、temporal validity 與 contextual compatibility 評分，選出同時受 query 與 update 影響的 evidence path。Rewrite 階段先進行 intra-unit rewriting，匹配並更新既有單元狀態與 valid-time，或提交新 MemoryUnit；再進行 inter-unit rewriting，檢查下游依賴是否仍獲有效證據支持，必要時標記為 outdated，兩者在同一局部區域內共同更新。實驗使用 LoCoMo 的 Single Hop、Multi-Hop、Open Domain、Temporal、Adversarial 類別，以 token-level F1、BLEU-1、LLM-J 與 Token Length 評估；MemConflict 則使用 Dynamic、Static、Conditional conflicts，指標包括 AA、UOCS、CRS、Macro-AA、SEH@3 與 SRS。預設 h=3、K_g=12、K_p=24。

## 對我們的啟發
- [ ] 實務上可將長期記憶的 retrieval 與 update 都限制在 query/update 共同定位的局部證據區域，以降低歷史記憶累積造成的 context 與 token 成本。
- [ ] 對會產生推論依賴的記憶，不宜只更新單一事實；應同步檢查下游依賴是否仍由有效證據支持，並將失效單元排除於 active evidence view。
- [ ] 若系統需要處理時間、條件或衝突資訊，可保留 superseded、pending 與 outdated 狀態，而非直接覆寫歷史記錄；但應以明確的 validity scope 與 dependency revision 控制當前可用證據。

## 限制與未來工作

論文僅在 LoCoMo 與 MemConflict 上評估，且主要使用 GPT 系列模型；對 MicroGraph、path scoring 與 rewriting 的實作細節及完整消融數據揭露有限。作者指出，HiGram 尚未整合 external knowledge 與 multimodal memory，並將其列為未來工作。
