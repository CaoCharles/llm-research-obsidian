# LitTraceQA: A Benchmark for Multi-Stage Grounding and Verification in Scientific Question Answering

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.07370)
- 📥 [PDF](https://arxiv.org/pdf/2608.07370v1)

## 摘要（中文翻譯）

科學文獻日益成為 language models、retrieval-augmented generation（RAG）系統與研究助理的知識來源，但根據論文回答研究問題不只是產生流暢文字。可靠系統必須找出相關論文、定位支持答案的具體證據，並確保回答忠實於證據。本文提出 LitTraceQA，一個針對科學論文的 literature-grounded question answering benchmark。系統接收研究問題與論文 metadata pool，需輸出三項相互連結的結果：canonical paper identifiers、supporting evidence locations，以及指定格式的答案，包括自由文本、multiple-choice 與 structured tables。基準涵蓋 tables、figures、text spans、equations or algorithms，以及 citation contexts 等證據類型。公開 development split 有 55 題；較大的最終標註集合則包含 4,978 個 unique questions、4,859 篇 gold papers。LitTraceQA 分別評估論文檢索、證據 grounding 與答案正確性，測試系統能否產生可驗證而非缺乏支持的科學回答。

## 問題背景

現有 scientific QA benchmark 常只評估答案正確性，或預先提供來源論文，因此無法判斷系統是否找對論文、定位到真正支持答案的證據。科學問題又常涉及跨論文數值比較、表格、圖形、方程式、演算法細節與 citation context；流暢但錯誤或無依據的回答可能被 answer-only 指標誤判為成功。LitTraceQA 要解決的是完整且可驗證的 retrieval-to-grounding-to-answer 評估問題。

## 解決方案

作者提出 LitTraceQA 的 traceable literature-grounded QA 框架。每筆資料以 research question 為中心，將 gold paper identifiers、typed evidence items、locators 與 requested-format answer 組成可檢查的 gold trace。任務同時涵蓋 hidden-source single-paper 與 multi-paper QA，並保留 table、figure、text、equation/algorithm、citation context 等證據型態。其核心創新不是新的模型架構，而是把 paper retrieval、evidence grounding 與 answer correctness 設為明確且相互依賴的輸出與評估階段，配合 strict conjunction 和 oracle diagnostic settings，定位系統失敗來源。資料建構則以 open-book 生成、grounding 驗證及 closed-book hardness filtering 提升可檢查性與難度。

## 核心貢獻
1. 將科學論文問答明確建模為 paper retrieval、typed evidence grounding 與 answer generation 三階段串聯任務，要求系統同時輸出論文識別碼、證據位置與答案。
2. 涵蓋 table、figure、text span、equation/algorithm、citation context 五類科學閱讀中常見的證據，並支援自由文本、multiple-choice 與 structured table 等答案格式。
3. 建立具 closed-book hardness filtering 與結構化驗證資訊的資料建構流程，並提出分階段、strict joint success 及 oracle diagnostic ladder 評估協定。

## 技術方法

LitTraceQA 將輸入定義為 query id、自然語言 question、answer types，以及固定的 paper metadata pool P；multiple-choice 題提供選項，table 題提供 schema 與 row alignment 規則。系統必須輸出預測論文集合 P̂、證據集合 Ê 與答案 â。資料建構採 generate–ground–challenge 流程：先從 27,487 筆近期 machine learning、computer vision 與 NLP 論文 metadata 及可檢索的 local text cache 選取候選論文；open-book generator 讀取論文內容，依序涵蓋五種 primary evidence type，生成自包含問題、gold papers、typed evidence、locator 與答案。接著以 automated grounding checks 確認每筆證據屬於宣告的 gold paper，且文字或數值可由 local paper text 找回；再將同一問題交給無論文內容的 GPT、Claude 與 Gemma challengers，移除可由記憶或猜測可靠回答的案例。評估分三層：paper retrieval 使用 canonical ID 的 question-level Precision、Recall、F1，亦可用 Recall@K、MRR、MAP、nDCG；evidence grounding 對 paper ID、source type、page 與 table/figure object ID 做 coarse exact match 或 set-level F1；answer correctness 依格式使用 multiple-choice accuracy、free-form exact match，以及 structured table 的 row F1 與 cell accuracy。另提供 end-to-end、oracle paper、oracle evidence 三種設定；strict joint success 要求三個階段皆正確，而非將分數平均。

## 關鍵結果

論文主要報告資料集組成與建構期 hardness 統計，未報告正式 retrieval-augmented baseline 的具體性能比較。

| 指標 | 數值 |
|---|---:|
| 公開 development split | 55 題 |
| 其中 hidden-source single-paper / multi-paper | 26 / 29 題 |
| 最終 unique questions | 4,978 |
| unique gold papers | 4,859 |
| gold-paper links | 8,612 |
| 平均每題 papers / evidence items | 1.73 / 2.62 |
| multi-paper questions | 3,228（64.85%）|
| single-paper questions | 1,750（35.15%）|
| multiple-choice / structured table | 3,029（60.8%）/ 1,949（39.2%）|
| table / figure / text span 題目 | 1,339（26.9%）/ 1,132（22.7%）/ 933（18.7%）|
| equation-algorithm / citation-context 題目 | 819（16.5%）/ 755（15.2%）|
| 所有 closed-book challengers 答錯 | 3,080（61.9%）|
| 恰有一個 challenger 答對 | 1,898（38.1%）|

上述 challenger 結果是資料建構時的閉卷難度篩選，不是正式 RAG 系統 leaderboard 結果；論文亦明確指出尚未提供 baseline retrieval-augmented systems 的評估數據。

## 對我們的啟發
- [ ] 實務上的 RAG 評估不應只計算答案 accuracy；應同步檢查 retrieved paper、證據類型與 locator 是否真正支持答案，才能區分 retrieval、grounding 和 generation 錯誤。
- [ ] 對跨論文比較任務，應以 paper 或 method 作為結構化 row key，將每個數值綁定到來源論文與證據位置，以降低跨來源數字錯配與 citation-attribution drift。
- [ ] 可採用 oracle paper 與 oracle evidence 測試建立診斷階梯：若 oracle evidence 下仍錯，問題主要在答案推理或格式化；若 oracle 設定顯著改善，則應優先提升檢索或證據定位。

## 限制與未來工作

目前集合仍需正式 benchmark release 才完整：evidence locator 尚未對各類型充分標準化，官方 train/dev/test 或 hidden split 尚未定義，single-paper 子集的定位需釐清，授權與資料再發布狀態需文件化。另缺乏充分 human quality control、專家抽查與 inter-annotator agreement；資料集中於 ICCV、NAACL、ACL 等近期 2024–2025 venue，存在領域與 venue imbalance。
