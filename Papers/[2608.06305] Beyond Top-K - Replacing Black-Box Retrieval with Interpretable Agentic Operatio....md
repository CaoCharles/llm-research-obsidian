# Beyond Top-K: Replacing Black-Box Retrieval with Interpretable Agentic Operations

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.06305)
- 📥 [PDF](https://arxiv.org/pdf/2608.06305v1)

## 摘要（中文翻譯）

長文件 Retrieval-augmented generation（RAG）目前主要採用固定切分文字、對 chunks 建立 embeddings，再呈現 query 的 top-k nearest neighbours。本文指出，對 financial statements、audit reports 與 regulatory returns 等文件，此設計在結構上不可靠。以一份 780 頁政府財務報告為例，86.8% 的內容行是表格列，數千個近似數字在同一 embedding space 中競爭；數字所繼承的單位標頭距離中位數為 13 行，chunk boundary 經常將數字與 lakh 或 crore 單位分開，造成兩個數量級的歧義。即使 table-aware chunker 修正單位問題，仍有 27–30% 的 numeric chunks 缺少 fiscal-year header。作者提出 READ（Reliable Embedding-free Agentic Document-search），讓 agent 透過 normalized lexical search、structural navigation 與 bounded span reads 直接讀取原始文件，並以 Model Context Protocol（MCP）提供可重播的 audit trail。在 51 題驗證問題上，READ 達 58.8%，dense retrieval 為 15.7%；調參後 dense 最佳為 35.3%，READ 仍高 23.5 個百分點。相同 agent 配合 top-k 工具僅達 27.5%，但 BM25 與 READ 無統計顯著差異，因此證據支持的是 embedding-based 與 embedding-free retrieval 的區分，而非 agentic search 勝過 lexical search。

## 問題背景

現有長文件 RAG 多以固定 chunk、embedding 與 top-k retrieval 將文件壓縮成少量相似片段。對財務報表等以表格布局、欄位、單位與 fiscal year 表達意義的文件，chunk boundary 可能分離數字與其 governing header；大量近似數字也會造成向量檢索混淆。即使改善 chunker，固定 partition 仍難在 query 產生後動態取得跨頁、跨列的完整證據，並且 retrieval rationale 不透明、難以審計。

## 解決方案

作者提出 READ（Reliable Embedding-free Agentic Document-search），將 retrieval interface 從不可檢查的 similarity-ranked top-k chunks 改為直接操作未切分的文件。READ 透過 MCP 暴露 normalized lexical search、structural navigation（list/outline）與 bounded span read；agent 先搜尋可猜測的文字或數字錨點，再查看行號與文件結構，向上或向外擴展讀取範圍以納入單位、年份與表格上下文，並可反覆修正查詢。每個 operation 都是文件與參數的 deterministic pure function，故 trajectory 可重播、引用與機械檢查。核心創新不是單純增加迭代，而是讓 agent 擁有 span-addressed、結構可見且可審計的原始語料介面；控制實驗也顯示，同一 agent 改用 top-k vector tool 時，效果明顯下降。

## 核心貢獻
1. 在真實的 780 頁政府財務報告上，量化表格比例、數字重複與單位標頭繼承距離，將 chunking 破壞結構語意的問題轉化為可測量現象。
2. 建立 table-aware chunker 作為 dense retrieval 的 steelman baseline；其將 unitless numeric chunks 在 2,000 字元設定下由 18.0% 降至 0.3%，但 fiscal-year header 缺失仍約 28.9%。
3. 提出 READ embedding-free agentic document-search interface，結合 normalized lexical search、outline/structural navigation 與 bounded line-span reads，並以 MCP 暴露可重播、可引用的檢索軌跡。

## 技術方法

研究以 Gujarat Finance Accounts 2024–25 Volume I 為 testbed：原始 PDF 為 780 頁，轉成 Markdown 後有 19,198 個非空行、1,683,730 個字元、16,664 個 table rows、58,791 個 numeric tokens。作者先分析 tabularity、numeric repetition，以及數字到 governing unit header 的距離，再比較 fixed-size chunker 與會向前回溯攜帶 unit/fiscal-year header 的 table-aware chunker。READ 不建立 embedding 或 vector index，而以 MCP server 提供四類工具：normalized grep、list、outline 與上限 400 行的 read。Agent 先以 lexical anchor 搜尋，再利用 line number 與 outline 定位結構，最後讀取足以涵蓋 header 的 bounded spans，必要時重複搜尋與縮放範圍。評估比較 READ、literal/naive grep、移除 outline 的 ablation、dense top-k、BM25、hybrid、agentic RAG（向量搜尋工具）、oracle chunks 與 long-context baseline；所有系統使用 gemini-2.5-pro，dense retriever 使用 bge-base-en-v1.5。51 題涵蓋 lookup、arithmetic、aggregation、navigation、unanswerable 與 conversion-limited。指標包括 deterministic exact-figure accuracy、固定的 LLM judge、機械式 groundedness、hallucination rate、evidence coverage、tool calls、tokens、成本與 latency。主要比較採 paired exact McNemar test、Holm correction、Wilson confidence intervals 與 paired bootstrap。

## 關鍵結果

| 系統 | Accuracy | Groundedness | Hallucination（5 題不可回答問題） | 每題成本 |
|---|---:|---:|---:|---:|
| READ | 58.8% | 58.0% | 40% | $0.058 |
| Dense，2,000 字元、k=8 | 15.7% | 47.9% | 80% | $0.023 |
| Dense 最佳調參，2,000 字元、k=16 | 35.3% | 論文未報告 | 論文未報告 | $0.029 |
| Agentic RAG／top-k tool | 27.5% | 42.6% | 0% | $0.050 |
| BM25 | 51.0% | 67.3% | 40% | $0.020 |
| Hybrid | 29.4% | 72.0% | 60% | $0.022 |

READ 相較原始 dense 的 paired accuracy 差異為 +43.1 個百分點，Holm 校正後 p=0.00002；相較最佳 dense 設定仍為 +23.5 個百分點，p=0.017。READ 與 BM25 的 7.8 個百分點差異不具統計顯著性（p=1.00），所以論文不支持「agentic search 勝過 lexical search」的較強結論。

## 對我們的啟發
- [ ] 對 exactness-critical 的財務文件，應優先保留原始行序、表格結構與可向上延伸的 header context，而不是只依賴固定 chunk 與向量相似度。
- [ ] 若採用 agentic retrieval，應記錄每次搜尋、導航與讀取的參數及原文行號，讓答案的 evidence chain 能被第三方重播與審計。
- [ ] 實務選型不應只看 accuracy：READ 每題成本為 $0.058、dense 為 $0.023，且 BM25 為 51.0% accuracy、成本 $0.020；因此低成本 lexical baseline 必須納入比較。

## 限制與未來工作

研究只使用一份 Gujarat Finance Accounts 2024–25、單一 backbone 與 51 題問題，外部有效性有限；題目由系統作者建立，且 benchmark 曾在實驗期間非盲目擴充，存在選擇偏差。READ 成本與延遲較高，groundedness 也不如 BM25 與 hybrid。PDF conversion damage、單一 converter，以及對能規劃工具呼叫的模型依賴，仍需在多文件、多模型與更大規模 benchmark 上驗證。
