# Beyond Top-K: Replacing Black-Box Retrieval with Interpretable Agentic Operations

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2608.06305)
- 📥 [PDF](https://arxiv.org/pdf/2608.06305v1)

## 摘要（中文翻譯）

長文件的 Retrieval-Augmented Generation（RAG）主要採用固定切分文字、對 chunks 建立 embeddings，再提供 query 的 top-k 近鄰。作者指出，對財務報表、審計報告與監管申報等文件，這種設計具有結構性缺陷：在一份 780 頁政府財務報告中，86.8% 的內容行是表格列，數千個相似數字共同競爭於 embedding 空間；數字所繼承的單位標頭距離中位數為 13 行，chunk 邊界經常將數值與 lakh 或 crore 單位分離，造成兩個數量級的歧義。即使採用 table-aware chunker，仍有 27–30% 的數字 chunks 缺少財政年度標頭。作者提出 READ（Reliable Embedding-free Agentic Document-search），讓 agent 透過 normalized lexical search、structural navigation 與 bounded span reads 直接讀取原始文件，並以 Model Context Protocol（MCP）提供可重播的審計軌跡。在 51 道驗證題上，READ 準確率為 58.8%，dense retrieval 為 15.7%；調優後 dense 為 35.3%，READ 仍高出 23.5 個百分點。相同 agent 搭配 top-k 工具僅得 27.5%，但 BM25 與 READ 的差異未達統計顯著，因此證據支持的是 embedding-based 與 embedding-free retrieval 的區別，而非 agentic 與 lexical search 的區別。

## 問題背景

傳統 RAG 將長文件預先切成固定 chunks，再以 embedding 選取 top-k；這對以表格、欄位、單位與年度標頭承載語意的財務文件並不穩健。數值與其 governing header 可能被切開，相似數字也容易在 embedding 空間競爭；固定 k 還無法依問題需要動態擴展證據範圍，導致漏檢、單位誤讀與無根據回答。

## 解決方案

作者提出 READ（Reliable Embedding-free Agentic Document-search），不對文件建立 embedding index，而讓 tool-calling agent 直接操作保留行號與結構的原始 Markdown。核心操作包括 normalized lexical search、結構導覽（list／outline）與 bounded span read。Agent 先以可猜測的詞彙或數字定位候選行，再查看段落與標題位置，向上或向外擴展讀取範圍以取得單位、年度和欄位脈絡，最後輸出帶有行號引用的答案。創新不只在於 agent 迭代，而在於把 retrieval API 改成可組合、deterministic、span-addressed 的文件操作，使整條證據鏈可重播與審計。

## 核心貢獻
1. 在真實的 780 頁政府財務報告上量化結構性檢索問題：86.8% 為表格列、數字重複比為 3.68 倍，且單位標頭距離數字列的中位數為 13 行。
2. 建立 table-aware chunker 作為 dense RAG 的強基準，將 2,000 字元 chunks 的 unitless 比例由 18.0% 降至 0.3%，同時揭示約 28.9% 的 numeric chunks 仍缺少 fiscal-year header。
3. 提出 READ embedding-free agentic document-search 介面，以 normalized grep、outline/list 結構導覽及受限 read 操作支援可引用、可重播的檢索軌跡，並以 AgenticVec 控制實驗區分迭代能力與檢索介面效果。

## 技術方法

研究將 780 頁 Gujarat Finance Accounts 2024–25 轉換為 Markdown，共 19,198 個非空行、1,683,730 個字元、189 個 section headers、16,664 個 table rows 與 58,791 個 numeric tokens。作者先分析表格比例、數字重複，以及數字列到最近 unit header 的距離，再比較 fixed-size chunker 與會向前攜帶 unit／fiscal-year header 的 table-aware chunker。READ 不建立 embedding 或 vector index，而是透過 MCP 提供四類唯讀工具：normalized grep、list、outline 與最多 400 行的 read。Agent 依序提出 lexical anchor、搜尋行號、利用結構定位、讀取 bounded span，必要時再修正搜尋；每次操作皆為文件與參數的 deterministic pure function，因此可重播並附帶 line citations。normalized matching 使用 Unicode NFKC、去除 emphasis markers、case folding，並建立 spaced 與 squashed 兩種 shadow forms，以處理 PDF 轉換造成的表格 cell 分隔、單字切分及數字千分位問題。比較系統包括 READ、其 literal／no-outline ablations、dense retrieval、BM25、hybrid、AgenticVec、oracle chunks 與 long-context；生成模型與 answer format 共用，dense 使用 BAAI/bge-base-en-v1.5。51 題涵蓋 lookup、arithmetic、aggregation、navigation、unanswerable 與 conversion-limited。評估包含 deterministic exact-figure accuracy、固定的 LLM judge、機械式 groundedness、hallucination、證據覆蓋率、tool calls、tokens、成本與延遲；統計採 paired exact McNemar、paired bootstrap confidence intervals，並以 Holm correction 修正多重比較。

## 關鍵結果

| 系統／設定 | 準確率 | Grounded | Hallucination（5 道不可回答題） | 成本／題 |
|---|---:|---:|---:|---:|
| READ | 58.8% | 58.0% | 40% | $0.058 |
| Dense，2,000 字元、k=8 | 15.7% | 47.9% | 80% | $0.023 |
| Dense 最佳調優，2,000 字元、k=16 | 35.3% | 論文未報告 | 論文未報告 | 約 $0.029 |
| Agentic RAG／top-k tool | 27.5% | 42.6% | 0% | $0.050 |
| BM25 | 51.0% | 67.3% | 40% | $0.020 |
| Hybrid | 29.4% | 72.0% | 60% | $0.022 |

READ 相對於 dense（k=8）高 43.1 個百分點，Holm 校正後 p=0.00002；相對最佳 dense 設定仍高 23.5 個百分點，p=0.017。相同 agent 改用 top-k 工具後僅得 27.5%，READ 領先 31.4 個百分點，p=0.012。BM25 為 51.0%，與 READ 的 7.8 個百分點差異不顯著（p=1.00）；作者明確指出，51 題不足以支持兩者等價。READ 在 lookup 題達 70.8%，dense 僅 12.5%。

## 對我們的啟發
- [ ] 對財務與監管文件，檢索單位不應只按固定字元長度切分；應保留表格、單位、年度與欄位脈絡，或允許模型在定位證據後動態擴展 span。
- [ ] 評估 RAG 時應同時檢查 evidence 是否被檢索、答案是否 grounded，以及 PDF conversion 是否已破壞來源資訊；否則可能把轉換錯誤誤歸因於 retriever。
- [ ] 在表格數字具有高詞面重複的場景，應把 BM25 或其他 embedding-free lexical 方法作為嚴格基準。本文結果顯示 BM25 與 READ 未呈現顯著差異，因此不能僅憑 READ 的結果宣稱 agentic search 優於 lexical search。

## 限制與未來工作

研究只使用一份 Gujarat Finance Accounts 2024–25、單一 PDF converter、單一 backbone 與 51 題，外部效度有限。題目由系統作者建立，且 benchmark 曾非盲目擴充，存在選題偏差。READ 成本與延遲高於 dense、BM25，groundedness 也不最高；BM25 與 READ 的差異尚未被可靠解析。
