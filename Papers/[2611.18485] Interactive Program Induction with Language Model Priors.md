# Interactive Program Induction with Language Model Priors

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2611.18485)
- 📥 [PDF](https://arxiv.org/pdf/2611.18485v1)

## 摘要（中文翻譯）

Program induction 是指學習者根據少量 input-output examples 還原程式。此典範讓使用者只需示範規則行為，便能將其套用到未見資料，而不必自行實作。然而，有限 examples 在理論上同時符合無限多個、且在未見輸入上可能產生不同輸出的程式，因此問題具有根本歧義。本文採 Bayesian perspective：給定程式 prior p⁰，透過額外 input-output examples 使 posterior 集中於目標程式。於 interactive program induction 中，學習者選擇資訊量最大的輸入並向 oracle 查詢輸出。作者推導 greedy query-selection algorithm，證明在每個答案至少攜帶 γ bits 資訊時，最多需 O((1/γ)log(1/p⁰(f⋆))) 次查詢，並在沒有其他等價類別的 prior mass 超過目標類別時，近似辨識目標程式。方法以 language model 作為 prior，在 PAC-style program equivalence 下，透過 importance sampling 估計查詢目標。在 CodeARC 上，相較 LM-only agent，準確率最高提升 22 個百分點，並最多少觀察 10.5 個 input-output examples。

## 問題背景

論文處理從少量 input-output examples 還原一般用途程式的互動式程式歸納問題。有限觀測無法唯一決定目標，傳統方法通常依賴限制表達力的手工 DSL，且一次性 LLM program induction 缺乏系統化查詢策略與理論保證。作者進一步指出，exact program equivalence 不可判定，必須同時處理無限程式空間、有限 oracle 預算與未見輸入上的泛化。

## 解決方案

作者將 interactive program induction 形式化為 Bayesian active learning：以 language model 對程式的機率分布作為 inductive prior，從候選 evaluation set 中選擇使目標程式 equivalence classes 預期 entropy reduction 最大的輸入，向 oracle 取得輸出後更新 posterior。演算法在某一類別的 posterior mass 超過 1/2 時停止。為處理 posterior 與 class entropy 不可直接計算的問題，作者以 LM conditioned proposal 產生程式 particles，利用 self-normalized importance sampling 修正 prior/proposal 差異，並依 evaluation set 上的行為將實作合併為類別。核心創新是把 LLM 的程式生成能力轉化為可分析的 prior、proposal 與資訊導向查詢機制。

## 核心貢獻
1. 將一般用途語言中的 interactive program induction 建模為 Bayesian active learning，並以 program equivalence class 作為推論目標。
2. 提出以 expected information gain 選擇 oracle query 的 greedy 演算法，並證明其 query complexity、終止與近似正確性結果。
3. 提出以 language model 產生 implementation particles，透過 importance sampling 近似 posterior、predictive distribution 與 equivalence-class entropy，並在 CodeARC 上驗證查詢效率與準確率提升。

## 技術方法

理論上，輸入空間 X 與輸出空間 Y 可為可數集合，目標是固定但未知的 f⋆。程式 prior p⁰ 反映哪些行為較可信，input distribution μ 定義 population error。作者從 μ 抽取 N 個輸入形成固定 evaluation set S，將兩個程式在 S 上完全一致定義為近似 equivalence；若返回目標類別，PAC bound 給出 errμ(f) ≤ [ln(1/p⁰(f))+ln(1/δ)]/N。每輪對 S 中候選輸入計算 equivalence-class posterior 的 expected information gain，選擇 entropy reduction 最大者，取得 oracle 輸出並刪除不一致程式；當某類別 mass 超過 1/2 即停止。實作上，LM 依含 seed examples 與歷史查詢的 prompt 產生 M 個 Python implementations，執行於 S 並依行為分成 classes。初始 prior 為 q₀，後續以 conditioned proposal qₜ 取樣，對一致 particle 使用 p⁰/qₜ 的 importance weight，並以 effective sample size threshold 觸發重抽樣。實驗使用 CodeARC anonymized split 的 1114 個 Python functions，設定 1 或 10 個 seed invocations、總 input-output budget 30；比較 CodeARC LM-only agent 與 EIG、uncertainty、diversity、random 等策略。指標包括 accuracy、平均觀察的 input-output examples、termination、每次查詢的 guaranteed information，以及不同 evaluation set 大小、particle budget 與 prior calibration 的分析。

## 對我們的啟發
- [ ] 在程式歸納或工具使用 agent 中，不應只讓 LLM 自行挑選問題；可依候選行為分歧計算 expected information gain，優先查詢能排除最多假設的輸入。
- [ ] evaluation set 的大小存在明確取捨：較小集合節省計算並容易形成粗粒度類別，但可能過早接受錯誤程式；較大集合提高泛化可靠性，卻降低目標類別被粒子覆蓋與收斂的機率。
- [ ] LLM prior 的校準直接影響 Bayesian 互動推論；實務部署應監測 prior majority class 的 calibration，增加多樣化 proposal、調整 sampling temperature，或避免錯誤高先驗類別過早取得多數。

## 限制與未來工作

方法的理論保證建立在 exact posterior、目標具正 prior mass、有限 evaluation set 與每次查詢至少有 γ bits 資訊等條件；有限 particles、proposal 支持不足與 prior miscalibration 會造成漏掉目標類別或錯誤早停。實驗僅使用 CodeARC、Python 與 deterministic oracle，且以固定 μ 定義等價；作者尚未實驗 noisy human oracle、其他程式語言或更廣泛任務。
