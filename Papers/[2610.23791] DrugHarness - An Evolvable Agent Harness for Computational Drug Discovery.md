# DrugHarness: An Evolvable Agent Harness for Computational Drug Discovery

## 連結
- 📄 [arXiv](https://arxiv.org/abs/2610.23791)
- 📥 [PDF](https://arxiv.org/pdf/2610.23791v1)

## 摘要（中文翻譯）

Computational drug discovery 需要 agents 組合科學操作，並適應持續變化的證據與限制。本文提出 DrugHarness，一個可演化的 agent harness，結合可組合的科學執行與條件式 skill induction。其環境整合超過 80 項科學操作、生物醫學資源及任務專用程式碼，並維持候選分子、結果與產物之間的關聯。系統由執行軌跡與結果回饋誘導具備可觀察適用條件、建議行動及支持證據的 action hypotheses，再由獨立 review agent 透過來源驗證及必要的 targeted execution trials 評估候選 skills。通過審查的 skills 會引導後續任務，並依回饋修訂。在 MolBench 與 SMDD-Bench 上，系統展現分子篩選、最佳化及受限設計能力；在 HPK1 前瞻研究中，合成化合物的 cellular IC50 為 14.19 nM，較最佳輸入參考提升 2.64 倍效力。

## 問題背景

藥物發現 agent 必須協調文獻、資料庫、分子表示、預測器與程式工具，依中間結果決定檢索、候選修改及計算流程。現有方法雖能整合工具或重用經驗，卻未充分處理三項問題：推薦是否由正確證據支持、來源策略在不同候選狀態與限制下是否仍適用，以及建議是否可執行、可驗證並能依後續結果修訂。

## 解決方案

作者提出 DrugHarness，將 composable scientific execution 與 conditional skill learning 統一於共享科學工作區。執行器可組合超過 80 項操作，並把候選、觀測、計算條件、來源、結果及交付物建立可追蹤關聯。學習器比較任務軌跡與允許的 outcome feedback，產生包含目標、可觀察適用條件、替代與推薦行動、來源及未解問題的 action hypothesis。獨立 review agent 檢查來源、科學前提與可執行性，必要時重現、消融或比較試驗；只有通過審查的 skill 才會部署，之後再由新軌跡與回饋修訂。

## 核心貢獻
1. 建立可組合的 computational drug discovery execution environment，整合超過 80 項科學操作、生物醫學資源與任務程式碼，並維持候選、結果及 artifacts 的關聯。
2. 提出 evidence-reviewed conditional skill evolution：從執行經驗誘導具適用條件與證據的 action hypotheses，由獨立 reviewer 進行來源核驗與 targeted trials，再以後續回饋修訂。
3. 以 MolBench、SMDD-Bench、回溯 skill evaluation 及前瞻 HPK1 實驗驗證，展示從 benchmark 任務到合成分子 cellular potency 的完整工作流程。

## 技術方法

系統包含科學執行與 skill 演化兩部分。執行環境提供十類、超過 80 項 agent-accessible operations，涵蓋證據檢索、標的與結構準備、virtual screening、de novo design、property prediction、multi-objective optimization、結構編輯、retrosynthesis 及評估；工具包括 BindingDB、RDKit、ADMET-AI、Boltz-2 與 scientific Python environment。每筆 experience 由任務目標與限制、action-observation 軌跡、deliverable 及允許的 outcome feedback 組成。學習器比較科學物件、endpoint、方法與當時證據狀態，形成 hypothesis h=(goal, condition, current action, recommended action, sources, unresolved information)，再編輯為候選 skill。獨立 reviewer 驗證來源與介面，必要時執行 reproduction、ablation 或 comparison trial，結果為 admit、reject 或 defer。任務內固定 skill version；executor 根據可見狀態判斷條件為 supported、contradicted 或 unknown。評估使用 MolBench 的 screening、affinity-comparison accuracy、Hits@3、GT rank、editing 與 optimization 指標，以及 SMDD-Bench 的任務成功率；另比較 HPK1 候選 docking、抑制預測與實驗 cellular IC50。論文未報告 DrugHarness 內部基礎模型的自訂神經網路架構；實驗使用 Codex、Hermes、Qwen 與 GPT-5.6 Terra 等配置。

## 關鍵結果

主要結果如下（數值均依論文報告）：

| 評估項目 | 方法／設定 | 結果 |
|---|---|---:|
| MolBench affinity-comparison accuracy | DrugHarness（w/o Evol.），Codex/GPT-5.6 Terra | 91.9% |
| MolBench affinity-comparison accuracy | MolClaw-CC 報告值 | 81.1% |
| MolBench mean Hits@3 | DrugHarness（w/o Evol.） | 1.24 |
| MolBench mean Hits@3 | MolClaw-CC | 0.80 |
| MolBench screening accuracy | DrugHarness（w/o Evol.） | 98.0% |
| MolBench editing | DrugHarness（w/o Evol.） | 39/39 任務成功 |
| MolBench optimization positive improvement | DrugHarness（w/o Evol.） | 94.9%，37/39 |
| Skill evolution：affinity accuracy | Qwen 歷史無 skill → frozen skills | 62.2% → 81.1% |
| Skill evolution：optimization success | 歷史無 skill → frozen skills | 79.5% → 87.2% |
| Skill evolution：valid JSON | 歷史無 skill → frozen skills | 34/39 → 39/39 |
| SMDD-Bench interaction-point discovery | DrugHarness/Codex vs 原 SMDD harness，同為 GPT-5.6 Terra | 28.0% vs 0.0% |
| SMDD-Bench 40 項 lead optimization | DrugHarness/Codex vs 原 SMDD harness | 60.0% vs 50.0% |
| HPK1 median MOE docking score | DrugHarness vs Biomni system-specific candidates | -8.180 vs -7.825 |
| HPK1 synthesized compound cellular IC50 | DrugHarness 設計化合物 | 14.19 nM |
| HPK1 potency improvement | 相對最佳輸入參考 37.47 nM | 2.64 倍 |

作者另報告該化合物在 1 nM 達 96.92% HPK1 inhibition，且 cellular activity 與兩個由具五年以上經驗 medicinal chemists 選出的化合物具競爭力。

## 對我們的啟發
- [ ] 若要讓 agent 經驗可重用，skill 不應只保存抽象建議，還應明確記錄可由 executor 觀察的適用條件、推薦行動、限制與來源。
- [ ] 科學工具鏈需要以候選分子為核心維持 provenance，將生成、預測、結構分析與最終交付物連結到同一物件，才能降低評估與提交對象不一致的風險。
- [ ] 將 skill 部署前的來源檢查與 targeted execution trial 納入流程，有助於把看似合理但未驗證的操作指南轉成可審查、可拒絕及可修訂的 agent 行為規則。

## 限制與未來工作

作者指出，尚未系統比較 runtime、計算成本、資源需求與人類專家。Skill evolution 只在單一 benchmark、有限任務及 retrospective、in-domain 設定下評估，對未見 target 與 task family 的泛化仍未知。實驗驗證規模與 developability 性質覆蓋也有限。未來將加入跨 benchmark、held-out 評估及更廣泛的實驗驗證。
