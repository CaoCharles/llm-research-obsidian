## 重點發現

- 評估 web agent 時不應只報告模型名稱；搜尋引擎、抓取工具、瀏覽流程與失敗處理會大幅改變結果，應固定或明確拆分 model 與 harness 的效應。 — [HyperBrowseComp: A Multilingual and Multimodal Stress Test for Web-Browsing Agents](https://arxiv.org/abs/2610.03574)
- 實務上不應只報告單一 tool naming 或 prompt representation 下的 ASR；至少應加入預先定義的 threat-preserving transformation，並報告 ΔASR 與 confidence interval。 — [Threat-Preserving Representation Sensitivity in Agent-Security Benchmarks](https://arxiv.org/abs/2610.03585)
- 對科學型 agent 而言，工具數量或一般規劃能力不足以保證可靠性；應把方法假設、適用範圍、輸入輸出型別與 provenance 設為可檢查的結構化約束。 — [HazardWeaver: Scientific Route Selection for Hazard Analysis Agents](https://arxiv.org/abs/2610.03591)
- 評估 RL 控制器時，不能只看 episode payoff；應加入同狀態 action RMSE、finite-grid 最優解、local action-ranking 與 Monte Carlo return 診斷，以區分策略表達問題和 value estimation 問題。 — [When a Correct Reward Is Not Enough: Diagnosing and Guiding PPO in an Analytically Solved Broker-Trader Game](https://arxiv.org/abs/2610.03598)
- 若 synthetic data 的目標是涵蓋困難案例，應先控制結構化 SQL complexity，再反向生成自然語言；論文的 SQL→NL ablation 顯示此順序優於 NL→SQL。 — [FALCON: A Model and Dataset Agnostic Framework for Synthetic Data Generation for NL2SQL Pairs](https://arxiv.org/abs/2610.03625)
