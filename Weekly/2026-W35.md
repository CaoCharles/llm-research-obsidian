## 重點發現

- 在受監管環境中，可將 RAG 的 retrieval 能力限制為可重現的特徵工程步驟，避免直接依賴非 deterministic 的 LLM 評分。 — [SENTRY: Deterministic, Intelligent Risk Assessment for IT Change Management](https://arxiv.org/abs/2608.21203)
- 在 biography、privacy leakage、factuality 或 abstention 評測中，應將姓名的公開證據狀態明確分層，避免把真實人物證據與模型 hallucination 或 name prior 混為一談。 — [No PUN Intended: Plausible Unknown Names for Person-Centred LLM Evaluation](https://arxiv.org/abs/2608.21206)
- 在 heterogeneous SDD workflow 中，不應假設 specification 是 agent-neutral；實務上應為不同 implementation agent 建立 portability smoke test 與 native/foreign quality baseline。 — [Specification Portability Across LLM Development Agents: Cross-Agent Compatibility in Specification-Driven Software Migration](https://arxiv.org/abs/2608.21208)
- 實務上的隱私控制不應只依賴情境判斷或 prompt 指令，還需要明確表達並檢驗每位使用者的欄位級允許與拒絕偏好。 — [Personalized Privacy Control in LLMs via Attention Head Intervention](https://arxiv.org/abs/2608.21209)
- 對持久記憶系統不能只測 attack success rate；應同時測 clean utility、utility retained、poison 在 context 中的占比、首位率與 evidence recall，否則可能把系統失效或過度防禦誤判為安全。 — [Utility Under Attack: Agent Memory Poisoning and the Limits of Content Screening and Provenance Ranking](https://arxiv.org/abs/2608.21230)
